# ADR-2026-05-28: Promote 40.50 through 40.90 to Canonical 10/30/50 Layers

## Status

Accepted

## Context

Modules `40.50` through `40.90` completed Phase B executable verification with deterministic and negative-path scenario evidence.

To run `50.05_software_spec_construction_guide.md` in a governance-compliant way, canonical requirement anchors and canonical verification evidence bindings were required before design-spec outputs could be finalized.

## Decision

1. Create canonical requirement anchors in `10_thought_simulator_req` for regulator, tick-cycle, snapshot, event-log, and experiment-runner behaviors.
2. Promote verification capsules, requirement deltas, and JSON evidence artifacts into canonical `30_verification` module folders.
3. Execute 50-band supporting design-spec outputs from canonical inputs, aligned to subsystem numeric bands.
4. Preserve exploratory-to-canonical asymmetry by treating `40.*` content as rationale input only, not formal trace edge endpoints.

## Consequences

- Canonical design construction can proceed using governance-complete source sets.
- Deterministic replay and negative-path obligations now have canonical evidence attachments.
- Future changes to promoted behaviors require updates in canonical 10/30/50 artifacts before release coupling.
