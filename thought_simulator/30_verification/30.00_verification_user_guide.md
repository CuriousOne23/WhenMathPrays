## Purpose

This document defines the standard process and file structure for verification work in the 30-series.

## Role in the Development Flow

The 30-series is the **evidence and verification layer**. It consumes prototypes from the 40-series and design decisions from the 50-series, then produces verifiable results that help mature the 10-series.

## Core Principles

- Verification must be **evidence-based**.
- Every verification document must clearly record the contribution of the **three flows**.
- Failures and partial results are highly valuable and must be documented honestly.

## Three-Flow Documentation Requirement

**All verification documents** (`verification_capsule.md`, `requirements_delta.md`, etc.) **SHALL** include a **Flows Alignment Statement** that explicitly records:

- **Forward Flow**: Which parts were driven by 20-series guidance
- **Backward Flow**: Which parts were driven by previous 40-series evidence
- **Iterative Design Flow**: Which parts were driven by 50-series design decisions

**Agreement Statement**: A short paragraph explaining why the three flows are in agreement (or noting any remaining tension / justification).

This creates a clear breadcrumb trail across the entire project.

## Standard Process

When a 40.xx module reaches sufficient maturity:

1. Create a matching **30.xx** verification subdirectory (e.g., `30.36_gb_prototypes` for `40.36_gb_prototypes`).
2. Create or update the corresponding **10.50.xx** design requirements file.
3. Perform verification and document evidence with the three-flow breakdown.

## Required Files in 30.xx Subdirectory

Every 30.xx verification folder **SHALL** contain at minimum:

- `30.xx_xxx_verification_capsule.md` — Main test results and summary
- `30.xx_xxx_requirements_delta.md` — Mapping to 20-series HLRs with three-flow breakdown
- Optional: Raw JSON run artifacts
