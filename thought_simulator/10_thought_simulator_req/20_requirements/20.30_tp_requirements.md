# 20.30_TP Requirements

## 1. Purpose

This document consolidates the ThoughtPoint (TP) requirements previously distributed across conceptual, architecture, and testing documents.

It defines the canonical TP requirement set for implementation, verification, and traceability.

## 2. TP Identity Requirements

- Every TP must have a unique and stable `tp_id`.
- TP identity must remain deterministic under deterministic execution mode.
- TP identity must be traceable across creation, movement, split, and merge operations.

## 3. TP State and Lifecycle Requirements

- A TP must carry at least:
  - basin affiliation
  - entropy state
  - energy state
  - trajectory history/provenance state
- TP lifecycle operations must include:
  - creation
  - basin movement
  - entropy update
  - tagging
  - splitting
  - merging
  - completion evaluation
- Every TP modification must be observable and logged.

## 4. TP Counter and Determinism Requirements

- TP state counters must increment strictly monotonically for mutating operations.
- Identical deterministic inputs must produce identical TP identity/counter trajectories.
- Determinism checks must include rerun comparison of TP identity and counter progression.

## 5. TP Entropy Requirements

- TP entropy must support representational, predictive, and structural components.
- Entropy components must remain non-negative.
- Entropy updates must be deterministic and reproducible.
- Entropy behavior must remain compatible with TS stability and observability requirements.

## 6. TP Split/Merge Requirements

- Split operations must preserve lineage from parent TP to child TPs.
- Merge operations must preserve lineage from source TPs to merged TP.
- Split/merge operations must be deterministic and fully logged.
- Split/merge error paths (invalid split count, empty merge sources, embedding mismatch) must be validated.

## 7. TP Provenance Requirements

- TP provenance must include creation source semantics.
- TP provenance must record parent IDs for split-created children.
- TP provenance must record merge source IDs for merged TPs.
- Provenance data must be preserved in serialized artifacts and remain lossless across adapters.

## 8. TP Serialization and IO Requirements

- TP state must be serializable to JSON-compatible structures.
- Required TP fields for interchange include:
  - `tp_id`
  - `current_basin_id`
  - entropy components and totals
  - `state_counter`
  - `history`
  - `provenance`
- Serialization schema evolution must follow backward compatibility rules.

## 9. TP Testing and Validation Requirements

- TP behavior must be covered by scenario-based verification harnesses.
- Harness runs must emit HLR/LLR references for TP scenarios.
- Harness output must include IO fields exercised.
- Harness output must include negative-path coverage status.
- TP verification artifacts must include canonical run state and determinism reruns.

## 10. TP Traceability Requirements

- TP test scenarios must map to architecture and validation requirements.
- TP requirements must be represented in the requirements traceability matrix.
- TP verification evidence must remain linked to requirement IDs and source sections.
