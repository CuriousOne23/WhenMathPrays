# 10.30_Basin Requirements (Canonical)

## 1. Purpose

This document is the canonical basin requirement anchor for promoted basin lifecycle behavior.

RB naming in this canonical anchor follows Routing Basin terminology for consistency with the 20-series design-constraint baseline.

## 2. Canonical HLR Set

- `HLR-20.330-001`: Basin state objects must expose a JSON-compatible IO contract that preserves `basin_id`, `tp_id`, and `state_counter` without transformation.
- `HLR-20.330-002`: Basin replay of identical deterministic contracts must produce identical final snapshots and identical verification digests.
- `HLR-20.330-003`: Basin validation must reject empty basin identifiers, duplicate provenance identifiers, and entropy-vector shape mismatches.

## 3. Canonical Scope

This canonical basin requirement anchor governs:

- basin IO contract preservation
- deterministic replay requirements
- validation and negative-path enforcement expectations
- basin-family contract applicability across OB, RB, GB, IB, TB, InB, OuB, and MB canonical variants
