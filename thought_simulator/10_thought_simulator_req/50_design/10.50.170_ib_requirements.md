# 10.50.170_IB Requirements (Canonical)

## 1. Purpose

This document is the canonical Inquiry Basin (IB) requirement anchor for promotion-governed asynchronous creation, bounded inquiry evolution, supervised lifecycle transitions, and deterministic TP-tagged observability behavior.

## 2. Canonical HLR Set

- `HLR-20.090-006`: IB must be instantiated only after GB approval from an IB-Creation-Request flow.
- `HLR-20.090-007`: IB must receive inquiry evidence through OB<->IB interaction and must reject direct OuB routing.
- `HLR-20.090-008`: IB must preserve deterministic inquiry-state fields and bounded evolution state.
- `HLR-20.090-019`: IB lifecycle transitions must be explicitly logged and observable.
- `HLR-20.090-020`: IB supervisory actions must be applied only at deterministic safe boundaries.
- `HLR-20.090-021`: IB merge operations must instantiate deterministic merged state and retire sources under GB-approved control.
- `HLR-20.090-023`: IB promotion to OuB must occur only after GB approval and must not mutate OB registry state.

## 3. Canonical Scope

This canonical IB requirement anchor governs:

- asynchronous GB-approved IB creation from pending inquiry requests
- deterministic bounded inquiry-state evolution and append-only TP tagging
- deterministic split/merge lifecycle controls with lineage and retirement visibility
- deterministic GB-mediated promotion and retirement behavior
- deterministic reject-with-audit behavior for direct OuB bypass, sequence violations, and safe-boundary violations

## 10.50.170.TCU IB CPU Execution Cycle Requirements

**Anchor authority:**
- 20.150_tcu_budgeting_requirements.md
- 10.10.10_system_architecture.md

### 10.50.170.TCU.10 Bounded per-tick cost
- Requirement ID: 10.50.170.TCU.10
- Statement: For any tick with fixed input cardinality N and fixed configuration, the subsystem
  MUST complete its work within a bounded number of CPU cycles C_max(ib) per tick phase,
  as constrained by 20.150. No unbounded or data-dependent worst-case growth is permitted.

### 10.50.170.TCU.20 Deterministic behavior under fixed conditions
- Requirement ID: 10.50.170.TCU.20
- Statement: For fixed seed, fixed input cardinality N, fixed configuration, and fixed hardware/runtime profile,
  the subsystem MUST exhibit deterministic CPU cycle consumption within
  [C_min(ib), C_max(ib)] for the same scenario ID, as defined in 20.150.

### 10.50.170.TCU.30 Provisional vs measured budgets (promotion-controlled)
- Requirement ID: 10.50.170.TCU.30
- Statement: The subsystem MUST maintain two distinct TCU budgets:
  - provisional-budget(ib): design-time estimate used for planning and scheduling.
  - measured-budget(ib): empirically measured values produced by 40_playground harnesses and verified in 30_verification capsules.
  These MUST NOT be conflated in normative documents.
  measured-budget(ib) MAY ONLY be updated through promotion-controlled evidence from 30.

### 10.50.170.TCU.40 Tick budget share
- Requirement ID: 10.50.170.TCU.40
- Statement: The subsystem MUST declare its target percentage of the global tick budget
  (per 20.150) as a provisional-budget(ib) value, and MUST be verifiable against
  measured-budget(ib) from 30_verification capsules.
