# 10.50.70_Snapshot Requirements (Canonical)

## 1. Purpose

This document is the canonical requirement anchor for deterministic snapshot behavior promoted from `40.70_snapshot_prototypes`.

## 2. Canonical HLR Set

- `HLR-20.470-001`: Snapshot serialization must be deterministic for equivalent state payloads and schema versions.
- `HLR-20.470-002`: Snapshot loading must preserve required identity fields and reject digest or schema mismatches.
- `HLR-20.470-003`: Snapshot schema-version contracts must remain explicit and validation-enforced for replay integrity.

## 3. Canonical Scope

This canonical snapshot requirement anchor governs:

- deterministic snapshot dump/load behavior
- schema and digest validation contracts
- replay-safe snapshot compatibility boundaries
- negative-path rejection behavior for corrupted snapshots

## 10.50.70.TCU Snapshot CPU Execution Cycle Requirements

**Anchor authority:**
- 20.150_tcu_budgeting_requirements.md
- 10.10.10_system_architecture.md

### 10.50.70.TCU.10 Bounded per-tick cost
- Requirement ID: 10.50.70.TCU.10
- Statement: For any tick with fixed input cardinality N and fixed configuration, the subsystem
  MUST complete its work within a bounded number of CPU cycles C_max(snapshot) per tick phase,
  as constrained by 20.150. No unbounded or data-dependent worst-case growth is permitted.

### 10.50.70.TCU.20 Deterministic behavior under fixed conditions
- Requirement ID: 10.50.70.TCU.20
- Statement: For fixed seed, fixed input cardinality N, fixed configuration, and fixed hardware/runtime profile,
  the subsystem MUST exhibit deterministic CPU cycle consumption within
  [C_min(snapshot), C_max(snapshot)] for the same scenario ID, as defined in 20.150.

### 10.50.70.TCU.30 Provisional vs measured budgets (promotion-controlled)
- Requirement ID: 10.50.70.TCU.30
- Statement: The subsystem MUST maintain two distinct TCU budgets:
  - provisional-budget(snapshot): design-time estimate used for planning and scheduling.
  - measured-budget(snapshot): empirically measured values produced by 40_playground harnesses and verified in 30_verification capsules.
  These MUST NOT be conflated in normative documents.
  measured-budget(snapshot) MAY ONLY be updated through promotion-controlled evidence from 30.

### 10.50.70.TCU.40 Tick budget share
- Requirement ID: 10.50.70.TCU.40
- Statement: The subsystem MUST declare its target percentage of the global tick budget
  (per 20.150) as a provisional-budget(snapshot) value, and MUST be verifiable against
  measured-budget(snapshot) from 30_verification capsules.
