# 10.50.37 Thought Router (TR) Requirements (Canonical)

## 1. Purpose

This document is the canonical requirement anchor for Thought Router (TR) behavior promoted from `40.37_tr_router_prototypes`, synchronized with the authoritative integration contract in `20.37_thought_router_tr_specification.md` (Semantic Interpretation Flow Contract, 2026-06-05).

It distinguishes:
- **Promoted proxy scope** — evidence-backed minimal deterministic basin routing (this document §2, §10.50.37.TR.*).
- **Full TR architecture** — normative in `20.37`, `20.31` §10, `20.106`, and `10.10.*`; verified incrementally beyond the 30.37 proxy capsule.

## 2. Canonical HLR Set (Promoted Proxy — Evidence-Backed)

- `HLR-20.437-001`: The Thought Router MUST perform deterministic routing of input messages to the appropriate basin (`math_basin`, `thought_basin`, or `general_basin`).
- `HLR-20.437-002`: The Thought Router MUST assign consistent ΔH% values based on routing decision.
- `HLR-20.437-003`: The Thought Router MUST reject invalid inputs and return an explicit error route without side effects.

## 3. Canonical HLR Set (Integration Contract — 20.37 Anchor)

The following 20-series HLRs are canonical via `20.37` and SHALL govern placement, ordering, and integration; they are **not** claimed as proven by the 30.37 proxy harness until separate verification is recorded:

- `HLR-20.037-049`: Semantic Interpretation Flow Contract is the authoritative integration reference for OB → TR-input → `tr_needs_update` → TR routine → `TP.TR` → RB.
- `HLR-20.037-050`: Implementations SHALL conform to OB/TR-input and `tr_needs_update` writer rules, TR exclusive-write/clear rules, and RB gating/consumption rules in 20.37.
- `HLR-20.037-051`: `tr_needs_update` lifecycle semantics defer to `20.31` §10 on overlap; 20.37 governs module placement, ordering, and TR field integration only.

**Authoritative narrative:** `20.37` — Semantic Interpretation Flow Contract (steps 1–9, canonical cycle, integration invariants).

**Dirty-flag semantics:** `20.31_semantic_specification.md` §10.

**DCB geometric overlay:** `20.106_dcb_requirements.md`; consumption gated per 20.37 §4.4 and HLR-20.037-046.

## 4. Canonical Scope

### 4.1 Promoted proxy scope (30.37 / 40.37 evidence)

- Deterministic content-based routing logic (keyword proxy)
- Consistent ΔH% assignment per route class
- Strict separation of concerns (routing proxy — no full meaning construction)
- Input validation and explicit error routing

### 4.2 Full TR integration scope (20.37 — architectural, not proxy-proven)

- OB writes TR-input fields; OB sets `tr_needs_update` when semantic-relevant inputs change; OB never writes `TP.TR`
- TR routine is exclusive `TP.TR` writer; clears `tr_needs_update` only on successful commit
- RB routes to TR iff `tr_needs_update`; RB consumes committed `TP.TR` for downstream routing
- Optional DCB ephemeral geometric hints consumed by TR only when `tr_needs_update` permits TR execution
- Twelve-field `TP.TR` semantic routing block (defined in 20.37 §6; deferred in proxy)

## 10.50.37.TR Thought Router Requirements (Promoted Proxy)

### 10.50.37.TR.10 Deterministic Routing

- Requirement ID: 10.50.37.TR.10
- Statement: For any given input message, the TR proxy MUST produce the same routing decision and ΔH% value under identical conditions.
- Traceability: HLR-20.437-001; 20.37 (determinism constraints §9); 30.37 run artifacts

### 10.50.37.TR.20 Basin Selection Rules

- Requirement ID: 10.50.37.TR.20
- Statement: The TR proxy MUST route inputs containing mathematical terms to `math_basin`, reflective/thought terms to `thought_basin`, and all others to `general_basin`.
- Traceability: HLR-20.437-001; proxy only — not normative OB-family registry semantics

### 10.50.37.TR.30 ΔH% Assignment

- Requirement ID: 10.50.37.TR.30
- Statement: The TR proxy MUST assign monotonic and consistent ΔH% values:
  - `math_basin` → 0.15
  - `thought_basin` → 0.08
  - `general_basin` → 0.05
- Traceability: HLR-20.437-002

### 10.50.37.TR.40 Input Validation

- Requirement ID: 10.50.37.TR.40
- Statement: The TR proxy MUST return `{"route": "error", "reason": "invalid_input"}` for malformed or empty inputs.
- Traceability: HLR-20.437-003

## 10.50.37.FLOW Semantic Interpretation Flow (Canonical Anchor — Not Proxy-Proven)

### 10.50.37.FLOW.10 Integration contract authority

- Requirement ID: 10.50.37.FLOW.10
- Statement: The OB → TR-input → `tr_needs_update` → TR routine → `TP.TR` → RB cycle SHALL conform to the Semantic Interpretation Flow Contract in `20.37` and SHALL NOT be reinterpreted by proxy routing alone.
- Traceability: HLR-20.037-049; 20.37 Semantic Interpretation Flow Contract

### 10.50.37.FLOW.20 Module conformance

- Requirement ID: 10.50.37.FLOW.20
- Statement: OB, TR routine, and RB responsibilities in the integration flow SHALL match 20.37 §§3–7 and SHALL defer `tr_needs_update` semantics to 20.31 §10 where overlapping.
- Traceability: HLR-20.037-050, HLR-20.037-051

### 10.50.37.FLOW.30 DCB overlay boundary

- Requirement ID: 10.50.37.FLOW.30
- Statement: DCB geometric hints SHALL be ephemeral, SHALL NOT set `tr_needs_update`, and SHALL be consumed by the TR routine only when RB routes to TR per 20.37 §4.4.
- Traceability: HLR-20.037-042 through HLR-20.037-047; 20.106
