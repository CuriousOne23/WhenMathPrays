# 10.50.37 Thought Router (TR) Requirements (Canonical)

## 1. Purpose

This document is the canonical requirement anchor for the Thought Router (TR) promoted from `40.37_tr_router_prototypes`.

## 2. Canonical HLR Set

- `HLR-20.437-001`: The Thought Router MUST perform deterministic routing of input messages to the appropriate basin (`math_basin`, `thought_basin`, or `general_basin`).
- `HLR-20.437-002`: The Thought Router MUST assign consistent ΔH% values based on routing decision.
- `HLR-20.437-003`: The Thought Router MUST reject invalid inputs and return an explicit error route without side effects.

## 3. Canonical Scope

This canonical requirement governs:
- Deterministic content-based routing logic
- Consistent ΔH% assignment per route
- Strict separation of concerns (routing only — no meaning construction)
- Input validation and error handling

## 10.50.37.TR Thought Router Requirements

**Anchor authority:**

### 10.50.37.TR.10 Deterministic Routing
- Requirement ID: 10.50.37.TR.10
- Statement: For any given input message, the TR MUST produce the same routing decision and ΔH% value under identical conditions.

### 10.50.37.TR.20 Basin Selection Rules
- Requirement ID: 10.50.37.TR.20
- Statement: The TR MUST route inputs containing mathematical terms to `math_basin`, reflective/thought terms to `thought_basin`, and all others to `general_basin`.

### 10.50.37.TR.30 ΔH% Assignment
- Requirement ID: 10.50.37.TR.30
- Statement: The TR MUST assign monotonic and consistent ΔH% values:
  - `math_basin` → 0.15
  - `thought_basin` → 0.08
  - `general_basin` → 0.05

### 10.50.37.TR.40 Input Validation
- Requirement ID: 10.50.37.TR.40
- Statement: The TR MUST return `{"route": "error", "reason": "invalid_input"}` for malformed or empty inputs.
