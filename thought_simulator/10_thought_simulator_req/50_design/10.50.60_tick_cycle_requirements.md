# 10.50.60_Tick Cycle Requirements (Canonical)

## 1. Purpose

This document is the canonical requirement anchor for deterministic tick-cycle execution promoted from `40.60_tick_cycle_skeleton`.

## 2. Canonical HLR Set

- `HLR-20.460-001`: Tick execution must remain deterministic and replayable for equivalent phase inputs.
- `HLR-20.460-002`: Tick sequencing must be strictly monotonic with no skipped or duplicate transitions in deterministic mode.
- `HLR-20.460-003`: Tick-cycle contracts must reject invalid phase order and non-monotonic tick requests.

## 3. Canonical Scope

This canonical tick-cycle requirement anchor governs:

- deterministic phase execution ordering
- monotonic tick progression constraints
- negative-path validation for sequencing and phase-order contracts
- replay-safe tick evidence outputs
- deterministic phase-boundary compatibility for observer-signal ingestion and split/merge arbitration ordering

## 10.50.60.TCU Tick Cycle CPU Execution Cycle Requirements

**Anchor authority:**

### 10.50.60.TCU.10 Bounded per-tick cost
- Requirement ID: 10.50.60.TCU.10
- Statement: For any tick with fixed input cardinality N and fixed configuration, the subsystem
  MUST complete its work within a bounded number of CPU cycles C_max(tick_cycle) per tick phase,
  as constrained by 20.150. No unbounded or data-dependent worst-case growth is permitted.

### 10.50.60.TCU.20 Deterministic behavior under fixed conditions
- Requirement ID: 10.50.60.TCU.20
- Statement: For fixed seed, fixed input cardinality N, fixed configuration, and fixed hardware/runtime profile,
  the subsystem MUST exhibit deterministic CPU cycle consumption within
  [C_min(tick_cycle), C_max(tick_cycle)] for the same scenario ID, as defined in 20.150.

### 10.50.60.TCU.30 Provisional vs measured budgets (promotion-controlled)
- Requirement ID: 10.50.60.TCU.30
- Statement: The subsystem MUST maintain two distinct TCU budgets:
  - provisional-budget(tick_cycle): design-time estimate used for planning and scheduling.
  - measured-budget(tick_cycle): empirically measured values produced by 40_playground harnesses and verified in 30_verification capsules.
  These MUST NOT be conflated in normative documents.
  measured-budget(tick_cycle) MAY ONLY be updated through promotion-controlled evidence from 30.

### 10.50.60.TCU.40 Tick budget share
- Requirement ID: 10.50.60.TCU.40
- Statement: The subsystem MUST declare its target percentage of the global tick budget
  (per 20.150) as a provisional-budget(tick_cycle) value, and MUST be verifiable against
  measured-budget(tick_cycle) from 30_verification capsules.
