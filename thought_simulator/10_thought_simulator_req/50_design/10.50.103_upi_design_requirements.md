# 10.50.103 UPI Design Requirements (Canonical)

**Document ID:** 10.50.103  
**Date:** 2026-06-08  
**Status:** Promoted — W2 GATE-B anchor (30.103 / 40.103 evidence)

## 1. Purpose

Canonical realization anchor for the **User Preference Integrator (UPI)**: FIFO `clarification_event` orchestration, GB governance gate, and authorized USP commits. Translates [20.103](../../20_requirements/20.103_upi_requirements.md) and W2 verification evidence into design-layer obligations.

## 2. Canonical HLR Set (verified W2 scope)

Evidence-backed obligations (exploratory coverage via 30.103 harness matrix):

- `HLR-20.103-005`–`008`: Clarification events commit through deterministic orchestration; incomplete events reject; FIFO ordering preserved.
- `HLR-20.103-009`–`011`: GB approve and veto paths propagate `gb_reason_code`; veto leaves USP unchanged.
- `HLR-20.103-012`–`014`: Deterministic replay under identical event sequences; integration sequence monotonicity.
- `HLR-20.103-015`–`016`: USP cap overflow and pending-commit cap bounds enforced.
- `HLR-20.103-022`: Append-only audit on all commit paths.

**Design-layer obligations (W2):**

- `HLR-10.50.103-001`: UPI SHALL delegate USP mutation exclusively to `USPStore.apply_commit` after GB evaluation — no direct envelope writes.
- `HLR-10.50.103-002`: Live GB evaluator integration is evidenced jointly with [30.36](../../30_verification/30.36_gb_prototypes/30.36_gb_prototypes_verification_capsule.md) W2 extension (`evaluate_upi_commit`).

## 3. Canonical Scope

- `clarification_event_v1` intake and FIFO `process_fifo`
- GB stub and live `evaluate_upi_commit` wiring
- `UpiCommitRecord` audit fields including `gb_reason_code`
- Replay-identical commit records

**Out of scope:** Pipeline A/B semantic mutation, CIL classification policy ([20.33](../../20_requirements/20.33_cil_requirements.md) base harness), full 20.80 supervisory matrix.
