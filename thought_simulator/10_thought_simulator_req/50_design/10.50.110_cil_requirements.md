# 10.50.110_CIL Requirements (Canonical)

## 1. Purpose

This document is the canonical Conversation Integration Layer (CIL) requirement anchor for promotion-governed CIL intake, classification, and supervisory-escalation behavior.

## 2. Canonical HLR Set

- `HLR-20.032-001`: CIL must process incoming TP state in deterministic FIFO sequence.
- `HLR-20.032-003`: CIL thread classification must be deterministic and bounded by explicit confidence policy.
- `HLR-20.032-005`: CIL must not directly instantiate inquiry channels without GB approval.
- `HLR-20.032-006`: CIL must apply deterministic timeout/default behavior by safety and operation class.
- `HLR-20.032-011`: CIL must reject unsupported profile/policy/enum states deterministically with fixed audit reason codes.
- `HLR-20.032-012`: CIL must apply execution-signature profile precedence over environment defaults.
- `HLR-20.032-014`: CIL ordering-critical decisions must derive from deterministic sequence/token state only.
- `HLR-20.032-015`: CIL routing/escalation-affecting transitions must occur only at deterministic safe boundaries.

## 3. Canonical Scope

This canonical CIL requirement anchor governs:

- deterministic FIFO-preserving intake and snapshot coherence
- deterministic classification, tie-break, and supervisory escalation behavior
- deterministic timeout/default and late-approval re-entry outcomes
- deterministic reject-with-audit behavior for unsupported profile/policy/enum states
- deterministic sequence and safe-boundary gating for routing/escalation state changes

## 10.50.110.TCU CIL CPU Execution Cycle Requirements

**Anchor authority:**

### 10.50.110.TCU.10 Bounded per-tick cost
- Requirement ID: 10.50.110.TCU.10
- Statement: For any tick with fixed input cardinality N and fixed configuration, the subsystem
  MUST complete its work within a bounded number of CPU cycles C_max(cil) per tick phase,
  as constrained by 20.150. No unbounded or data-dependent worst-case growth is permitted.

### 10.50.110.TCU.20 Deterministic behavior under fixed conditions
- Requirement ID: 10.50.110.TCU.20
- Statement: For fixed seed, fixed input cardinality N, fixed configuration, and fixed hardware/runtime profile,
  the subsystem MUST exhibit deterministic CPU cycle consumption within
  [C_min(cil), C_max(cil)] for the same scenario ID, as defined in 20.150.

### 10.50.110.TCU.30 Provisional vs measured budgets (promotion-controlled)
- Requirement ID: 10.50.110.TCU.30
- Statement: The subsystem MUST maintain two distinct TCU budgets:
  - provisional-budget(cil): design-time estimate used for planning and scheduling.
  - measured-budget(cil): empirically measured values produced by 40_playground harnesses and verified in 30_verification capsules.
  These MUST NOT be conflated in normative documents.
  measured-budget(cil) MAY ONLY be updated through promotion-controlled evidence from 30.

### 10.50.110.TCU.40 Tick budget share
- Requirement ID: 10.50.110.TCU.40
- Statement: The subsystem MUST declare its target percentage of the global tick budget
  (per 20.150) as a provisional-budget(cil) value, and MUST be verifiable against
  measured-budget(cil) from 30_verification capsules.
