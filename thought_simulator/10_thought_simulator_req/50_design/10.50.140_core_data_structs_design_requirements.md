# 10.50.140 Core Data Structs Design Requirements (Canonical)

**Document ID:** 10.50.140  
**Date:** 2026-06-08  
**Status:** Approved — W2 GATE-B struct anchor; CP 30.00 review 2026-06-08 (30.140 / 40.100 evidence)

## 1. Purpose

Canonical realization anchor for **Track H conversation-layer structs** and envelope separation guards: `UspSnapshot`, `InputRepairTag`, `ConversationLayerState`, and audit export shapes. Translates [20.39](../../20_requirements/20.39_ts_core_data_structures.md) §3.1–3.2 and W2 verification evidence into design-layer obligations.

## 2. Canonical HLR Set (verified W2 scope)

Evidence-backed obligations (20.39 §3.1–3.2 families demonstrated in 30.140):

- `HLR-20.039-021`: Conversation-layer state is modeled separately from the four runtime envelopes (`semantic_core`, `exec_plan`, `exec_trace`, `supervisory`).
- `HLR-20.039-022`: `UspSnapshot` is immutable for an IIInB repair pass; `usp_version_ref` is content-addressed and round-trips canonically.
- `HLR-20.039-023`: `InputRepairTag` remains intake-bound and ordered for export.
- `HLR-20.039-024`: Track H audit structs are data-only, versioned, and canonically ordered before export/hash.
- `HLR-20.039-025`: USP rules, clarification payloads, and repair tags SHALL NOT be stored inside runtime envelopes.
- `HLR-20.039-019`: Unknown schema versions SHALL reject deterministically.

**Design-layer obligations (W2):**

- `HLR-10.50.140-001`: Struct modules SHALL expose canonical serialization and digest helpers consumed by USP, UPI, IIInB, and COB pin paths.
- `HLR-10.50.140-002`: Golden fixture `golden_usp_snapshot_v1.json` SHALL remain the regression anchor for snapshot round-trip and digest compatibility.

## 3. Canonical Scope

This anchor governs:

- conversation-layer envelope partition and forbidden-field guards
- `UspSnapshot` / `InputRepairTag` canonical ordering and audit struct exports
- IIInB digest compatibility for pinned `usp_version_ref`
- schema-version rejection for unsupported struct payloads

**Out of scope:** USP commit logic ([20.102](../../20_requirements/20.102_usp_requirements.md)), UPI orchestration ([20.103](../../20_requirements/20.103_upi_requirements.md)), full four-envelope MTP modeling (broader 20.39 §3.0).
