# 10.50.50 InB Design Requirements (Canonical)

**Document ID:** 10.50.50
**Date:** 2026-06-08  
**Status:** Approved — W1 GATE-A ready (CP review 2026-06-08; 30.220 / 40.50 evidence)

## 1. Purpose

Canonical realization anchor for **Input Basin (InB)**: non-inferential external-signal intake, deterministic canonicalization, bounded reject/degrade, and explicit handoff to Track H `input_semantic_repair` (IIInB). Translates [20.100](../../20_requirements/20.100_inb_requirements.md) and W1 verification evidence into design-layer obligations for implementations.

## 2. Canonical HLR Set (verified W1 scope)

Evidence-backed obligations (23/26 from 20.100 demonstrated in 30.220):

- `HLR-20.100-001` … `HLR-20.100-012`: Bounded intake, no inference, deterministic canonicalization, schema/wire validation, FIFO order, transport isolation, provenance, replay contract.
- `HLR-20.100-014` … `HLR-20.100-016`: Profile activation at safe boundary; deterministic rejects for unsupported schema/profile/wire-map.
- `HLR-20.100-018` … `HLR-20.100-023`: Platform-independent replay; tick-boundary first stage (no MTP mutation); zero-event window semantics.
- `HLR-20.100-025`: Deterministic fixture matrix (valid, malformed, oversize, unsupported).
- `HLR-20.100-026`: No semantic interpretation at handoff.

**Design-layer handoff (W1 GATE-A):**

- `HLR-10.50.50-001`: On accept, InB SHALL emit versioned handoff with `next_stage: input_semantic_repair` and ordering **`InB → IIInB → RB`** per [20.101](../../20_requirements/20.101_iiinb_requirements.md) HLR-20.101-003.
- `HLR-10.50.50-002`: InB SHALL use wire/schema identifiers `inb_intake_v1` and `inb_wire_v1` (or successor versions under explicit migration) in verification fixtures.

## 3. Canonical Scope

This anchor governs:

- non-semantic Unicode NFKC and surface-form canonicalization
- bounded payload/token/field limits with fixed audit reason codes
- transport/session metadata isolation from semantic payload
- deterministic diagnostic export ordering (`export_intake_diagnostics`)
- tick-boundary `run_first_stage` behavior without downstream invocation (evidence: [40.50 `run_first_stage`](../../40_thought_simulator_playground/40.50_inb_prototypes/prototype.py) — no MTP mutation; see `positive_tick_boundary_first_stage` in 30.220)
- explicit IIInB handoff contract (not direct RB semantic routing)

**Out of scope:** semantic shorthand repair ([20.101](../../20_requirements/20.101_iiinb_requirements.md)), USP/UPI, Pipeline A basin chain.
