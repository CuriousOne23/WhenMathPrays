# 10.50.80_Event Log Requirements (Canonical)

## 1. Purpose

This document is the canonical requirement anchor for deterministic event-log behavior promoted from `40.300_event_log_prototypes`.

## 2. Canonical HLR Set

- `HLR-20.480-001`: Event logs must preserve append-only deterministic ordering for equivalent event sequences.
- `HLR-20.480-002`: Event replay contracts must produce stable verification digests for equivalent traces.
- `HLR-20.480-003`: Event ingestion must reject malformed events and non-monotonic sequence numbers.

## 3. Canonical Scope

This canonical event-log requirement anchor governs:

- event ordering and append-only constraints
- deterministic replay digest behavior
- event schema validation and negative-path rejection
- replay-safe observability evidence fields

## 10.50.80.TCU Event Log CPU Execution Cycle Requirements

**Anchor authority:**
- 20.150_tcu_budgeting_requirements.md
- 10.10.10_system_architecture.md

### 10.50.80.TCU.10 Bounded per-tick cost
- Requirement ID: 10.50.80.TCU.10
- Statement: For any tick with fixed input cardinality N and fixed configuration, the subsystem
  MUST complete its work within a bounded number of CPU cycles C_max(event_log) per tick phase,
  as constrained by 20.150. No unbounded or data-dependent worst-case growth is permitted.

### 10.50.80.TCU.20 Deterministic behavior under fixed conditions
- Requirement ID: 10.50.80.TCU.20
- Statement: For fixed seed, fixed input cardinality N, fixed configuration, and fixed hardware/runtime profile,
  the subsystem MUST exhibit deterministic CPU cycle consumption within
  [C_min(event_log), C_max(event_log)] for the same scenario ID, as defined in 20.150.

### 10.50.80.TCU.30 Provisional vs measured budgets (promotion-controlled)
- Requirement ID: 10.50.80.TCU.30
- Statement: The subsystem MUST maintain two distinct TCU budgets:
  - provisional-budget(event_log): design-time estimate used for planning and scheduling.
  - measured-budget(event_log): empirically measured values produced by 40_playground harnesses and verified in 30_verification capsules.
  These MUST NOT be conflated in normative documents.
  measured-budget(event_log) MAY ONLY be updated through promotion-controlled evidence from 30.

### 10.50.80.TCU.40 Tick budget share
- Requirement ID: 10.50.80.TCU.40
- Statement: The subsystem MUST declare its target percentage of the global tick budget
  (per 20.150) as a provisional-budget(event_log) value, and MUST be verifiable against
  measured-budget(event_log) from 30_verification capsules.
