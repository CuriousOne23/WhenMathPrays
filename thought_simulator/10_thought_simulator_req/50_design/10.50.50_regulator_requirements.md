# 10.50.50_Regulator Requirements (Canonical)

## 1. Purpose

This document is the canonical requirement anchor for regulator decision behavior promoted from `40.1100_regulator_prototypes`.

## 2. Canonical HLR Set

- `HLR-20.450-001`: Regulator decisions must be deterministic and replayable for equivalent inputs in deterministic mode.
- `HLR-20.450-002`: Regulator policy modes must produce explicit, auditable action outputs with stable rationale semantics.
- `HLR-20.450-003`: Regulator input validation must reject unsupported policy modes and invalid numeric pressure values.

## 10.50.50.TCU Regulator CPU Execution Cycle Requirements

**Anchor authority:**
- 20.150_tcu_budgeting_requirements.md
- 10.10.10_system_architecture.md

### 10.50.50.TCU.10 Bounded per-tick cost
- Requirement ID: 10.50.50.TCU.10
- Statement: For any tick with fixed input cardinality N and fixed configuration, the subsystem
  MUST complete its work within a bounded number of CPU cycles C_max(regulator) per tick phase,
  as constrained by 20.150. No unbounded or data-dependent worst-case growth is permitted.

### 10.50.50.TCU.20 Deterministic behavior under fixed conditions
- Requirement ID: 10.50.50.TCU.20
- Statement: For fixed seed, fixed input cardinality N, fixed configuration, and fixed hardware/runtime profile,
  the subsystem MUST exhibit deterministic CPU cycle consumption within
  [C_min(regulator), C_max(regulator)] for the same scenario ID, as defined in 20.150.

### 10.50.50.TCU.30 Provisional vs measured budgets (promotion-controlled)
- Requirement ID: 10.50.50.TCU.30
- Statement: The subsystem MUST maintain two distinct TCU budgets:
  - provisional-budget(regulator): design-time estimate used for planning and scheduling.
  - measured-budget(regulator): empirically measured values produced by 40_playground harnesses and verified in 30_verification capsules.
  These MUST NOT be conflated in normative documents.
  measured-budget(regulator) MAY ONLY be updated through promotion-controlled evidence from 30.

### 10.50.50.TCU.40 Tick budget share
- Requirement ID: 10.50.50.TCU.40
- Statement: The subsystem MUST declare its target percentage of the global tick budget
  (per 20.150) as a provisional-budget(regulator) value, and MUST be verifiable against
  measured-budget(regulator) from 30_verification capsules.
