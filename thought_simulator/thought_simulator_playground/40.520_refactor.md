# **1. Program Context**

This program implements the playground‑side refactor required by **20.520**.  
It introduces the **minimal inference layer** into the 40‑series and realigns all affected modules (TPU, ISc, routing, XP, OuB, TR, RB, and structural definitions).

**This program must be executed *after 40.510 has been fully completed and approved*.**

40.510 established:

- the modern playground structure  
- module action definitions (create / redo / extend / keep)  
- wave sequencing  
- reviewer gates  
- evidence requirements  
- cross‑module invariants  

40.520 depends on all of these.  
It cannot be executed safely or coherently unless 40.510 is complete.

20.520 provides the architectural deltas;  
40.510 provides the program machinery;  
40.520 applies both.

# **3. Program Purpose**

This program introduces the **minimal inference layer** into the playground and realigns all affected modules with the updated architecture.

Specifically, the program will:

- implement ΔH% scoring  
- implement incomplete‑meaning detection  
- implement merge validation  
- implement safe‑boundary commit rules  
- update routing to be deterministic and inference‑aware  
- update XP and OuB boundaries  
- update TR and RB to respect ΔH% and incomplete meaning  
- update struct definitions and guidelines to match 20.520  

The goal is to produce a **complete, testable, evidence‑backed implementation** of the 20.520 architectural changes.

# **6. Module Action Definitions**

### **Create**
A new module introduced by 20.520 (e.g., ISc).

### **Redo**
A full rebuild of a module whose architecture changed significantly (e.g., TPU, SRP, routing tables).

### **Extend**
A module that keeps its structure but must integrate new inference signals or boundaries (e.g., XP, OuB, TR, RB).

### **Keep**
No modules in 40.520 are “keep.”
