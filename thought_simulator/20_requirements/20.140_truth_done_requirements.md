# **20.140 — Truth and Done Evaluation Requirements (v0.4, Fully Rewritten)**  
**Document ID:** 20.140  
**Version:** 0.4  
**Date:** 2026‑06‑24  
**Status:** Draft — Architecture‑Aligned Rewrite (TP‑Local Evaluation Only)

---

# **0. Purpose**

Truth and Done evaluation is the **Pipeline A evaluation stage** that:

- consumes TB‑committed interpretation inputs  
- evaluates truth hypotheses  
- computes uncertainty (`h_percent_q32`)  
- computes completion (`done_state`)  
- emits deterministic audit records  

Truth/Done is an **evaluation authority**, not an evidence extractor, interpreter, router, or TS‑side snapshot writer.  
Truth/Done operates **only on TP/OuBA fields** and produces **TP‑local outputs** that flow into **OuBA → OuBB**.

---

# **1. Scope**

Truth/Done covers:

- truth hypothesis evaluation  
- confidence and uncertainty accounting  
- completion evaluation  
- messy‑input gating  
- deterministic ordering  
- TP‑local audit generation  

Truth/Done does **not**:

- read or write any TS‑side snapshot  
- read or write any global meaning store  
- perform OB evidence extraction  
- perform TB channel interpretation  
- perform routing or arbitration  
- perform latent inference or probabilistic search  

---

# **2. Placement in the Pipeline**

Truth/Done runs **inside Pipeline A**, after:

1. OB evidence extraction  
2. TB channel interpretation  
3. ΔH% normalization  
4. merge of lane‑local meaning  

Truth/Done produces TP‑local evaluation outputs that finalize into **OuBA**, which Pipeline B consumes.

Truth/Done does **not** interact with MTP or any TS‑side commit mechanism.

---

# **3. Inputs**

Truth/Done consumes only explicit structured fields from TP/OuBA:

- `truth_hypothesis_records[]` (TB outputs)  
- `channel_interpretations{}` (TB context; read‑only)  
- `propositions[]`  
- `lineage[]`  
- `delta_h` / ΔH% fields (Q32.32)  
- `stability_metadata`  
- `overflow_metadata`  
- `messy_input_record` (read‑only; 20.17)  
- `thought_router_fields` / committed `TP.TR` (read‑only; 20.37)  
- `policy_signature` and bound `success_criteria`  
- prior‑cycle `truth_hypotheses` and `done_state` (continuity only)  

Truth/Done does **not** read:

- `exec_plan`, `exec_trace`  
- `routing_epoch_id`, `routing_metadata`  
- Pipeline B artifacts  
- any TS‑side snapshot  

---

# **4. Outputs**

Truth/Done produces a TP‑local structure:

```
truth_done_output {
  truth_hypotheses[],
  done_state{},
  h_percent_q32,
  uncertainty_audit{},
  evaluation_audit_records[]
}
```

### **4.1 truth_hypotheses[] minimum schema**

```
truth_hypothesis_record {
  hypothesis_id,
  proposition_ref,
  truth_status,              // OPEN | SUPPORTED | REFUTED | UNKNOWN
  confidence_q32,            // Q32.32
  evidence_refs[],           // canonical sort
  last_updated_cycle,
  evaluation_reason_codes[]  // canonical sort
}
```

### **4.2 done_state minimum schema**

```
done_state {
  completion_status,         // NOT_DONE | PARTIAL | DONE | BLOCKED
  completion_reason_codes[], // canonical sort
  policy_criteria_ref,
  last_evaluated_cycle,
  blocked_by_messy_input?
}
```

### **4.3 Canonical ordering**

Before export or hashing:

- `truth_hypotheses[]` sorted by `hypothesis_id`  
- `evidence_refs[]` sorted lexicographically  
- `evaluation_reason_codes[]` sorted lexicographically  
- `completion_reason_codes[]` sorted lexicographically  

---

# **5. Evaluation Rules**

Truth evaluation uses deterministic, policy‑bounded logic over explicit structured fields.

Confidence updates use Q32.32 numeric policy.  
Example (GitHub‑safe):

```
$T_{new}=T_{old}+\Delta T$
```

Done evaluation uses explicit `success_criteria` and does not infer completion from latent or unstated state.

---

# **6. Messy‑Input Gating**

Truth/Done treats `messy_input_record` as **read‑only**:

- `MI_CONTRA` prevents collapsing parallel traces unless contradiction is explicitly arbitrated  
- `MI_VAGUE` caps commitment and confidence  
- `MI_INCOMP` prevents `DONE` when required slots remain unresolved  
- `MI_AFFECT` influences uncertainty only via explicit structured fields  
- `MI_NOISE` does not affect stabilized conceptual evidence  

Truth/Done does not create, modify, or clear messy‑input tags.

---

# **7. Determinism & Replay**

Truth/Done outputs are reproducible from:

- TP/OuBA effective input state  
- `policy_signature` and bound evaluation policies  

Seed does not influence evaluation.

Replay is defined over **TP → OuBA**, not over any TS‑side snapshot.

---

# **8. Functional Boundaries**

- **TB**: produces interpretation inputs  
- **Truth/Done**: evaluates truth, uncertainty, and completion  
- **RB/TR**: do not consume truth/done outputs in the same cycle  
- **Pipeline B**: consumes OuBA; does not modify truth/done outputs  
- **TS snapshots**: not involved  

---

# **9. Normative Requirements (HLRs)**  
*(All SHALL statements appear only here.)*

### **Truth Evaluation**

**HLR‑20.140‑001 — Deterministic truth evaluation**  
Truth evaluation SHALL compute `truth_hypotheses[]` using deterministic field‑based logic over TP/OuBA inputs.

**HLR‑20.140‑002 — TB input authority**  
Truth evaluation SHALL treat TB‑committed `truth_hypothesis_records[]` as authoritative interpretation inputs.

**HLR‑20.140‑003 — No OB/TB re‑interpretation**  
Truth evaluation SHALL NOT re‑interpret OB evidence or re‑derive TB channel semantics.

**HLR‑20.140‑004 — No invented content**  
Truth evaluation SHALL NOT invent propositions, hypotheses, or evidence references not present in approved inputs.

**HLR‑20.140‑005 — Q32.32 numeric policy**  
Truth evaluation SHALL compute `confidence_q32` and `h_percent_q32` using canonical Q32.32 numeric policy.

**HLR‑20.140‑006 — Negative‑zero normalization**  
Truth evaluation SHALL normalize negative zero to positive zero before comparison or export.

---

### **Done Evaluation**

**HLR‑20.140‑007 — Deterministic completion evaluation**  
Done evaluation SHALL compute `completion_status` using explicit `success_criteria` bound to `policy_signature`.

**HLR‑20.140‑008 — No latent inference**  
Done evaluation SHALL NOT infer completion from latent or unstated state.

**HLR‑20.140‑009 — MI_CONTRA gating**  
Under active `MI_CONTRA`, done evaluation SHALL NOT collapse parallel traces unless contradiction is explicitly arbitrated.

**HLR‑20.140‑010 — MI_VAGUE gating**  
Under active `MI_VAGUE`, done evaluation SHALL cap commitment and confidence according to policy.

**HLR‑20.140‑011 — MI_INCOMP gating**  
Under active `MI_INCOMP`, done evaluation SHALL NOT emit `DONE` when required slots remain unresolved.

---

### **Messy‑Input Handling**

**HLR‑20.140‑012 — Messy‑input read‑only**  
Truth/Done SHALL treat `messy_input_record` as read‑only and SHALL NOT create, modify, or clear messy‑input tags.

---

### **Ordering & Determinism**

**HLR‑20.140‑013 — Cycle ordering**  
Truth/Done SHALL preserve deterministic cycle ordering using `cycle_id` and canonical sequence tokens.

**HLR‑20.140‑014 — Replay determinism**  
Truth/Done outputs SHALL be reproducible for identical TP/OuBA input state and `policy_signature`.

**HLR‑20.140‑015 — Seed independence**  
Truth/Done outputs SHALL NOT depend on seed.

**HLR‑20.140‑016 — Allocation independence**  
Truth/Done output derivation SHALL NOT depend on TP creation order, allocation sequence, or container address identity.

---

### **Approved Read Set**

**HLR‑20.140‑017 — Approved input enforcement**  
Truth/Done SHALL read only the approved field set defined in §3.

**HLR‑20.140‑018 — Forbidden reads**  
Truth/Done SHALL NOT read `exec_plan`, `exec_trace`, `routing_epoch_id`, `routing_metadata`, or any TS‑side snapshot.

**HLR‑20.140‑019 — Routing metadata read‑only**  
Truth/Done SHALL treat `thought_router_fields` and committed `TP.TR` as read‑only routing metadata.

---

### **Outputs & Ordering**

**HLR‑20.140‑020 — Output schema conformance**  
Truth/Done SHALL emit `truth_hypotheses`, `done_state`, `h_percent_q32`, and audit records conforming to §4 minimum schemas.

**HLR‑20.140‑021 — Canonical ordering**  
Truth/Done SHALL apply canonical ordering to all lists before export or hashing.

---

### **Boundaries**

**HLR‑20.140‑022 — Pipeline A only**  
Truth/Done SHALL operate exclusively in Pipeline A.

**HLR‑20.140‑023 — No routing writes**  
Truth/Done SHALL NOT write `TP.TR`, routing flags, or routing metadata.

**HLR‑20.140‑024 — No extra cycles**  
Truth/Done SHALL NOT trigger additional OB, TB, RB, or TR cycles.

**HLR‑20.140‑025 — B‑side isolation**  
Pipeline B SHALL NOT modify truth/done outputs; corrections SHALL route through a subsequent Pipeline A cycle.

---

### **Verification & Policy**

**HLR‑20.140‑026 — Testability**  
Truth/Done SHALL be testable through deterministic fixtures covering nominal, boundary, ambiguous, and messy‑input‑gated cases.

**HLR‑20.140‑027 — Policy traceability**  
Truth/Done decisions SHALL be traceable to explicit policy references and reason codes.

**HLR‑20.140‑028 — TB schema enforcement**  
Truth/Done SHALL reject TB records that violate 20.31 minimum schema with deterministic audit reason codes.

**HLR‑20.140‑029 — Uncertainty accounting**  
Truth/Done SHALL compute uncertainty using only explicit ΔH%, missing‑mass, and structured hypothesis mass fields.

**HLR‑20.140‑030 — Truth metadata (TPTB)**  
If TPTB is produced, Truth/Done SHALL generate it as TP‑local evaluation‑derived metadata and SHALL NOT modify it downstream.
