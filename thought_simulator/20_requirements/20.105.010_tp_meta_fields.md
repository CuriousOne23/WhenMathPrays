# **20.105.010_tp_meta_fields.md**  
### **TP Metadata Fields — Provenance, Structure, and Upstream Annotation**

---

## **1. Purpose**
This document defines the metadata fields carried by the Thought Packet (TP) within Path A.  
Metadata fields provide upstream‑observed information that downstream primitives use for deterministic meaning refinement, routing, structural interpretation, and truth‑relation mapping.  
This document is a normative extension of **20.105_tp_requirements.md**.

---

## **2. Scope**
This specification covers:

- metadata field definitions  
- provenance rules  
- commit boundaries  
- immutability constraints  
- upstream annotation responsibilities  
- downstream consumption expectations  

It does **not** define primitive behavior, defect classification logic, or meaning‑refinement rules.  
Those remain in their respective primitive specifications.

---

## **3. TP Metadata Field Categories**
TP metadata fields are grouped into the following categories:

- **intake_metadata** — observations from InB and IIInB  
- **normalization_metadata** — observations and repairs from IE  
- **structural_metadata** — structural geometry annotations from OB‑Set  
- **routing_metadata** — routing arbitration and pathway information  
- **expressive_metadata** — expressive or stylistic observations  
- **repair_metadata** — deterministic repair provenance  
- **provenance_metadata** — commit lineage and replay‑safety fields  
- **entropy_metadata** — ΔH% trajectory fields  
- **continuity_metadata** — identity and conversation‑layer anchors  

Each category contains one or more fields defined below.

---

## **4. Normative Requirements**

### **4.1 Metadata Presence**
**HLR‑20.105.010‑001**  
The TP **shall** contain a metadata section composed of zero or more metadata fields defined in this document.

### **4.2 Metadata Immutability**
**HLR‑20.105.010‑002**  
Metadata fields **shall** be immutable once committed by TPU, except where a primitive is explicitly authorized to update a specific field.

### **4.3 Metadata Provenance**
**HLR‑20.105.010‑003**  
Each metadata field **shall** record its provenance, identifying the primitive that produced or last updated the field.

### **4.4 Metadata Accessibility**
**HLR‑20.105.010‑004**  
All metadata fields **shall** be accessible to downstream primitives without requiring re‑inspection or re‑derivation of upstream observations.

### **4.5 Metadata Integrity**
**HLR‑20.105.010‑005**  
Metadata fields **shall** preserve their values across TPU commits unless explicitly replaced by a new commit.

### **4.6 Metadata Replay Safety**
**HLR‑20.105.010‑006**  
Metadata fields **shall** support deterministic replay, meaning that re‑executing the same TP through the same primitives yields identical metadata values.

## **5. Metadata Field Definitions**

### **5.1 intake_metadata**
Fields produced by InB and IIInB.

- `intake_status`  
- `defect_list`  
- `token_observations`  
- `unicode_flags`  
- `length_flags`

### **5.2 normalization_metadata**
Fields produced by IE.

- `normalized_tokens`  
- `repair_actions`  
- `repair_confidence`  
- `token_alignment_map`

### **5.3 structural_metadata**
Fields produced by OB‑Set.

- `structural_roles`  
- `segment_boundaries`  
- `constraint_surfaces`  
- `smoothing_actions`

### **5.4 routing_metadata**
Fields produced by RBU, RB, RTU, and CTP.

- `routing_pathway`  
- `routing_confidence`  
- `arbitration_trace`  
- `routing_features`

### **5.5 expressive_metadata**
Fields produced by IIInB and IE.

- `elongation_patterns`  
- `abbreviation_patterns`  
- `omission_patterns`  
- `stylization_flags`

### **5.6 repair_metadata**
Fields produced by IE and TPU.

- `repair_origin`  
- `repair_type`  
- `repair_provenance`  
- `repair_alignment`

### **5.7 provenance_metadata**
Fields produced by TPU.

- `commit_id`  
- `commit_sequence`  
- `primitive_origin`  
- `commit_timestamp`

### **5.8 entropy_metadata**
Fields produced by TR and OuBA.

- `delta_h`  
- `entropy_trace`  
- `entropy_commit_map`

### **5.9 continuity_metadata**
Fields consumed by COB, CIL, CST.

- `identity_anchors`  
- `referent_lineage`  
- `continuity_flags`  
- `stability_flags`

---

## **6. Metadata Commit Boundaries**

### **6.1 TPU Commit Rule**
**HLR‑20.105.010‑007**  
TPU **shall** commit metadata fields atomically, ensuring that all metadata updates produced by a primitive occur within a single commit boundary.

### **6.2 Upstream Annotation Rule**
**HLR‑20.105.010‑008**  
Upstream primitives **shall** annotate metadata fields only with observations made from their own point of view and shall not infer downstream meaning.

### **6.3 Downstream Consumption Rule**
**HLR‑20.105.010‑009**  
Downstream primitives **shall** consume metadata fields without modifying them, except where explicitly authorized.

## **7. Metadata Equations**

### **7.1 ΔH% Entropy Trajectory**
The entropy trajectory is computed as:

$$
\Delta H\\% = \frac{H_{\text{current}} - H_{\text{previous}}}{H_{\text{previous}}} \times 100
$$

### **7.2 Commit Lineage Mapping**
Commit lineage is represented as:

$$
\text{commit}\_{sequence} = \\{ c_1, c_2, \ldots, c_n \\}
$$

where each $c_i$ is a TPU commit identifier.
