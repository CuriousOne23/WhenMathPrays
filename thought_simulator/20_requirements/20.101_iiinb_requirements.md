# 20.101 IIInB Requirements

**Document ID:** 20.101  
**Version:** 0.1  
**Date:** 2026-06-07  
**Status:** Approved v0.1 — Track H (2026-06-07; CuriousOne23, Copilot, Grok)

## Purpose

Defines deterministic **Input Inference/Repair Basin (IIInB)** behavior as the profiled pre–Pipeline A stage **`input_semantic_repair`**: bounded semantic shorthand repair using read-only [20.102](20.102_usp_requirements.md) USP rules after [20.100](20.100_inb_requirements.md) InB surface normalization.

**Intake ordering (HQ-001):** `InB → IIInB → RB`

IIInB is **not** a Pipeline A basin in the RB→OB→TR→TB chain; it is an optional repair slice before routing.

## Non-Goals

- **Surface canonicalization** — owned by InB ([20.100](20.100_inb_requirements.md)).
- **Silent gap-fill or generative completion** — escalate unknown segments to CIL clarification ([20.103](20.103_upi_requirements.md) path).
- **`MI_INCOMP` inquiry** — IB-Creation-Request pathway ([20.17](20.17_messy_input_handling.md), [20.90](20.90_ib_requirements.md)).
- **Post-output mismatch repair** — owned by IMR ([20.45](20.45_imr_requirements.md)).
- **USP writes** — owned by UPI only.
- **Meaning commitment** — IIInB SHALL NOT write `semantic_core`, `TP.TR`, or MTP semantics.

## Parent Scope

- **Program:** [20.510](20.510_refactoring_for_input_correction_track_h.md) Track H
- **Reads:** InB canonicalized intake, USP snapshot (`usp_version_ref`)
- **Writes:** Intake-bound repair tags on TP only ([20.105](20.105_tp_requirements.md) — Stage 3)
- **Escalates:** Unknown segments → CIL (not UPI directly)
- **Does not modify:** 20.10, 20.12, 20.20, 20.30 bootstrap documents

## Functional Boundaries

| Component | Relationship to IIInB |
|-----------|----------------------|
| **InB** | Upstream surface norm handoff |
| **USP** | Read-only rule snapshot per repair pass |
| **RB** | Downstream first Pipeline A routing stage after repair |
| **CIL** | Receives escalation for unknown shorthand |
| **UPI / IMR** | No direct invocation by IIInB |

## Normative Requirements

### Activation and placement

1. **HLR-20.101-001:** IIInB SHALL execute as stage wire **`input_semantic_repair`** only when `profile_enabled = true` for the active execution signature ([20.90](20.90_ts_parameter_table.md)).
2. **HLR-20.101-002:** When `profile_enabled = false`, TS SHALL skip `input_semantic_repair` with zero semantic effect and SHALL NOT load USP.
3. **HLR-20.101-003:** IIInB SHALL run only after InB handoff and before RB on the intake path: **`InB → IIInB → RB`**.
4. **HLR-20.101-004:** IIInB SHALL NOT execute as a stage inside the RB→OB→TR→TB basin chain.

### USP consumption

5. **HLR-20.101-005:** IIInB SHALL load USP via read-only snapshot pinned by `usp_version_ref` per [20.102](20.102_usp_requirements.md) HLR-20.102-006.
6. **HLR-20.101-006:** IIInB SHALL record `usp_version_ref` on every `iiinb_repair_record` for replay pinning.
7. **HLR-20.101-007:** IIInB SHALL apply only `ACTIVE` USP rules using deterministic precedence per [20.102](20.102_usp_requirements.md) HLR-20.102-012.
8. **HLR-20.101-008:** IIInB SHALL NOT mutate USP state.

### Repair semantics

9. **HLR-20.101-009:** IIInB SHALL perform **bounded pattern→expansion repair** only — no latent inference, no multi-stable meaning selection without USP rule coverage.
10. **HLR-20.101-010:** IIInB SHALL segment intake text into bounded spans (`input_segments[]`) before rule matching; segmentation SHALL be deterministic under versioned profile rules.
11. **HLR-20.101-011:** On rule match, IIInB SHALL emit `repair_outcome = APPLIED` with `rule_id`, `segment_ref`, and `resolved_segment_ref` on intake-bound TP fields.
12. **HLR-20.101-012:** On no matching rule for a shorthand-eligible segment, IIInB SHALL emit `repair_outcome = ESCALATED` and SHALL queue CIL escalation — **not** guess meaning.
13. **HLR-20.101-013:** IIInB SHALL NOT auto-resolve `MI_VAGUE` or `MI_INCOMP` semantics; messy-input tags from [20.17](20.17_messy_input_handling.md) remain authoritative for those pathways.

### Write authority (TP only)

14. **HLR-20.101-014:** IIInB writes SHALL be confined to intake-bound TP fields: `input_repair_tags[]`, `input_segments[]`, `iiinb_escalation_refs[]` — per [20.105](20.105_tp_requirements.md) Stage 3 integration.
15. **HLR-20.101-015:** IIInB SHALL NOT write MTP, `semantic_core`, `TP.TR`, OB evidence, or truth fields.
16. **HLR-20.101-016:** IIInB SHALL append one `iiinb_repair_record` per repair pass to conversation-scoped audit storage (not `exec_trace`).

### Escalation

17. **HLR-20.101-017:** IIInB escalation SHALL emit `iiinb_escalation_ref` linked to `segment_ref` and SHALL hand off to CIL deterministic escalation interface — not to UPI or IMR directly.
18. **HLR-20.101-018:** IIInB SHALL NOT block Pipeline A waiting for clarification; escalated segments proceed with explicit unknown markers per policy.

### Bounds, TCU, and determinism

19. **HLR-20.101-019:** IIInB SHALL enforce a maximum of **32** segment spans per turn (default = 32) and **16** rule applications per turn (default = 16); overflow SHALL use deterministic truncate-with-audit policy.
20. **HLR-20.101-020:** IIInB SHALL report TCU usage per repair pass and SHALL remain within IIInB budget ranges defined in [20.150](20.150_tcu_budgeting_requirements.md) (Stage 3 row).
21. **HLR-20.101-021:** IIInB behavior SHALL be deterministic and replayable: identical InB output, `usp_version_ref`, and profile state SHALL yield identical repair tags and escalation refs.
22. **HLR-20.101-022:** IIInB SHALL use fixed reason codes for truncate, USP load failure, cap exceeded, and unsupported-profile outcomes.

### Cross-program separation

23. **HLR-20.101-023:** IMR SHALL NOT invoke IIInB, UPI, or clarification in the same cycle; bounded re-application of IIInB on a later cycle MAY occur only via approved Pipeline A re-interpretation field lists ([20.45](20.45_imr_requirements.md) Type B), not via IMR direct call.
24. **HLR-20.101-024:** IIInB SHALL NOT read or write Pipeline B envelopes (`exec_plan`, `exec_trace`).

### Parent compliance and testability

25. **HLR-20.101-025:** IIInB requirements SHALL satisfy and SHALL NOT weaken parent invariants in 20.10 and 20.30 or reopen [20.100](20.100_inb_requirements.md) InB non-goals.
26. **HLR-20.101-026:** IIInB SHALL remain fully testable via fixtures: profile off (skip), empty USP (escalate only), rule apply, multi-rule precedence, cap truncate.
27. **HLR-20.101-027:** IIInB audit exports SHALL use canonical field ordering per [20.95](20.95_ts_numeric_policy.md).
28. **HLR-20.101-028:** IIInB diagnostic records SHALL be consumable by MB without mutating repair state.

## Wire Schemas (Normative Minimum — v0.1)

### `iiinb_repair_record`

```text
iiinb_repair_record {
  iiinb_event_id,
  cycle_id,
  input_packet_id,
  usp_version_ref,           // pinned read snapshot
  profile_enabled,
  segment_count,
  applied_rule_count,
  repair_outcomes[],         // APPLIED | ESCALATED | SKIPPED | TRUNCATED (per segment)
  rule_ids[],                // canonical sort when APPLIED
  escalation_refs[],         // when ESCALATED
  cap_status,                // OK | SEGMENT_CAP | APPLY_CAP
  tcu_cost,
  reason_codes[],
  rationale_codes[]
}
```

### Intake-bound TP fields (IIInB write contract)

```text
input_repair_tag {
  segment_ref,
  repair_outcome,
  rule_id?,
  resolved_segment_ref?,
  usp_version_ref,
  iiinb_event_id
}

iiinb_escalation_ref {
  escalation_id,
  segment_ref,
  iiinb_event_id,
  escalation_reason_code
}
```

## Verification Focus

- `profile_enabled = false` → skip with no USP load.
- `InB → IIInB → RB` ordering in trace fixtures.
- Rule apply vs escalate determinism.
- No `semantic_core` / `TP.TR` diff when only IIInB runs.
- IMR indirect-only coupling (no same-cycle clarification).
