# **20.31 — Semantic Specification (v0.6, Fully Rewritten)**  
**Status:** Normative — Meaning‑Side Specification  
**Scope:** Defines the semantic structures used *inside Pipeline A and Pipeline B*, including TP semantics, OB/TB/IB behavior, truth evaluation, ΔH% flow, and replay invariants.  
**Excludes:** MTP, semantic_core, global meaning stores, commit semantics, MTPU‑prm, Path‑A→B handoff.

---

# **0. Purpose**

20.31 defines the **meaning‑side semantic structures** used by the Thought Simulator (TS) during a single cycle.  
These structures exist **only inside TP, OuBA, and OuBB** and are **not stored globally**.

This specification covers:

- TP semantic fields  
- OB/TB/IB semantic behavior  
- ΔH% flow  
- truth evaluation semantics  
- completion semantics  
- messy‑input semantics  
- deterministic replay semantics  

It does **not** define any global meaning store.

---

# **1. Semantic Structures (TP / OuBA / OuBB)**

Meaning is represented **only** in:

- **TP** — lane‑local Thought Packet  
- **OuBA** — final meaning output of Pipeline A  
- **OuBB** — final meaning output of Pipeline B  

There is **no global semantic store**.

## **1.1 TP Semantic Fields**

Each TP contains:

- `proposition_set[]`  
- `truth_evidence[]`  
- `completion_state`  
- `delta_h_percent`  
- `messy_input_record`  
- `semantic_tags[]`  
- `lane_local_identity`  
- `ob_trace[]`  
- `tb_trace[]`  
- `policy_markers[]`  

These fields are **local to the cycle**.

### GitHub‑friendly math example  
If a TP computes a ΔH% update:

$ \Delta H\\% = \frac{H_{after} - H_{before}}{H_{before}} $

Underscores inside `\text{...}` are safe.

---

# **2. OB Semantics (Observation Basis)**

OB primitives operate on TP fields and produce:

- evidence  
- ΔH% contributions  
- semantic tags  
- messy‑input markers  
- OB‑specific interpretations  

OB primitives are **deterministic** and **lane‑local**.

### **HLR‑20.31‑001 — OB Determinism**  
Given identical TP input, OB primitives SHALL produce identical output.

---

# **3. TB Semantics (Truth Basis)**

TB evaluates:

- proposition plausibility  
- truth evidence  
- ΔH% adjustments  
- contradiction markers  
- completion signals  

TB does **not** write to any global store.

### **HLR‑20.31‑002 — Truth Evaluation**  
Truth evaluation SHALL be deterministic and SHALL operate only on TP fields.

### GitHub‑friendly math example  
Truth score update:


$ T_{new} = T_{old} + \Delta T $


---

# **4. IB Semantics (Inquiry Basin)**

IB is created only with GB approval and performs:

- deeper truth evaluation  
- recursive evidence gathering  
- structured inquiry  

IB operates **only on TP** and produces **TP‑local** updates.

### **HLR‑20.31‑003 — IB Isolation**  
IB SHALL NOT write to any global structure.

---

# **5. ΔH% Semantics**

ΔH% tracks epistemic change within a cycle.

### **HLR‑20.31‑004 — ΔH% Update Rule**  
ΔH% SHALL be computed deterministically from OB/TB contributions.

$ \Delta H\\%_{total} = \sum_i \Delta H\\%_{OB_i} + \Delta H\\%_{TB} $

---

# **6. Completion Semantics**

Completion state indicates whether meaning construction is:

- incomplete  
- partially complete  
- complete  
- complete‑with‑uncertainty  

### **HLR‑20.31‑005 — Completion Determinism**  
Completion SHALL be derived solely from TP fields and TB results.

---

# **7. Messy‑Input Semantics**

Messy input is tracked **only in TP**.

### **HLR‑20.31‑006 — Messy Input Record**  
`messy_input_record` SHALL capture:

- malformed structures  
- ambiguous phrasing  
- contradictory cues  
- incomplete evidence  

Messy input does **not** propagate beyond the cycle.

---

# **8. Semantic Replay Invariants**

Replay is defined over **TP → OuBA → OuBB**, not over any global meaning store.

### **HLR‑20.31‑007 — Replay Determinism**  
Given identical input and identical seeds:

- TP evolution  
- OB/TB/IB behavior  
- ΔH%  
- completion  
- OuBA  
- OuBB  

SHALL be identical.

### GitHub‑friendly math  
If two runs have identical seeds:

$ \text{Replay}(x, s) = \text{Replay}(x, s) $

---

# **9. Pipeline B Semantic Constraints**

Pipeline B:

- reads OuBA  
- performs realization  
- produces OuBB  
- SHALL NOT modify meaning  

### **HLR‑20.31‑008 — Meaning/Expression Separation**  
Pipeline B SHALL NOT modify propositions, truth evidence, ΔH%, or completion state.

---

# **10. Policy Semantics**

Policy markers in TP enforce:

- safety  
- routing  
- inquiry limits  
- overflow behavior  

### **HLR‑20.31‑009 — Policy Determinism**  
Policy evaluation SHALL be deterministic and SHALL operate only on TP fields.

---

# **11. Overflow and Stability Semantics**

Overflow triggers:

- deterministic degradation  
- tagging  
- bounded evidence truncation  

### **HLR‑20.31‑010 — Overflow Determinism**  
Overflow SHALL produce deterministic, auditable TP‑local effects.

---

# **12. Summary**

20.31 defines the **meaning‑side semantic structures** used inside a TS cycle:

- TP is the sole meaning container  
- OuBA and OuBB are the only outputs  
- No global meaning store exists  
- No semantic_core  
- No MTP involvement  
- All semantics are deterministic  
- All math is GitHub‑friendly  

This rewrite removes all obsolete architecture and aligns 20.31 with the corrected TS model.
