# 20.51 RBU Primitive — Register/Belief/Usage Commit (Path A)

**Document ID:** 20.51_rbu_prim  
**Version:** 0.3  
**Status:** Draft — Path A Primitive  
**Purpose:** Define the RBU primitive as the Path A meaning‑side commit stage for identity, stance, register, tone, and semantic tags, without committing TPTB or TPSF (now Path B / SSR responsibilities).

---

## 1. Overview

RBU is the Path A primitive that commits meaning‑side identity and usage fields for a Thought Packet (TP) after IdOB has refined identity-conditioned meaning. It does **not** commit TPTB or TPSF; those are produced downstream in Path B from OuBA/SSR. RBU finalizes local identity, stance, register, tone, and semantic tags for the current TP turn, preparing it for routing (CTP → RB → RTU) while preserving Path A invariants.

---

## 2. Role in Path A Flow

In Clean and Corrected Path A, RBU appears after IdOB in the meaning‑side loop:

- Clean Path A (conceptual):

  ```
  InB → SOB → SROB → CnOB → SmOB → SSG → TR → CTP → RB → RTU → IdOB → RBU → CTP → RB → RTU → IdOB → RBU → ... → OuBA
  ```

- Corrected Path A (conceptual):

  ```
  InB → IIInB → IE → ISc → CEx → CE → TPU → IMR → SOB → SROB → CnOB → SmOB → SSG → TR → CTP → RB → RTU → IdOB → RBU → ... → CTP → RB → RTU → OuBA
  ```

RBU operates strictly on meaning fields produced by IdOB and does not alter structural geometry.

---

## 3. High-Level Requirements

- **HLR-20.051-001:** RBU commits local identity cues (subculture, persona, role) into the TP’s meaning fields based on IdOB output.
- **HLR-20.051-002:** RBU commits stance, register, and tone for the TP, derived from IdOB-refined meaning, without modifying structural geometry.
- **HLR-20.051-003:** RBU attaches semantic tags and lineage markers (e.g., source, prior TP references) to the TP’s meaning fields for replay and audit.
- **HLR-20.051-004:** RBU operates deterministically and boundedly; repeated evaluation under identical inputs produces replay-equivalent meaning commits.
- **HLR-20.051-005:** RBU does not produce or commit TPTB or TPSF; those are derived in Path B from OuBA/SSR and are outside Path A scope.
- **HLR-20.051-006:** RBU preserves strict pre-/post-semantic separation by only operating on meaning fields that IdOB has already refined.
- **HLR-20.051-007:** RBU prepares the TP for routing via CTP → RB → RTU by ensuring meaning-side identity and usage fields are fully committed and stable.
- **HLR-20.051-008:** RBU maintains envelope and boundary-condition compliance as defined in pa_boundary_conditions.md and related Path A reference manuals.
**HLR-20.051-009:** RBU SHALL execute after every IdOB cycle, committing meaning-side identity and usage fields before routing (CTP → RB → RTU). RBU SHALL NOT be deferred only to the final cycle before OuBA.

---

## 4. Inputs and Outputs

- **Inputs:**
  - TP snapshot from CTP containing:
    - structural fields (immutable)
    - IdOB-refined meaning fields
    - identity profiles and referential bindings

- **Outputs:**
  - TP snapshot with:
    - committed identity cues (local subculture, persona, role)
    - committed stance, register, tone
    - semantic tags and lineage markers
    - unchanged structural geometry
    - ready state for routing (RB/RTU) and eventual OuBA

---

## 5. Invariant Compliance

RBU must:

- respect structural/meaning separation (no changes to structure vectors or envelopes),
- maintain monotonic accumulation of meaning signals (no destructive edits),
- preserve replay equivalence under CTP snapshot comparison,
- operate within correction_context when invoked in corrected paths, without violating boundedness or determinism.

---

## 6. Path B / SSR Boundary

RBU is the **last meaning‑side commit primitive in Path A**.  
It does **not** define or commit:

- TPTB (truth-to-belief metadata),
- TPSF (truth/safety semantic fields).

These are constructed in Path B from OuBA output and SSR formatting. RBU’s responsibility ends at committing Path A meaning‑side identity and usage fields.
