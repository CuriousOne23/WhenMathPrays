# **20.51 — RBU Primitive (Register / Belief / Usage Commit)**  
**Document ID:** 20.51  
**Version:** 2.0 (Structural Optimization + TP‑Field Update)  
**Status:** Normative — Path‑A Primitive  
**Purpose:** Commit meaning‑side identity, stance, register, tone, and semantic tags after IdOB refinement  

---

# **1. Purpose** *(Informative)*

The Register/Belief/Usage Commit primitive (RBU‑prm) is the **meaning‑side commit stage** of Path‑A.  
Its role is to commit **identity‑conditioned meaning fields** refined by IdOB into the Thought Packet (TP), including:

- identity  
- stance  
- register  
- tone  
- semantic tags  
- lineage markers  

RBU does **not** commit truth‑to‑belief (TPTB) or truth/safety fields (TPSF).  
Those belong to **Path‑B / SSR**.

RBU prepares the TP for routing through:

```
CTP → RB → RTU → IdOB → RBU → …
```

RBU performs **no structural modification** and **no semantic inference**.

---

# **2. Position in Path‑A** *(Informative)*

RBU appears after IdOB in the meaning‑side loop.

### **Clean Path‑A (conceptual)**

```
InB → SOB → SROB → CnOB → SmOB → SSG → TR → CTP → RB → RTU → IdOB → RBU → …
```

### **Corrected Path‑A (conceptual)**

```
InB → IIInB → IE → ISc → CEx → CE → TPU → IMR
→ SOB → SROB → CnOB → SmOB → SSG → TR → CTP → RB → RTU → IdOB → RBU → …
```

RBU operates **only** on meaning fields refined by IdOB.  
RBU does **not** alter structural geometry or pre‑semantic fields.

---

# **3. Normative Requirements (HLRs)**

---

## **3.1 Meaning‑Side Commit Requirements**

### **HLR‑20.051‑001 — Identity Commit**  
RBU SHALL commit identity cues (subculture, persona, role) into `TP.semantic.identity` based on IdOB output.

### **HLR‑20.051‑002 — Stance/Register/Tone Commit**  
RBU SHALL commit stance, register, and tone into:

- `TP.semantic.stance`  
- `TP.semantic.register`  
- `TP.semantic.tone`

RBU SHALL NOT modify structural geometry or non‑semantic TP fields.

### **HLR‑20.051‑003 — Semantic Tags & Lineage Markers**  
RBU SHALL attach semantic tags to `TP.semantic.tags` and lineage markers to `TP.metadata.lineage_markers`, preserving all other metadata fields.

### **HLR‑20.051‑004 — Deterministic Commit**  
RBU SHALL operate deterministically; identical inputs SHALL produce replay‑equivalent meaning commits.

### **HLR‑20.051‑005 — No TPTB/TPSF Commit**  
RBU SHALL NOT produce or commit TPTB or TPSF.  
These fields belong exclusively to Path‑B / SSR.

### **HLR‑20.051‑006 — Pre/Post‑Semantic Separation**  
RBU SHALL operate only on meaning fields refined by IdOB and SHALL NOT modify structural geometry or pre‑semantic fields.

---

## **3.2 TP Field Protection**

### **HLR‑20.051‑010 — TP Field Protection**  
RBU SHALL NOT modify:

- `TP.process`  
- `TP.context`  
- `TP.intake`  
- `TP.ssg_signature`  
- `TP.ssg_layer_bitmap`  
- `TP.ssg_reason_code`  
- `TP.ssg_status`  
- `TP.presemantic_cues`  
- `TP.tr_input_cues`

RBU SHALL modify only the meaning‑side fields listed in §4.

---

## **3.3 Routing Preparation**

### **HLR‑20.051‑007 — Routing Readiness**  
RBU SHALL prepare the TP for routing via:

```
CTP → RB → RTU
```

by ensuring meaning‑side identity and usage fields are fully committed and stable.

### **HLR‑20.051‑008 — Boundary Compliance**  
RBU SHALL maintain envelope and boundary‑condition compliance as defined in Path‑A boundary specifications.

### **HLR‑20.051‑009 — Per‑Cycle Execution**  
RBU SHALL execute after **every IdOB cycle**, committing meaning‑side fields before routing.  
RBU SHALL NOT defer commits only to the final cycle before OuBA.

---

# **4. Inputs and Outputs (Normative)**

---

## **4.1 Inputs**

RBU SHALL accept a TP snapshot from CTP containing:

- structural fields (immutable)  
- IdOB‑refined meaning fields  
- identity profiles  
- referential bindings  
- lineage metadata  
- semantic tags  
- usage cues  

RBU SHALL NOT modify structural fields or pre‑semantic fields.

---

## **4.2 Outputs**

RBU SHALL output a TP snapshot with updates **only** to:

- `TP.semantic.identity`  
- `TP.semantic.stance`  
- `TP.semantic.register`  
- `TP.semantic.tone`  
- `TP.semantic.tags`  
- `TP.metadata.lineage_markers`  

All other TP fields SHALL remain unchanged.

---

# **5. Invariant Compliance (Normative)**

RBU SHALL:

### **Structural/Meaning Separation**  
- preserve structural geometry  
- avoid modifying structural vectors or envelopes  

### **Monotonic Meaning Accumulation**  
- commit meaning signals without destructive edits  
- preserve IdOB‑refined meaning fields  

### **Replay Equivalence**  
- produce identical commits for identical CTP snapshots  

### **Bounded Determinism**  
- operate within correction_context without violating boundedness  

---

# **6. Path‑B / SSR Boundary (Normative)**

RBU is the **final meaning‑side commit primitive in Path‑A**.

### RBU SHALL NOT commit:

- TPTB (truth‑to‑belief metadata)  
- TPSF (truth/safety semantic fields)  

These fields are constructed exclusively in **Path‑B** from OuBA and SSR.

RBU’s responsibility ends at committing **Path‑A meaning‑side identity and usage fields**.
