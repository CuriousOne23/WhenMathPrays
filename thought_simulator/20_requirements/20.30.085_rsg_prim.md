# **20.30.085 — RSG‑prm (Response Surface Generator Primitive)**  
**Status:** Normative (HLR‑20.30.085‑xxx only)  
**Scope:** Surface‑form realization, expression‑layer rendering, seed‑isolated variability  
**Excludes:** Meaning construction, semantic evaluation, safety evaluation, truth evaluation

---

# **1. Introduction (informative)**

The **Response Surface Generator (RSG)** is the final expression‑layer primitive of Pipeline B.  
It receives the fully validated realization substrate and realization plan from upstream Path B primitives and produces the final **surface‑form response**.  
RSG performs **expression‑only rendering**: it does not modify meaning, does not reinterpret metadata, and does not perform semantic inference.

RSG operates exclusively on the **SSR** packet and downstream realization metadata.  
All variability is controlled by the response‑generator seed.

---

# **2. Purpose (informative)**

The purpose of RSG is to:

- convert realization steps into surface‑form linguistic constructs  
- apply tone, style, and structural cues  
- incorporate truth‑aware and safety‑aware expression patterns  
- apply seed‑isolated expressive variability  
- produce a deterministic, replay‑safe output for OuBB  

RSG does not:

- modify SSR  
- reinterpret meaning  
- evaluate truth or safety  
- perform planning or routing  
- generate alternative meaning paths  

---

# **3. Input Specification (informative)**

RSG consumes the following fields:

### **3.1 Realization Plan (from RPlan)**  
- `ssr.rplan.rplan_status`  
- `ssr.rplan.ordered_steps[]`  
- `step_id`, `step_type`, `payload`, `constraint_set`, `continuity_weight`, `step_status`

### **3.2 Partial Realization (from RPU)**  
- `ssr.rpu_partial.rpu_status`  
- `ssr.rpu_partial.accumulated`  
- `ssr.rpu_partial.step_records[]`

### **3.3 Metadata (from SSR)**  
- `ssr.truth_tags`  
- `ssr.safety_flags`  
- `ssr.tptb_fields`  
- `ssr.tpsf_fields`  
- `ssr.provenance_chain`  
- `ssr.continuity_fields`

### **3.4 Response‑Generator Seed**  
A seed controlling expressive variability.

### **3.5 Commit Metadata**  
- `commit_id`  
- `seed_scope_ref`  

RSG does not access any Pipeline A structures beyond SSR.

---

# **4. Transfer / Process Specification (informative)**

RSG executes a deterministic rendering pipeline consisting of:

### **4.1 Step Realization Assembly**  
RSG assembles realization fragments from:

- `ssr.rplan.ordered_steps[]`  
- `ssr.rpu_partial.accumulated`  

Fragments are combined in index order.

### **4.2 Expression Pattern Selection**  
Expression patterns are selected deterministically from:

- truth metadata (`ssr.tptb_fields`)  
- safety metadata (`ssr.tpsf_fields`)  
- continuity cues  
- realization step types  

No inference is performed; patterns are selected by direct lookup.

### **4.3 Seed‑Isolated Variability**  
Let:

```
seed = seed_scope_ref
```

Variability applies only to:

- lexical choice  
- phrasing  
- stylistic shading  
- ordering of equivalent expressions  

Meaning remains unchanged.

### **4.4 Surface‑Form Construction**

Let:

```
R = ⟨ r_1, r_2, …, r_k ⟩
```

be the ordered realization fragments.

The final surface‑form output is:

```
output = combine(r_1, r_2, …, r_k, seed)
```

where `combine` is deterministic for a fixed seed.

### **4.5 Replay Determinism**

Replay determinism requires:

```
(SSR, seed) → identical output
```

Meaning is fixed in SSR; only expression varies with seed.

---

# **5. Output Specification (informative)**

RSG produces:

- `ssr.rsg.output_text` — the final surface‑form response  
- `ssr.rsg.output_metadata` — tone/style/structure metadata  
- `ssr.rsg.realization_trace` — mapping from realization steps to output segments  
- `ssr.rsg.rsg_status` — `COMPLETE` or `ABORTED`  
- `ssr.rsg.reason_code` — non‑empty on failure  

RSG does not modify SSR and does not write to any Pipeline A structure.

---

# **6. High‑Level Requirements (normative)**

### **HLR‑20.30.085‑001 — SSR‑Only Operation**  
RSG **SHALL** operate exclusively on the finalized SSR and downstream Path B metadata.

### **HLR‑20.30.085‑002 — No Meaning Mutation**  
RSG **SHALL NOT** modify meaning, reinterpret meaning, or alter any semantic field in SSR.

### **HLR‑20.30.085‑003 — Deterministic Rendering**  
For a fixed `(SSR, seed)` tuple, RSG **SHALL** produce deterministic surface‑form output.

### **HLR‑20.30.085‑004 — Seed‑Isolated Variability**  
RSG **SHALL** restrict expressive variability exclusively to the response‑generator seed.

### **HLR‑20.30.085‑005 — No Truth or Safety Evaluation**  
RSG **SHALL NOT** perform truth evaluation or safety evaluation and **SHALL** treat TPTB/TPSF fields as authoritative.

### **HLR‑20.30.085‑006 — Metadata‑Driven Expression**  
RSG **SHALL** select expression patterns solely from SSR metadata without inference.

### **HLR‑20.30.085‑007 — Replay Equivalence**  
RSG **SHALL** satisfy replay equivalence: identical `(SSR, seed)` inputs produce identical output.

### **HLR‑20.30.085‑008 — No Write‑Back**  
RSG **SHALL NOT** write to SSR, MTP, or any Pipeline A structure.

### **HLR‑20.30.085‑009 — Output Completeness**  
RSG **SHALL** populate all fields in the Output Specification on every execution path.

### **HLR‑20.30.085‑010 — Abort Conditions**  
RSG **SHALL** set `ssr.rsg.rsg_status = ABORTED` and write a non‑empty `reason_code` when required inputs are absent or malformed.
