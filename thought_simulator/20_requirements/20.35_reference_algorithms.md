# 20.35 Reference Algorithms

## 1. Purpose and Scope
This document provides deterministic, mechanism-level reference algorithms for TS.

These algorithms operationalize the semantics defined in:
- 20.30 TS Functional Model
- 20.31 Semantic Specification

This document SHALL:
- define deterministic input/output signatures
- avoid hidden state and probabilistic branching
- preserve existing semantics without redefining them
- use explicit field-wise operations and deterministic safe-boundary handling
- remain auditable and replayable

This document SHALL NOT:
- introduce benchmark targets, multipliers, or comparative claims
- introduce new semantics beyond 20.30 and 20.31
- rely on latent inference or opaque model behavior

## 2. Reference Algorithm Conventions
### 2.1 General notation
- `state` means the current canonical TS state object.
- `tp` means a Thought Packet.
- `mtp` means the current Master Thought Packet.
- `lanes` means the deterministic set of projected lane packets.
- `evidence` means structured OB output fields.
- `signature` means the execution signature, including seed and profile-bound deterministic settings.
- `safe_boundary` means a point at which mutation is permitted by policy.

### 2.2 Determinism rules
Each algorithm SHALL:
- read only declared inputs
- produce the same output for identical inputs and signature state
- apply explicit ordering rules when combining records
- emit deterministic logging and reason codes

### 2.3 Field operation rules
Common field operations are:
- `overwrite`: replace the field value deterministically
- `sum`: add numeric values deterministically
- `max`: keep the greater ordered value deterministically
- `min`: keep the lesser ordered value deterministically
- `weighted`: combine values with explicit deterministic weights
- `rule_based`: select the value indicated by a declared rule table

### 2.4 Traceability rule
Each algorithm references its semantic source in comments or headings only. It SHALL NOT add new meaning or policy.

## 3. Splitting Algorithms
### 3.1 TP to lane projection
```pseudocode
INPUT: tp, routing_plan, signature
OUTPUT: lanes, split_log

ASSERT signature is deterministic and valid
ASSERT routing_plan is canonical and ordered

lanes := empty list
split_log := empty list

FOR each lane_rule in routing_plan in canonical order:
    lane := new lane packet
    lane.visible_fields := project(tp.fields, lane_rule.visible_fields)
    lane.suppressed_fields := project(tp.fields, lane_rule.suppressed_fields)
    lane.semantic_tags := select(tp.semantic_tags, lane_rule.tag_filter)
    lane.delta_h_potential := compute_lane_delta_h(tp, lane_rule)
    lane.projection_id := lane_rule.id
    lane.lineage := append(tp.lineage, lane_rule.id)
    lanes.append(lane)
    split_log.append(log_split(tp.id, lane.projection_id, lane.delta_h_potential))
END FOR

RETURN lanes, split_log
```

### 3.2 Visible vs suppressed semantics
```pseudocode
INPUT: tp, projection_spec
OUTPUT: visible_view, suppressed_view

visible_view := empty record
suppressed_view := empty record

FOR each field in tp.fields in canonical field order:
    IF field is allowed by projection_spec THEN
        visible_view[field.name] := field.value
    ELSE
        suppressed_view[field.name] := field.value
    END IF
END FOR

RETURN visible_view, suppressed_view
```

### 3.3 Delta-H potential assignment

```pseudocode
delta_h_potential := 0

FOR each field in lane_rule.contributing_fields in canonical order:
```

## 4. Merging Algorithms
### 4.1 Lane TP to MTP merge
```pseudocode
INPUT: lanes, mtp, merge_policy
OUTPUT: updated_mtp, merge_log

updated_mtp := copy(mtp)
merge_log := empty list

FOR each lane in lanes in canonical order:
    FOR each field in lane.visible_fields in canonical field order:
        updated_mtp[field.name] := merge_field(updated_mtp[field.name], field.value, merge_policy[field.name])
    END FOR
    updated_mtp.lineage := merge_lineage(updated_mtp.lineage, lane.lineage)
    merge_log.append(log_merge(lane.id, updated_mtp.id))
END FOR

RETURN updated_mtp, merge_log
```

### 4.2 Field-wise merge rules
```pseudocode
INPUT: existing_value, incoming_value, merge_rule
OUTPUT: merged_value

SWITCH merge_rule.type:
    CASE overwrite:
        merged_value := incoming_value
    CASE sum:
        merged_value := existing_value + incoming_value
    CASE max:
        merged_value := max(existing_value, incoming_value)
    CASE min:
        merged_value := min(existing_value, incoming_value)
    CASE weighted:
        merged_value := (existing_value * merge_rule.existing_weight) + (incoming_value * merge_rule.incoming_weight)
    CASE rule_based:
        merged_value := apply_rule_table(existing_value, incoming_value, merge_rule.rule_table)
    DEFAULT:
        merged_value := existing_value
END SWITCH

RETURN merged_value
```

### 4.3 Conflict resolution
```pseudocode
INPUT: field_name, existing_value, incoming_value, conflict_policy
OUTPUT: resolved_value, conflict_record

IF values are equal THEN
    resolved_value := existing_value
    conflict_record := none
ELSE
    resolved_value := apply_conflict_policy(field_name, existing_value, incoming_value, conflict_policy)
    conflict_record := log_conflict(field_name, existing_value, incoming_value, resolved_value)
END IF

RETURN resolved_value, conflict_record
```

### 4.4 Lineage merge
```pseudocode
INPUT: existing_lineage, incoming_lineage
OUTPUT: merged_lineage

merged_lineage := concatenate(existing_lineage, incoming_lineage)
merged_lineage := deduplicate_preserving_order(merged_lineage)

RETURN merged_lineage
```

## 5. Delta-H% Normalization Algorithms
### 5.1 Per-basin Delta-H contribution
```pseudocode
INPUT: basin_outputs
OUTPUT: basin_delta_h

basin_delta_h := 0

FOR each output in basin_outputs in canonical order:
    basin_delta_h := basin_delta_h + output.delta_h_value
END FOR

RETURN normalize_numeric(basin_delta_h)
```

### 5.2 Global Delta-H normalization
```pseudocode
INPUT: basin_delta_h_values, global_limit
OUTPUT: normalized_delta_h_values, normalization_log

sum_delta_h := sum(basin_delta_h_values)
normalization_log := empty list

IF sum_delta_h <= global_limit THEN
    normalized_delta_h_values := basin_delta_h_values
ELSE
    scale_factor := global_limit / sum_delta_h
    normalized_delta_h_values := empty list

    FOR each value in basin_delta_h_values in canonical order:
        normalized_value := value * scale_factor
        normalized_delta_h_values.append(normalized_value)
    END FOR

    normalization_log.append(log_normalization(sum_delta_h, global_limit, scale_factor))
END IF

RETURN normalized_delta_h_values, normalization_log
```

### 5.3 Overflow-triggered Delta-H compression
```pseudocode
INPUT: delta_h_values, overflow_state
OUTPUT: compressed_delta_h_values

IF overflow_state is not active THEN
    RETURN delta_h_values
END IF

compressed_delta_h_values := empty list
FOR each value in delta_h_values in canonical order:
    compressed_value := compress_value_deterministically(value, overflow_state.compression_rule)
    compressed_delta_h_values.append(compressed_value)
END FOR

RETURN compressed_delta_h_values
```

### 5.4 Missing-mass accounting
```pseudocode
INPUT: original_delta_h, normalized_delta_h
OUTPUT: missing_mass

missing_mass := original_delta_h - normalized_delta_h
IF missing_mass < 0 THEN
    missing_mass := 0
END IF

RETURN missing_mass
```

## 9. Overflow/Degradation Algorithms
### 9.1 Lane truncation
```pseudocode
INPUT: lanes, overflow_policy
OUTPUT: truncated_lanes, overflow_log

IF count(lanes) > overflow_policy.max_lanes THEN
    truncated_lanes := take_first(lanes, overflow_policy.max_lanes)
    overflow_log.append(log_overflow("lane_truncation", count(lanes), count(truncated_lanes)))
END IF

RETURN truncated_lanes, overflow_log
```

### 9.2 Evidence truncation
```pseudocode

    overflow_log.append(log_overflow("evidence_truncation", size(evidence_list), size(truncated_evidence)))
```

## 14. Appendix: Worked Mini-Examples
### 14.1 Splitting example
Input TP has fields `{propositions, stance, affect, intent, lineage}`.
Lane A receives `propositions` and `stance`; Lane B receives `intent` and `affect`.
Suppressed fields remain recorded in the lane projection metadata.

### 14.2 Merging and Delta-H normalization example
Lane A contributes Delta-H 0.30 and Lane B contributes Delta-H 0.50.
Global limit is 0.60, so normalized values are scaled deterministically and missing mass is recorded as `0.20`.

### 14.3 TB interpretation and overflow tagging example
OB evidence yields deterministic stance = neutral, affect = constrained, intent = clarify, logic = consistent, social = defer.
If lane count exceeds the configured limit, the overflow tag is set and routing fan-out is reduced deterministically.
