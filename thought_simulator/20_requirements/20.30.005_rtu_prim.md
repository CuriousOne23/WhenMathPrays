# 20.30.005 — RTU‑prm (Routing TP Update Primitive)

## 1. Scope
This section defines the RTU‑prm primitive responsible for producing routing‑layer updates to the TP prior to Path A interpretation. RTU‑prm operates only on routing metadata and does not perform semantic, truth, safety, or commit‑layer computation.

## 2. Informative Overview
RTU‑prm updates routing metadata used by TR‑prm and the scheduler. It determines lane activation, lane suppression, and routing‑relevant signals derived from the user request and prior TP state. RTU‑prm does not modify semantic_core, truth_hypotheses, TPTB, TPSF, ΔH%, H%, or any MTP‑level structure.

## 3. Normative Requirements

### 3.1 Routing Metadata Construction
- **HLR‑20.30.005‑001:** RTU‑prm **SHALL** construct a routing_update object containing only routing‑layer fields required by TR‑prm and the scheduler.
- **HLR‑20.30.005‑002:** RTU‑prm **SHALL** ensure routing_update contains no semantic, truth, safety, or commit‑layer fields.
- **HLR‑20.30.005‑003:** RTU‑prm **SHALL** include lane_activation signals indicating which interpretive lanes are eligible for execution.
- **HLR‑20.30.005‑004:** RTU‑prm **SHALL** include lane_suppression signals indicating which lanes must not be executed in the current cycle.
- **HLR‑20.30.005‑005:** RTU‑prm **SHALL** include routing_reason codes describing why each lane was activated or suppressed.

### 3.2 Determinism and Replay Safety
- **HLR‑20.30.005‑006:** RTU‑prm **SHALL** produce routing_update deterministically from the user request and prior TP routing metadata.
- **HLR‑20.30.005‑007:** RTU‑prm **SHALL** not depend on global state, stochastic processes, or latent‑space sampling.
- **HLR‑20.30.005‑008:** RTU‑prm **SHALL** ensure that identical inputs produce identical routing_update outputs.

### 3.3 Structural Constraints
- **HLR‑20.30.005‑009:** RTU‑prm **SHALL** not modify semantic_core.
- **HLR‑20.30.005‑010:** RTU‑prm **SHALL** not modify truth_hypotheses.
- **HLR‑20.30.005‑011:** RTU‑prm **SHALL** not modify TPTB or TPSF.
- **HLR‑20.30.005‑012:** RTU‑prm **SHALL** not modify ΔH% or H%.
- **HLR‑20.30.005‑013:** RTU‑prm **SHALL** not modify merge_result or update_structure.
- **HLR‑20.30.005‑014:** RTU‑prm **SHALL** not modify any MTP‑level field.

### 3.4 Routing Signal Semantics
- **HLR‑20.30.005‑015:** RTU‑prm **SHALL** compute lane_activation using only routing‑relevant features of the user request and prior TP routing metadata.
- **HLR‑20.30.005‑016:** RTU‑prm **SHALL** compute lane_suppression when a lane is structurally incompatible with the request or violates routing constraints.
- **HLR‑20.30.005‑017:** RTU‑prm **SHALL** ensure that lane_activation and lane_suppression do not conflict; if conflict arises, suppression **SHALL** take precedence.
- **HLR‑20.30.005‑018:** RTU‑prm **SHALL** include a routing_confidence scalar in $[0,1]$ indicating routing stability (informative to TR‑prm but not a probability).

### 3.5 Interaction with TR‑prm and Scheduler
- **HLR‑20.30.005‑019:** RTU‑prm **SHALL** expose routing_update to TR‑prm without requiring TR‑prm to recompute routing signals.
- **HLR‑20.30.005‑020:** RTU‑prm **SHALL** ensure routing_update is complete and self‑contained for scheduling decisions.
- **HLR‑20.30.005‑021:** RTU‑prm **SHALL** not invoke TR‑prm, OB‑prm, TB‑prm, RB‑prm, or any interpretive primitive.

### 3.6 Error and Constraint Handling
- **HLR‑20.30.005‑022:** RTU‑prm **SHALL** detect structurally invalid routing metadata and replace it with a deterministic fallback routing_update.
- **HLR‑20.30.005‑023:** RTU‑prm **SHALL** log routing_error codes when fallback routing is used.
- **HLR‑20.30.005‑024:** RTU‑prm **SHALL** ensure fallback routing preserves safety by suppressing unsafe or undefined lanes.

## 4. Mathematical Notes (Informative)
Routing confidence is a structural stability indicator, not a probability. A typical form is:

$$
routing\_confidence = 1 - \frac{\text{num\_suppressed\_lanes}}{\text{total\_lanes}}
$$

This value is used only as a routing heuristic and has no semantic or truth‑evaluation meaning.

## 5. Outputs
RTU‑prm produces a routing_update object containing:
- lane_activation  
- lane_suppression  
- routing_reason codes  
- routing_confidence  
- routing_error (optional)

No other fields are permitted.
