# **6.1.1 Intake & Pre‑Correction Group**

### **Mini‑Flow**
```
InB → IIInB → IE
```

### **What this group does**
Creates a **bounded, normalized, replayable intake object** and applies **initial bounded repairs** before any correction scoring or expansion.

### **Primitive breakdown**
- **InB** — Raw intake boundary; captures user input and initializes TP representation fields.  
- **IIInB** — Bounded intake repair; fixes structural defects, malformed tokens, and USP‑required repairs.  
- **IE** — Intake Envelope; produces the normalized, structured, replayable intake object used by all downstream correction primitives.

### **Why this group sits here**
- Correction cannot begin until the intake object is normalized.  
- IE must occur **before** any scoring or expansion (ISc, CEx).  
- This group ensures Path A always starts from a deterministic intake substrate.

---

# **6.1.2 Correction Group (Only active in correction mode)**

### **Mini‑Flow**
```
ISc → CEx → CE → TPU → IMR
```

### **What this group does**
Evaluates, expands, selects, commits, and validates corrections to the intake object before semantic interpretation begins.

### **Primitive breakdown**
- **ISc** — Scores correction candidates using bounded heuristics.  
- **CEx** — Expands correction hypotheses (structural, lexical, USP‑driven).  
- **CE** — Selects the winning correction candidate.  
- **TPU** — Commits the corrected TP representation.  
- **IMR** — Mismatch Review; determines whether another correction cycle is required.

### **Why this group sits here**
- Correction must complete **before** any semantic or structural interpretation.  
- OB‑set primitives (SOB, SROB, etc.) must operate on a stable, corrected TP.  
- IMR is the final gate before entering the semantic pipeline.

---

# **6.1.3 Structural Interpretation Group (OB‑Set)**

### **Mini‑Flow**
```
SOB → SROB → CnOB → SmOB → SSG
```

### **What this group does**
Builds the **field‑structural vector** of the TP — the structured, stabilized field‑geometry that IdOB uses for **identity‑conditioned semantic mapping on the manifold**.

This is the stage where Path A constructs the *geometric substrate* that IdOB will interpret.

---

### **Primitive breakdown**

- **SOB — Structural Object Builder**  
  Establishes the initial structural segmentation and field boundaries.  
  Produces the coarse‑grained structural frame that all later OBs refine.

- **SROB — Semantic Role Object Builder**  
  Assigns structural roles (agent, patient, target, modifier, etc.) to the segmented fields.  
  Converts raw structure into a role‑bearing field graph.

- **CnOB — Constraint Object Builder**  
  Applies structural and relational constraints to the field graph.  
  Ensures the field‑structural vector obeys internal consistency rules.

- **SmOB — Smoothing Object Builder**  
  Harmonizes inconsistencies, resolves structural tension, and smooths the field geometry.  
  Produces a stable, low‑noise structural manifold input.

- **SSG — Structural Stabilization Gate**  
  Freezes the field‑structural vector.  
  Guarantees IdOB receives a deterministic, stable structural substrate.

---

### **Why this group sits here**

- IdOB requires a **fully stabilized field‑structural vector** to perform identity‑conditioned semantic mapping.  
- Routing (RBU → CTP → RB → RTU) must occur **after** structural stabilization.  
- Correction must occur **before** any OB‑set primitive.  
- The OB‑set is the **structural foundation** of Path A meaning construction — everything downstream depends on it.

---

# **6.1.4 Routing Preparation Group**

### **Mini‑Flow**
```
RBU → CTP → RB → RTU
```

### **What this group does**
Prepares and executes routing decisions, then commits routing metadata for downstream semantic interpretation.

### **Primitive breakdown**
- **RBU** — Routing Build‑Up; enriches TP with routing‑relevant metadata.  
- **CTP** — Consolidated TP; aggregates OB‑set outputs into a routing‑ready structure.  
- **RB** — Routing Basin; performs routing arbitration and selects the routing path.  
- **RTU** — Routing Tag Update; commits routing metadata to TP.

### **Why this group sits here**
- Routing must occur **after** structural stabilization (SSG).  
- IdOB requires routing metadata to perform semantic interpretation.  
- RTU is the final routing commit before semantic interpretation.

---

# **6.1.5 Semantic Interpretation & Truth‑Relation Group**

### **Mini‑Flow**
```
IdOB → TR → OuBA
```

### **What this group does**
Performs semantic interpretation, maps truth‑relations, and finalizes Path A.

### **Primitive breakdown**
- **IdOB** — Identity Object Builder; performs semantic interpretation, meaning refinement, and identity‑conditioned meaning resolution.  
- **TR** — Truth‑Relation Mapper; maps truth‑relations and prepares the TP for IB‑side truth evaluation (TB).  
- **OuBA** — Output Builder A‑side; finalizes the TP snapshot for A→B transfer.

### **Why this group sits here**
- Semantic interpretation must occur **after routing**.  
- TR must occur **after semantic meaning is committed**.  
- OuBA is the final A‑side commit before IB (TB, TPTB, Safety Basins, TPSF) and Path B.
