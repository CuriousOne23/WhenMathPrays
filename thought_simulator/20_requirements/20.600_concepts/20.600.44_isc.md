# **20.600.44 — ISc (Inference Scalar / Semantic Projection Engine)**  
### *Conceptual Overview*

---

## **Purpose**

The ISc is the **semantic projection engine** of the Thought Simulator.  
It operates **after** semantic meaning exists and is responsible for:

- comparing meanings to the envelope  
- detecting semantic defects  
- resolving referents  
- repairing incomplete or inconsistent meaning  
- computing the **nearest valid meaning**  
- proposing corrected meaning to the IB  

> **ISc fixes the *meaning* so it can be committed.**

It is the semantic counterpart to IIInB.

---

# **What ISc *Is***  
Each item includes a concrete example.

---

## **1. A semantic comparison engine**  
ISc compares:

- $M_0$ (prior meaning)  
- $M_c$ (candidate meaning)  
- envelope constraints  
- MI tags  
- USP rules  

**Example:**  
User input:  
> “turn it on”  
ISc compares “it” against envelope referents and finds exactly one match: **desk lamp**.

---

## **2. A referent resolver**  
ISc resolves pronouns and implicit entities when the envelope yields a **unique** candidate.

**Example:**  
User input:  
> “call her”  
Envelope shows only one female contact → **Sarah**.  
ISc resolves “her” → Sarah.

---

## **3. A semantic defect detector**  
ISc identifies:

- missing semantic roles  
- contradictions  
- unsafe merges  
- type violations  
- ΔH% anomalies  

**Example:**  
User input:  
> “book a flight to Paris from Paris”  
ISc detects a contradiction in source/destination.

---

## **4. A projection engine**  
ISc computes the **nearest valid meaning** $M'$ that satisfies all constraints.

**Example:**  
User input:  
> “schedule meeting”  
Envelope shows a single upcoming time the user referenced: **tomorrow at 3**.  
ISc proposes:  
> schedule(meeting, time=tomorrow_3pm)

---

## **5. A semantic repair generator**  
ISc uses Detection’s local repair options to generate candidate repairs.

**Example:**  
User input:  
> “send it”  
Detection flags missing recipient.  
Envelope shows a single active conversation → **Alice**.  
ISc proposes:  
> send(message, recipient=Alice)

---

## **6. A projection cost calculator**  
ISc evaluates how far $M_c$ deviates from $M_0$ and the envelope.

**Example:**  
User input:  
> “delete everything”  
Envelope shows this violates safety constraints → projection cost is infinite → reject.

---

## **7. A proposer, not an applier**  
ISc **never applies** corrections.  
It only proposes $M'$ to the IB.

**Example:**  
ISc proposes:  
> turn_on(desk_lamp)  
IB decides whether to accept or reject.

---

# **What ISc *Is Not***  
Each item includes a concrete example **and the primitive that *does* handle it**, ensuring no architectural holes.

---

## **1. Not a TP repair module**  
ISc does not fix surface text.

**Example:**  
User input:  
> “turn on lights kitchen”  
ISc does **not** insert “the” or “in the.”

**Handled By:**  
→ **IIInB**, which normalizes the TP before meaning is built.

---

## **2. Not a shorthand expander**  
ISc does not expand elliptical or shorthand input.

**Example:**  
User input:  
> “again”  
ISc does **not** expand this.

**Handled By:**  
→ **IIInB**, which expands to “repeat the last action.”

---

## **3. Not a USP surface normalizer**  
ISc does not apply USP rules that affect surface form.

**Example:**  
User input:  
> “open door”  
ISc does **not** insert “the.”

**Handled By:**  
→ **IIInB**, which expands to “open the door.”

---

## **4. Not a semantic_core constructor**  
ISc does not build meaning from TP.

**Example:**  
User input:  
> “add milk, eggs, and bread”  
ISc does **not** create semantic_core.

**Handled By:**  
→ **Pipeline A**, which constructs semantic_core from normalized TP.

---

## **5. Not a global gatekeeper**  
ISc does not decide whether a correction is accepted.

**Example:**  
ISc proposes:  
> schedule(meeting, time=tomorrow_3pm)  
ISc does **not** apply it.

**Handled By:**  
→ **IB**, which accepts or rejects the proposal.

---

## **6. Not envelope‑modifying**  
ISc does not change the envelope, CIL, COB, or long‑duration meaning.

**Example:**  
User input:  
> “forget Sarah”  
ISc does **not** modify the envelope.

**Handled By:**  
→ **Governance layer**, which handles memory and long‑duration state.

---

## **7. Not creative**  
ISc does not invent meaning not supported by the envelope.

**Example:**  
User input:  
> “send message”  
ISc does **not** guess a recipient if multiple exist.

**Handled By:**  
→ **IB**, which may request clarification from the user.

---

# **Why ISc Exists**

Without ISc:

- referents would remain unresolved  
- contradictions would go undetected  
- missing semantic roles would break execution  
- meaning would drift unpredictably  
- envelope constraints would be unenforced  
- semantic_core would be unsafe to commit  

ISc ensures that **meaning is valid, consistent, and safe** before the IB commits it.
