# 20.167 RPlan — Realization Plan Constructor Primitive

## Purpose

RPlan is the planning primitive for Path B. It accepts the realization substrate
`tp.rsub` from REx, maps each substep to a typed realization step, assigns execution
order and constraint sets, derives per-step continuity weights from
`tp.continuity_fields`, and produces the ordered realization plan `tp.rplan` for
consumption by RPU. RPlan performs no execution, no meaning interpretation, and no
scoring.

**[HLR-20.167-001]** The RPlan primitive SHALL accept `tp.rsub` as its activation
input and SHALL produce `tp.rplan` as a fully populated, ordered realization plan
before RPU begins execution for the same turn.

## Input Contract

The table below defines all inputs RPlan reads. No other TP field, external store,
or runtime service may be accessed during RPlan execution.

| Field | Source Primitive | Required | Type | Validity Constraint |
|---|---|---|---|---|
| `tp.rsub` | REx | Required | structured object | must be present; `rsub_status` ∈ {`READY`, `BLOCKED`} |
| `tp.rsub.rsub_status` | REx | Required | enum | `READY` or `BLOCKED`; any other value is a pre-condition fault |
| `tp.rsub.substeps` | REx | Required | array | non-null; may be empty only when `rsub_status = BLOCKED` |
| `tp.rsub.substeps[i].substep_id` | REx | Required | string | non-empty; unique within the array |
| `tp.rsub.substeps[i].substep_type` | REx | Required | enum | must be a recognised substep_type value; defines the realization action |
| `tp.rsub.substeps[i].payload` | REx | Required | structured object | type-specific; must conform to the schema for `substep_type` |
| `tp.rsub.substeps[i].depends_on` | REx | Optional | array of substep_id | may be absent or empty; each ref must name a `substep_id` in the same array |
| `tp.continuity_fields` | CoHI | Required | structured object | must be present |
| `tp.continuity_fields[j].field_ref` | CoHI | Required | string | identifies a prior TP field; must be a valid TP field path |
| `tp.continuity_fields[j].continuity_score` | CoHI | Required | float | $\gamma_j \in [0, 1]$ |
| `tp.truth_tags` | A-side | Required | array | may be empty |
| `tp.safety_flags` | A-side | Required | array | may be empty |

**[HLR-20.167-002]** The RPlan primitive SHALL read only the fields enumerated in
the Input Contract table; it SHALL NOT read from COB, from any meaning-layer field
written by LI, or from any realization-layer field written by a prior RPU execution.

**[HLR-20.167-003]** The RPlan primitive SHALL perform a pre-condition check before
planning begins: if `tp.rsub` is absent, if `tp.rsub.rsub_status` is not a
recognised enum value, or if `tp.rsub.substeps` is null when `rsub_status = READY`,
RPlan SHALL set `tp.rplan.rplan_status` to `BLOCKED`, SHALL write
`reason_code = PRE_CONDITION_FAULT`, and SHALL halt without constructing any steps.

## Transfer Function

### Abort Path

When `tp.rsub.rsub_status = BLOCKED` on entry and the pre-condition check passes,
RPlan takes the abort path without constructing any realization steps.

**[HLR-20.167-004]** When `tp.rsub.rsub_status = BLOCKED`, the RPlan primitive SHALL
set `tp.rplan.rplan_status` to `BLOCKED`, SHALL propagate `tp.rsub.reason_code` into
`tp.rplan.reason_code`, SHALL write an empty `ordered_steps` array, and SHALL NOT
construct any realization step.

### Planning Path

When `tp.rsub.rsub_status = READY`, RPlan applies the following construction
procedure.

**Step mapping.** Each substep $u_i$ in `tp.rsub.substeps` maps to exactly one
realization step $s_i$ in `tp.rplan.ordered_steps`. The mapping is injective: one
substep produces one step; no substep is silently dropped.

**Ordering.** Steps are topologically sorted by the dependency graph implied by
`depends_on` fields. When no dependency exists between two steps, their relative
order follows the source index order of `tp.rsub.substeps`.

**[HLR-20.167-005]** The RPlan primitive SHALL assign each step $s_i$ a unique,
monotonically increasing `index` consistent with a valid topological sort of the
dependency graph defined by `tp.rsub.substeps[i].depends_on`; upon detecting a
dependency cycle it SHALL set `rplan_status = BLOCKED` with
`reason_code = DEPENDENCY_CYCLE` and SHALL halt plan construction.

**Constraint derivation.** The constraint set $C_i$ for step $s_i$ is the union of
three sources: (1) the TP field refs that `substep_type` requires to be resolved at
execution time, (2) the `step_id` values of all steps that $s_i$ depends on, and
(3) any entries in `tp.safety_flags` whose scope covers $s_i$'s `substep_type`.

**[HLR-20.167-006]** The RPlan primitive SHALL derive $C_i$ for each step $s_i$ as
the union of type-required TP field refs, dependency `step_id` refs, and applicable
`tp.safety_flags` entries, and SHALL write the result into
`tp.rplan.ordered_steps[i].constraint_set`.

**Continuity weight computation.** Let $\Gamma = \langle \gamma_1, \dots, \gamma_m \rangle$
be the continuity scores from `tp.continuity_fields`, and let
$\alpha_{ij} \in \{0, 1\}$ be the relevance mask: $\alpha_{ij} = 1$ when
`tp.continuity_fields[j].field_ref` appears in the payload field paths of substep
$u_i$, and $0$ otherwise. The continuity weight for step $s_i$ is:

$$
\omega_i = \begin{cases}
\dfrac{\displaystyle\sum_{j=1}^{m} \alpha_{ij}\,\gamma_j}{\displaystyle\sum_{j=1}^{m} \alpha_{ij}}
& \text{if } \displaystyle\sum_{j=1}^{m} \alpha_{ij} > 0 \

\[10pt]
0 & \text{otherwise}
\end{cases}
$$

**[HLR-20.167-007]** The RPlan primitive SHALL compute $\omega_i$ using the formula
above and SHALL write the result into
`tp.rplan.ordered_steps[i].continuity_weight`; it SHALL NOT write a value outside
$[0, 1]$.

**Plan viability check.** Let $\text{resolved}(0)$ be the set of TP fields already
present in the TP at plan-construction time, and let $\text{produces}(s_i)$ be the
set of TP field refs and step identifiers that step $s_i$ resolves upon successful
execution. A constraint set $C_i$ is forward-satisfiable when every ref it contains
is either available at construction time or produced by an earlier step:

$$
\text{sat}(C_i,\, S) = \forall\, r \in C_i :
r \in \text{resolved}(0) \cup \bigcup_{j < i} \text{produces}(s_j)
$$

The full plan is viable when every step constraint is forward-satisfiable:

$$
\text{viable}(S) = \forall\, i \in \{1, \dots, k\} : \text{sat}(C_i,\, S)
$$

**[HLR-20.167-008]** The RPlan primitive SHALL evaluate $\text{viable}(S)$ after
constructing all steps; if $\text{viable}(S) = \text{false}$, it SHALL set
`tp.rplan.rplan_status` to `BLOCKED` and SHALL write
`reason_code = UNSATISFIABLE_CONSTRAINT` identifying the lowest index $i$ where
$\text{sat}(C_i, S) = \text{false}$; otherwise it SHALL set
`tp.rplan.rplan_status` to `VIABLE`.

## Output Contract

The table below defines all fields RPlan writes. RPU must validate presence and
type of every required field before beginning its own execution.

| Field | Type | Legal Values | Semantics |
|---|---|---|---|
| `tp.rplan.rplan_status` | enum | `VIABLE`, `BLOCKED` | Overall plan viability; RPU reads this first to select abort or execution path |
| `tp.rplan.reason_code` | string | non-empty on `BLOCKED`; empty string on `VIABLE` | Machine-readable cause; RPU propagates this into `tp.rpu_partial.reason_code` on abort |
| `tp.rplan.ordered_steps` | array | non-null; empty only when `rplan_status = BLOCKED` | Ordered sequence of realization steps for RPU to execute in ascending `index` order |
| `tp.rplan.ordered_steps[i].step_id` | string | non-empty; unique within array | RPU uses this as the key for `step_records` entries in `tp.rpu_partial` |
| `tp.rplan.ordered_steps[i].index` | integer | $i \geq 1$; monotonically increasing | RPU executes steps in ascending `index` order; gaps are not permitted |
| `tp.rplan.ordered_steps[i].step_type` | enum | recognised substep_type values | Identifies which realization action RPU invokes for this step |
| `tp.rplan.ordered_steps[i].payload` | structured object | per `step_type` schema | Parameters RPU passes verbatim to the realization action |
| `tp.rplan.ordered_steps[i].constraint_set` | set of field refs and step_ids | may be empty | RPU evaluates this set against `resolved(j-1)` before executing step $s_j$; an unresolved ref causes `HALTED` |
| `tp.rplan.ordered_steps[i].continuity_weight` | float | $\omega_i \in [0, 1]$ | RPU passes $\omega_i$ as the weight argument to $\text{exec}(s_i, \omega_i)$; higher values indicate stronger continuity alignment |
| `tp.rplan.ordered_steps[i].step_status` | enum | `VIABLE`, `BLOCKED` | Per-step viability as set during plan construction; RPU may use this for pre-flight validation |

**[HLR-20.167-009]** The RPlan primitive SHALL populate all fields in the Output
Contract table for every execution path (`VIABLE` and `BLOCKED`); no output field
SHALL be left absent or null except where the table explicitly permits it.

**[HLR-20.167-010]** The RPlan primitive SHALL NOT write to any meaning-layer field
owned by LI, any representation-layer field owned by TPTB, TPSF, or CoHI, or any
realization substrate field owned by REx.

## When

RPlan runs once per turn. Its position in the Path B execution order is fixed: after
REx has committed `tp.rsub` and before RPU reads `tp.rplan`.

**[HLR-20.167-011]** The RPlan primitive SHALL NOT begin execution until REx has
written `tp.rsub` to a completed state for the current turn, as indicated by
`tp.rsub.rsub_status` holding a recognised enum value.

**[HLR-20.167-012]** The RPlan primitive SHALL complete all writes to `tp.rplan`
before RPU begins execution for the same turn.

## Why

REx produces a realization substrate that specifies what must be realized but not in
what order, under what constraints, or with what continuity weighting. Without RPlan
as a dedicated planning step, RPU would need to derive ordering, constraint sets, and
continuity weights at execution time — coupling execution logic to substrate
interpretation and making the realization chain non-deterministic and non-auditable.
RPlan provides a single, inspectable planning artifact that cleanly separates "what
to do and in what order" from "doing it."

## Is Not

RPlan is not a meaning extractor.
RPlan is not a semantic interpreter.
RPlan is not a surface generator.
RPlan is not a scorer.
RPlan is not a router.
RPlan is not a memory system.
RPlan is not REx; it does not construct or evaluate the realization substrate.
RPlan is not RPU; it produces the plan that RPU executes but does not execute any
step itself.

## Example

REx has committed `tp.rsub` with `rsub_status = READY` and three substeps:

- $u_1$: `substep_id = "ref-confirm"`, `substep_type = REFERENT_CONFIRM`, `depends_on = []`
- $u_2$: `substep_id = "reg-apply"`, `substep_type = REGISTER_APPLY`, `depends_on = ["ref-confirm"]`
- $u_3$: `substep_id = "tok-emit"`, `substep_type = TOKEN_EMIT`, `depends_on = ["reg-apply"]`

Pre-condition check passes. `rsub_status = READY`. Planning path begins.

**Step mapping and ordering.** Topological sort of $u_1 \to u_2 \to u_3$ yields
index assignment 1, 2, 3. No cycle detected.

**Constraint derivation.** $C_1 = \emptyset$. $C_2 = \{\texttt{tp.meaning},\,\texttt{ref-confirm}\}$.
$C_3 = \{\texttt{reg-apply}\}$.

**Continuity weight computation.** `tp.continuity_fields` has one entry:
`field_ref = "tp.meaning"`, $\gamma_1 = 0.91$. Relevance mask: $\alpha_{21} = 1$,
all others $0$. Result: $\omega_1 = 0$, $\omega_2 = 0.91$, $\omega_3 = 0$.

**Viability check.** All $\text{sat}(C_i, S) = \text{true}$; `rplan_status = VIABLE`.

RPU receives `tp.rplan` with three entries at indices 1–3, continuity weights
$\langle 0,\, 0.91,\, 0 \rangle$, and fully populated constraint sets, and begins
step execution without any further planning.
