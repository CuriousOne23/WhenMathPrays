# Purpose
Tables below will be used to map old 20.40 HLR #'s to the created sub-OB's.

### 20.40.010 — SOB HLR Semantic Reference  
**HLR format:** `HLR‑20.40.010‑xxx`, where `xxx` is the HLR number in the table below.

| #    | Short name                          | Semantic meaning                                                                                          |
|------|--------------------------------------|-----------------------------------------------------------------------------------------------------------|
| 001  | Structural segmentation              | Segment TP into structural units (sentences, clauses, lists, tables, code, math blocks).                 |
| 002  | Preserve order                       | Preserve original order of all structural units.                                                          |
| 003  | List identification                  | Detect and explicitly represent list structures.                                                          |
| 004  | Modality classification              | Classify each structural unit by modality (declarative, interrogative, imperative, etc.).                |
| 005  | Modality annotation                  | Annotate modality in TP structure without altering text.                                                  |
| 006  | Operator‑hint extraction             | Extract operator hints (summarize, compare, classify, derive, plan, explain, etc.).                      |
| 007  | Operator‑hint residue                | Encode operator hints as residue fragments.                                                               |
| 008  | Domain‑hint extraction               | Extract domain hints (math‑like, code‑like, narrative‑like, etc.).                                        |
| 009  | Domain‑hint residue                  | Encode domain hints as residue fragments without interpreting semantics.                                  |
| 010  | Tone‑hint extraction                 | Extract tone hints (formal, casual, technical, supportive, urgent, neutral).                              |
| 011  | Tone‑hint residue                    | Encode tone hints as residue fragments without modifying TP.                                              |
| 012  | Constraint‑hint extraction           | Extract constraint hints (precision, conciseness, politeness, safety, formatting).                        |
| 013  | Constraint‑hint residue              | Encode constraint hints as residue fragments for later CnOB processing.                                   |
| 014  | No structural loss                   | No structural unit may be lost, merged incorrectly, or reordered.                                         |
| 015  | Deterministic metadata               | Structural metadata must be deterministic and reproducible.                                               |
| 016  | Residue set creation                 | Produce residue fragments for unresolved structure and extracted hints.                                   |
| 017  | Residue addressability               | Residue fragments must be addressable by RB using geometric addressing.                                   |
| 018  | Entropy reduction                    | Residue entropy after SOB must be strictly less than raw TP entropy.                                      |
| 019  | Route to SROB                        | Residue must be suitable for routing into SROB.                                                           |
| 020  | No direct semantic/constraint route  | Must not route directly into semantic OBs or constraint OBs.                                              |
| 021  | No semantic interpretation           | Must not perform semantic interpretation.                                                                 |
| 022  | No intent/role inference             | Must not infer meaning, intent, or semantic roles.                                                        |
| 023  | No constraint logic                  | Must not apply or enforce constraint logic.                                                               |
| 024  | No TP text modification              | Must not modify original TP text.                                                                         |
| 025  | Residue hashability                  | Each residue fragment $r_i$ must be hashable into an address fragment $h_i$.                              |
| 026  | XOR query address                    | Combined query address must satisfy: $$q = h_1 \oplus h_2 \oplus \dots \oplus h_n$$                       |
| 027  | Geometric invariants compliance      | Residue must not violate monotonicity, smoothness, or curvature‑invariance requirements.                  |
| 028  | SOB output components                | SOB must output a structured TP, a residue set, and all associated metadata (structural, operator‑hint, domain‑hint, tone‑hint, constraint‑hint). |
| 029  | Valid SROB input guarantee           | SOB output must be structurally valid, residue‑complete, and guaranteed to be acceptable as input to SROB without requiring reinterpretation or fallback logic. |
