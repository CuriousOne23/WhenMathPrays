## **1. Purpose**

IIInB performs **deterministic, bounded, pre‑semantic surface‑level repair** on the output of InB.  
It applies **strict, rule‑based, non‑inferential expansions** that:

- normalize user‑approved shorthand  
- correct deterministic surface irregularities  
- preserve original meaning without constructing new meaning  
- prepare input for IE and CEx without semantic interpretation  

IIInB is the **second primitive in Path A**:

```
InB → IIInB → IE → CEx → CE → ISc → TPU → OB family → RB → IdOB → OuBA
```

---

## **2. Scope**

IIInB is a **TP‑touching primitive** that:

- reads the IntakeBuffer  
- produces a repaired, normalized surface form  
- MUST NOT perform semantic inference  
- MUST NOT access global state  
- MUST NOT inspect TP history  
- MUST NOT modify semantic_core  
- MUST NOT introduce new meaning  

IIInB is **deterministic**, **replayable**, and **bounded**.

---

## **3. Inputs and Outputs**

### **Input**
- `InB_Output` (canonicalized surface tokens, spans, punctuation, and metadata)

### **Output**
- `IIInB_Output` (normalized surface form, still pre‑semantic)

### **Output Characteristics**
- deterministic  
- reversible (no semantic loss)  
- no new referents  
- no new commitments  
- no semantic enrichment  
- no envelope‑dependent behavior  

---

## **4. Allowed Transformations (Normative)**

IIInB MAY perform the following **strictly deterministic** operations:

### **4.1 Deterministic Shorthand Expansion**
Only expansions that are:

- user‑approved  
- deterministic  
- context‑free  
- meaning‑preserving  

Examples (allowed):

- “w/” → “with”  
- “btw” → “by the way”  
- “idk” → “I don’t know”  
- “u” → “you” (if user‑approved)  

Examples (NOT allowed):

- “again” → “repeat the last action” (semantic)  
- “same as before” → “repeat previous command” (semantic)  
- “lights kitchen” → “lights in the kitchen” (semantic)  

### **4.2 Deterministic Surface Repair**
- fix spacing  
- normalize punctuation  
- normalize casing (if user‑approved)  
- expand deterministic contractions (“I’m” → “I am”)  
- normalize repeated characters (“soooo” → “so”)  

### **4.3 Deterministic Token Rewriting**
- canonicalize emoji to token form  
- canonicalize repeated punctuation  
- normalize Unicode variants  

### **4.4 Deterministic Pattern‑Based Repair**
Only if:

- pattern is local  
- pattern is deterministic  
- pattern does NOT require context or history  

Allowed example:

- “dont” → “don’t”  
- “cant” → “can’t”  

---

## **5. Forbidden Transformations (Normative)**

IIInB MUST NOT:

### **5.1 Perform Semantic Inference**
Forbidden:

- inferring intent  
- inferring referents  
- inferring actions  
- inferring commands  
- inferring missing arguments  
- inferring relationships  

### **5.2 Use Envelope or TP History**
Forbidden:

- reading CE  
- reading CIL  
- reading TP history  
- reading semantic_core  
- reading prior user messages  

### **5.3 Modify Meaning**
Forbidden:

- adding new meaning  
- removing meaning  
- reinterpreting meaning  
- resolving ambiguity  
- resolving pronouns  
- resolving ellipsis  

### **5.4 Perform Creative Expansion**
Forbidden:

- “lights kitchen” → “lights in the kitchen”  
- “again” → “repeat the last action”  
- “same as before” → “repeat previous command”  

### **5.5 Perform Non‑Deterministic Repair**
Forbidden:

- user‑dependent heuristics  
- probabilistic expansions  
- context‑dependent expansions  

---

## **6. Determinism Requirements**

IIInB MUST satisfy:

- **Replay determinism:** same input → same output  
- **No nondeterministic branching**  
- **No stochastic behavior**  
- **No user‑profile‑dependent behavior**  
- **No global‑state‑dependent behavior**  

---

## **7. Pre‑Semantic Boundary Requirements**

IIInB MUST NOT:

- interpret meaning  
- construct meaning  
- evaluate truth  
- evaluate intent  
- evaluate commands  
- evaluate referents  

IIInB operates **strictly before** any semantic or constraint extraction.

---

## **8. Error Handling**

IIInB MUST:

- preserve malformed input  
- annotate unrepairable segments (if ruleset requires)  
- never drop tokens  
- never reorder tokens  
- never hallucinate content  

---

## **9. Ruleset Behavior**

IIInB MAY use a **deterministic IIInB_Ruleset**:

- versioned  
- monotonic  
- deterministic  
- no semantic rules  
- no context‑dependent rules  

RulesetID is stored in metadata for replay.

---

## **10. Metadata Requirements**

IIInB MUST attach:

```
metadata: {
  ruleset_id: RulesetID,
  timestamp,
  input_hash,
  repair_operations: Array<RepairOp>
}
```

---

## **11. Security & Safety Boundaries**

IIInB MUST NOT:

- execute commands  
- interpret commands  
- modify system state  
- access external resources  
- access user identity  
- access environment variables  

---

## **12. Normative Summary**

IIInB is a **deterministic, bounded, pre‑semantic surface repair primitive** that:

- normalizes surface form  
- preserves meaning  
- performs no inference  
- performs no semantic enrichment  
- prepares input for IE and CEx  
- enforces Path‑A determinism  
- respects pre‑semantic boundaries
