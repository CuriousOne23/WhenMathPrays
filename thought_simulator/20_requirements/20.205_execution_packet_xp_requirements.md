# 20.205 Execution Packet (XP) Requirements

**Document ID:** 20.205  
**Version:** 0.1  
**Date:** 2026-06-06  
**Status:** Draft — rough draft (Stage 2, **unapproved** per [20.500](20.500_refactoring_for_dual_TS_pipeline.md))

## Purpose

Defines normative **Execution Packet (XP)** topology, field schema, lifecycle, and replay posture for Pipeline B. XP is the **logical aggregate** that binds one realization episode to a single `commit_id` per `cycle_id` — indexing `exec_plan` and `exec_trace` without becoming a fourth authoritative state envelope.

This module **implements** XP obligations from [20.206](20.206_pipeline_a_b_synchronization_contract.md) (HLR-20.206-016–019) and SHALL NOT weaken [20.12_ts_invariants.md](20.12_ts_invariants.md) (HLR-20.012-001, HLR-20.012-004).

**Naming authority:** [20.500](20.500_refactoring_for_dual_TS_pipeline.md) §5.2 (XP, `commit_id`, Pipeline B). **There is no TP-B.**

## 1. XP vs TP Boundary

| Artifact | Pipeline | Authority |
|----------|----------|-----------|
| **TP** | A | Lane-local projection; provenance/history only |
| **XP** | B | Per-commit realization index; **not** meaning authority |

1. **HLR-20.205-001:** XP SHALL NOT alias TP; implementations SHALL NOT define TP-B, `tp_b_id`, or lane-scoped execution packets.
2. **HLR-20.205-002:** XP SHALL NOT carry `tp_id`, `lane_id`, lane merge lineage, or lane-local basin outputs.
3. **HLR-20.205-003:** TP SHALL NOT reference XP, `exec_plan`, or `exec_trace` (20.105, 20.31-013).

---

## 2. Topology

XP scope is **MTP-commit-scoped** and **singular per normal B episode**:

```text
mtp_update → commit_id C
       → XP(C, cycle_id N)  ── indexes ──► exec_plan + exec_trace
```

4. **HLR-20.205-004:** Exactly one primary `xp_record` SHALL exist per (`commit_id`, `cycle_id`) for a normal realization episode (20.206 HLR-20.206-017).
5. **HLR-20.205-005:** XP SHALL bind to exactly one `commit_id` and one `semantic_snapshot_ref` for its primary episode; all indexed B artifacts SHALL reference the same pair.
6. **HLR-20.205-006:** XP SHALL NOT span multiple `commit_id` values or multiple MTP commits within one primary record.

---

## 3. Logical Wrapper Model (Not a Fourth Envelope)

XP is an **index and audit carrier** — not a merged state blob.

| Envelope | Write authority | XP relationship |
|----------|-----------------|-----------------|
| `exec_plan` | B planning modules | XP holds `exec_plan_ref` |
| `exec_trace` | B expression / IMR | XP holds `exec_trace_ref` |
| `semantic_core` | Pipeline A only | XP holds read-only `semantic_snapshot_ref` |
| `supervisory` | GB / IMR triggers | XP MAY hold `supervisory_trigger_refs[]` (append-only pointers) |

7. **HLR-20.205-007:** XP SHALL NOT embed authoritative copies of `exec_plan` or `exec_trace` bodies as a substitute for envelope separation (HLR-20.012-004; 20.500 OQ-002).
8. **HLR-20.205-008:** XP SHALL NOT be a write target for planning or expression logic; modules SHALL write `exec_plan` and `exec_trace` directly, then update XP refs.
9. **HLR-20.205-009:** Stripping XP alongside `exec_plan` and `exec_trace` SHALL leave `semantic_core` unchanged (E1 equivalence — 20.206 §5).

---

## 4. `xp_record` Schema (Normative Minimum)

```text
xp_record {
  xp_id,                          // stable unique ID for this record
  commit_id,
  cycle_id,
  mtp_id,
  semantic_snapshot_ref,          // frozen post-mtp_update snapshot (hash or ref)
  routing_epoch_id,
  policy_signature,
  execution_signature,

  xp_pass_seq,                    // 0 = primary pass; increments on IMR Type A retry
  xp_status,                      // OPEN | PLANNING | EXPRESSING | IMR_EVAL | CLOSED | ERROR

  exec_plan_ref,                  // current plan for active pass
  exec_trace_ref,                 // append-only trace log for episode
  xp_pass_history[],              // optional audit: {xp_pass_seq, exec_plan_ref, reason_code}

  seed_scope_ref?,                // expression-only; 20.160 / 20.12-010
  oub_artifact_ref?,               // latest OuB output ref (denormalized convenience)
  imr_summary_ref?,               // optional pointer to final imr_record in trace

  supervisory_trigger_refs[],     // append-only CorrectionTrigger IDs emitted this episode

  xp_audit_log[]                  // append-only lifecycle events
}
```

10. **HLR-20.205-010:** Every `xp_record` SHALL include all required top-level fields: `xp_id`, `commit_id`, `cycle_id`, `semantic_snapshot_ref`, `routing_epoch_id`, `xp_pass_seq`, `xp_status`, `exec_plan_ref`, `exec_trace_ref`.
11. **HLR-20.205-011:** `xp_id` SHALL be unique within the conversation replay horizon and SHALL be assigned deterministically from `(commit_id, cycle_id, xp_pass_seq, policy_signature)`.
12. **HLR-20.205-012:** `semantic_snapshot_ref` SHALL resolve to the same frozen snapshot identified by `commit_id` at XP open (20.206 HLR-20.206-007).
13. **HLR-20.205-013:** `routing_epoch_id` on XP SHALL match the `routing_epoch_id` on the active `exec_plan` for the current pass (HLR-20.012-013).

### 4.1 Forbidden XP fields

| Field class | Posture |
|-------------|---------|
| `tp_id`, `lane_id` | **Forbidden** |
| `truth_hypotheses`, `done_state` writes | **Forbidden** — read-only via snapshot ref only |
| `thought_router_fields` writes | **Forbidden** |
| `routing_metadata` from RB | **Forbidden** |
| Embedded `semantic_core` mutable body | **Forbidden** — ref only |

14. **HLR-20.205-014:** XP validation SHALL reject records containing `tp_id` or `lane_id` with reason code `XP_FORBIDDEN_LANE_FIELD`.

## 5. Lifecycle

```text
OPEN → PLANNING → EXPRESSING → IMR_EVAL → CLOSED
                  └─ (Type A retry) ─► PLANNING  [xp_pass_seq++]
any state ──► ERROR (deterministic, audited)
```

15. **HLR-20.205-015:** XP SHALL be created only after resolvable `mtp_commit_record` / `commit_id` exists (20.206 HLR-20.206-013).
16. **HLR-20.205-016:** XP `OPEN` SHALL record `xp_audit_log` entry `{event: XP_OPEN, commit_id, semantic_snapshot_ref}` before any `exec_plan` write.
17. **HLR-20.205-017:** XP transition to `PLANNING` SHALL precede first `exec_plan` mutation; `EXPRESSING` SHALL precede OuB invocation; `IMR_EVAL` SHALL precede IMR evaluation.
18. **HLR-20.205-018:** XP `CLOSED` SHALL occur only after IMR evaluation completes (or deterministic early-close on GB halt) for the active `xp_pass_seq`.
19. **HLR-20.205-019:** XP in `ERROR` state SHALL preserve all prior envelope refs, SHALL NOT clear `exec_trace`, and SHALL append fixed `xp_error_code` to `xp_audit_log`.

### 5.1 Audit log minimum

```text
xp_audit_entry {
  event_seq,
  event_type,       // XP_OPEN | PASS_START | PASS_CLOSE | XP_CLOSE | XP_ERROR
  xp_pass_seq,
  cycle_id,
  stage_id?,        // aligns with 20.36 stage records
  reason_codes[]
}
```

20. **HLR-20.205-020:** `xp_audit_log` SHALL be append-only with deterministic `event_seq` ordering per `xp_id`.

## 6. IMR Type A Retry Passes (Resolves 20.206-D4)

IMR Type A MAY schedule a realization-only retry on the **same** frozen `semantic_snapshot_ref` (20.45 HLR-20.045-004).

21. **HLR-20.205-021:** Type A retries SHALL NOT create a second primary `xp_record` for the same (`commit_id`, `cycle_id`); they SHALL increment `xp_pass_seq` on the existing record.
22. **HLR-20.205-022:** Each Type A retry SHALL allocate a new `exec_plan_ref` and SHALL append to the same `exec_trace_ref` (append-only log).
23. **HLR-20.205-023:** `xp_pass_history[]` SHALL record `{xp_pass_seq, exec_plan_ref, reason_code: IMR_TYPE_A_RETRY}` for every retry pass.
24. **HLR-20.205-024:** Type A retries SHALL NOT change `commit_id` or `semantic_snapshot_ref` on the XP record.
25. **HLR-20.205-025:** Maximum Type A passes per (`commit_id`, `cycle_id`) SHALL obey IMR conversation caps (20.45 HLR-20.045-016); exceeding caps SHALL close XP without further passes.

Type B and Type C triggers SHALL NOT open new XP passes in the same cycle; they enqueue supervisory triggers for subsequent Pipeline A cycles (20.206 §6).

## 7. Serialization and Fixtures (Resolves 20.206-D1)

26. **HLR-20.205-026:** Canonical trace serialization SHALL store XP as a **reference index** (`xp_id` + refs to `exec_plan` / `exec_trace` envelopes), not as an inlined merge of envelope bodies.
27. **HLR-20.205-027:** Playground and debug exporters MAY inline envelope bodies adjacent to `xp_record` for human inspection, but golden replay fixtures SHALL use ref form for deterministic diffing (20.36).
28. **HLR-20.205-028:** `strip_scope` for E1 meaning equivalence SHALL include `[exec_plan, exec_trace, xp_record]` — stripping XP index artifacts SHALL not affect `semantic_core` hash (20.36 Class 1).

### 7.1 Golden fixture minimum (XP)

```yaml
fixture_id: REPLAY_C1_XP_INDEX
replay_class: REPLAY_CLASS_1
xp_assertions:
  - one_xp_per_commit_cycle
  - no_lane_id_on_xp
  - xp_refs_match_exec_envelopes
  - strip_includes_xp_record
```

---

## 8. Cross-Envelope Integrity

29. **HLR-20.205-029:** `exec_plan` and `exec_trace` referenced by XP SHALL each carry `commit_id` and `cycle_id` matching the parent `xp_record`.
30. **HLR-20.205-030:** XP SHALL NOT reference stale `routing_epoch_id` relative to its active `exec_plan` (HLR-20.012-013).
31. **HLR-20.205-031:** When `supervisory_trigger_refs[]` is non-empty, each ID SHALL resolve to an append-only supervisory queue entry emitted during the same `cycle_id` (20.45).

---

## 9. Regeneration Posture (E2 Preview)

Full-trace reproducibility (20.206 E2; detail in 20.207) treats XP as **derivable**:

32. **HLR-20.205-032:** Given identical `(semantic_snapshot_ref, routing_epoch_id, seed_scope_ref, policy_signature)` and published routing tables, regeneration SHALL reproduce equivalent `exec_plan` / `exec_trace` content and MAY allocate a new `xp_id` while preserving deterministic pass history semantics.
33. **HLR-20.205-033:** Regenerated XP SHALL NOT be required for meaning replay (E1); regeneration is a full-trace fidelity concern only.

---

## 10. Verification Focus

- One `xp_record` per (`commit_id`, `cycle_id`) on happy path
- Zero `lane_id` / `tp_id` on XP and referenced exec envelopes
- Type A retry: `xp_pass_seq` increments; same `commit_id`; new `exec_plan_ref`
- Strip test: remove XP + exec envelopes → `semantic_core` identical
- Negative: XP open before `commit_id` → `B_START_WITHOUT_COMMIT`
- Negative: inlined merged plan+trace inside XP body → schema reject
