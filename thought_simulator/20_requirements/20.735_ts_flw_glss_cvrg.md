# **0. Introduction, Purpose, Assumptions, and How to Read This Document**

## **0.1 Introduction**

This document provides the **complete, cross‑referenced flow coverage** for all primitives,
processes, reference objects, governance objects, and TS‑level concepts defined in the
**20.700.xxx glossary family**.

It consolidates:

- flows explicitly defined in **20.705**
- flows catalogued in **20.710** (Primitive Flows, PF series)
- flows catalogued in **20.715** (Process Flows, PRF series)
- flows catalogued in **20.720** (Reference‑Object Flows, ROF series)

This document does **not** define new behavior.
It organizes, validates, and cross‑checks the flows that are already normatively defined elsewhere.

## **0.2 Purpose**

The purpose of this document is to:

1. **Provide a complete flow atlas**
   Every primitive‑to‑primitive flow — including process, reference‑object, governance, and
   TS‑concept flows — is enumerated and classified.

2. **Ensure glossary completeness**
   Every item in the 20.700.xxx glossary family is represented by at least one flow.

   Requirement semantics remain in the 20.1xx–20.3xx documents.

   Each flow is mapped to the requirement family that normatively defines its behavior.

   Every flow‑catalog ID (PF, PRF, ROF, GVF, TSCF) from 20.710–20.730 is cross‑referenced
   to its glossary classification and requirement namespace.

## **0.3 Assumptions**

### **A. Requirement Namespace Rule**

When a requirement family is referenced (e.g., **20.30**, **20.40**, **20.110**), the reference
is to the **entire requirement namespace**, including all sub‑documents.

For example:

- **"20.40"** refers to:
  - 20.40_ob_requirements.md
  - 20.40.010_sob_prim.md
  - 20.40.020_srob_prim.md
  - 20.40.030_cnob_prim.md
  - 20.40.040_smob_prim.md
  - 20.40.060_ssg_prim.md
  - …and all other 20.40.xxx files

This is the **intended interpretation** of the 20‑series requirement hierarchy.

### **B. Flow Boundary Rule**

Every non‑primitive flow must:

- **begin with a primitive**, and
- **end with a primitive**,

even when the internal step is a process, reference object, governance object, or TS‑concept.

This ensures:

- deterministic boundaries
- glossary alignment
- consistent visualization semantics

### **C. Glossary Authority Rule**

The **20.700.xxx glossary family** is the authoritative source for:

- primitive definitions
- process definitions
- reference‑object definitions
- governance‑object definitions
- TS‑level conceptual definitions

This document reflects those definitions but does not override them.

### **D. Visualization‑Only Scope**

This file is a **reference visualization layer**.
Normative behavior is defined in:

- 20.1xx (core requirements)
- 20.2xx (primitive requirements)
- 20.3xx (process requirements)
- 20.110 / 20.169 (basin requirements)
- 20.205 / 20.206 / 20.207 (XP, A/B sync, replay)

This document only **organizes** flows; it does not define their semantics.

### **E. Catalog Document Scope**

The flow catalogs (20.710–20.730) enumerate flows using short canonical IDs:

| Series | Source Document | ID Range       |
|--------|----------------|----------------|
| PF     | 20.710         | PF‑01 – PF‑09  |

These IDs are used verbatim in Sections F–J and are not replacements for the flow names
used in Sections A–E.
