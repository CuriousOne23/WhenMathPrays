# **1. Purpose**

The **Truth Basin (TB)** is a **post‑TS, post‑Merge, post‑TPU** subsystem responsible for **truth‑interpretation** over a **frozen semantic snapshot**.  

TB is **not** part of Pipeline A.  
TB performs **no lane‑parallel computation**, **no TP writes**, and **no meaning construction**.

TB consumes:

- the **committed semantic_core** (from MTP)  
- the **frozen TP(N+1)** state  
- the **stable proposition set**  
- the **evidence graph**  

TB produces:

- **truth_interpretation_input{}** for 20.140  
- **no TP or MTP mutations**  
- **no channel_interpretations**  
- **no truth_hypotheses on TP**  

TB is part of the **Truth/Done subsystem**, not the meaning‑construction pipeline.

---

# **2. Architectural Positioning (Updated)**

TB sits **after** the entire inference path:

```
Pipeline A:
    InB → IIInB → CEx → CE → ISc → TPU (Merge internal) → TP(N+1) → mtp_update → MTP.semantic_core

Post‑TS (Path‑B):
    TB → Truth/Done (20.140) → IB (inquiry) → GBIB → GB
```

Key points:

- TB is **not** a Pipeline‑A basin.  
- TB is **not** lane‑parallel.  
- TB does **not** write to TP or MTP.  
- TB is **read‑only** with respect to all meaning‑bearing structures.  
- TB is **paired with IB**, which is also post‑TS.

---

# **3. Scope**

TB:

- reads **semantic_core**  
- reads **propositions[]**  
- reads **evidence graphs**  
- computes **truth_interpretation_input{}**  
- performs **no semantic repair**  
- performs **no routing**  
- performs **no ΔH% logic**  
- performs **no Merge participation**  
- performs **no TR interaction**  
- performs **no lane‑local operations**

TB SHALL NOT:

- write TP  
- write MTP  
- write channel_interpretations  
- write truth_hypotheses  
- set tr_needs_update  
- influence routing or ΔH%  
- participate in Pipeline A

---

# **4. Inputs**

TB receives a **frozen, immutable** post‑TPU snapshot:

```
tb_input {
    semantic_core_snapshot,
    propositions[],
    evidence_graph{},
    lineage_refs[],
    stability_metadata,
    policy_signature,
    mtp_snapshot_id
}
```

All fields are **read‑only**.

---

# **5. Outputs**

TB produces a single structured object:

```
truth_interpretation_input {
    proposition_id,
    evidence_refs[],
    contradiction_markers?,
    entailment_markers?,
    uncertainty_markers?,
    affect_markers?,
    logic_markers?,
    stance_markers?,
    confidence_q32
}
```

This object is consumed **only** by **20.140 Truth/Done**.

TB produces **no writes** to TP, MTP, or semantic_core.

---

# **6. Forbidden Actions (Critical)**

TB SHALL NOT:

- write `truth_hypotheses`  
- write `channel_interpretations{}`  
- write any TP field  
- write any MTP field  
- set `tr_needs_update`  
- read or write `TP.TR`  
- read or write routing metadata  
- read or write ΔH% fields  
- perform messy‑input classification  
- perform semantic repair  
- perform routing or lane arbitration  
- participate in Merge  
- participate in Pipeline B  
- generate meaning  
- modify semantic content  

TB is **purely interpretive**, **post‑TS**, and **read‑only**.

# **7. High‑Level Requirements (HLRs)**

### **HLR‑20.060‑001 — Post‑TS Position**
TB SHALL operate only after TP(N+1) and semantic_core are fully committed.

### **HLR‑20.060‑002 — Read‑Only Semantics**
TB SHALL NOT mutate TP, MTP, semantic_core, or any Pipeline‑A structure.

### **HLR‑20.060‑003 — No Lane Parallelism**
TB SHALL NOT operate per‑lane; it consumes the unified semantic snapshot.

### **HLR‑20.060‑004 — No Channel Interpretations**
TB SHALL NOT produce `channel_interpretations{}`; these are Pipeline‑A artifacts and are removed.

### **HLR‑20.060‑005 — No Truth Hypotheses on TP**
TB SHALL NOT write `truth_hypotheses` to TP or MTP.

### **HLR‑20.060‑006 — Truth‑Evaluation Input Only**
TB SHALL produce only `truth_interpretation_input{}` for 20.140.

### **HLR‑20.060‑007 — Determinism**
TB outputs SHALL be deterministic for identical semantic_core snapshots.

### **HLR‑20.060‑008 — No TR Interaction**
TB SHALL NOT read or write `TP.TR` or `thought_router_fields`.

### **HLR‑20.060‑009 — No Messy‑Input Classification**
TB SHALL NOT classify or modify messy‑input tags; this is Pipeline‑A only.

### **HLR‑20.060‑010 — No ΔH% Participation**
TB SHALL NOT read or write ΔH% fields.

### **HLR‑20.060‑011 — No Routing Influence**
TB SHALL NOT influence RB routing or lane structure.

### **HLR‑20.060‑012 — No Merge Participation**
TB SHALL NOT participate in Merge or lineage mutation.

### **HLR‑20.060‑013 — Replay Equivalence**
TB outputs SHALL be replay‑equivalent under identical semantic snapshots.

### **HLR‑20.060‑014 — Inference-Path Exclusion**
TB SHALL operate exclusively in the Post‑TS Path (TP → IB → TB → GBIB → GB) and SHALL NOT appear in the input‑side inference path.  

TB SHALL NOT:
- generate candidate sets
- perform semantic interpretation
- interact with InB, IIInB, CEx, CE, ISc, COP, Merge, or TPU
- participate in Path A or Path B
- influence meaning construction or semantic_core formation

TB MAY read:

- `semantic_core.evidence_graph{}`  
- `semantic_core.lineage[]`  
- `semantic_core.stability_metadata`  
- `policy_signature`  
- `mtp_snapshot_id`

TB SHALL NOT read:

- TP fields  
- MTP fields other than semantic_core snapshot  
- ΔH%  
- routing metadata  
- TR fields  
- messy_input_record  
- any Pipeline‑B envelopes

---

# **9. Interpretation Logic (Minimal)**

TB performs:

- contradiction detection  
- entailment detection  
- uncertainty detection  
- stance extraction  
- affect extraction  
- logic‑structure extraction  

All based solely on **frozen semantic_core**.

TB performs **no inference**, **no repair**, **no generation**, and **no probabilistic reasoning**.
