# 20.60 TB Requirements

**Document ID:** 20.60  
**Version:** 0.3  
**Date:** 2026-06-06  
**Status:** CP-approved — dual-pipeline TB specification (v0.2 CP refinements applied)

## Purpose

Defines deterministic **Truth Basin (TB)** behavior, interfaces, invariants, and observability for **semantic interpretation** within **Pipeline A (meaning construction)**.

TB transforms structured OB evidence into explicit interpretation channel outputs and `truth_hypotheses`-compatible records that feed truth/done evaluation ([20.140](20.140_truth_evaluation_requirements.md)). TB is an **interpretation** basin — not a routing authority (RB), not an evidence extractor (OB), and not a TR derivator (20.37).

This module SHALL NOT weaken invariants in [20.12_ts_invariants.md](20.12_ts_invariants.md).

**Semantic authority:** channel semantics defer to [20.31](20.31_semantic_specification.md) §5; `truth_hypotheses` record shape per HLR-20.031-023.

## Parent Scope

- **Pipeline:** Pipeline A only — TB SHALL NOT read `exec_plan` or `exec_trace`
- **Upstream:** OB evidence (20.40), RB routing context (20.50 read-only to TB)
- **Downstream:** truth/done evaluation (20.140), Merge/`mtp_update`
- **Messy-input:** classifiers at TB safe boundaries per [20.17](20.17_messy_input_handling.md)
- **Numeric encoding:** `confidence_q32` and channel weights Q32.32 per [20.95](20.95_ts_numeric_policy.md)
- **Does not modify:** 20.10, 20.12, 20.20, 20.30 bootstrap documents

## Non-Goals

- RB routing, split/merge arbitration — RB (20.50)
- OB pattern extraction — OB (20.40)
- TR derivation (`TP.TR`) — TR routine (20.37)
- Final truth/done scoring logic — 20.140 (TB supplies inputs, not evaluation algorithms)
- Pipeline B presentation smoothing — OuB (20.17-024)
- GB supervisory policy — 20.16/20.80

## 1. Dual-Pipeline Boundary Discipline

| Concern | TB posture |
|---------|------------|
| `semantic_core` | Writes interpretation projections and hypothesis records via Merge/`mtp_update` |
| `TP.TR`, `thought_router_fields` | **No read for derivation, no write**; MAY set `tr_needs_update = true` when semantic-relevant fields change |
| `truth_hypotheses` | **Writes** schema-versioned records per 20.31-023; SHALL NOT read prior hypotheses for latent inference |
| `exec_plan`, `exec_trace`, `supervisory` | **No read/write** |
| `routing_epoch_id` | **No read/write; no advance** |
| `messy_input_record` | MAY classify at safe boundaries (read/write tags per 20.17); **no resolve/smooth/clear** |
| Seed | **SHALL NOT influence** TB interpretation outputs (HLR-20.012-010) |

**Pipeline B forbidden:** OuB SHALL NOT smooth contradiction or vagueness in `semantic_core` unless TB commitment rules explicitly authorize a scoped presentation field (20.17-024).

## 2. TB Input and Output Contracts

### 2.1 Input (deterministic TB input object)

TB SHALL accept (HLR-20.060-021):

- structured OB `evidence_fields[]` and TR-input context (read-only)
- lane identifier and RB `routing_filter` context (read-only)
- lineage/provenance fields
- ΔH% contribution and missing-mass context (Q32.32)
- read-only MTP / `semantic_core` fields per approved set (§7)
- `policy_signature`

TB SHALL NOT depend on TP creation order or allocation identity (HLR-20.060-040).

### 2.2 Output (deterministic TB record)

TB SHALL emit (HLR-20.060-022):

```text
tb_output {
  channel_interpretations{
    stance{},
    affect{},
    intent{},
    logic{},
    social{}
  },
  truth_hypothesis_records[],  // 20.31-023 schema; sort by hypothesis_id
  lineage_additions[],
  execution_diagnostics{},
  messy_input_delta?,          // when detector fires at TB boundary
  overflow_metadata?
}
```

**`truth_hypotheses` record minimum (per 20.31-023):** `hypothesis_id`, `proposition_ref`, `truth_status`, `confidence_q32` (Q32.32), `evidence_refs[]`, `last_updated_cycle`.

**Dirty flag:** when TB modifies semantic-relevant TP/MTP projection fields, TB SHALL set `tr_needs_update = true` and SHALL NOT write `TP.TR` (20.37 §3.3).

**Canonical ordering:** `truth_hypothesis_records[]` and nested `evidence_refs[]` SHALL sort deterministically before export/replay diff (HLR-20.060-038).

**`channel_interpretations{}` ordering (HLR-20.060-044):** Top-level channel keys SHALL sort lexicographically (`affect`, `intent`, `logic`, `social`, `stance`); nested field maps SHALL sort keys lexicographically; ID arrays SHALL sort by stable ID; numeric weights SHALL be canonical Q32.32 before export and replay diff.

## 3. Interpretation Channels

TB SHALL support five explicit deterministic channels (HLR-20.060-005):

| Channel | Output semantics |
|---------|------------------|
| **stance** | Declared position relative to propositions |
| **affect** | Structured valence and intensity markers |
| **intent** | Communicative / action objective |
| **logic** | Conditional, entailment, contradiction structure at interpretation layer |
| **social** | Politeness, register-intent at meaning layer (not OuB register selection) |

Each channel output SHALL be explicit, auditable, and attributable to OB evidence inputs (20.31-006). TB SHALL NOT emit probabilistic latent-state artifacts (HLR-20.060-010).

---

## 4. Messy-Input at TB Safe Boundaries

Per [20.17](20.17_messy_input_handling.md), TB participates in classification and interpretation under messy-input constraints:

| Class | TB obligation |
|-------|----------------|
| `MI_CONTRA` | Interpret channels per parallel trace; **no forced single-winner stance** unless `contradiction_status = GB_ARBITRATED` |
| `MI_VAGUE` | Reflect underspec in channel outputs; **no slot fill**; commitment capped per 20.90 §H |
| `MI_AFFECT` | Primary target when RB routes affect/stance/social paths (20.17-028); tags before Merge commit |
| `MI_INCOMP` | Surface incomplete interpretation markers; may trigger IB-Creation-Request pathway — **no generative completion** |
| `MI_NOISE` | Interpret stabilized conceptual evidence, not surface noise (HLR-20.060-008) |

**Detector order:** MI_CONTRA → MI_VAGUE → MI_AFFECT → MI_INCOMP → MI_NOISE; export sort canonical (20.17-038).

TB SHALL NOT use affect tagging to auto-resolve vagueness or contradiction (20.31-006, 20.17-012).

---

## 5. Truth Hypotheses and 20.140 Boundary

| Layer | Authority |
|-------|-----------|
| TB (this document) | Produces interpretation channels + `truth_hypothesis_records[]` compatible with 20.31-023 |
| 20.140 | Consumes explicit fields; computes deterministic truth/done evaluation and completion status |

TB SHALL NOT perform final truth/done scoring (HLR-20.060-033). TB records SHALL supply explicit `evidence_refs[]` traceable to OB outputs.

TB SHALL NOT read prior `truth_hypotheses` entries for latent Bayesian or embedding-based inference (HLR-20.060-041); prior records MAY be read only for deterministic ID continuity and cycle stamping (`last_updated_cycle`).

---

## 6. Bounds, Overflow, and Replay

- TB SHALL enforce 20.30 §8 interpretation channel/hypothesis bounds and per-basin TCU envelopes (HLR-20.060-024).
- On exceedance, emit canonical overflow telemetry per 20.30 §8.3 (HLR-20.060-025); no silent interpretation drop (HLR-20.060-026).
- Under overflow, preserve messy-input primary flags (20.17-031).
- Outputs SHALL reproduce from `(OB evidence, RB context, read-only MTP, policy_signature)` — seed excluded (HLR-20.060-009).
- Strip replay removing Pipeline B envelopes SHALL preserve TB-committed interpretation in `semantic_core` (20.36 Class 1, HLR-20.060-036).

---

## 7. Approved Read Set

**Approved reads (HLR-20.060-039, HLR-20.060-045):** TB MAY read only:

- OB `evidence_fields[]`, TR-input context (read-only), ΔH% context
- RB routing context: lane id, `routing_filter` summary fields (read-only)
- lane-local TP projections: propositions refs, lineage, `messy_input_record` (read/write tags per 20.17)
- MTP / `semantic_core`: `propositions[]`, `lineage[]`, `overflow_metadata`, `stability_metadata`, `policy_signature`, `mtp_snapshot_id`
- existing `truth_hypotheses` **IDs and cycle stamps only** for record continuity (HLR-20.060-041)

TB interpretation derivation SHALL NOT consume any MTP or `semantic_core` field outside this approved set (HLR-20.060-045).

**Explicit forbidden reads (HLR-20.060-043):** TB SHALL NOT read `TP.TR`, `thought_router_fields`, or `routing_semantics` for interpretation derivation (20.37). TB SHALL NOT read `exec_plan`, `exec_trace`, `routing_epoch_id`, full `truth_hypotheses` content for latent inference, or supervisory envelope state.

## Worked Example — MI_AFFECT Route + Hypothesis Record

| Step | Actor | Outcome |
|------|-------|---------|
| 1 | RB | Routes lane to affect/stance/social TB modules (`MI_AFFECT`, 20.17-028) |
| 2 | TB | Reads OB evidence; emits `channel_interpretations.affect` + `social` |
| 3 | TB | Appends `truth_hypothesis_record` with `confidence_q32`, `evidence_refs[]` |
| 4 | TB | Does **not** resolve parallel `MI_CONTRA` trace |
| 5 | TB | Sets `tr_needs_update = true` if interpretation changes TR-relevant projections |
| 6 | Merge | Commits to `semantic_core`; canonical sort by `hypothesis_id` |
| 7 | 20.140 | Consumes records for truth/done evaluation (downstream) |
| 8 | Strip replay | Pipeline B removed → TB interpretation bytes stable |

## Normative Requirements

1. HLR-20.060-001: TB SHALL produce structured truth interpretation fields.
2. HLR-20.060-002: TB SHALL operate over bounded, explicit inputs only and SHALL NOT rely on hidden or latent state.
3. HLR-20.060-003: TB SHALL NOT perform RB routing control, split arbitration, or merge arbitration authority.
4. HLR-20.060-004: TB execution ordering and channel-evaluation ordering SHALL be deterministic for identical effective state.
5. HLR-20.060-005: TB SHALL support stance, affect, intent, logic, and social interpretation channels as explicit deterministic outputs.
6. HLR-20.060-006: TB interpretations SHALL preserve lineage/provenance continuity across channels and across cycles.
7. HLR-20.060-007: TB outputs SHALL preserve compatibility with upstream ΔH% contribution and missing-mass accounting context.
8. HLR-20.060-008: TB SHALL support deterministic handling of noisy or ill-formed input effects by interpreting stabilized conceptual evidence rather than surface-form noise.
9. HLR-20.060-009: TB outputs SHALL be deterministic and reproducible for identical lane evidence input, MTP context, and `policy_signature`; seed SHALL NOT influence TB outputs.
10. HLR-20.060-010: TB SHALL NOT emit probabilistic latent-state artifacts as primitive outputs.
11. HLR-20.060-011: TB SHALL NOT perform hallucinated correction or unstated-content invention during interpretation.
12. HLR-20.060-012: TB SHALL expose deterministic test interfaces with explicit inputs, expected outputs, invariants, and failure modes.
13. HLR-20.060-013: TB SHALL expose test hooks sufficient for unit, integration, system, and property-based verification of interpretation behavior.
14. HLR-20.060-014: TB lifecycle transitions (entry, running, completion/exit) SHALL be explicitly logged and observable.
15. HLR-20.060-015: TB SHALL expose observability data required by MB pathways, including interpretation rationale fields, channel outputs, lane identifiers, and provenance context.
16. HLR-20.060-016: TB telemetry SHALL support deterministic diagnostic consumption by GB, OuB, and IB without mutating TB core semantics.
17. HLR-20.060-017: TB SHALL define measurable TCU budgets (min/typ/max) and per-tick TCU reporting fields.
18. HLR-20.060-018: TB overload/degradation behavior SHALL be deterministic, policy-bounded, and auditable.
19. HLR-20.060-019: TB behavior SHALL be platform-independent and SHALL NOT depend on hardware-, OS-, or runtime-specific nondeterministic effects.
20. HLR-20.060-020: TB contracts SHALL prioritize top-down thought-processing semantics over implementation-specific mechanics.
21. HLR-20.060-021: TB SHALL accept a deterministic input object containing structured OB evidence fields, lane identifier, RB routing context, lineage/provenance fields, ΔH% contribution and missing-mass context, and MTP snapshot fields required for interpretation.
22. HLR-20.060-022: TB SHALL emit a deterministic output object containing channel interpretation fields, `truth_hypotheses`-compatible interpretation records, updated lineage/provenance fields, TB execution diagnostics, and observability/telemetry fields required by MB, GB, OuB, and IB.
23. HLR-20.060-023: TB SHALL function as a deterministic semantic-interpretation basin that transforms structured evidence into explicit truth-evaluation inputs without assuming OB evidence-extraction authority or RB routing authority.
24. HLR-20.060-024: TB SHALL enforce applicable global boundedness constraints defined in 20.30 section 8, including interpretation channel/hypothesis bounds and per-basin TCU envelopes.
25. HLR-20.060-025: When a global bound condition affects TB interpretation, TB SHALL emit deterministic overflow/degradation tags and stability telemetry conforming to the canonical overflow field schema in 20.30 section 8.3.
26. HLR-20.060-026: TB degradation behavior under global-bound exceedance SHALL follow deterministic, policy-bounded actions, including deterministic interpretation truncation/compression, and SHALL NOT silently drop interpretation fields without explicit tagging and logging.
27. HLR-20.060-027: TB SHALL operate exclusively in Pipeline A; SHALL NOT read `exec_plan` or `exec_trace` (HLR-20.038-021).
28. HLR-20.060-028: TB SHALL NOT write `TP.TR` or `thought_router_fields`; MAY set `tr_needs_update = true` when semantic-relevant interpretation fields change (20.37).
29. HLR-20.060-029: TB SHALL NOT read, write, or advance `routing_epoch_id`; social channel SHALL NOT encode OuB register/voice directives (20.31-021); TB SHALL NOT read `thought_router_fields` or `TP.TR` for derivation (HLR-20.060-043).
30. HLR-20.060-030: TB messy-input classifiers SHALL follow 20.17 detector order; TB SHALL NOT smooth contradiction, fill underspec slots, or clear messy-input tags.
31. HLR-20.060-031: TB affect/stance/social interpretation under `MI_AFFECT` SHALL execute on RB-routed lanes per fixed policy table before Merge commit (20.17-028).
32. HLR-20.060-032: `confidence_q32` and numeric channel weights SHALL use canonical Q32.32 per 20.95; −0→+0 before comparison and export (HLR-20.060-034).
33. HLR-20.060-033: TB SHALL produce truth-evaluation **inputs** only; final truth/done scoring SHALL remain in [20.140](20.140_truth_evaluation_requirements.md).
34. HLR-20.060-034: TB numeric interpretation fields SHALL use canonical Q32.32; equality and replay diff SHALL use canonical integer form.
35. HLR-20.060-035: GB and MB MAY consume TB telemetry read-only; GB SHALL NOT mutate TB interpretation outputs or write `TP.TR` on TB's behalf.
36. HLR-20.060-036: Strip replay removing Pipeline B envelopes SHALL preserve TB-committed interpretation and `truth_hypotheses` records in `semantic_core` for Pipeline A-only equivalence (20.36 Class 1).
37. HLR-20.060-037: Scoped presentation fields that appear to smooth contradiction SHALL require explicit TB commitment rules and SHALL NOT violate active `conflict_flag` without `contradiction_status = GB_ARBITRATED` (20.17-024).
38. HLR-20.060-038: TB channel maps, `truth_hypothesis_records[]`, and nested `evidence_refs[]` SHALL use deterministic canonical ordering before export, hash, and replay diff per 20.95/20.39.
39. HLR-20.060-039: TB SHALL read only the approved field set in §7; reads outside that set SHALL be conformance failures.
40. HLR-20.060-040: TB output derivation SHALL NOT depend on TP creation order, allocation sequence, or container address identity.
41. HLR-20.060-041: TB SHALL NOT read prior `truth_hypotheses` content for latent inference; MAY read `hypothesis_id` and `last_updated_cycle` only for deterministic record continuity.
42. HLR-20.060-042: TB `truth_hypothesis_records[]` SHALL conform to minimum schema in 20.31-023 before Merge commit and 20.140 consumption.
43. HLR-20.060-043: TB SHALL NOT read `TP.TR`, `thought_router_fields`, or `routing_semantics` from MTP or `semantic_core` for interpretation derivation; TR routing semantics are consumed by RB only (20.37, 20.50).
44. HLR-20.060-044: `channel_interpretations{}` nested maps and arrays SHALL use deterministic canonical ordering before export, hash, and replay diff — lexicographic channel and field-key sort; stable-ID array sort; numeric weights canonical Q32.32.
45. HLR-20.060-045: TB interpretation outcomes SHALL depend only on the approved TP/MTP field set in §7; any read or implicit dependency on fields outside that set SHALL be a conformance failure.

## TB Invariants

- **Determinism:** identical effective input state yields identical TB interpretation outputs and channel semantics.
- **Isolation:** TB SHALL not assume RB routing authority or OB evidence-extraction authority.
- **Interpretation boundary:** TB produces channels and hypothesis records; 20.140 evaluates truth/done.
- **Auditability:** each interpretation field SHALL be attributable to explicit evidence inputs and deterministic steps.

## Conformance

Implementation conforms when:

- five interpretation channels emit explicit deterministic fields
- no RB routing or split/merge performed by TB
- no exec-envelope access; no `routing_epoch_id` advance
- messy-input rules followed without resolution/smoothing
- `truth_hypothesis_records[]` match 20.31-023 schema with canonical ordering
- seed change does not alter TB outputs for fixed inputs
- strip replay preserves TB interpretation in `semantic_core`
- TB does not read `thought_router_fields` or `TP.TR` for derivation
- `channel_interpretations{}` uses canonical nested ordering in replay export
- interpretation depends only on §7 approved MTP field allowlist

## Verification Focus

- 20.36 Class 1: strip B → TB interpretation + hypotheses stable
- 20.36 Class 2: overflow preserves messy-input primary flags through TB path
- 20.36 Class 5: no OuB-style smoothing when `conflict_flag` active without GB_ARBITRATED
- 20.37: TB sets `tr_needs_update` when appropriate; never writes `TP.TR`
- 20.50: `MI_AFFECT` routes to correct TB module family per policy table
- Golden fixture rejects non-canonical `hypothesis_id` sort order
- Prior-hypothesis latent-inference harness negative test (HLR-041)
- Fixture rejects non-canonical `channel_interpretations` key ordering
- Harness rejects TB reads of `thought_router_fields` and out-of-allowlist MTP fields
