# 20.166 REx — Realization Extractor Primitive

## Purpose

REx is the extraction primitive for Path B. It accepts the meaning-layer fields
committed by LI and the continuity context from CoHI, applies the substrate
construction function $\Phi$ to decompose committed meaning into typed realization
substeps, and writes the resulting realization substrate `tp.rsub` for consumption
by RPlan. REx performs no meaning interpretation, no planning, and no surface
generation.

**[HLR-20.166-001]** The REx primitive SHALL consume the meaning-layer fields
produced by LI and the continuity fields produced by CoHI, and SHALL produce
`tp.rsub` as a fully populated realization substrate before RPlan begins execution
for the same turn.

## Input Contract

The table below defines all inputs REx reads. No other TP field, external store, or
runtime service may be accessed during REx execution.

| Field | Source Primitive | Required | Type | Validity Constraint |
|---|---|---|---|---|
| `tp.meaning` | LI | Required | structured object | must be present when `tp.mli_status = RESOLVED`; may be absent only when `tp.mli_status = CONFLICT` |
| `tp.mli_status` | LI | Required | enum | ∈ {`RESOLVED`, `CONFLICT`}; any other value is a pre-condition fault |
| `tp.mli_confidence` | LI | Required | float | $\in [0, 1]$ |
| `tp.mli_conflict` | LI | Required | array | non-null; non-empty only when `tp.mli_status = CONFLICT` |
| `tp.mli_reason_code` | LI | Required | string | may be empty string when `tp.mli_status = RESOLVED` |
| `tp.mli_revision_cycles` | LI | Required | integer | $\geq 0$ |
| `tp.continuity_fields.structural_history` | CoHI | Required | structured object | must be present; may be empty |
| `tp.continuity_fields.referential_history` | CoHI | Required | structured object | must be present; may be empty |
| `tp.continuity_fields.conversation_objects` | CoHI | Required | array | must be present; may be empty |
| `tp.continuity_fields.topic_threads` | CoHI | Required | array | must be present; may be empty |
| `tp.continuity_fields.continuity_markers` | CoHI | Required | array | must be present; may be empty |
| `tp.truth_tags` | A-side | Required | array | may be empty |
| `tp.safety_flags` | A-side | Required | array | may be empty |

**[HLR-20.166-002]** The REx primitive SHALL read only the fields enumerated in the
Input Contract table; it SHALL NOT read from COB directly, from any realization
substrate field written by a prior REx execution, or from any field owned by RPlan,
RPU, or OuBB.

**[HLR-20.166-003]** The REx primitive SHALL perform a pre-condition check before
extraction begins: if `tp.mli_status` is absent or not a recognised enum value, or
if `tp.meaning` is absent when `tp.mli_status = RESOLVED`, REx SHALL set
`tp.rsub.rsub_status` to `BLOCKED`, SHALL write
`reason_code = PRE_CONDITION_FAULT`, and SHALL halt without constructing any substep.

## Transfer Function

### Abort Path

When `tp.mli_status = CONFLICT` on entry and the pre-condition check passes, REx
evaluates whether the conflict set is resolvable before proceeding.

A conflict entry $c \in$ `tp.mli_conflict` is resolvable when at least one tag in
`tp.truth_tags` asserts the truth of $c$'s referent AND no entry in `tp.safety_flags`
prohibits acting on $c$'s referent. The conflict set is fully unresolvable when no
entry survives this test:

$$
\text{unresolvable} = \forall\ c \in \texttt{tp.mli}_{conflict} :
\neg\ \text{truth-asserted}(c,\ \texttt{tp.truth}_{tags})
\ \lor\ \text{safety-blocked}(c,\ \texttt{tp.safety}_{flags})
$$

**[HLR-20.166-004]** When `tp.mli_status = CONFLICT` and the conflict set is fully
unresolvable, REx SHALL set `tp.rsub.rsub_status` to `BLOCKED`, SHALL write
`reason_code = UNRESOLVABLE_CONFLICT`, and SHALL NOT construct any substep.

### Construction Path

When `tp.mli_status = RESOLVED`, or when `tp.mli_status = CONFLICT` and at least
one conflict entry is resolvable, REx applies the substrate construction function
$\Phi$.

Let $M$ denote the committed meaning from `tp.meaning` and let
$\Gamma = \\{\gamma_{\text{sh}},\ \gamma_{\text{rh}},\ \gamma_{\text{co}},\ \gamma_{\text{tt}},\ \gamma_{\text{cm}}\\}$
denote the five continuity field components (structural history, referential
history, conversation objects, topic threads, continuity markers). $\Phi$ maps
$M$ and $\Gamma$ to an ordered substep sequence:

$$
\langle u_1,\ u_2,\ \dots,\ u_k \rangle = \Phi(M,\ \Gamma)
$$

Each substep $u_i$ is a 4-tuple:

$$
u_i = \bigl(\text{substep}_{id_i},\ \text{substep}_{type_i},\ p_i,\ D_i\bigr)
$$

where $p_i$ is the type-specific payload incorporating applicable $\Gamma$ components,
and $D_i \subseteq \\{\text{substep}_{id_j} \mid j < i\\}$ is the dependency set
derived from structural dependencies in $M$.

**[HLR-20.166-005]** The REx primitive SHALL apply $\Phi$ to decompose `tp.meaning`
into substeps $\langle u_1, \dots, u_k \rangle$, each typed by a recognised
`substep_type` value drawn from the clause structure, discourse roles, referential
anchors, polarity, and dependency graph embedded in `tp.meaning`; it SHALL produce
at least one substep when `tp.mli_status = RESOLVED`.

**[HLR-20.166-006]** The REx primitive SHALL reject any substep produced by $\Phi$
whose `substep_type` is not a recognised enum value; upon detecting an unrecognised
type it SHALL set `tp.rsub.rsub_status` to `BLOCKED`, SHALL write
`reason_code = INVALID_SUBSTEP_TYPE` identifying the offending substep, and SHALL
discard all constructed substeps.

**[HLR-20.166-007]** The REx primitive SHALL incorporate applicable
`tp.continuity_fields` entries into the payload $p_i$ of each substep $u_i$: a
continuity entry is applicable to $u_i$ when its referent appears in the clause or
discourse fragment that $u_i$ realises; inapplicable entries SHALL NOT be written
into any substep payload.

The `rsub_status` value is determined by the outcome of the transfer function:

$$
\text{rsub}_{status} = \begin{cases}
\texttt{BLOCKED} & \text{pre-condition fault, unresolvable conflict, or invalid substep type} \\
\texttt{READY}   & \Phi(M,\ \Gamma) \text{ produces } k \geq 1 \text{ valid substeps}
\end{cases}
$$

## Output Contract

The table below defines all fields REx writes. RPlan must validate presence and
type of every required field before beginning its own execution.

| Field | Type | Legal Values | Semantics |
|---|---|---|---|
| `tp.rsub.rsub_status` | enum | `READY`, `BLOCKED` | Overall substrate viability; RPlan reads this first to select abort or planning path |
| `tp.rsub.reason_code` | string | non-empty on `BLOCKED`; empty string on `READY` | Machine-readable cause; RPlan propagates this into `tp.rplan.reason_code` on abort |
| `tp.rsub.substeps` | array | non-null; empty only when `rsub_status = BLOCKED` | Ordered substep sequence for RPlan to map into `tp.rplan.ordered_steps` |
| `tp.rsub.substeps[i].substep_id` | string | non-empty; unique within array | RPlan uses this as the source key when constructing `step_id` values in `tp.rplan` |
| `tp.rsub.substeps[i].substep_type` | enum | recognised substep_type values | Identifies the realization action; RPlan maps this to `step_type` in `tp.rplan` |
| `tp.rsub.substeps[i].payload` | structured object | per `substep_type` schema; continuity-augmented | Parameters passed verbatim by RPlan into `tp.rplan.ordered_steps[i].payload` |
| `tp.rsub.substeps[i].depends_on` | array of substep_id | may be empty; each ref must name a `substep_id` in the same array | RPlan uses these to derive the dependency graph for topological sort and constraint derivation |

**[HLR-20.166-008]** The REx primitive SHALL populate all fields in the Output
Contract table for every execution path (`READY` and `BLOCKED`); no output field
SHALL be left absent or null except where the table explicitly permits it.

**[HLR-20.166-009]** The REx primitive SHALL NOT write to any meaning-layer field
owned by LI, any representation-layer field owned by TPTB, TPSF, or CoHI, or any
field owned by RPlan, RPU, or OuBB.

## When

REx runs once per turn. Its position in the Path B execution order is fixed: after
LI has committed all meaning-layer fields and before RPlan reads `tp.rsub`.

**[HLR-20.166-010]** The REx primitive SHALL NOT begin execution until LI has
written all meaning-layer fields to a completed state for the current turn, as
indicated by `tp.mli_status` holding a recognised enum value.

**[HLR-20.166-011]** The REx primitive SHALL complete all writes to `tp.rsub`
before RPlan begins execution for the same turn.

## Why

LI commits meaning into a structured but interpretation-oriented representation.
That representation is not yet in the form RPlan needs: RPlan requires typed
substeps with explicit dependency graphs and continuity-augmented payloads. Without
REx as a dedicated extraction step, RPlan would need to interpret raw meaning fields
directly, coupling plan construction to meaning semantics and making the realization
pipeline brittle. REx provides a clean, typed handoff that decouples meaning from
planning.

## Is Not

REx is not a semantic interpreter; it does not re-derive or challenge the meaning
committed by LI.
REx is not a planner; it produces the substrate RPlan plans from.
REx is not a scorer.
REx is not a router.
REx is not a memory system.
REx does not modify COB.
REx does not generate surface expression.
REx does not perform global inference.

## Example

LI has set `tp.mli_status = RESOLVED` and committed `tp.meaning` indicating a
request to "summarize the dataset." `tp.mli_confidence = 0.94`.
`tp.continuity_fields.conversation_objects` contains one entry representing the
dataset referenced three turns earlier. `tp.truth_tags` asserts that object as
currently active. `tp.safety_flags` is empty.

Pre-condition check passes. `tp.mli_status = RESOLVED`. Construction path begins.

$\Phi$ decomposes `tp.meaning` into three substeps:

- $u_1$: `substep_id = "ref-resolve"`, `substep_type = REFERENT_RESOLVE`,
  `depends_on = []`, payload includes the conversation object from
  `tp.continuity_fields.conversation_objects`.
- $u_2$: `substep_id = "discourse-frame"`, `substep_type = DISCOURSE_FRAME`,
  `depends_on = ["ref-resolve"]`, payload sets discourse role to `SUMMARIZE`.
- $u_3$: `substep_id = "polarity-set"`, `substep_type = POLARITY_SET`,
  `depends_on = ["discourse-frame"]`, payload sets clause polarity to `AFFIRMATIVE`.

All three `substep_type` values are recognised. No inapplicable continuity entries
are written into any payload. `tp.rsub.rsub_status` is set to `READY`. RPlan reads
`tp.rsub` and begins topological sort of $\langle u_1, u_2, u_3 \rangle$ without
any further meaning interpretation.
