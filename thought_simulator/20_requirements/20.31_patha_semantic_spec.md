# 20.31_patha_semantic_spec.md (v1.0 — Path A Semantic Specification)

---

## 0. Introduction

This document defines the **semantic structures and behaviors used inside Pipeline A** of the Thought Simulator (TS). Pipeline A is responsible for meaning construction, truth evaluation, epistemic change tracking, and semantic tagging. All semantics defined here are **TP‑local**, deterministic, and non‑global.

Pipeline B semantics are **explicitly out of scope**.

---

## 1. Purpose

The purpose of 20.31 is to specify:

- TP‑local semantic fields  
- OB/TB/IB semantic behavior  
- $\Delta H\%$ computation  
- messy‑input handling  
- completion semantics  
- deterministic replay invariants  

All semantics defined here exist **only inside TP and OuBA** and are **not stored globally**.

---

## 2. Scope

This specification defines **Pipeline A semantic structures only**:

- TP semantic fields  
- OB/TB/IB behavior  
- epistemic change ($\Delta H\%$)  
- truth‑evidence semantics  
- completion state semantics  
- messy‑input semantics  
- deterministic replay rules  

**Excluded:**

- Pipeline B semantics  
- SSR (Semantic Snapshot)  
- `semantic_core`  
- commit semantics  
- global meaning stores  
- Path‑A→B handoff  

---

## 3. TP Semantic Structures

Meaning is represented only in:

- **TP** — lane‑local Thought Packet  
- **OuBA** — final meaning output of Pipeline A  

There is **no global semantic store**.

---

### 3.1 TP Semantic Fields

Each TP contains the following semantic fields:

- `proposition_set[]`  
- `truth_evidence[]`  
- `completion_state`  
- `h_percent`  
- `messy_input_record`  
- `semantic_tags[]`  
- `lane_local_identity`  
- `ob_trace[]`  

These fields are **local to the cycle** and do not persist beyond TP → OuBA commit.

---

## 4. OB Semantics (Observation Basis)

OB primitives operate exclusively on TP fields and produce:

- evidence  
- $\Delta H\\%$ contribution to H%  
- semantic tags  
- messy‑input markers  
- OB‑specific interpretations  

OB behavior is deterministic and lane‑local.

**HLR‑20.31‑001 — OB Determinism**  
OB primitives **SHALL** produce identical output given identical TP input.

---

## 5. TB Semantics (Truth Basis)

TB evaluates:

- proposition plausibility  
- truth evidence  
- contradiction markers  
- completion signals  

TB does not write to any global store.

**HLR‑20.31‑002 — Truth Evaluation Determinism**  
Truth evaluation **SHALL** operate only on TP fields and **SHALL** be deterministic.

Inline update rule: $T_{\text{new}} = T_{\text{old}} + \Delta T$

Block form:

$$
T_{\text{new}} = T_{\text{old}} + \Delta T
$$

---

## 6. IB Semantics (Inquiry Basin)

IB is created only with governance approval and performs:

- deeper truth evaluation  
- recursive evidence gathering  
- structured inquiry  

IB operates only on TP and produces TP‑local updates.

**HLR‑20.31‑003 — IB Isolation**  
IB **SHALL NOT** write to any global structure.

---

## 7. H% Semantics

H% tracks epistemic change within a single Pipeline A cycle.

**HLR‑20.31‑004 — H% Update Rule**  
H% **SHALL** be computed deterministically from OB and TB contributions.

$$
H\\%(n+1) = H\\%(n)\ + \ \sum_i \Delta H\\%_{{OB}_i}
$$

---

## 8. Completion Semantics

Completion state indicates whether meaning construction is:

- incomplete  
- partially complete  
- complete  
- complete‑with‑uncertainty  

**HLR‑20.31‑005 — Completion Determinism**  
Completion **SHALL** be derived solely from TP fields and TB results.

---

## 9. Messy‑Input Semantics

Messy input is tracked only inside TP.

**HLR‑20.31‑006 — Messy Input Record**  
`messy_input_record` **SHALL** capture:

- malformed structures  
- ambiguous phrasing  
- contradictory cues  
- incomplete evidence  

Messy input does not propagate beyond the cycle.

---

## 10. Replay Invariants

### **HLR‑20.31‑007 — Replay Determinism**  
Replay **SHALL** produce identical output when both the TP input and the seed are identical.

$$
x_1 = x_2 \ \land\  s_1 = s_2 
\Rightarrow\ 
\text{Replay}(x_1, s_1) = \text{Replay}(x_2, s_2)
$$

---

## 11. Policy Semantics

Policy markers in TP enforce:

- safety  
- routing  
- inquiry limits  
- overflow behavior  

**HLR‑20.31‑008 — Policy Determinism**  
Policy evaluation **SHALL** be deterministic and **SHALL** operate only on TP fields.

---

## 12. Overflow and Stability Semantics

Overflow triggers:

- deterministic degradation  
- tagging  
- bounded evidence truncation  

**HLR‑20.31‑009 — Overflow Determinism**  
Overflow **SHALL** produce deterministic, auditable TP‑local effects.

---

## 13. Summary

This specification defines the **semantic structures and behaviors of Pipeline A**:

- TP is the sole meaning container  
- OuBA is the only meaning output  
- No global meaning store exists  
- All semantics are deterministic  
- Path‑B semantics are out of scope
