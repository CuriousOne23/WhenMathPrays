# 20.140 Truth/Done Evaluation Requirements

**Document ID:** 20.140  
**Version:** 0.3  
**Date:** 2026-06-06  
**Status:** Approved v0.3 — §8 second-pass GATE (2026-06-07; CuriousOne23, Copilot, Grok; boundary check only; no edits)

## Purpose

Defines deterministic **Truth/Done evaluation** — the Pipeline A stage that consumes TB-committed interpretation inputs and computes final `truth_hypotheses` scoring updates, uncertainty (H%) accounting, and `done_state` completion status.

Truth/Done is an **evaluation authority** — not an evidence extractor (OB), not an interpretation basin (TB), not a routing authority (RB/TR), and not a geometric overlay (DCB). It SHALL operate only on explicit structured fields committed to `semantic_core` or merged lane projections.

This module SHALL NOT weaken invariants in [20.12_ts_invariants.md](20.12_ts_invariants.md).

**Integration contract:** TB produces truth-evaluation **inputs** per [20.60](20.60_tb_requirements.md) HLR-20.060-033; TR is read-only routing metadata per [20.37](20.37_thought_router_tr_specification.md) HLR-20.037-016; pipeline placement per [20.36](20.36_canonical_end_to_end_trace.md) §2.1 (`truth_done_evaluation` after `merging`, before `mtp_update`).

**Schema authority:** `truth_hypotheses` record shape per [20.31](20.31_semantic_specification.md) HLR-20.031-023; numeric encoding per [20.95](20.95_ts_numeric_policy.md).

## Parent Scope

- **Pipeline:** Pipeline A only — Truth/Done SHALL NOT read `exec_plan` or `exec_trace`
- **Upstream:** TB interpretation outputs (20.60), Merge field integration (20.30 §3.6), ΔH% normalization
- **Downstream:** `mtp_update` commits evaluated `truth_hypotheses` and `done_state` to `semantic_core`
- **Messy-input:** read-only gating per [20.17](20.17_messy_input_handling.md); no resolve/smooth/clear
- **Policy defaults:** completion and commitment thresholds per [20.90](20.90_ts_parameter_table.md) §H
- **Does not modify:** 20.10, 20.12, 20.20, 20.30 bootstrap documents

## Non-Goals

- OB evidence extraction — OB (20.40)
- TB channel interpretation — TB (20.60)
- TR derivation (`TP.TR`, `thought_router_fields`) — TR routine (20.37)
- RB routing, split/merge arbitration — RB (20.50)
- Pipeline B presentation, OuB expression, IMR corrections
- Latent probabilistic inference, embedding search, or heuristic completion guessing
- Numeric threshold policy as normative in this module (deferred to 20.90 / 50-series where applicable)

## 1. Dual-Pipeline Boundary Discipline

| Concern | Truth/Done posture |
|---------|-------------------|
| `semantic_core` | Writes evaluated `truth_hypotheses` and `done_state` at `mtp_update` boundary |
| `TP.TR`, `thought_router_fields` | **Read-only metadata** per 20.37-016; **no write** |
| `routing_metadata` | **No read** for evaluation derivation (HLR-20.140-043) |
| `tr_needs_update` | **No write** — evaluation is downstream of TR routing for the cycle |
| `exec_plan`, `exec_trace`, `supervisory` | **No read/write** |
| `routing_epoch_id` | **No read/write; no advance** |
| `messy_input_record` | **Read-only** for completion gating; **no resolve/smooth/clear** |
| Seed | **SHALL NOT influence** truth/done outputs (HLR-20.012-010) |

**Pipeline B forbidden:** OuB, IMR, SRP, OpBeh/OBG/XlateR SHALL NOT mutate evaluated truth/done fields in `semantic_core` retroactively (20.12-003).

**Upstream forbidden reads (other modules):** OB, RB, TR, DCB, and COP SHALL NOT read `truth_hypotheses` or `done_state` for upstream derivation — Truth/Done is strictly downstream (20.037-063, 20.050-043, 20.040-041, 20.106-026).

## 2. TB / Truth/Done Boundary

| Layer | Authority |
|-------|-----------|
| TB (20.60) | Produces `channel_interpretations{}` and `truth_hypothesis_records[]` as evaluation **inputs**; does not perform final truth/done scoring |
| Truth/Done (this document) | Consumes committed TB inputs + explicit MTP context; computes deterministic `truth_status`/`confidence_q32` updates, H% accounting, and `done_state` |

Truth/Done SHALL NOT re-interpret OB evidence or re-derive TB channel semantics (HLR-20.140-018). Truth/Done SHALL treat TB records as authoritative interpretation inputs for the evaluation pass.

TB `truth_hypothesis_records[]` SHALL conform to 20.31-023 **before** Truth/Done consumption (20.060-042). Truth/Done SHALL NOT require records that violate minimum schema.

---

## 3. Pipeline Placement and Lifecycle

Truth/Done SHALL execute in Pipeline A after `merging` and `delta_h_normalization`, and before `mtp_update` (20.36 §2.1, HLR-20.140-019).

Per-cycle obligations:

1. Read merged `semantic_core` projection and lane-integrated TB outputs
2. Evaluate truth hypotheses in canonical `hypothesis_id` order
3. Compute uncertainty (H%) accounting fields from explicit mass inputs
4. Evaluate `done_state` against explicit `success_criteria` from `policy_signature`
5. Emit deterministic audit records with reason codes and threshold context
6. Commit field-wise updates at `mtp_update` — no silent overwrite of unrelated meaning fields

Truth/Done SHALL NOT trigger additional OB/TB/RB cycles within the same evaluation pass (HLR-20.140-020).

## 4. Truth Evaluation Contract

### 4.1 Inputs

Truth evaluation SHALL consume only explicit structured fields (HLR-20.140-004, HLR-20.140-005):

- merged `truth_hypothesis_records[]` / `truth_hypotheses` per 20.31-023
- `channel_interpretations{}` (read-only evaluation context)
- `propositions[]`, `lineage[]`, `delta_h` / ΔH% fields (Q32.32)
- `stability_metadata`, `overflow_metadata`
- `messy_input_record` (read-only gating)
- `thought_router_fields` / committed `TP.TR` (read-only metadata per 20.37-016)
- `policy_signature` and bound `success_criteria` / truth-evaluation policy refs

### 4.2 Outputs

Truth/Done SHALL emit (HLR-20.140-021):

```text
truth_done_output {
  truth_hypotheses[],       // evaluated records; sort by hypothesis_id
  done_state{},
  h_percent_q32,              // uncertainty accounting; Q32.32
  uncertainty_audit{},        // mass accounting fields per 20.36-012
  evaluation_audit_records[]  // when/why/how + threshold context
}
```

**`truth_hypotheses` evaluated record minimum (20.31-023 + evaluation extensions):**

```text
truth_hypothesis_record {
  hypothesis_id,
  proposition_ref,
  truth_status,             // OPEN | SUPPORTED | REFUTED | UNKNOWN
  confidence_q32,           // Q32.32 canonical
  evidence_refs[],          // canonical sort; traceable to OB outputs
  last_updated_cycle,
  evaluation_reason_codes[] // deterministic audit codes
}
```

**`done_state` minimum:**

```text
done_state {
  completion_status,        // NOT_DONE | PARTIAL | DONE | BLOCKED
  completion_reason_codes[],// MUST sort by reason_code lexicographic before export/hash
  policy_criteria_ref,
  last_evaluated_cycle,
  blocked_by_messy_input?   // when MI_* gates block completion
}
```

**`done_state.completion_reason_codes[]` ordering:** SHALL sort by `reason_code` lexicographic before export, hash, and replay diff (HLR-20.140-038).

**Canonical ordering (HLR-20.140-038):** `truth_hypotheses[]`, nested `evidence_refs[]`, `evaluation_reason_codes[]`, and `done_state.completion_reason_codes[]` SHALL sort deterministically before export, hash, and replay diff — `hypothesis_id` / `reason_code` lexicographic primary keys per 20.95/20.39.

### 4.3 Evaluation rules

- Truth evaluation SHALL use deterministic field-based logic only — no latent embeddings (HLR-20.140-004)
- `truth_status` transitions SHALL be explicit, policy-bounded, and auditable (HLR-20.140-009)
- `confidence_q32` updates SHALL use canonical Q32.32; −0→+0 before comparison and export (HLR-20.140-034)
- Truth/Done SHALL NOT invent hypotheses, propositions, or evidence not present in approved inputs (HLR-20.140-022)
- Evaluation SHALL remain bounded — no unbounded scanning, probabilistic search, or inference loops (HLR-20.140-012)

---

## 5. Done Evaluation Contract

Done evaluation SHALL consume explicit completion fields and policy-bound `success_criteria` only (HLR-20.140-006, HLR-20.140-010).

Done evaluation SHALL NOT infer completion from:

- latent or unstated state
- Pipeline B expression artifacts
- unresolved `MI_VAGUE` underspec slots (unless policy explicitly allows partial completion with capped commitment per 20.90 §H)
- active `MI_CONTRA` / `conflict_flag` without `contradiction_status = GB_ARBITRATED` (20.17)
- `MI_INCOMP` with unresolved `missing_slots[]` when policy requires slot satisfaction

When messy-input gates block completion, `done_state.completion_status` SHALL be `BLOCKED` or `PARTIAL` with explicit `blocked_by_messy_input` markers and deterministic reason codes (HLR-20.140-029).

---

## 6. Messy-Input Gating (Read-Only)

| Class | Truth/Done obligation |
|-------|----------------------|
| `MI_CONTRA` | SHALL NOT collapse parallel traces to a single winning `truth_status` unless `contradiction_status = GB_ARBITRATED` |
| `MI_VAGUE` | SHALL cap commitment / done confidence per `messy_input.commitment_strength.cap_until_resolved` (20.90 §H); SHALL NOT treat unresolved slots as satisfied |
| `MI_INCOMP` | SHALL NOT emit `DONE` when required slots remain unresolved per policy |
| `MI_AFFECT` | MAY influence uncertainty weighting only through explicit structured channel fields — not affect-driven slot fill |
| `MI_NOISE` | SHALL evaluate stabilized conceptual evidence already committed by OB/TB — not surface-form noise |

Truth/Done SHALL NOT clear, smooth, or rewrite messy-input tags (20.17, HLR-20.140-030).

---

## 7. Approved Read Set

**Approved reads (HLR-20.140-039, HLR-20.140-045):** Truth/Done MAY read only:

- merged TB outputs: `truth_hypothesis_records[]`, `channel_interpretations{}`
- `propositions[]`, `stance{}`, `affect{}`, `intent{}`, `lineage[]`, `semantic_tags[]` (meaning-layer only)
- `delta_h` / ΔH% and missing-mass context (Q32.32)
- `stability_metadata`, `overflow_metadata`
- `messy_input_record` (read-only)
- `thought_router_fields` / committed `TP.TR` (read-only routing metadata per 20.37-016)
- prior-cycle `truth_hypotheses` and `done_state` for deterministic field-wise update continuity
- `policy_signature`, bound truth-evaluation policy, and `success_criteria`
- `mtp_snapshot_id`, `cycle_id`

Truth/Done SHALL NOT read `routing_metadata`, execution/supervisory envelopes, or any MTP/`semantic_core` field outside this approved set (HLR-20.140-043, HLR-20.140-045). Truth/Done evaluation outcomes SHALL depend only on fields in this approved set; any read or implicit dependency on fields outside the set SHALL be a conformance failure.

**Explicit forbidden reads (HLR-20.140-043):** Truth/Done SHALL NOT read `exec_plan`, `exec_trace`, `routing_epoch_id`, `routing_metadata`, supervisory envelope state, or Pipeline B realization artifacts. Truth/Done SHALL NOT read OB raw `evidence_fields[]` except via committed `evidence_refs[]` already embedded in TB records.

---

## 8. Determinism, Replay, and MTP Integration

- Truth/Done outputs SHALL reproduce from `(merged semantic projection, policy_signature)` — **seed excluded** (HLR-20.140-024)
- Identical effective input state SHALL yield identical `truth_hypotheses`, `done_state`, and H% accounting (HLR-20.140-007)
- Authoritative ordering SHALL use deterministic `cycle_id` / sequence tokens — not wall-clock timestamps (HLR-20.140-008)
- MTP integration SHALL use explicit field-wise updates; SHALL NOT mutate immutable finalized lineage entries (HLR-20.140-013, HLR-20.140-014)
- Strip replay removing Pipeline B envelopes SHALL preserve Truth/Done-committed `truth_hypotheses` and `done_state` in `semantic_core` (20.36 Class 1, HLR-20.140-027)
- Evaluation SHALL NOT depend on TP creation order, allocation sequence, or container address identity (HLR-20.140-040)

## Worked Example — TB Input → Truth/Done → MTP Commit

| Step | Actor | Outcome |
|------|-------|---------|
| 1 | Merge | Integrates lane TB outputs; `truth_hypothesis_records[]` sorted by `hypothesis_id` |
| 2 | Truth/Done | Reads TB records + `messy_input_record`; no OB re-interpretation |
| 3 | Truth/Done | Updates `truth_status` from `OPEN` → `SUPPORTED` where evidence_refs satisfy policy |
| 4 | Truth/Done | `MI_VAGUE` active → caps confidence; `done_state = PARTIAL` |
| 5 | Truth/Done | Emits `evaluation_audit_records[]` with threshold context |
| 6 | Truth/Done | Does **not** set `tr_needs_update`; does **not** write `TP.TR` |
| 7 | `mtp_update` | Commits evaluated `truth_hypotheses` + `done_state` to `semantic_core` |
| 8 | Strip replay | Pipeline B removed → truth/done bytes stable in `semantic_core` |

## Normative Requirements

1. HLR-20.140-001: TS SHALL compute evaluated `truth_hypotheses` using deterministic field-based evaluation logic.
2. HLR-20.140-002: TS SHALL compute `done_state` using explicit completion criteria bound to `policy_signature`.
3. HLR-20.140-003: Truth and done evaluation SHALL be auditable per cycle with deterministic when/why/how context.
4. HLR-20.140-004: Truth evaluation SHALL operate over structured explicit fields only and SHALL NOT use latent probabilistic embeddings.
5. HLR-20.140-005: Truth evaluation SHALL consume only explicit TP/MTP fields in the approved read set (§7), including TB-committed hypothesis records, evidence references, lineage, ΔH% context, and stability indicators.
6. HLR-20.140-006: Done evaluation SHALL consume explicit completion fields and policy-bound `success_criteria` and SHALL NOT infer completion from latent or unstated state.
7. HLR-20.140-007: Truth and done outputs SHALL be deterministic and reproducible for identical merged semantic input state and `policy_signature`.
8. HLR-20.140-008: Truth and done evaluation SHALL preserve deterministic cycle ordering semantics and SHALL use `cycle_id` and canonical sequence tokens as the ordering authority — not wall-clock timestamps.
9. HLR-20.140-009: Evaluated `truth_hypotheses` SHALL remain schema-versioned, explicit, and traceable to source evidence references and proposition identifiers.
10. HLR-20.140-010: Completion criteria SHALL be explicit, bounded, and configured by policy rather than inferred heuristics.
11. HLR-20.140-011: Truth and done evaluation SHALL emit deterministic audit records with when, why, how, and threshold context.
12. HLR-20.140-012: Truth and done evaluation SHALL remain bounded and SHALL NOT require unbounded scanning, probabilistic search, or inference loops.
13. HLR-20.140-013: Truth and done evaluation SHALL integrate with MTP updates through explicit field-wise updates and SHALL NOT mutate immutable finalized lineage entries.
14. HLR-20.140-014: Truth and done evaluation SHALL remain consistent with MTP schema requirements and split/merge lineage semantics.
15. HLR-20.140-015: Truth and done evaluation SHALL be testable through deterministic fixtures covering nominal, boundary, ambiguous, messy-input-gated, and completion-edge cases.
16. HLR-20.140-016: Truth evaluation requirements in this module SHALL satisfy and SHALL NOT weaken parent invariants defined by 20.10, 20.12, and 20.30.
17. HLR-20.140-017: Truth/Done SHALL operate exclusively in Pipeline A; SHALL NOT read `exec_plan` or `exec_trace` (HLR-20.038-021).
18. HLR-20.140-018: Truth/Done SHALL NOT perform OB-class evidence extraction or TB-class channel interpretation; it SHALL consume TB-committed records as evaluation inputs only.
19. HLR-20.140-019: Truth/Done SHALL execute after merging and ΔH% normalization and before `mtp_update` in the same Pipeline A cycle (20.36 §2.1).
20. HLR-20.140-020: Truth/Done SHALL NOT trigger additional OB, TB, RB, or TR cycles within the same evaluation pass.
21. HLR-20.140-021: Truth/Done SHALL emit evaluated `truth_hypotheses`, `done_state`, H% accounting fields, and deterministic evaluation audit records conforming to §4.2 minimum schemas.
22. HLR-20.140-022: Truth/Done SHALL NOT invent propositions, hypotheses, or evidence references not present in approved inputs.
23. HLR-20.140-023: Truth/Done SHALL NOT write `TP.TR`, `thought_router_fields`, or `tr_needs_update`.
24. HLR-20.140-024: Truth/Done outputs SHALL be reproducible from `(merged semantic projection, policy_signature)`; seed SHALL NOT influence evaluation results (HLR-20.012-010).
25. HLR-20.140-025: Truth/Done SHALL treat `thought_router_fields` and committed `TP.TR` as read-only routing metadata per 20.37-016 and SHALL NOT derive interpretation semantics solely from routing metadata.
26. HLR-20.140-026: Truth/Done SHALL NOT read, write, or advance `routing_epoch_id`.
27. HLR-20.140-027: Strip replay removing Pipeline B envelopes SHALL preserve Truth/Done-committed `truth_hypotheses` and `done_state` in `semantic_core` for Pipeline A-only equivalence (20.36 Class 1).
28. HLR-20.140-028: Truth/Done stage records in canonical fixtures SHALL include truth hypothesis update fields, `done_state`, and uncertainty accounting fields per 20.36-012.
29. HLR-20.140-029: When messy-input gates block completion or force capped commitment, Truth/Done SHALL emit explicit `BLOCKED` or `PARTIAL` `done_state` with deterministic reason codes — never silent `DONE`.
30. HLR-20.140-030: Truth/Done SHALL NOT create, modify, or clear messy-input tags; evaluation gating SHALL remain read-only relative to 20.17 classifiers.
31. HLR-20.140-031: Under active `MI_CONTRA` with `conflict_flag`, Truth/Done SHALL NOT collapse parallel traces to a single winning truth outcome unless `contradiction_status = GB_ARBITRATED`.
32. HLR-20.140-032: Under active `MI_VAGUE`, Truth/Done SHALL enforce `messy_input.commitment_strength.cap_until_resolved` (20.90 §H) on confidence and completion commitment fields.
33. HLR-20.140-033: Under active `MI_INCOMP` with unresolved required slots, Truth/Done SHALL NOT emit `completion_status = DONE` when policy requires slot satisfaction.
34. HLR-20.140-034: Numeric truth/done fields (`confidence_q32`, `h_percent_q32`, commitment weights) SHALL use canonical Q32.32 per 20.95; −0→+0 before comparison and export.
35. HLR-20.140-035: GB and MB MAY consume Truth/Done audit telemetry read-only; GB SHALL NOT mutate evaluated truth/done outputs or write `TP.TR` on Truth/Done's behalf.
36. HLR-20.140-036: When Truth/Done is disabled by policy, `mtp_update` SHALL commit prior-cycle truth/done fields unchanged; conformance harnesses SHALL verify identical semantics to no-evaluation baseline for fixed inputs.
37. HLR-20.140-037: Truth/Done SHALL NOT read upstream routing modules' forbidden fields for reverse coupling; upstream modules SHALL NOT read evaluated `truth_hypotheses` or `done_state` for same-cycle routing derivation (20.037-063, 20.050-043).
38. HLR-20.140-038: `truth_hypotheses[]`, nested `evidence_refs[]`, `evaluation_reason_codes[]`, and `done_state.completion_reason_codes[]` SHALL use deterministic canonical ordering before export, hash, and replay diff — `hypothesis_id` / `reason_code` lexicographic primary keys per 20.95/20.39.
39. HLR-20.140-039: Truth/Done SHALL read only the approved field set in §7; reads outside that set SHALL be conformance failures.
40. HLR-20.140-040: Truth/Done output derivation SHALL NOT depend on TP creation order, allocation sequence, or container address identity.
41. HLR-20.140-041: Truth/Done MAY read prior-cycle `truth_hypotheses` and `done_state` only for deterministic field-wise continuity; SHALL NOT use prior records for latent Bayesian or embedding-based inference.
42. HLR-20.140-042: Truth/Done SHALL reject TB records that violate 20.31-023 minimum schema with deterministic audit reason codes and SHALL NOT silently coerce invalid records.
43. HLR-20.140-043: Truth/Done SHALL NOT read `exec_plan`, `exec_trace`, `routing_epoch_id`, `routing_metadata`, or supervisory envelope state for evaluation derivation.
44. HLR-20.140-044: H% / uncertainty accounting SHALL derive only from explicit ΔH%, missing-mass, and structured hypothesis mass fields — not from Pipeline B artifacts or latent state.
45. HLR-20.140-045: Truth/Done evaluation outcomes SHALL depend only on the approved TP/MTP field set in §7; any read or implicit dependency on fields outside that set SHALL be a conformance failure.

## Functional Boundaries

- **TB:** interpretation inputs and channel semantics
- **Truth/Done:** deterministic truth scoring, H% accounting, and completion evaluation
- **RB/TR:** no consumption of evaluated truth/done outputs for same-cycle routing
- **MTP update:** commits evaluated fields to authoritative `semantic_core`

## Conformance

Implementation conforms when:

- truth/done executes post-merge, pre-`mtp_update` in Pipeline A order
- TB boundary honored — no OB/TB re-interpretation inside evaluator
- evaluated `truth_hypotheses` and `done_state` match 20.31-023 + §4.2 schemas with canonical ordering
- no exec-envelope access; no `routing_epoch_id` advance; no `tr_needs_update` writes
- messy-input gating read-only; no tag clear/smooth
- seed change does not alter truth/done outputs for fixed merged inputs
- strip replay preserves truth/done bytes in `semantic_core`
- approved read set enforced; `routing_metadata` not read
- evaluation depends only on §7 approved field allowlist

## Verification Focus

- 20.36 Class 1: strip B → `truth_hypotheses` + `done_state` stable
- 20.36 Class 2: overflow + messy-input flags preserved through truth/done path
- 20.36 Class 5: `MI_CONTRA` blocks forced single-winner truth; `MI_VAGUE` caps commitment
- TB boundary negative test: evaluator does not re-derive channel interpretations
- Golden fixture rejects non-canonical `hypothesis_id` sort order
- Golden fixture rejects non-canonical `done_state.completion_reason_codes[]` sort order
- Prior-hypothesis latent-inference harness negative test (HLR-041)
- Harness rejects reads of `exec_plan`, `routing_metadata`, out-of-allowlist MTP fields
- Truth/Done-disabled policy path matches no-evaluation baseline
- `MI_INCOMP` unresolved slots → not `DONE` when policy requires satisfaction
