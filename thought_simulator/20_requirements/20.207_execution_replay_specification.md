# 20.207 Execution Replay Specification

**Document ID:** 20.207  
**Version:** 0.1  
**Date:** 2026-06-06  
**Status:** Approved v0.1 — Stage 4 GATE (2026-06-07; CuriousOne23, Copilot, Grok)

## Purpose

Defines normative **Pipeline B regeneration and full-trace replay** semantics — operationalizing equivalence class **E2** from [20.206](20.206_pipeline_a_b_synchronization_contract.md) and HLR-20.012-012 (trace reproducibility).

B artifacts (`exec_plan`, `exec_trace`, XP index) are **derivable evidence**: given frozen committed meaning and published execution tables, an implementation SHALL reproduce equivalent B envelopes without re-running Pipeline A meaning construction.

This module SHALL NOT weaken [20.12_ts_invariants.md](20.12_ts_invariants.md). **E1 meaning strip** (HLR-20.012-011) remains the primary meaning authority test; E2 is a **full-trace fidelity** test.

## 1. Equivalence Classes (Replay Modes)

Three replay modes from 20.206 — this document owns **E2** procedure and pass criteria.

| Mode | ID | Operation | Pass criterion |
|------|-----|-----------|----------------|
| **Strip** | E1 | Remove B envelopes (+ XP index) | `semantic_core` identical to A-only replay |
| **Regenerate** | E2 | Re-run B from frozen meaning + tables + seed | `exec_plan` / `exec_trace` / XP **equivalent** to captured trace |
| **Post-correction** | E3 | Replay after Type B A-cycle | `semantic_core` diffs traceable to `correction_trigger_id` |

1. **HLR-20.207-001:** E1 strip replay SHALL NOT require Pipeline B execution and SHALL NOT use regenerated B artifacts as meaning authority.
2. **HLR-20.207-002:** E2 regeneration replay SHALL execute Pipeline B only against a frozen `semantic_snapshot_ref` identified by `commit_id`.
3. **HLR-20.207-003:** E3 replay SHALL treat post-correction `semantic_core` changes as Pipeline A writes in subsequent cycles; E2 regeneration for cycle **N** SHALL use the pre-correction snapshot unless the fixture explicitly tests post-correction B passes.

## 2. Regeneration Inputs (Mandatory)

E2 regeneration SHALL be a deterministic function of explicit inputs only — no TP, no `lane_id`, no latent state.

### 2.1 Required input tuple

```text
regeneration_input {
  commit_id,
  semantic_snapshot_ref,     // frozen post-mtp_update semantic_core
  cycle_id,
  routing_epoch_id,          // published tables for this epoch
  policy_signature,
  execution_signature,
  seed_scope_ref,              // expression-only per HLR-20.012-010
  published_routing_tables,    // SRP epoch tables (20.55/20.56)
  conversation_id?             // audit scope only
}
```

4. **HLR-20.207-004:** E2 regeneration SHALL reject inputs missing any required field with `REGEN_INPUT_INCOMPLETE`.
5. **HLR-20.207-005:** E2 regeneration SHALL reject `semantic_snapshot_ref` that does not resolve to the `commit_id` index with `REGEN_COMMIT_MISMATCH`.
6. **HLR-20.207-006:** E2 regeneration SHALL reject stale `routing_epoch_id` relative to published tables with `REGEN_STALE_EPOCH` (HLR-20.012-013).
7. **HLR-20.207-007:** E2 regeneration SHALL NOT read TP instances, `tp_id`, or `lane_id` (20.206, 20.105).

### 2.2 Forbidden regeneration shortcuts

| Shortcut | Posture |
|----------|---------|
| Copy original `exec_plan` / `exec_trace` without re-execution | **Invalid** as regeneration — allowed only as fixture baseline compare |
| Re-derive meaning from B artifacts | **Forbidden** — B is not meaning authority |
| Mutate `semantic_core` during regeneration | **Forbidden** |

8. **HLR-20.207-008:** Regeneration implementations SHALL perform B stage replay (`srp_lookup → trig_rb → exec_plan_commit → oub_expression → imr_evaluation` per 20.36 §2.2) or an algorithmically equivalent deterministic replanning path that produces equivalent envelopes.

---

## 3. Regeneration Outputs

9. **HLR-20.207-009:** E2 regeneration SHALL produce regenerated `exec_plan`, `exec_trace`, and `xp_record` bound to the same `commit_id` and `cycle_id` as the input tuple.
10. **HLR-20.207-010:** Regenerated `xp_id` MAY differ from the captured trace `xp_id` (20.205 HLR-20.205-032); equivalence SHALL be evaluated on envelope **content**, not on surrogate IDs.
11. **HLR-20.207-011:** Regenerated envelopes SHALL NOT be written into `semantic_core` or MTP meaning fields.

### 3.1 Equivalence definition

Regenerated artifacts are **equivalent** to captured artifacts when, after canonical serialization (20.95):

| Envelope | Equivalence rule |
|----------|------------------|
| `exec_plan` | Byte-identical OR `plan_equivalence_hash` match (excludes surrogate IDs) |
| `exec_trace` | Entry-wise semantic equivalence: same stage outcomes, `imr_record` taxonomy, reason codes; surrogate `imr_event_id` MAY differ if content hash matches |
| `xp_record` | Same `commit_id`, `cycle_id`, `xp_pass_seq` history semantics, matching exec refs content |

12. **HLR-20.207-012:** PoC harnesses SHALL implement at minimum **byte-identical** comparison for `exec_plan`; `exec_trace` MAY use content-hash equivalence with documented excluded surrogate fields (open D12).
13. **HLR-20.207-013:** Regeneration equivalence failure SHALL emit `replay_verdict = FAIL_REGEN_DIFF` with deterministic diff artifact path (20.36 verdict family extension).

## 4. Regeneration Procedure (Logical)

```text
1. Load semantic_snapshot_ref for commit_id (read-only)
2. Validate routing_epoch_id against published tables
3. Bind seed_scope_ref (expression-only)
4. Execute B stages in 20.36 order
5. Materialize exec_plan, exec_trace, xp_record
6. Compare to captured baseline (if fixture provides baseline)
7. Emit regen_verdict
```

14. **HLR-20.207-014:** Regeneration SHALL NOT skip IMR evaluation when the captured baseline includes IMR stages unless the fixture marks `imr_eval_excluded = true` with fixed reason code.
15. **HLR-20.207-015:** Type A IMR retry passes SHALL regenerate with matching `xp_pass_seq` count and equivalent per-pass `exec_plan` content (20.205 §6).
16. **HLR-20.207-016:** Type B `CorrectionTrigger` artifacts in `exec_trace` SHALL regenerate identically for the originating cycle; regeneration SHALL NOT apply Type B corrections to `semantic_core` (E3 is a separate A-cycle replay).

## 5. Relationship to 20.36 Replay Classes (Resolves OQ-005)

| Artifact | Role |
|----------|------|
| **20.207** (this document) | **Standalone normative** spec for E2 regeneration inputs, procedure, equivalence |
| **20.36 Classes 1–5** | Existing strip (E1) and governance tests — unchanged in Stage 2 |
| **20.36 Class 1 sub-assertion** | PoC **minimum**: add optional `b_regeneration_equivalent` on Class 1 happy path |
| **20.36 Class 6** (proposed) | **Optional** full E2 suite — Stage 4 addition to 20.36, not required for PoC gate |

17. **HLR-20.207-017:** PoC acceptance SHALL require E1 strip pass on 20.36 Classes 1–5 per existing HLR-20.036-016; E2 regeneration pass SHALL be required on at least **one** Class 1 golden fixture via `b_regeneration_equivalent` sub-assertion traced to this document.
18. **HLR-20.207-018:** A dedicated `REPLAY_CLASS_6` full regeneration suite MAY be added to 20.36 in Stage 4; it SHALL NOT be mandatory for initial PoC if HLR-20.207-017 is satisfied.
19. **HLR-20.207-019:** Strip scope for E1 SHALL remain `[exec_plan, exec_trace]` (and `xp_record` per 20.205); regeneration scope SHALL include all B envelopes but SHALL exclude `semantic_core` body comparison except identity check that input snapshot is unchanged.

### 5.1 Class 1 sub-assertion (PoC minimum)

```yaml
fixture_id: REPLAY_C1_HAPPY_DUAL_PIPELINE
replay_class: REPLAY_CLASS_1
assertions:
  - semantic_core_replay_equivalent      # E1 — existing
  - b_regeneration_equivalent            # E2 — new sub-assertion (20.207)
regeneration_input:
  commit_id: <from mtp_update>
  semantic_snapshot_ref: <frozen>
  routing_epoch_id: <epoch>
  seed_scope_ref: <seed>
```

20. **HLR-20.207-020:** The `b_regeneration_equivalent` assertion SHALL execute: capture baseline B envelopes → strip → regenerate from `regeneration_input` → compare per §3.1.

## 6. Seed and Epoch Boundaries

21. **HLR-20.207-021:** Identical `seed_scope_ref` and `routing_epoch_id` with identical `regeneration_input` SHALL produce equivalent regenerated B envelopes (determinism).
22. **HLR-20.207-022:** Different `seed_scope_ref` with identical frozen `semantic_snapshot_ref` SHALL produce different `exec_trace` expression selections where seed-bound AND SHALL produce identical `semantic_core` when stripped (HLR-20.012-010).
23. **HLR-20.207-023:** Different `routing_epoch_id` (with valid published tables) MAY produce different `exec_plan` triples; regeneration SHALL document epoch table version in diff artifacts.

---

## 7. IMR and Supervisory Replay

24. **HLR-20.207-024:** Regenerated `imr_record` entries SHALL preserve `trigger_type`, `evaluator_signal_code`, `correction_trigger_id` presence/absence, and cap status semantics.
25. **HLR-20.207-025:** Regeneration of cycles with Type B triggers SHALL NOT execute the subsequent A correction pass as part of E2; testing E3 requires a separate A-cycle replay fixture.
26. **HLR-20.207-026:** Regenerated supervisory trigger queue entries SHALL be equivalent in effect class and target fields; GB approval flags SHALL match captured baseline.

## 8. Verdict Taxonomy

Extends 20.36 `replay_verdict` for regeneration:

| Verdict | Meaning |
|---------|---------|
| `PASS` | E1 strip and/or E2 regeneration satisfied |
| `FAIL_REGEN_DIFF` | Regenerated B envelopes not equivalent |
| `FAIL_REGEN_INPUT` | Invalid or incomplete `regeneration_input` |
| `FAIL_REGEN_EPOCH` | Stale or missing routing epoch tables |
| `FAIL_REGEN_FORBIDDEN_READ` | Regeneration path read TP / `lane_id` |

27. **HLR-20.207-027:** Harnesses implementing E2 SHALL emit one of the above verdicts with fixed reason codes for CI export.

---

## 9. Negative Fixtures (Minimum)

28. **HLR-20.207-028:** Negative fixture `REGEN_NO_COMMIT` — regeneration without resolvable `commit_id` → `FAIL_REGEN_INPUT`.
29. **HLR-20.207-029:** Negative fixture `REGEN_TP_READ` — regeneration path consumes `tp_id` → `FAIL_REGEN_FORBIDDEN_READ`.
30. **HLR-20.207-030:** Negative fixture `REGEN_STALE_EPOCH` — unpublished `routing_epoch_id` → `FAIL_REGEN_EPOCH`.

---

## 10. Verification Focus

- Class 1 happy path: E1 strip + `b_regeneration_equivalent` (PoC minimum)
- Seed variant: regen differs in `exec_trace`, strip identical `semantic_core`
- Type A retry fixture: `xp_pass_seq` > 0 regenerates with per-pass plan equivalence
- IMR Type B cycle: regen preserves trigger in `exec_trace`; no `semantic_core` mutation in E2
- Zero `lane_id` in regeneration inputs and outputs
