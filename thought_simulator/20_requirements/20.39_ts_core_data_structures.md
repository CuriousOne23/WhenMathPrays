# 20.39 TS Core Data Structures

**Document ID:** 20.39  
**Version:** 0.2  
**Date:** 2026-06-04  
**Status:** Draft - For CP Review

## Purpose
This document provides **guidance** on core data structures to support consistent and effective prototyping in the 40-series. It aims to inform final decisions in the 10-series once prototyping insights are available.

## Role in the Development Flow
This document serves as **guidance only**. Its primary purpose is to direct exploration and experimentation in the 40-series. Discoveries, trade-offs, and challenges identified here will help mature the canonical definitions in the 10-series.

## Non-Goals
- This is **not** the final data structure specification.
- It does not override semantic requirements defined in 20.31.
- Exact memory layouts, optimizations, and implementation details belong in the 50-series design phase.

## Core Structure Guidance

**HLR-20.039-001:** 40-series prototypes SHOULD implement MTP as the central meaning container, incorporating the key fields outlined in 20.31 Semantic Specification.

**HLR-20.039-002:** TP SHOULD be implemented as a lightweight, lane-specific projection or view derived from the MTP.

**HLR-20.039-003:** IB SHOULD include rich metadata (priority, uncertainty, ΔH% trajectory, lineage, evidence accumulation, etc.) to enable effective GB population control.

**HLR-20.039-004:** OB, RB, and TB SHOULD be designed to satisfy the semantic contracts defined in 20.31 and their respective component documents.

**HLR-20.039-005:** GB state SHOULD remain minimal, focused strictly on supervisory responsibilities (no direct meaning construction).

## Design Guidance for 40-series

**HLR-20.039-006:** Prototypes SHOULD explore the use of immutable structures for stability-critical components.

**HLR-20.039-007:** Lineage and provenance tracking SHOULD support efficient deterministic replay and auditing.

**HLR-20.039-008:** Safety policy structures (especially RB) SHOULD enable fast lookup and clear violation reporting.

**HLR-20.039-009:** All major structures SHOULD support deterministic serialization for debugging and traceability.

## Exploration Directives for 40-series
- Evaluate trade-offs between memory efficiency, clarity, and performance.
- Test different approaches to immutability and versioning.
- Document challenges in maintaining full determinism while achieving acceptable runtime characteristics.
- Identify any semantic fields from 20.31 that prove difficult to implement efficiently or clearly.
- Capture lessons learned regarding data structure design for later incorporation into the 10-series.
