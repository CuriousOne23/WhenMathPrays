# 20.39 TS Core Data Structures

**Document ID:** 20.39  
**Version:** 0.1  
**Date:** 2026-06-04  
**Status:** Draft - For CP Review

## Purpose
This document defines the core data structures required to implement the Thought Simulator in a consistent, efficient, and semantically correct manner.

## Scope
Covers primary structures: TP, MTP, IB, OB, RB, TB, GB state, buffers, and supporting types.

## Core Structures

### Master Thought Packet (MTP)

**HLR-20.039-001:** MTP SHALL be the central meaning container with the fields defined in 20.31 Semantic Specification.

**HLR-20.039-002:** MTP SHALL include:
- propositions, stance, affect, intent
- delta_h (with missing_mass accounting)
- lineage, semantic_tags, truth_hypotheses
- done_state, stability_metadata, overflow_metadata
- tr_needs_update flag

### Thought Packet (TP)

**HLR-20.039-003:** TP SHALL be a lightweight, lane-specific view derived from MTP.

**HLR-20.039-004:** TP SHALL contain local projections, evidence fields, and temporary computation state.

### Inquiry Buffer (IB)

**HLR-20.039-005:** IB SHALL represent an active inquiry with full metadata (priority, uncertainty, ΔH% trajectory, lineage, etc.).

**HLR-20.039-006:** IB population SHALL be managed exclusively by GB per 20.10 and 20.16.

### Output Buffer (OB), Request Buffer (RB), Thought Buffer (TB)

**HLR-20.039-007:** OB, RB, and TB SHALL follow the semantics and field requirements defined in 20.31 and component-specific documents (20.40, 20.50, 20.60).

### Global Brain (GB) State

**HLR-20.039-008:** GB state SHALL be minimal and supervisory only (no direct meaning construction).

**HLR-20.039-009:** GB SHALL maintain active population counts, coherence metrics, and commitment queues.

### Supporting Structures

**HLR-20.039-010:** All structures SHALL support deterministic serialization for replay and debugging.

**HLR-20.039-011:** Memory layout SHALL prefer contiguous blocks and cache-friendly access patterns where performance is critical.

**HLR-20.039-012:** Immutable data SHALL be used liberally for stability and thread safety.

## Relationship and Safety Structures

**HLR-20.039-013:** RB SHALL maintain efficient lookup structures for safety policy enforcement.

**HLR-20.039-014:** Lineage and provenance chains SHALL be implemented as immutable linked structures or versioned trees.
