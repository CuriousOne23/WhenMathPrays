# 20.168 RPU — Realization Production Unit Primitive

## Purpose

RPU is the execution primitive for Path B. It accepts the ordered realization plan
`tp.rplan` from RPlan, executes each step in index order using continuity-weighted
execution logic, and produces a typed partial realization `tp.rpu_partial` and
realization-layer update fields for consumption by OuBB. RPU performs no planning,
no meaning interpretation, and no scoring; it executes exactly what RPlan specified.

**[HLR-20.168-001]** The RPU primitive SHALL accept `tp.rplan` as its activation
input and SHALL produce `tp.rpu_partial` and all realization-layer update fields
required by OuBB before OuBB begins execution for the same turn.

## Input Contract

The table below defines all inputs RPU reads. No other TP field, external store, or
runtime service may be accessed during RPU execution.

| Field | Source Primitive | Required | Type | Validity Constraint |
|---|---|---|---|---|
| `tp.rplan` | RPlan | Required | structured object | must be present; `rplan_status` ∈ {`VIABLE`, `BLOCKED`} |
| `tp.rplan.rplan_status` | RPlan | Required | enum | `VIABLE` or `BLOCKED`; any other value is a pre-condition fault |
| `tp.rplan.ordered_steps` | RPlan | Required | array | non-null; may be empty only when `rplan_status = BLOCKED` |
| `tp.rplan.ordered_steps[i].step_id` | RPlan | Required | string | non-empty; unique within the array |
| `tp.rplan.ordered_steps[i].index` | RPlan | Required | integer | $i \geq 1$; array must be monotonically increasing in `index` |
| `tp.rplan.ordered_steps[i].constraint_set` | RPlan | Required | set of field refs | may be empty; each ref must name a valid TP field |
| `tp.rplan.ordered_steps[i].continuity_weight` | RPlan | Required | float | $\omega_i \in [0, 1]$ |
| `tp.rplan.ordered_steps[i].step_status` | RPlan | Required | enum | ∈ {`VIABLE`, `BLOCKED`} |
| `tp.continuity_fields` | CoHI | Required | structured object | must be present; used during exec weight application |
| `tp.truth_tags` | A-side | Required | array | may be empty |
| `tp.safety_flags` | A-side | Required | array | may be empty |

**[HLR-20.168-002]** The RPU primitive SHALL read only the fields enumerated in the
Input Contract table; it SHALL NOT read from COB, from any meaning-layer field, or
from any realization substrate field written by REx.

**[HLR-20.168-003]** The RPU primitive SHALL perform a pre-condition check before
execution begins: if `tp.rplan` is absent, if `tp.rplan.rplan_status` is not a
recognised enum value, or if `tp.rplan.ordered_steps` is null when
`rplan_status = VIABLE`, RPU SHALL set `tp.rpu_partial.rpu_status` to `ABORTED`,
SHALL write `reason_code = PRE_CONDITION_FAULT`, and SHALL halt without executing
any step.

## Transfer Function

### Abort Path

When `tp.rplan.rplan_status = BLOCKED` on entry (and the pre-condition check passes),
RPU takes the abort path: no steps are executed.

**[HLR-20.168-004]** When `tp.rplan.rplan_status = BLOCKED`, the RPU primitive SHALL
set `tp.rpu_partial.rpu_status` to `ABORTED`, SHALL propagate `tp.rplan.reason_code`
into `tp.rpu_partial.reason_code`, SHALL mark all step records as `SKIPPED`, and
SHALL NOT execute any realization step.

### Execution Path

When `tp.rplan.rplan_status = VIABLE`, RPU applies the following ordered execution
loop.

Let $S = \langle s_1, s_2, \dots, s_k \rangle$ be `tp.rplan.ordered_steps` sorted
by ascending `index`. Each step $s_i$ carries constraint set $C_i$ and continuity
weight $\omega_i \in [0, 1]$.

The resolved field set after executing $j$ steps is:

$$
\text{resolved}(j) = \bigcup_{i=1}^{j} \text{fields}\ \left(\text{exec}(s_i,\  \omega_i)\right)
$$

A step $s_j$ is blocked when its constraint set is not satisfied by the fields
resolved so far:

$$
\text{blocked}(s_j) = C_j \not\subseteq \text{resolved}(j - 1)
$$

Execution halts at the first blocked step, or completes if none is blocked:

$$
j^* = \begin{cases}
\min\{\ j \mid \text{blocked}(s_j)\,\} & \text{if any step is blocked} \\
k + 1 & \text{otherwise}
\end{cases}
$$

The accumulated partial realization delivered to OuBB is:

$$
P = \bigoplus_{i=1}^{\min(j^*-1,\; k)} \text{exec}(s_i,\ \omega_i)
$$

where $\oplus$ is the realization accumulation operator and each
$\text{exec}(s_i, \omega_i)$ applies `tp.continuity_fields` to weight the
contribution of step $s_i$.

**[HLR-20.168-005]** The RPU primitive SHALL execute steps in strictly ascending
`index` order; it SHALL NOT execute step $s_j$ before steps $s_1, \ldots, s_{j-1}$
have each completed or been marked `HALTED`.

**[HLR-20.168-006]** The RPU primitive SHALL apply the continuity weight $\omega_i$
supplied by RPlan to each call to $\text{exec}(s_i, \omega_i)$; it SHALL NOT
substitute, override, or recompute $\omega_i$ from `tp.continuity_fields` directly.

**[HLR-20.168-007]** Upon detecting $\text{blocked}(s_{j^*}) = \text{true}$, the
RPU primitive SHALL immediately set the step record for $s_{j^*}$ to `HALTED`, SHALL
set `tp.rpu_partial.rpu_status` to `HALTED`, SHALL write `reason_code` identifying
the unsatisfied constraint, and SHALL mark all subsequent steps
$s_{j^*+1}, \ldots, s_k$ as `SKIPPED`.

The `rpu_status` value is determined by the outcome of the execution path:

$$
\text{rpu\_status} = \begin{cases}
\texttt{ABORTED}  & \text{if } \texttt{rplan\_status} = \texttt{BLOCKED} \text{ or pre-condition fault} \\
\texttt{HALTED}   & \text{if } j^* \leq k \\
\texttt{COMPLETE} & \text{if } j^* = k + 1
\end{cases}
$$

## Output Contract

The table below defines all fields RPU writes. OuBB must treat any field not listed
here as unmodified by RPU.

| Field | Type | Legal Values | Semantics |
|---|---|---|---|
| `tp.rpu_partial.rpu_status` | enum | `COMPLETE`, `HALTED`, `ABORTED` | Overall execution outcome for the turn |
| `tp.rpu_partial.reason_code` | string | non-empty on `HALTED` or `ABORTED`; empty string on `COMPLETE` | Machine-readable cause of non-completion |
| `tp.rpu_partial.accumulated` | structured object | $P$ as defined in §Transfer Function | Partial realization result consumed by OuBB |
| `tp.rpu_partial.step_records[i].step_id` | string | mirrors `tp.rplan.ordered_steps[i].step_id` | Identifies which plan step this record covers |
| `tp.rpu_partial.step_records[i].step_status` | enum | `DONE`, `HALTED`, `SKIPPED` | Per-step execution outcome |
| `tp.rpu_partial.step_records[i].exec_result` | structured object | populated on `DONE`; null on `HALTED` or `SKIPPED` | Realization contribution of the step |
| Realization-layer update fields | per OuBB input contract | defined by OuBB input contract | Fields OuBB reads to assemble final output |

**[HLR-20.168-008]** The RPU primitive SHALL populate all fields in the Output
Contract table for every execution path (`COMPLETE`, `HALTED`, and `ABORTED`); no
output field SHALL be left absent or null except where the table explicitly permits null.

**[HLR-20.168-009]** The RPU primitive SHALL NOT write to any meaning-layer field
owned by LI, any realization substrate field owned by REx, any plan field owned by
RPlan, or any representation-layer field owned by TPTB, TPSF, or CoHI.

## When

RPU runs once per turn. Its position in the Path B execution order is fixed: after
RPlan has committed `tp.rplan` and before OuBB reads `tp.rpu_partial`.

**[HLR-20.168-010]** The RPU primitive SHALL NOT begin execution until RPlan has
written `tp.rplan` to a completed state for the current turn, as indicated by
`tp.rplan.rplan_status` holding a recognised enum value.

**[HLR-20.168-011]** The RPU primitive SHALL complete all writes to `tp.rpu_partial`
and all realization-layer update fields before OuBB begins execution for the same turn.

## Why

RPlan constructs a sequenced, constraint-annotated plan but does not execute it.
Separating plan construction (RPlan) from plan execution (RPU) means each primitive
has a single, auditable responsibility. OuBB needs a fully realized partial — not a
plan — and RPU is the primitive that bridges that gap. The typed output contract
ensures OuBB can validate what it receives before producing final output, making the
entire realization chain traceable step by step.

## Is Not

RPU is not a meaning extractor.
RPU is not a semantic interpreter.
RPU is not a planner; it executes the plan RPlan constructed and does not alter it.
RPU is not a scorer.
RPU is not a router.
RPU is not a memory system.
RPU is not RPlan; it executes the plan RPlan constructed but does not modify it.
RPU is not OuBB; it produces `tp.rpu_partial` but does not generate final output.

## Example

RPlan has committed `tp.rplan` with `rplan_status = VIABLE` and three steps:

- $s_1$: `step_id = "confirm-referent"`, $C_1 = \emptyset$, $\omega_1 = 0.88$
- $s_2$: `step_id = "apply-register"`, $C_2 = \{\texttt{tp.meaning}\}$, $\omega_2 = 0.91$
- $s_3$: `step_id = "emit-tokens"`, $C_3 = \{\texttt{confirm-referent},\, \texttt{apply-register}\}$, $\omega_3 = 0.85$

Pre-condition check passes. `rplan_status = VIABLE`. Execution path begins.

RPU executes $s_1$: $C_1 = \emptyset$ is trivially satisfied;
$\text{exec}(s_1, 0.88)$ succeeds; step record set to `DONE`; `resolved(1)` now
includes `confirm-referent`.

RPU executes $s_2$: $C_2 = \{\texttt{tp.meaning}\}$; `tp.meaning` was written by LI
and is in `resolved(1)` via the TP field set; $\text{exec}(s_2, 0.91)$ applies
formal register weighting; step record set to `DONE`; `resolved(2)` includes
`apply-register`.

RPU executes $s_3$: $C_3 \subseteq \text{resolved}(2)$; $\text{exec}(s_3, 0.85)$
accumulates surface token payload into $P$; step record set to `DONE`.

No step is blocked, so $j^* = 4$ and `rpu_status = COMPLETE`. OuBB reads
`tp.rpu_partial.accumulated` = $P$, all three step records `DONE`, and proceeds to
final output assembly with no further interpretation.
