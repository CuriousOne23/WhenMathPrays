# 20.38 TS Implementation Guidelines

**Document ID:** 20.38  
**Version:** 0.4  
**Date:** 2026-06-06  
**Status:** CP-approved — dual-pipeline prototyping guidance (v0.3 refinements applied)

## Purpose

Provides **practical guidance** for 40-series playground prototypes and early implementation efforts. Bridges architectural principles (20.10), invariants (20.12), and the functional model (20.30) into actionable coding directions under the **dual-pipeline** architecture.

Identifies areas requiring validation before finalizing 10-series canonical specs.

## Role in the Development Flow

**Guidance only** — directs 40-series exploration. Lessons learned inform 10-series refinements. Normative behavior remains in 20.12 and hardened modules (20.17, 20.45, 20.16, 20.80, 20.36); this document does not override them.

## Parent Scope

- **Informs:** 40-series prototypes, replay harnesses, PoC acceptance
- **Companion:** struct layout in [20.39_ts_core_data_structures.md](20.39_ts_core_data_structures.md)
- **Does not modify:** 20.10, 20.12, 20.20, 20.30 bootstrap documents

## Non-Goals

- Final implementation specification (10-series)
- Exact algorithms (20.35)
- Final data structures (20.39)
- Override of 20.31 semantic requirements

## 1. Dual-Pipeline Implementation Patterns

11. **HLR-20.038-011:** Prototypes SHOULD implement Pipeline A (meaning construction) and Pipeline B (Execution Manifold) as **separate code paths** with an explicit handoff at `mtp_update` → `srp_lookup`, per 20.30 HLR-20.030-322–324.

12. **HLR-20.038-012:** Pipeline B SHOULD consume `semantic_core` as a **read-only snapshot**; prototypes SHOULD NOT pass mutable MTP references into realization planning or expression modules.

21. **HLR-20.038-021:** Pipeline A SHOULD NOT read `exec_plan` or `exec_trace` for meaning construction, basin routing, or Thought Router derivation; the only Pipeline B → Pipeline A consumption path SHOULD be explicit, bounded `CorrectionTrigger` queue intake per HLR-20.012-014.

13. **HLR-20.038-013:** IMR feedback into Pipeline A SHOULD use explicit `CorrectionTrigger` queue consumption — never direct writes to meaning fields from Pipeline B code paths.

14. **HLR-20.038-014:** SRP compilation SHOULD run off the per-turn hot path; hot-path code SHOULD perform table lookup only against published `routing_epoch_id` tables (HLR-20.012-006).

---

## 2. Envelope Write Guards

15. **HLR-20.038-015:** Prototypes SHOULD enforce [20.12](20.12_ts_invariants.md) write-authority at module boundaries: `semantic_core` (A only), `exec_plan` + `exec_trace` (B only), `supervisory` (GB only).

16. **HLR-20.038-016:** Harness and debug builds SHOULD fail fast on cross-envelope writes; violations SHOULD map to `replay_verdict = FAIL_ENVELOPE` per [20.36](20.36_canonical_end_to_end_trace.md).

17. **HLR-20.038-017:** Module logic SHOULD own policy and transitions; core structs SHOULD be **data-only** per [HLR-20.039-020](20.39_ts_core_data_structures.md) — no embedded behavior, callbacks, or implicit policy in container types.

---

## 3. Phase Ordering and Safe Boundaries

1. **HLR-20.038-001:** Prototypes SHOULD use a modular, layered architecture reflecting 20.10 separation of concerns.

2. **HLR-20.038-002:** Prototypes SHOULD separate deterministic core logic from non-deterministic layers (expression selection, seed-driven output, UI).

3. **HLR-20.038-003:** Exploration SHOULD validate that meaning-state mutation occurs only through explicit, typed Pipeline A primitive operators.

4. **HLR-20.038-004:** Prototypes SHOULD implement strict fixed phase ordering per 20.36 stage sequences; GB intervention SHOULD apply only at enumerated safe boundaries — not mid-phase.

5. **HLR-20.038-005:** 40-series code SHOULD prioritize auditability, debuggability, and full deterministic replay from `(input, prior_MTP, seed, routing_epoch_id, policy_signature)`.

6. **HLR-20.038-006:** Conflicts between 20-series guidance and prototype reality SHOULD be documented for 10-series resolution with trace IDs and reproduction fixtures.

## 4. Governance Module Integration

Prototypes SHOULD wire hardened modules at these integration points:

| Module | Integration point | Implementation note |
|--------|-------------------|---------------------|
| 20.17 Messy input | InB, OB, TB, Merge | Classify at safe boundaries; never smooth in OuB |
| 20.45 IMR | Post-OuB evaluation | Type A/B/C paths; cap/cooldown counters in `exec_trace` |
| 20.16 GB caps | GB evaluation pass | Per-cycle counters; deferred queue at cap exceed |
| 20.80 GB policy | GB + external iface | Rate limits before caps; mode state machine |

18. **HLR-20.038-018:** Messy-input classifiers SHOULD run in fixed detector order (CONTRA → VAGUE → AFFECT → INCOMP → NOISE) per 20.17; exported `messy_input_class[]` SHOULD use canonical lexicographic sort.

19. **HLR-20.038-019:** GB prototypes SHOULD NOT advance `routing_epoch_id`, mutate messy-input tags, or read OuB artifacts for IB/arbitration decisions (20.16/20.80 dual-pipeline rules).

---

## 5. Replay Harness (20.36)

9. **HLR-20.038-009:** Prototypes SHOULD build deterministic replay capability **early** — before adding governance complexity.

20. **HLR-20.038-020:** PoC harnesses SHOULD implement all five replay test classes (`REPLAY_CLASS_1` through `REPLAY_CLASS_5`) with golden fixtures, `strip_scope`, and `replay_verdict` export before claiming Execution Manifold conformance.

**Minimum harness checklist:**

- Class 1: strip `exec_plan` + `exec_trace` → `semantic_core` diff vs A-only baseline
- Class 2: overflow tags + messy-input preservation
- Class 3: IMR Type A/B/C paths + pre-correction strip checkpoint
- Class 4: GB cap + rate-limit independent enforcement
- Class 5: multi-cycle segmented fixture with `strip_checkpoint`

---

## 6. Recommended Practices for 40-series

7. **HLR-20.038-007:** Use strong typing and explicit contracts between pipelines, envelopes, and basin modules.

8. **HLR-20.038-008:** Implement structured logging with fixed `deterministic_reason_codes` at every stage record (20.36 §2.3).

10. **HLR-20.038-010:** Evaluate performance vs. clarity trade-offs; prefer clarity until replay classes 1–3 pass.

22. **HLR-20.038-022:** `lineage[]` and other provenance arrays SHOULD use deterministic canonical ordering before serialization — `(module_id, tp_seq, lineage_seq)` per [HLR-20.039-019](20.39_ts_core_data_structures.md) and 20.95 — so replay diffs remain stable.

**Additional practices:**

- Canonical-serialize all snapshot diffs per [20.95_ts_numeric_policy.md](20.95_ts_numeric_policy.md) (Q32.32 authoritative fields)
- Log `routing_epoch_id` on every Pipeline B commit; reject stale-epoch consumption
- Seed variability confined to expression/realization paths (HLR-20.012-010)
- Append-only `exec_trace` and `supervisory` logs — no in-place mutation of prior records

---

## 7. Anti-Patterns (Avoid in 40-series)

| Anti-pattern | Why it fails |
|--------------|--------------|
| OuB writes stance/goals into `semantic_core` | Breaks HLR-20.012-011 strip replay |
| IMR directly patches MTP fields | Violates HLR-20.012-009 trigger-only IMR |
| GB stores meaning in supervisory blob | GB god-module risk (20.10-099) |
| Combined `exec_plan` + `exec_trace` struct | Violates HLR-20.012-004 |
| TP carries `routing_epoch_id` | Couples meaning layer to execution epoch (20.39-018) |
| Latent inference in messy-input or GB paths | Forbidden in 20.17, 20.16, 20.80 |
| Pipeline A reads `exec_plan` / `exec_trace` for routing | Violates HLR-20.038-021 / HLR-20.012-014 |
| Behavior or policy embedded in structs | Violates HLR-20.039-020; use module logic |

---

## 8. Exploration Directives for 40-series

- Implement envelope write guards before optimizing performance.
- Map each replay class to at least one runnable golden fixture (20.36 YAML stubs → concrete harness cases).
- Test Pipeline A → B snapshot handoff with immutable `semantic_core` copies.
- Document TCU/overflow behavior when global bounds trip (Class 2).
- Prototype deferred-queue drain and cap-counter reset at cycle boundaries (20.16/20.80).
- Feed back 20.31 fields that are hard to represent cleanly (→ 10-series).
- Capture module-boundary diagrams showing which files own which envelope writers.
- Enforce Pipeline A read boundary: no imports of `exec_plan` / `exec_trace` in meaning-construction modules (HLR-20.038-021).
- Sort `lineage[]` canonically before golden-fixture export (HLR-20.038-022).
