# 20.38 TS Implementation Guidelines

**Document ID:** 20.38  
**Version:** 0.2  
**Date:** 2026-06-04  
**Status:** Draft - For CP Review

## Purpose
This document provides **practical guidance** for the 40-series playground prototypes and future implementation efforts. It helps bridge the architectural principles (20.10) and functional model (20.30) into actionable coding directions, while identifying areas that need validation before finalizing the 10-series.

## Role in the Development Flow
This document serves as **guidance only**. Its primary purpose is to direct exploration in the 40-series. Lessons learned, challenges discovered, and successful patterns found here will inform refinements and decisions in the 10-series (canonical requirements).

## Non-Goals
- This is **not** the final implementation specification.
- It does not define exact algorithms (see 20.35).
- It does not define final data structures (see 20.39).
- It does not override semantic requirements in 20.31.

## Key Implementation Guidance

**HLR-20.038-001:** 40-series prototypes SHOULD explore a modular, layered architecture that reflects the separation of concerns defined in 20.10.

**HLR-20.038-002:** Prototypes SHOULD demonstrate clear separation between deterministic core logic and non-deterministic layers (output, randomness, UI).

**HLR-20.038-003:** Exploration SHOULD validate that all state mutation occurs only through explicit, typed primitive operators.

**HLR-20.038-004:** Prototypes SHOULD test strict fixed phase ordering with well-defined safe boundaries for GB intervention.

**HLR-20.038-005:** Code written in the 40-series SHOULD prioritize auditability, debuggability, and full deterministic replay from seed + input.

**HLR-20.038-006:** Any conflicts or practical difficulties discovered between 20-series guidance and real implementation SHOULD be documented for 10-series resolution.

## Recommended Practices for 40-series

**HLR-20.038-007:** Use strong typing and explicit contracts in prototypes.

**HLR-20.038-008:** Implement structured logging with traceable reason codes.

**HLR-20.038-009:** Build deterministic replay capability early in prototyping.

**HLR-20.038-010:** Evaluate performance vs. clarity trade-offs and document findings.

## Exploration Directives for 40-series
- Test different modular structures and layering approaches.
- Identify which principles from 20.10 are straightforward to implement and which are challenging.
- Document efficiency, memory usage, and complexity observations.
- Highlight any areas where the current 20-series guidance needs clarification or adjustment for the 10-series.
