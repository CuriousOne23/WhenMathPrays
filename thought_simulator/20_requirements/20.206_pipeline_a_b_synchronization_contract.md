# 📄 **20.206 Pipeline A↔B Synchronization Contract**  
**Document ID:** 20.206  
**Version:** 0.3 (Strengthened Rewrite)  
**Date:** 2026‑06‑17  
**Status:** Approved — Modernized, Strengthened, Reviewer‑Ready  
**Authority:** This module owns the normative A↔B boundary, freeze semantics, commit_id authority, B read/write sets, determinism boundary, equivalence classes, and B→A return‑path limits.

---

# **0. Purpose**

This module defines the **synchronization contract** between **Pipeline A (meaning construction)** and **Pipeline B (realization)**. It establishes:

- when meaning is frozen  
- how `commit_id` identifies the authoritative semantic snapshot  
- what Pipeline B may read  
- what Pipeline B may write  
- what Pipeline B is forbidden from accessing  
- determinism and replay boundaries  
- equivalence classes (E1/E2/E3)  
- IMR return‑path limits  

This module SHALL govern all A↔B interactions and SHALL NOT be weakened by any sibling module.

---

# **1. Cycle Topology and Phase Ordering**

Pipeline A constructs meaning.  
Pipeline B realizes meaning.  
The boundary between them is **`mtp_update` → commit_id → freeze**.

### **Requirements**

**HLR‑20.206‑001**  
Pipeline A SHALL complete meaning construction, including Merge, Truth/Done, and all semantic updates, before emitting `mtp_update`.

**HLR‑20.206‑002**  
Every `mtp_update` SHALL emit exactly one `commit_id` that uniquely identifies the frozen `semantic_core` snapshot for that cycle.

**HLR‑20.206‑003**  
Pipeline B SHALL NOT begin realization for a cycle until a valid `commit_id` and frozen `semantic_snapshot_ref` are available.

**HLR‑20.206‑004**  
Pipeline B SHALL execute at most one primary realization pass per (`commit_id`, `cycle_id`), except when an IMR Type A retry authorizes a same‑snapshot re‑run using the same XP record.

**HLR‑20.206‑005**  
Pipeline B SHALL NOT use lane parallelism, TP instances, or lane‑local provenance as structural inputs.

---

# **2. Freeze Contract**

After `mtp_update`, the `semantic_core` snapshot is **frozen** for the referenced `commit_id`.

### **Requirements**

**HLR‑20.206‑006**  
For a given `commit_id`, Pipeline B SHALL treat the referenced `semantic_core` snapshot as read‑only for the duration of the B pass.

**HLR‑20.206‑007**  
Pipeline B SHALL NOT modify, patch, smooth, reinterpret, or retroactively revise any field in the frozen snapshot.

**HLR‑20.206‑008**  
Pipeline A SHALL NOT emit a second `mtp_update` for the same cycle after Pipeline B has begun realization for that cycle’s `commit_id`.

**HLR‑20.206‑009**  
Any attempt to start Pipeline B without a resolvable post‑commit `semantic_snapshot_ref` SHALL fail deterministically with reason code `B_START_WITHOUT_COMMIT`.

---

# **3. Allowed and Forbidden Inputs to Pipeline B**

Pipeline B consumes only the frozen meaning envelope and approved metadata.

### **Allowed Inputs**

**HLR‑20.206‑010**  
Pipeline B MAY read the following fields from the frozen snapshot:  
- `propositions[]`, `stance`, `goals[]`, `delta_h`  
- `truth_hypotheses`, `done_state`  
- `messy_input_record` (read‑only)  
- `policy_signature`, `execution_signature`  
- `routing_epoch_id`  
- any field explicitly marked as part of the committed meaning envelope

### **Forbidden Inputs**

**HLR‑20.206‑011**  
Pipeline B SHALL NOT read:  
- TP instances or `tp_id`  
- `lane_id`  
- lane‑local provenance  
- routing metadata from RB  
- uncommitted merge drafts  
- DCB geometry  
- TR ephemeral state  
- any pre‑commit or pre‑merge structure

**HLR‑20.206‑012**  
Any B read referencing forbidden inputs SHALL fail with `FAIL_B_FORBIDDEN_TP_READ`.

---

# **4. Pipeline B Output Contract**

Pipeline B produces realization artifacts only.

### **Requirements**

**HLR‑20.206‑013**  
Pipeline B SHALL write only:  
- `exec_plan`  
- `exec_trace`  
- append‑only IMR supervisory triggers  

**HLR‑20.206‑014**  
Every `exec_plan` and `exec_trace` record SHALL carry `commit_id`, `cycle_id`, and `routing_epoch_id`.

**HLR‑20.206‑015**  
XP SHALL serve as a logical index over B artifacts and SHALL NOT introduce a new authoritative state envelope.

**HLR‑20.206‑016**  
Exactly one primary XP record SHALL exist per (`commit_id`, `cycle_id`). IMR Type A retries SHALL increment `xp_pass_seq` on the same record.

---

# **5. Determinism and Replay Boundary**

Pipeline B must be deterministic under fixed conditions.

### **Requirements**

**HLR‑20.206‑017**  
Given a fixed `semantic_snapshot_ref`, fixed `routing_epoch_id`, and fixed seed, Pipeline B SHALL produce deterministic `exec_plan` and `exec_trace` outputs.

**HLR‑20.206‑018**  
Pipeline B logs SHALL be sufficient to replay realization deterministically (E2).

**HLR‑20.206‑019**  
Seed variability SHALL affect realization selection only and SHALL NOT influence the frozen meaning snapshot.

---

# **6. Equivalence Classes (E1, E2, E3)**

### **Requirements**

**HLR‑20.206‑020**  
Meaning equivalence class **E1** SHALL hold: stripping B artifacts from a cycle SHALL yield a `semantic_core` identical to Pipeline A‑only replay.

**HLR‑20.206‑021**  
Full‑trace reproducibility class **E2** SHALL treat B artifacts as derivable evidence, not meaning authority.

**HLR‑20.206‑022**  
Post‑correction meaning class **E3** SHALL apply only in subsequent cycles; same‑cycle IMR SHALL NOT mutate `semantic_core`.

---

# **7. B→A Return Path (IMR)**

Pipeline B may request corrections, but may not modify meaning.

### **Requirements**

**HLR‑20.206‑023**  
IMR MAY enqueue `CorrectionTrigger` entries, but Pipeline A SHALL consume them only in subsequent cycles.

**HLR‑20.206‑024**  
Type B corrections SHALL reference the frozen snapshot consumed by B and SHALL NOT use TP or lane inputs.

**HLR‑20.206‑025**  
Supervisory commands SHALL NOT bypass the freeze contract without emitting append‑only audit evidence.

---

# **8. Ordering and Concurrency Guards**

### **Requirements**

**HLR‑20.206‑026**  
Within a cycle, the ordering SHALL be:  
`mtp_update` → B start → trig_rb → srp_lookup → exec_plan_commit → oub_expression → imr_evaluation.

**HLR‑20.206‑027**  
Any write to `semantic_core` during an active B pass SHALL fail with `FAIL_ENVELOPE_A_WRITE_DURING_B`.

**HLR‑20.206‑028**  
Pipeline B SHALL NOT reference TP or lane‑local structures at any point during realization.

---

# **9. Verification Requirements**

### **Requirements**

**HLR‑20.206‑029**  
Golden fixture: one `commit_id`, one XP, zero lane identifiers in B envelopes.

**HLR‑20.206‑030**  
Negative fixture: B start without `mtp_update` SHALL produce `B_START_WITHOUT_COMMIT`.

**HLR‑20.206‑031**  
Freeze test: any attempted write to `semantic_core` during B SHALL produce `FAIL_ENVELOPE_A_WRITE_DURING_B`.

**HLR‑20.206‑032**  
E1 strip test: removing B artifacts SHALL yield a meaning‑identical snapshot.
