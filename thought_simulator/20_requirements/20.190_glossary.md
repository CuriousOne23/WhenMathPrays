## Purpose

Canonical glossary and **Primitive Intent Catalog** for the refactored 20-series.  
This document is the **intent enforcement layer**: it defines what each component owns, when it runs, and what it is *not* — to prevent authority drift across modules.

Normative HLRs remain in linked 20.xx modules; entries here are descriptive unless explicitly marked otherwise.

**Directory layout:** Runtime-pipeline concept blocks (B0–B8) → 20.01_architecture_map.md.

---

## How to Read This Catalog

Each entry uses a fixed seven-field template:

| Field | Meaning |
|-------|---------|
| **Purpose** | Architectural role: what would be absent without this entry |
| **Focus** | Operational ownership: what this component owns in one sentence |
| **When** | Pipeline A / B / conversation layer / post-TS / pre-A |
| **Why** | The specific problem this entry solves |
| **Is not** | Common confusions (1–3) |
| **Example** | One concrete scenario |
| **Normative home** | Authoritative 20.xx module |

---

## Category Structure

| Category | Suffix | Definition |
|----------|----------|----------|
| **1. Primitives** | -prm | A primitive is a TP‑holding, TP‑reading, and TP‑capable‑of‑modifying atomic operation in the TS pipeline. |
| **2. Processes** | -prc | A process is a pure logic operation (TS‑Level Concept executor) that does not hold or modify the TP. It is executed inside a primitive. |
| **3. Reference Objects** | -ref | Reference objects are data structures used by primitives and processes. They do not hold or modify the TP |
| **4. Governance** | -gov | Audit, correction, safety, and supervisory mechanisms |
| **5. TS-Level Concepts** | -tsc | TS‑Level Concepts are semantic logic layers (meaning inference, scoring logic, routing logic, etc.). They are not blocks and do not appear in flows |

---

## **6. Flow Diagram Rules**

### **Primitive Flow (TP pipeline)**  
Only primitives appear:

```
PrimitiveA-prm → PrimitiveB-prm → PrimitiveC-prm
```

### **Process Flow (conceptual)**  
Must be labeled and must suffix categories:

```
Process Flow:
PrimitiveA-prm
   ↓ reads TP
ProcessName-prc (tsc: ConceptX)
   ↓ returns result
PrimitiveB-prm
   ↓ writes TP
```

### **Mixed Flow (allowed only with explicit labeling)**  
```
Process Flow:
PrimitiveA-prm → ProcessName-prc (tsc: ConceptX) → PrimitiveB-prm
```

# 1. Primitives

---

## InB (Input Basin) — 20.100

- **Purpose:** Provides the deterministic, non-inferential front door for all external signals entering the architecture.
- **Focus:** Deterministic external-signal intake, schema validation, and **non-inferential** surface canonicalization.
- **When:** Pipeline A entry; first deterministic stage after external input.
- **Why:** Normalize wire form and preserve FIFO ordering without guessing user meaning.
- **Is not:** Semantic repair (IIInB); inquiry (IB); truth interpretation (TB); routing authority.
- **Example:** `"teh"` → canonical token; `"Yeah Baby!"` → tagged, not interpreted.
- **Normative home:** 20.100; messy-input classes in 20.17.

---

## IIInB (Input Inference/Repair Basin) — 20.101

- **Purpose:** Applies user-sanctioned shorthand expansions before context extraction, keeping repair rule-bound and auditable.
- **Focus:** Bounded **semantic shorthand repair** via explicit User Semantic Profile (USP) rules.
- **When:** Optional stage `input_semantic_repair`; ordering **InB → IIInB → RB**.
- **Why:** Apply user-approved shorthand expansions deterministically without constructing meaning.
- **Is not:** Interpretation; candidate generation; truth evaluation; meaning construction.
- **Example:** USP rule expands "quicker-ish" → canonical form.
- **Normative home:** 20.101.

---

## CEx (ContextExtractor) — New

- **Purpose:** Bridges global conversation state and the inference path by producing a bounded, replayable context slice for ISc.
- **Focus:** Deterministic extraction of **bounded, relevant, replayable** context from CIL to form the Context Envelope (CE).
- **When:** Inference path: **IIInB → CEx → CE → ISc**.
- **Why:** ISc needs context but cannot read global state directly.
- **Is not:** A semantic interpreter; a meaning constructor; a Thought Packet (TP) writer.
- **Example:** Reads CIL; extracts active referents + lineage + relevant USP entries.
- **Normative home:** 20.33 (CIL), 20.44 (ISc), architecture discussion.

---

## **ISc (Inference Scorer) — 20.44**

- **Purpose:** Performs deterministic scoring of interpretation candidates by executing the **truth_hypotheses‑prc** process over the candidate_set{}, producing stable, auditable scoring fields in the TP without accessing global state.
- **Focus:** Reads CE‑produced candidate_set{}; applies truth_hypotheses‑prc; writes scoring‑layer fields (`tp.score_set`, `tp.score_conflict`, `tp.score_reason_code`) into the TP for downstream routing and TPU commit.
- **When:** Path A inference sequence: **CE‑prm → ISc‑prm → TPU‑prm(Merge process)**. Runs after candidate extraction and before merge/commit.
- **Why:** Ensures that candidate interpretation scoring is deterministic, local, and reproducible, preventing global‑state leakage and ensuring that routing and TPU commit operate on stable, non‑probabilistic scoring data.
- **Is not:** A semantic generator; a meaning constructor; a truth evaluator; a global inference engine; a CIL reader; a semantic repair mechanism; a TS‑level concept.
- **Example:** Given multiple referent candidates extracted by CEx‑prm, ISc‑prm applies truth_hypotheses‑prc to compute deterministic scores and writes the resulting score_set into the TP for TR‑prm to route.
- **Normative home:** 20.44.

## TPU (Thought Packet Updater) — Corrected

- **Purpose:** Acts as the sole safe writer to TP and semantic_core, committing validated semantic updates into durable meaning.
- **Focus:** Deterministic, boundary‑enforced TP updates based strictly on CE+CEx + ISc output; TPU performs no split or merge operations.
- **When:** Inference/correction path: **CE → ISc → TPU → TP(N+1)**.
- **Why:** Preserve the single‑writer invariant; ensure all semantic commits are deterministic, auditable, and free of topology logic.
- **Is not:** A topology engine; a semantic interpreter; a candidate generator; a CIL reader.
- **Example:** ISc selects a corrected referent; TPU applies the change to TP(N), producing TP(N+1) and freezing semantic_core under a new `commit_id`.
- **Normative home:** 20.105, architecture discussion.

---

## IB (Inquiry Basin) — 20.90

- **Purpose:** Manages post-TS ambiguity lifecycle, generating clarification proposals only after meaning is fully committed.
- **Focus:** Post-TS ambiguity detection, inquiry-state evolution, and clarification proposal generation.
- **When:** **Post-TS only**: **TB → IB → GBIB → GB**.
- **Why:** Handle unresolved ambiguity after meaning is fully committed.
- **Is not:** Pipeline A; lane-parallel; semantic repair; TP writer; candidate generator.
- **Example:** IB detects unresolved referent ambiguity and proposes clarification.
- **Normative home:** 20.90 v0.4.

---

## OB (Object Basin) — 20.40

- **Purpose:** Extracts lane‑local structured evidence and enforces object‑identity constraints, issuing mechanical SplitRequest or MergeRequest signals when TP structure violates or satisfies those constraints.
- **Focus:** Lane‑local evidence extraction and identity‑based structural checks; OB may request split/merge operations but does not perform them.
- **When:** Pipeline A `ob_processing`.
- **Why:** Ensure each TP entering the OB is structurally consistent with the OB’s identity contract; when incompatible fields coexist in a single TP, or when multiple TPs carry complementary object‑relevant fields, OB issues a mechanical request for split or merge. These topology events are recorded in the TP for later resolution by downstream OBs or Path B.
- **Is not:** A topology engine (does not perform split/merge itself); TR; TB; semantic interpreter; B‑side planner.
- **Example:** OB receives a TP containing mutually incompatible fields under its identity definition → OB issues SplitRequest; or OB receives multiple TPs with complementary object‑semantic fields → OB issues MergeRequest.
- **Normative home:** 20.40.

---

## TE (Topology Executor) — 20.131

- **Purpose:** Executes approved split and merge operations on TPs, updating topology markers and lineage so that downstream primitives see a structurally consistent, replayable topology state.
- **Focus:** Deterministic, mechanical application of OB-issued SplitRequest/MergeRequest events, including TP creation/combination, field partition/reconciliation, and append-only topology/lineage logging.
- **When:** Pipeline A topology stage, **conditionally invoked only when a TP carries an OB-issued split/merge request that has been approved by RB arbitration**; ordering: `OB → [TE if requested] → RB → next OB`.
- **Why:** OB can only detect structural conflicts/complementarities and request split/merge; RB can only arbitrate. TE is required to actually perform the topology change, preserve lineage, update ΔH% and missing-mass markers, and record a deterministic topology event log in the TP.
- **Is not:** OB (does not detect identity conflicts); RB (does not arbitrate policy); TPU (does not commit semantic updates); TR (does not derive semantic routing); a truth evaluator; a B-side merge engine.
- **Example:** OB receives a TP with mutually incompatible fields under its identity contract and writes a SplitRequest into the TP; RB arbitrates and approves; TE executes the split, creating two lane TPs with partitioned fields, shared parent lineage, updated ΔH% contribution markers, and an appended topology_event_log entry describing the split.
- **Normative home:** 20.130 (split/merge requirements) and 20.131 (TE requirements).

---

## RB (Relational Basin) — 20.50

- **Purpose:** Routes the TP to downstream basins through governed relational transitions, without consulting B-side routing tables.
- **Focus:** Deterministic relational projection and routing to downstream basins.
- **When:** Pipeline A `routing`.
- **Why:** Governed movement between basins without B-side routing tables.
- **Is not:** SRP; TrigRB; TR.
- **Example:** `MI_INCOMP` routes toward IB-Creation-Request.
- **Normative home:** 20.50.

---

## TR (Thought Router) — 20.37

- **Purpose:** Selects the next meaning-layer transition deterministically, integrating geometric and cultural signals without writing to the TP.
- **Focus:** Deterministic routing of the TP through the meaning-layer topology.
- **When:** Path A (post-TPU), after OB and DCB, before RB.
- **Why:** Select the next relational transition using geometric, cultural, and trajectory signals.
- **Is not:** A semantic interpreter; a TP writer; a candidate generator; a CE/CEx participant.
- **Example:** TR receives DCB curvature events and OB evidence, then selects the next RB relation.
- **Normative home:** 20.37.

---

## SRP (Semantic Routing Planner) — 20.55

- **Purpose:** Separates routing table maintenance (cold path) from per-cycle execution lookup (hot path) on the B side.
- **Focus:** Cold-path routing table compile; hot-path deterministic lookup.
- **When:** Pipeline B planning.
- **Why:** Separate table maintenance from A-cycle routing.
- **Is not:** RB; IMR writer.
- **Example:** B envelopes carry `routing_epoch_id`.
- **Normative home:** 20.55.

---

## OuB (Output Basin) — 20.206, 20.207

- **Purpose:** Realises the frozen `exec_plan` into surface output, confining all nondeterminism (seed-driven expression variation) to this single B-side stage so that everything upstream remains fully replayable.
- **Focus:** Surface-form realization of the `exec_plan` under `seed_scope`; append of OuB refs to `exec_trace`.
- **When:** Terminal stage of Pipeline B; after OpBeh / OBG / XlateR planning; ordering **XlateR → OuB → exec_trace append**.
- **Why:** Realization must be separated from planning so that different surface forms can be generated from identical frozen meaning without re-running Pipeline A.
- **Is not:** A semantic interpreter; a TP or semantic_core writer; a meaning constructor; a Pipeline A participant; a routing authority.
- **Example:** Two calls with different seeds produce different surface phrasings of identical `semantic_core`; both append separate OuB refs to `exec_trace`.
- **Normative home:** 20.206, 20.207.

---

## **LI (Local Inference Primitive) — 20.112**

- **Purpose:** Commits the first layer of meaning in Path B by applying the TS‑level concept **MLI** to the TP, producing a stable, locally‑resolved meaning state before any global inference, scoring, routing, or B‑side planning occurs.
- **Focus:** Reads representation‑layer fields from Path A; invokes **MLI‑prc**; writes meaning‑layer fields (`tp.meaning`, `tp.mli_status`, `tp.mli_confidence`, `tp.mli_conflict`, `tp.mli_reason_code`, `tp.mli_revision_cycles`) into the TP.
- **When:** First primitive of Path B, immediately after Path A representation freeze and before ISc, TR, TPU, or any B‑side planning. Runs every turn.
- **Why:** Ensures deterministic, auditable, local‑first meaning commitment so that all downstream primitives operate on a stable semantic substrate. Prevents semantic drift and unstable global inference by forcing meaning to be resolved before any higher‑order reasoning.
- **Is not:** A global inference engine; a scorer; a router; a semantic_core builder; a B‑side planner; a TP aggregator; or MLI itself. Does not read from MTP or generate XP.
- **Example:** Given an ambiguous utterance (“Can you check that for me”), LI reads the TP’s representation fields, applies MLI‑prc to classify the utterance as a *request*, and writes the resolved meaning and confidence into the TP for downstream primitives.
- **Normative home:** 20.112.

---

## TP (Thought Packet) — 20.105

- **Purpose:** Serves as the lane‑local semantic object that Pipeline A primitives read, inspect, and mechanically transform during meaning construction.
- **Focus:** Contains object‑semantic fields, structural notes, lineage metadata, and topology markers (split/merge events) used by OB, Split/Merge, TR, RB, and TPU.
- **When:** Active throughout Pipeline A; instantiated at intake; may be mechanically split or merged by topology operations; updated only by TPU.
- **Why:** Provide the deterministic, auditable semantic substrate on which OB identity checks, topology events, routing decisions, and TPU commits operate.
- **Is not:** A semantic interpreter; a scorer; a truth evaluator; a topology executor; TP never decides, infers, or writes to itself.
- **Example:** A TP enters an OB containing incompatible fields under that OB’s identity contract → OB issues SplitRequest → topology block creates lane TPs with shared lineage → TPU later commits the surviving lane.
- **Normative home:** 20.105.

# 2. Processes

---

## Pipeline A / Pipeline B — 20.500, 20.206

- **Purpose:** Enforces clean separation between meaning construction and realization so that each phase can be audited, replayed, and governed independently.
- **Focus:** Pipeline A is the meaning-construction path; Pipeline B is the realization path from frozen meaning.
  - **Pipeline A:** Input-side primitives *(InB → IIInB → CEx → CE → ISc → TPU)* and meaning-layer routing primitives *(OB → DCB → TR → RB)*.
  - **Pipeline B:** Realization path beginning after TP snapshot, including IB, TB, GBIB, GB, and OuB.
- **When:** Pipeline A runs on every input cycle; Pipeline B runs after `mtp_update`.
- **Why:** Clean separation between meaning construction (A) and realization/expression (B).
- **Is not:** A merge of semantic and realization logic; a shared writer path.
- **Normative home:** 20.500, 20.206.

---

## Four-Path Model (TS Processing Paths) — New

- **Purpose:** Prevents architectural drift by making each TS processing trajectory distinct, non-overlapping, and explicitly selected at InB.
- **Focus:** The four distinct, non-overlapping TS pipelines: Normal Path, Clarification Path, Inference Path, and Post-TS Interrogation Path.
- **When:** Path determined by InB path selection at entry.
- **Why:** Prevent architectural drift and stage confusion.
- **Is not:** A single pipeline; a merged flow; a semantic generator.
- **Example:** Ambiguous input triggers Clarification Path; semantic update triggers Inference Path.
- **Normative home:** Architecture discussion.

---

## Truth/Done — 20.140

- **Purpose:** Provides the explicit completion-detection gate that terminates a processing cycle based on truth hypothesis and done-state evaluation.
- **Focus:** Terminal evaluation over `truth_hypotheses` and `done_state`.
- **When:** Pipeline A `truth_done_evaluation`.
- **Why:** Explicit completion detection; prevent runaway processing cycles.
- **Is not:** IMR satisfaction; IB resolution.
- **Example:** `done_state` reached under clean rules.
- **Normative home:** 20.140.

---

## Split (Pipeline A Split) — 20.130

- **Purpose:** Provides the mechanical branching mechanism that creates multiple lane TPs when a single TP violates an OB’s identity constraints and cannot be evaluated as one coherent object instance.
- **Focus:** Mechanical duplication and partitioning of a TP into multiple lane TPs based on an OB‑issued SplitRequest; each lane TP carries a structurally consistent subset of the original fields with shared lineage metadata.
- **When:** Pipeline A topology stage, triggered only after an OB detects internal structural incompatibility; ordering: **OB → SplitRequest → Topology Block (Split) → [lane TPs]**.
- **Why:** A single TP may contain mutually incompatible object‑semantic fields under the OB’s identity definition; splitting preserves each structurally valid hypothesis for downstream OBs or Path B to resolve.
- **Is not:** A semantic interpreter; a truth evaluator; an inference mechanism; a TP writer; a scorer; a B‑side process. Split is purely mechanical and never performed by TPU.
- **Example:** OB receives a TP with `risk_level = high` and `safety_state = safe`, which cannot coexist under its identity contract → OB issues SplitRequest → topology block creates Lane A TP (`risk_level = high`) and Lane B TP (`safety_state = safe`) with shared `lineage_id`.
- **Normative home:** 20.130.

---

## Merge (Pipeline A Merge) — 20.130

- **Purpose:** Provides the mechanical combine operation that unifies multiple lane TPs into a single MTP draft when an OB determines that the lanes carry complementary object‑relevant fields that must be evaluated together.
- **Focus:** Deterministic, mechanical combination of lane TPs based on an OB‑issued MergeRequest; includes lineage consolidation and ΔH% accounting, producing a single MTP draft for later TPU commit.
- **When:** Pipeline A topology stage, triggered only after an OB detects multi‑TP convergence; ordering: **OB → MergeRequest → Topology Block (Merge) → MTP draft → TPU**.
- **Why:** When multiple TPs carry complementary or mutually reinforcing object‑semantic fields relevant to the same OB, they must be structurally unified so downstream OBs or Path B can evaluate them as one coherent object instance.
- **Is not:** A truth evaluator; a semantic interpreter; a scorer; a TP writer; a B‑side merge. Merge is purely mechanical and never performed by TPU.
- **Example:** OB receives two TPs, one containing `object_id = X` and another containing `object_attributes = {color: red}`, both relevant to the same object → OB issues MergeRequest → topology block merges them into a single MTP draft with consolidated lineage and ΔH%.
- **Normative home:** 20.130.

---

## **MLI (Meaning‑Layer Inference) — 20.111**

- **Purpose:** Provides deterministic, non‑neural reasoning over the meaning state so that semantic implications, commitments, and structural consequences are derived without probabilistic inference. **Executed by LI‑prm as the meaning‑layer inference process for Path B.**
- **Focus:** Rule‑based meaning‑layer transformations applied after meaning extraction but before governance or neural intuition.
- **When:** Invoked **inside LI‑prm** at the start of Path B, after Path A primitives populate the representation layer and before any COP2 request or global inference is formed.
- **Why:** Ensures that semantic reasoning is deterministic, auditable, and independent of neural models; prevents ambiguity or implication resolution from being delegated to probabilistic inference.
- **Is not:** A primitive; a basin; neural inference; a governance mechanism; a TP writer; a semantic_core builder.
- **Example:** MLI derives that “If X implies Y” and “X is asserted,” then Y must be added to the meaning state with deterministic justification; LI‑prm then writes this resolved meaning into the TP.
- **Normative home:** 20.111 (MLI Requirements).

# 3. Reference Objects

---

## TB (Truth Basin) — 20.60

- **Purpose:** Produces structured truth hypotheses over a frozen semantic snapshot for downstream supervisory evaluation.
- **Focus:** Structured truth-interpretation over the *frozen* semantic_core snapshot; truth hypothesis shaping from Object Basin (OB) evidence.
- **When:** **Interpretive Basin Chain (IBC)** — after TPU commit, outside Path A; Pipeline A `tb_interpretation`.
- **Why:** Provide deterministic `truth_hypotheses{}` consumed by GBIB/GB for supervisory evaluation; separate interpretation from terminal evaluation.
- **Is not:** A Path-A primitive; a meaning constructor; a TP writer; a candidate generator; a CE/CEx participant.
- **Example:** TB-logic evaluates logical coherence; TB-stance evaluates stance truth; TB-intent evaluates intent consistency. TB emits hypothesis band; may tag MI_INCOMP.
- **Normative home:** 20.60.

---

## DCB (Directional Conversation Basin) — 20.106

- **Purpose:** Provides geometric trajectory observations that TR uses to select the next relational transition.
- **Focus:** Geometric observation of TP trajectory and curvature.
- **When:** Pipeline A.
- **Why:** Provide directional-change events for TR.
- **Is not:** OB; semantic interpreter; persistent writer.
- **Example:** Curvature spike → directional-change event.
- **Normative home:** 20.106.

## CIL (Conversation Integration Layer) — 20.33

- **Focus:** Deterministic conversation intake, FIFO preservation, and escalation to supervisory paths.
- **When:** Conversation layer; before TS intake boundaries.
- **Why:** Provide ordered, auditable integration separate from meaning construction.
- **Is not:** A context object; a semantic interpreter; a TP writer.
- **Example:** Clarification event delivered to UPI.
- **Normative home:** 20.33.

## COB (Conversation Object Basin) — 20.32

- **Purpose:** Maintains long-horizon conversation object lifecycle and lineage separately from TP/MTP.
- **Focus:** Durable conversation-object lifecycle and lineage.
- **When:** Conversation layer.
- **Why:** Maintain long-horizon continuity separate from TP/MTP.
- **Is not:** A semantic interpreter; a TP writer; a context provider.
- **Example:** TP promotion to COB-visible object.
- **Normative home:** 20.32.

## TrigRB (Trigger Relational Basin) — 20.57

- **Purpose:** Detects realization-relevant semantic triggers over frozen meaning before B-side planning begins.
- **Focus:** B-side semantic trigger detection over frozen semantic_core.
- **When:** Pipeline B first stage after `mtp_update`.
- **Why:** Detect realization-relevant triggers without re-entering Path A.
- **Is not:** TR; RB; SRP compiler.
- **Example:** Emits trigger codes for SRP lookup.
- **Normative home:** 20.57.

## OpBeh / OBG / XlateR (B-Side Planning Triple) — 20.41, 20.42, 20.43

- **Purpose:** Determines operational behavior, voice/register identity, and expression mapping from frozen meaning before OuB.
- **Focus:** B-side operational behavior (OpBeh), voice/register identity (OBG — Output Behavior Governor), and expression mapping (XlateR — Translator/Register).
- **When:** Pipeline B planning before OuB.
- **Why:** Deterministic planning from frozen meaning without seed-driven identity selection.
- **Is not:** OB; TR; RB; seed-driven identity selection.
- **Example:** `exec_plan` carries `opbeh_id`, `obg_id`, `xlater_id`.
- **Normative home:** 20.41–20.43.

---

## IE (Intake Envelope, Structured Intake Object) — New

- **Purpose:** Provides a deterministic, bounded, replayable representation of the user's input that can be safely passed to downstream components.
- **Focus:** The structured, normalized, repaired intake object produced by InB → IIInB.
- **When:** Immediately after IIInB; before CEx.
- **Why:** Deterministic, bounded, replayable representation of the user's input for downstream consumption.
- **Is not:** A semantic interpretation; a candidate generator; a truth evaluator.
- **Example:** Normalized tokens + USP-applied repairs + structural tags.
- **Normative home:** 20.100, 20.101.

---

## USP (User Semantic Profile) — 20.101, 20.33

- **Purpose:** Provides the authoritative, user-approved rule set that governs all shorthand repair in IIInB and all context extraction in CEx, ensuring that semantic personalisation is explicit, auditable, and consent-bound.
- **Focus:** Persistent, user-approved mapping of shorthand forms, preferred expansions, and semantic commitments consumed by IIInB and CEx.
- **When:** Loaded at session initialisation; read by IIInB during `input_semantic_repair`; read by CEx during context extraction.
- **Why:** Without USP, repair decisions in IIInB would be inferred rather than rule-bound, violating the non-inferential constraint on the input path.
- **Is not:** A semantic interpreter; a candidate generator; a TP writer; a live inference mechanism; a truth evaluator.
- **Example:** USP entry maps "quicker-ish" → "reduce latency by ~20%"; IIInB applies the rule deterministically without constructing meaning.
- **Normative home:** 20.101 (repair rules); 20.33 (CEx consumption).

---

## CE (ContextEnvelope) — New

- **Purpose:** Delivers safe, isolated context to ISc without exposing global conversation state.
- **Focus:** Bounded, deterministic, replayable context object consumed by ISc.
- **When:** Immediately before ISc in the inference path.
- **Why:** Provide ISc with safe, isolated context without exposing global state.
- **Is not:** A history; a semantic object; a TP writer; a CIL proxy.
- **Example:** CE contains active referents, lineage IDs, relevant commitments.
- **Normative home:** Architecture discussion; 20.44.

---

## candidate_set{} (Interpretation Candidates) — New

- **Purpose:** Presents ISc with a finite, pre-generated set of structured interpretations so that scoring is deterministic and bounded.
- **Focus:** Finite set of structured interpretation candidates generated from the intake envelope + CE.
- **When:** Produced before ISc; consumed by ISc.
- **Why:** ISc requires a finite, deterministic candidate set to score.
- **Is not:** Generated by TB; generated by IB; generated by free inference.
- **Example:** Candidate interpretations of ambiguous pronoun references.
- **Normative home:** 20.44 (ISc).

---

## MTP (Master Thought Packet) — 20.115

- **Purpose:** Serves as the authoritative, post‑topology, post‑TPU semantic representation for the entire meaning state at a given commit. MTP is the single, global semantic object that Pipeline B reads.
- **Focus:** Holds the merged, lane‑agnostic semantic state produced after all Split/Merge operations have been resolved and TPU has committed the resulting structure. Contains consolidated object‑semantic fields, lineage roll‑ups, ΔH% accounting, and the frozen semantic_core.
- **When:** Created immediately after topology Merge and finalized at TPU commit; remains immutable for the lifetime of the commit and is the sole semantic input to Path B (TB → IB → GBIB → GB).
- **Why:** Provide a deterministic, auditable, replay‑stable meaning representation that unifies all lane‑local hypotheses into a single authoritative semantic state. Ensures Pipeline B operates on a stable, fully‑resolved meaning snapshot.
- **Is not:** A lane‑local TP; a mutable structure; a topology executor; a scorer; a truth evaluator; MTP is never modified by primitives and is never used as an operand in Pipeline A.
- **Example:** After OB issues MergeRequest for two lane TPs with complementary object‑semantic fields, the topology block produces a merged draft; TPU commits it, producing an MTP containing the unified fields, consolidated lineage, and frozen semantic_core.
- **Normative home:** 20.115.

---

## XP / exec_plan / exec_trace — 20.500, 20.207

- **Purpose:** Captures regenerable execution artifacts per commit_id, keeping B-side audit separate from A-side semantic state.
- **Focus:** Execution artifacts per `commit_id`; B-side audit partition.
  - **exec_plan (XP):** B-side execution plan produced from frozen meaning.
  - **exec_trace:** Append-only audit record of OuB refs and IMR records.
- **When:** Pipeline B.
- **Why:** Execution is regenerable; meaning replay uses semantic_core only.
- **Is not:** TP; MTP; semantic_core.
- **Example:** `exec_trace` holds OuB refs + IMR records.
- **Normative home:** 20.500, 20.207.

---

## commit_id / semantic_snapshot_ref — 20.120, 20.36

- **Purpose:** Binds each A-cycle semantic commit to its B-cycle realization, enabling deterministic replay and audit.
- **Focus:** Freeze markers for committed meaning.
- **When:** Emitted at `mtp_update`.
- **Why:** Bind A-cycle commit to B-cycle realization.
- **Is not:** Draft snapshot; mutable reference.
- **Example:** B consumes `semantic_snapshot_ref` read-only.
- **Normative home:** 20.120, 20.36.

---

## routing_epoch_id — 20.55, 20.45

- **Purpose:** Binds B-side execution planning to a specific, immutable SRP routing table epoch.
- **Focus:** SRP (Semantic Routing Planner) table epoch identifier.
- **When:** B envelopes only.
- **Why:** Bind execution planning to a specific routing table; prevent epoch mismatch.
- **Is not:** A-cycle routing state; mutable by IMR.
- **Example:** IMR consumes read-only.
- **Normative home:** 20.55, 20.45.

- **Focus:** Append-only IMR audit block on `exec_trace`.
- **When:** Every IMR evaluation.
- **Why:** Every mismatch evaluation must be auditable and traceable.
- **Is not:** A TP write; a semantic_core mutation; a replayable artifact.
- **Normative home:** 20.45.

## IMR Types A / B / C — 20.45

- **Purpose:** Classifies each mismatch by severity so that the correct corrective authority — realization, semantic, or GB-gated — is invoked.
- **Focus:** Three-tier mismatch classification with precedence ordering.

| Type | Name | Authority |
|------|------|-----------|
| **A** | Expression mismatch | Realization retry only |
| **B** | Semantic mismatch | May emit CorrectionTrigger |
| **C** | Safety mismatch | GB-gated |

- **When:** Every IMR evaluation.
- **Why:** Ensure the correct corrective pathway is invoked per mismatch severity.
- **Is not:** A semantic rewrite authority; a free-form correction signal.
- **Precedence:** C > B > A.
- **Normative home:** 20.45.

## CorrectionTrigger — 20.45

- **Purpose:** Schedules bounded corrective pathways via append-only signal, preventing direct semantic_core writes and chained correction loops.
- **Focus:** Append-only supervisory signal scheduling bounded corrective pathways.
- **When:** Emitted by IMR; Type B consumed next cycle only.
- **Why:** Correct semantic mismatches without direct semantic_core writes or correction chains.
- **Is not:** Direct semantic_core write; chained correction loops.
- **Normative home:** 20.45.

## GBIB (Governance Basin — Inquiry Branch) — 20.90, 20.30

- **Purpose:** Acts as the supervisory evaluation stage between IB and GB, filtering inquiry proposals before they reach the Governance Basin so that only well-formed, non-redundant clarification requests proceed.
- **Focus:** Supervisory pre-screening of IB inquiry proposals; evaluation of inquiry validity, deduplication, and priority before GB gate.
- **When:** Post-TS supervisory chain: **IB → GBIB → GB**; runs after IB generates a clarification proposal and before GB renders a governance decision.
- **Why:** Prevent malformed, duplicate, or low-priority inquiry proposals from reaching GB; preserve GB for authoritative decisions only.
- **Is not:** IB (which generates proposals); GB (which renders the final governance decision); a TP writer; a Pipeline A primitive; a semantic interpreter.
- **Example:** IB proposes a clarification request for an unresolved pronoun referent; GBIB checks for duplicate open inquiries and validity before forwarding to GB.
- **Normative home:** 20.90, 20.30.

---

## GB (Governance Basin) — 20.30

- **Purpose:** Provides the terminal supervisory authority over inquiry creation, safety mismatches (IMR Type C), and any corrective action that cannot be resolved within Pipeline A or B alone.
- **Focus:** Final governance decisions over GBIB-screened inquiry proposals, IMR Type C escalations, and IB-Creation-Requests.
- **When:** Post-TS supervisory chain terminal stage: **GBIB → GB**; also invoked directly for IMR Type C safety mismatches.
- **Why:** Centralise all consequential supervisory authority in one basin so that governance decisions are auditable, non-redundant, and architecturally bounded.
- **Is not:** IB (ambiguity detection); GBIB (pre-screening); IMR (mismatch classification); a semantic interpreter; a TP or semantic_core writer; a Pipeline A primitive.
- **Example:** IMR Type C safety mismatch escalated → GB renders governance decision (block / reroute / flag); outcome appended to `exec_trace`.
- **Normative home:** 20.30.

## Random Seed Boundary — 20.12, 20.207

- **Purpose:** Confines all nondeterminism to B-side expression selection so that A-side meaning is fully replayable from semantic_core.
- **Focus:** Confine nondeterminism to B-side expression selection under `seed_scope`.
- **When:** OuB under `seed_scope`.
- **Why:** Meaning replay invariant; A-side must be fully deterministic.
- **Is not:** A-cycle planning; OpBeh identity selection.
- **Example:** Different seeds → different surface text; identical semantic_core.
- **Normative home:** 20.12, 20.207.

- **Focus:** Normalized compute-cost unit reported per tick / per primitive.
- **When:** Reported per tick / per primitive.

- **Example:** OpBeh vs OuB cost recorded separately.

## Messy-Input Taxonomy (MI_*) — 20.17

- **Purpose:** Classifies all malformed or ambiguous input conditions so that routing, repair, and escalation decisions are made deterministically rather than ad hoc.
- **Focus:** Structured classification of problematic input conditions with deterministic downstream routing implications.
- **When:** Applied at InB / IIInB during input canonicalization.
- **Why:** Prevent ad hoc handling of malformed input; ensure deterministic routing per class.
- **Is not:** Semantic interpretation; truth evaluation; a repair mechanism.

| Class | Focus | Example |
|-------|-------|---------|

| `MI_INCOMP` | Commitment-blocked incompleteness | Missing slots → IB-Creation-Request |

- **Normative home:** 20.17.
