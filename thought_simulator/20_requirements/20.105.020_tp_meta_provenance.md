# **20.105.020_tp_meta_provenance.md**  
### **TP Metadata Provenance — Origin, Commit Lineage, and Primitive Responsibilities**

---

## **1. Purpose**
This document defines the provenance rules governing metadata fields within the Thought Packet (TP).  
Provenance ensures that each metadata field records its origin, commit lineage, and primitive‑level responsibility, enabling deterministic replay, stable routing, and consistent downstream meaning refinement.

---

## **2. Scope**
This specification covers:

- provenance structure  
- primitive‑origin rules  
- commit lineage rules  
- update authorization rules  
- replay‑safety constraints  

It does **not** redefine metadata fields (20.105.010) or primitive behavior.

---

## **3. Provenance Structure**
Each metadata field carries provenance information describing:

- the primitive that produced the field  
- the primitive that last updated the field  
- the TPU commit in which the field was written  
- the lineage of commits affecting the field  

Provenance is stored in the TP as structured metadata.

---

## **4. Normative Requirements**

### **4.1 Primitive Origin Recording**
**HLR‑20.105.020‑001**  
Each metadata field **shall** record the identity of the primitive that produced it.

### **4.2 Last‑Update Recording**
**HLR‑20.105.020‑002**  
Each metadata field **shall** record the identity of the primitive that last updated it.

### **4.3 Commit Identifier Recording**
**HLR‑20.105.020‑003**  
Each metadata field **shall** record the TPU commit identifier associated with its most recent update.

### **4.4 Commit Lineage Preservation**
**HLR‑20.105.020‑004**  
Metadata fields **shall** preserve a lineage of commit identifiers representing all commits that modified the field.

### **4.5 Authorized Update Enforcement**
**HLR‑20.105.020‑005**  
Metadata fields **shall** only be updated by primitives explicitly authorized to modify those fields.

### **4.6 Immutable Provenance History**
**HLR‑20.105.020‑006**  
Provenance history **shall** be immutable once recorded, except when extended by authorized updates.

### **4.7 Replay‑Safety**
**HLR‑20.105.020‑007**  
Provenance information **shall** support deterministic replay, ensuring identical provenance when the same TP is re‑executed through the same primitive sequence.

### **4.8 Provenance Visibility**
**HLR‑20.105.020‑008**  
All provenance information **shall** be visible to downstream primitives without requiring re‑inspection of upstream behavior.

## **5. Primitive Responsibilities**

### **5.1 InB / IIInB**
Record provenance for:

- intake_status  
- defect_list  
- token_observations  
- unicode_flags  
- length_flags  

### **5.2 IE**
Record provenance for:

- normalized_tokens  
- repair_actions  
- repair_confidence  
- token_alignment_map  

### **5.3 OB‑Set**
Record provenance for:

- structural_roles  
- segment_boundaries  
- constraint_surfaces  
- smoothing_actions  

### **5.4 Routing Primitives (RBU, RB, RTU, CTP)**
Record provenance for:

- routing_pathway  
- routing_confidence  
- arbitration_trace  
- routing_features  

### **5.5 IdOB**
Record provenance for:

- identity‑conditioned meaning updates  
- expressive meaning refinement metadata  

(IdOB does not modify TP fields directly; provenance applies to TPU commits triggered by IdOB.)

### **5.6 TR**
Record provenance for:

- truth‑relation mapping fields  
- entropy_metadata updates  

### **5.7 OuBA**
Record provenance for:

- SSR‑A snapshot metadata  
- entropy trajectory updates  

### **5.8 TPU**
Record provenance for:

- commit_id  
- commit_sequence  
- primitive_origin  
- commit_timestamp  

TPU is the authoritative provenance writer.

---

## **6. Provenance Equations**

### **6.1 Commit Lineage Representation**
Commit lineage is represented as:

$$
\text{lineage} = \{ c_1, c_2, \ldots, c_n \}
$$

where each $c_i$ is a TPU commit identifier.

### **6.2 Provenance Update Rule**
When a primitive $P$ updates a metadata field:

$$
\text{provenance.last\_update} = P
$$

and the commit lineage is extended:

$$
\text{lineage} \leftarrow \text{lineage} \cup \{ c_{\text{new}} \}
$$
