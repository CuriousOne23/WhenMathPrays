# **20.40.030 — CnOB Requirements (Constraint OB Layer)**  
**Status:** Normative  
**Parent:** 20.40_ob_requirements.md  
**Scope:** Requirements for the Constraint OB (CnOB) layer in Path A.  
**Purpose:** Define mandatory constraint extraction, normalization, classification, and residue‑formation rules for the third OB layer.

---

## **1. Informative Overview (No SHALLs)**

The Constraint OB (CnOB) layer is the **third classification layer** in Path A.  
Its purpose is to extract, normalize, and classify **constraints** from the refined structural output of SROB.

CnOB performs:

- constraint extraction  
- constraint normalization  
- constraint classification  
- constraint strength and scope detection  
- conflict detection (without resolution)  
- constraint‑residue formation  

CnOB does **not** interpret domain semantics, resolve constraint conflicts, or apply constraints.  
Its output must be ready for semantic processing by SmOB.

---

## **2. Normative Requirements**

### **2.1 Constraint Extraction**

**HLR‑20.40.030‑001**  
The CnOB layer **SHALL** extract explicit constraints from the SROB output, including precision, conciseness, tone, safety, and formatting constraints.

**HLR‑20.40.030‑002**  
The CnOB layer **SHALL** extract implicit constraints when they are structurally inferable from the normalized TP.

---

### **2.2 Constraint Normalization**

**HLR‑20.40.030‑003**  
The CnOB layer **SHALL** normalize extracted constraints into canonical internal forms.

**HLR‑20.40.030‑004**  
The CnOB layer **SHALL** ensure that normalized constraints preserve the intent of the original constraint expression.

---

### **2.3 Constraint Classification**

**HLR‑20.40.030‑005**  
The CnOB layer **SHALL** classify constraints into structural, semantic‑agnostic, formatting, safety, and behavioral categories.

**HLR‑20.40.030‑006**  
The CnOB layer **SHALL** detect constraint strength levels, including soft, medium, and hard constraints.

**HLR‑20.40.030‑007**  
The CnOB layer **SHALL** detect constraint scope, including global, local, and unit‑level scopes.

---

### **2.4 Constraint Conflict Detection**

**HLR‑20.40.030‑008**  
The CnOB layer **SHALL** detect conflicting constraints without resolving them.

**HLR‑20.40.030‑009**  
The CnOB layer **SHALL** represent detected conflicts as residue fragments for later processing.

---

### **2.5 Residue Formation**

**HLR‑20.40.030‑010**  
The CnOB layer **SHALL** produce residue fragments representing normalized constraints, constraint classifications, and detected conflicts.

**HLR‑20.40.030‑011**  
The CnOB layer **SHALL** ensure that constraint‑residue fragments remain addressable by the routing block (RB).

**HLR‑20.40.030‑012**  
The CnOB layer **SHALL** ensure that constraint entropy after CnOB is strictly less than the entropy of the SROB output.

---

### **2.6 Prohibited Behavior**

**HLR‑20.40.030‑013**  
The CnOB layer **SHALL NOT** perform domain‑specific semantic interpretation.

**HLR‑20.40.030‑014**  
The CnOB layer **SHALL NOT** apply or enforce constraint logic.

**HLR‑20.40.030‑015**  
The CnOB layer **SHALL NOT** modify the original TP text.

---

### **2.7 Routing Requirements**

**HLR‑20.40.030‑016**  
The CnOB layer **SHALL** produce output suitable for routing into SmOB as the next classification layer.

**HLR‑20.40.030‑017**  
The CnOB layer **SHALL NOT** route directly into domain‑specific semantic OBs.

---

## **3. Mathematical Requirements (Normative)**

These requirements govern the geometric properties of constraint‑residue fragments produced by CnOB.

**HLR‑20.40.030‑018**  
The CnOB layer **SHALL** ensure that each constraint‑residue fragment $c_i$ is hashable into an address fragment $g_i$.

Inline example:  
$g_i = hash(c_i)$

**HLR‑20.40.030‑019**  
The CnOB layer **SHALL** ensure that the combined query address $q_c$ formed by the routing block satisfies:

$$
q_c = g_1 \oplus g_2 \oplus \dots \oplus g_n
$$

**HLR‑20.40.030‑020**  
The CnOB layer **SHALL** ensure that constraint‑residue fragments do not violate geometric invariants defined in 20.40, including smoothness, monotonicity, and curvature‑invariance.

---

## **4. Outputs**

**HLR‑20.40.030‑021**  
The CnOB layer **SHALL** output:

- a constraint‑normalized TP  
- a constraint‑residue set  
- normalized constraint metadata  
- constraint‑classification metadata  
- constraint‑strength metadata  
- constraint‑scope metadata  
- conflict‑detection metadata  

**HLR‑20.40.030‑022**  
The CnOB layer **SHALL** guarantee that its output is valid input for SmOB.
