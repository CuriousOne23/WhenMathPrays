# **20.107 — CEx Extract**  
**Document ID:** 20.107  
**Version:** 0.2  
**Date:** 2026‑06‑12  
**Upstream:** IIInB  
**Downstream:** CE (20.108), ISc (20.44)

---

# **1. Purpose** *(Informative)*

CEx (Context Extractor) is the module that reads **CIL** and produces a **bounded, deterministic, structured context envelope (CE)**.  
It performs no semantic repair, no inference, and no meaning generation.  
Its role is strictly mechanical: extract explicit context fields and normalize them into CE.

---

# **2. Position in the Inference Path** *(Informative)*

```
InB → IIInB → CEx → CE → ISc → Merge → TPU → TP(N+1)
```

CEx sits between IIInB and ISc and is the first module that transforms CIL into a structured object.

---

# **3. Scope** *(Informative)*

CEx:

- reads CIL  
- extracts explicit, bounded context  
- normalizes surface‑form fields  
- emits CE  
- records extraction audit entries  

CEx does **not**:

- infer meaning  
- repair semantics  
- classify messy input  
- read or write TP/MTP  
- read routing metadata or ΔH%  
- use embeddings or probabilistic reasoning  

---

# **4. Inputs** *(Informative)*

CEx consumes:

```
cex_input {
    cil_record,
    iiinb_projection,
    mtp_snapshot_id,
    policy_signature
}
```

All inputs are read‑only.

---

# **5. Outputs** *(Informative)*

CEx emits:

```
ce_output {
    ce_record,
    extraction_audit[],
    version_tag
}
```

The CE schema is defined in 20.108.

---

# **6. Extraction Behavior** *(Informative)*

CEx extracts only explicit fields present in CIL, applies deterministic normalization, enforces bounded limits, and records all drops or truncations in the audit trail.  
Malformed CIL still produces a CE containing only valid extracted fields.

---

# **7. Allowlist / Denylist Model** *(Informative)*

**Allowlist examples:**

- user‑provided context strings  
- timestamps  
- structural metadata  
- conversation window slices  
- explicit parameters  

**Denylist examples:**

- inferred semantics  
- embeddings  
- routing metadata  
- ΔH%  
- semantic_core fields  
- TB/IB fields  
- Pipeline‑B envelopes  

---

# **8. Determinism and Replay** *(Informative)*

CEx produces identical CE for identical CIL and policy_signature.  
Ordering, normalization, and field selection are canonical and deterministic.

---

# **9. Error Handling** *(Informative)*

CEx never halts the pipeline.  
Malformed or partial CIL results in:

- extraction of valid fields  
- dropping invalid fields  
- audit entries describing the drops  
- emission of CE regardless of input quality  

---

# **10. High‑Level Requirements (HLRs)**

### **HLR‑20.107‑001**  
CEx SHALL be the only module permitted to read CIL.

### **HLR‑20.107‑002**  
CEx SHALL extract only explicit, structured, bounded context fields from CIL.

### **HLR‑20.107‑003**  
CEx SHALL NOT perform semantic repair, inference, or meaning generation.

### **HLR‑20.107‑004**  
CEx SHALL emit CE in deterministic, canonical form.

### **HLR‑20.107‑005**  
CEx SHALL NOT read or write TP, MTP, routing metadata, ΔH%, or semantic_core.

### **HLR‑20.107‑006**  
CEx SHALL enforce allowlist‑only extraction and SHALL drop denylisted fields with audit entries.

### **HLR‑20.107‑007**  
CEx SHALL NOT classify or modify messy_input tags.

### **HLR‑20.107‑008**  
CEx SHALL NOT use embeddings, probabilistic reasoning, or latent inference.

### **HLR‑20.107‑009**  
CEx SHALL produce identical CE for identical CIL and policy_signature.

### **HLR‑20.107‑010**  
CEx SHALL NOT trigger downstream modules or perform multi‑stage extraction.

### **HLR‑20.107‑011**  
CEx SHALL record all drops, truncations, and normalizations in extraction_audit.

### **HLR‑20.107‑012**  
CEx SHALL NOT modify CIL or any upstream structure.

### **HLR‑20.107‑013**  
CEx SHALL enforce bounded size limits on extracted fields.

### **HLR‑20.107‑014**  
CEx SHALL NOT read Pipeline‑B envelopes or execution traces.

### **HLR‑20.107‑015**  
CEx SHALL emit CE even when CIL is malformed, extracting only valid fields.

---

# **11. Conformance** *(Informative)*

CEx conforms when:

- CE is deterministic  
- only allowlisted fields appear in CE  
- no semantic inference occurs  
- no TP/MTP/routing/ΔH% fields are accessed  
- extraction_audit is complete and deterministic  
- malformed CIL still yields a valid CE  
- replay produces identical CE
