# **20.40.060.700 — OuBA Field Reference (v0.3)**  
**Status:** Informational Reference  
**Scope:** Defines the meaning, origin, and consumption of all TP → OuBA → SSR fields.  
**Excludes:** Normative requirements, Path‑A semantics, Path‑B truth determination, realization behavior.

---

# **0. Introduction**

This reference document explains the fields that flow through the OuBA primitive.  
These fields originate in the Thought Processor (TP), are frozen by OuBA, and are consumed by Path B truth and safety engines.

Each field is described in terms of:

- what it **is**  
- what it **is not**  
- where it is **produced**  
- where it is **consumed**  
- a **realistic example** from TP processing  

This document contains **no normative requirements**.

---

# **1. Purpose**

The purpose of this reference is to provide clear, architectural definitions for all fields present in:

- TP semantic state  
- OuBA input object  
- SSR output object  

This document helps readers understand the meaning and lifecycle of each field without needing to infer semantics from other specifications.

# **3. Field Definitions (with examples)**

Each subsection defines a single field and includes a realistic TP‑level example.

---

## **3.1 `proposition_set[]`**

### **What it is**  
A list of meaning‑level propositions extracted or constructed during Path A processing.  
Represents the structured semantic content of the user input.

### **What it is not**  
Not truth tags.  
Not safety flags.  
Not a logical proof.  
Not a global meaning store.

### **Produced by**  
OB, IB, and TB interactions inside TP.

### **Consumed by**  
Path B truth and safety engines.

### **Example**  
```
proposition_set[] = [
  "The user wants to compare two operating systems.",
  "The user expresses a preference for privacy.",
  "The user is considering switching to Zorin OS."
]
```

---

## **3.2 `truth_evidence[]`**

### **What it is**  
Raw meaning‑level evidence supporting or contradicting propositions.  
Includes structural evidence, plausibility hints, contradiction markers, and identity‑conditioned evidence.

### **What it is not**  
Not truth determinations.  
Not TPTB truth tags.  
Not TPSF safety flags.  
Not authoritative truth.

### **Produced by**  
OB and IB.  
TB may annotate evidence but does not determine truth.

### **Consumed by**  
Path B truth determination (TPTB) and safety determination (TPSF).

### **Example**  
```
truth_evidence[] = [
  { "type": "support", "source": "OB", "detail": "User explicitly states preference." },
  { "type": "support", "source": "TB", "detail": "Lexical consistency across sentences." },
  { "type": "contradiction", "source": "OB", "detail": "Ambiguous phrasing in second clause." }
]
```

---

## **3.3 `completion_state`**

### **What it is**  
A structural indicator of whether TP meaning construction has reached a stable, interpretable state.

### **What it is not**  
Not a truth indicator.  
Not an epistemic measure.  
Not a safety flag.

### **Produced by**  
TP completion logic.

### **Consumed by**  
OuBA (freeze point) and Path B routing.

### **Example**  
```
completion_state = "complete"
```

or

```
completion_state = "partial"
```

---

## **3.4 `h_percent`**

### **What it is**  
The accumulated epistemic state of the TP.  
Represents the total epistemic weight derived from OB‑produced ΔH% contributions.

### **What it is not**  
Not ΔH%.  
Not truth.  
Not evidence.  
Not a confidence score.

### **Produced by**  
TP using the update rule:
 
$H\_{final}\  =\  H\_{initial}\  -\  \sum_i \Delta H\_{OB_i}$

### **Consumed by**  
Path B truth and safety engines.

### **Example**  

$H\_{final}\ =\  0.82$  
$H\_{initial}\ =\  1.00$

Derived from OB contributions such as:

```
ΔH = [0.12, 0.08, -0.02]
```

A ΔH > 0, reduces entropy.

## **3.5 `messy_input_record`**

### **What it is**  
A record of structural irregularities, ambiguities, or malformed input detected during Path A processing.

### **What it is not**  
Not an error.  
Not a truth indicator.  
Not a safety flag.

### **Produced by**  
OB and TB.

### **Consumed by**  
Path B truth and safety engines.

### **Example**  
```
messy_input_record = [
  "Missing verb in clause 2.",
  "Ambiguous referent: 'it' could refer to OS or device."
]
```

---

## **3.6 `semantic_tags[]`**

### **What it is**  
Meaning‑level tags describing semantic categories, roles, or contextual attributes of propositions.

### **What it is not**  
Not truth tags.  
Not safety flags.  
Not policy markers.

### **Produced by**  
OB, IB, and TB.

### **Consumed by**  
Path B truth and safety engines.

### **Example**  
```
semantic_tags[] = [
  "preference",
  "technology",
  "privacy",
  "migration_intent"
]
```

---

## **3.7 `lane_local_identity`**

### **What it is**  
Identity‑conditioned context used to interpret meaning within the TP’s identity manifold.

### **What it is not**  
Not a user profile.  
Not a global identity store.  
Not a truth indicator.

### **Produced by**  
TP identity subsystem.

### **Consumed by**  
Path B truth and safety engines.

### **Example**  
```
lane_local_identity = {
  "mode": "technical_user",
  "context": "OS_migration_discussion"
}
```

---

## **3.8 `ob_trace[]`**

### **What it is**  
A trace of OB operations performed during meaning construction.

### **What it is not**  
Not a semantic summary.  
Not a truth record.  
Not a safety record.

### **Produced by**  
OB.

### **Consumed by**  
Path B truth and safety engines.

### **Example**  
```
ob_trace[] = [
  "OB.lexical_parse",
  "OB.semantic_role_assignment",
  "OB.identity_conditioning",
  "OB.evidence_extraction"
]
```

## **3.10 `policy_markers[]`**

### **What it is**  
Markers indicating policy‑conditioned constraints or annotations applied during TP processing.

### **What it is not**

### **Consumed by**


# **5. Field Lifecycle Summary**

All fields originate in TP, are frozen by OuBA, and are consumed by Path B.  
None of these fields represent truth or safety determinations; they are inputs to those processes.
