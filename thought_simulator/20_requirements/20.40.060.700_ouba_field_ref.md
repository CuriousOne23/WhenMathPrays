# **20.40.060.700 — OuBA Field Reference (v1.0, Updated Option‑C)**  
**Status:** Informational Reference  
**Scope:** Describes the meaning, origin, and consumption of all TP → OuBA → TPSnS → SSR fields used by COB, CST, and Path B.  
**Excludes:** Normative requirements, Path‑A semantics, Path‑B truth determination logic, realization behavior.

---

# **0. Introduction**

This reference document explains every field that flows through the OuBA primitive.  
These fields originate in the Thought Processor (TP), are frozen by OuBA into the **TP Snapshot State (TPSnS)**, and are consumed by:

- **COB behavior engines**  
- **CST truth‑alignment engines**  
- **Path B truth and safety engines**  
- **SSR storage and replay systems**

The goal is to clarify:

- what each field **is**  
- what it **is not**  
- where it is **produced**  
- where it is **consumed**  
- how it fits into the meaning‑transfer pipeline  
- examples illustrating realistic usage

This document is purely descriptive and contains **no normative requirements**.

---

# **1. Purpose**

The reference provides architectural clarity for all fields present in:

- TP semantic, metadata, context, provenance, and identity‑layer state  
- OuBA input object  
- TPSnS output object  
- SSR storage envelopes  

It enables downstream implementers (COB, CST, Path B, SSR) to understand the meaning and lifecycle of each field without needing to infer semantics from other specifications.

# **3. Field Definitions (with examples)**

Each field is described in terms of meaning, origin, consumption, and a realistic example.

---

## **3.1 `proposition_set[]`**

**Meaning:**  
Structured propositions representing the TP’s interpreted meaning.

**Not:**  
Truth, safety, or global meaning stores.

**Produced by:**  
OB, IB, TB.

**Consumed by:**  
COB, CST, Path B.

**Example:**  
```
[
  "The user is evaluating operating systems.",
  "The user prefers privacy-preserving environments."
]
```

---

## **3.2 `truth_evidence[]`**

**Meaning:**  
Raw evidence supporting or contradicting propositions.

**Not:**  
Truth determinations or safety flags.

**Produced by:**  
OB, IB, TB.

**Consumed by:**  
COB, CST, Path B.

**Example:**  
```
[
  { "type": "support", "detail": "Explicit user statement." },
  { "type": "contradiction", "detail": "Ambiguous referent in clause 2." }
]
```

---

## **3.3 `completion_state`**

**Meaning:**  
Indicates whether meaning construction reached a stable state.

**Produced by:**  
TP completion logic.

**Consumed by:**  
COB, CST, Path B.

**Example:**  
```
"complete"
```

---

# **5. Field Lifecycle Summary**

- All fields originate in TP or OuBA.  
- OuBA freezes them into TPSnS.  
- TPSnS is consumed by COB, CST, Path B, and SSR.  
- None of these fields represent truth or safety determinations; they are inputs to those processes.  
- TPSnS is immutable once produced.

---

| **CST** | semantic envelope, context envelope, provenance envelope, identity‑layer snapshot |
