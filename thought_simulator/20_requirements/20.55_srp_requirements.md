# 20.55 SRP (Semantic Routing Planner) Requirements

**Document ID:** 20.55  
**Version:** 0.1  
**Date:** 2026-06-06  
**Status:** Draft — rough draft (Stage 2, **unapproved** per [20.500](20.500_refactoring_for_dual_TS_pipeline.md))

## Purpose

Defines **Semantic Routing Planner (SRP)** behavior: **cold-path** compilation of epoch-coherent routing tables and **hot-path** table lookup only during Pipeline B realization. SRP SHALL NOT run per-turn compilation on the hot path (HLR-20.012-006).

This module SHALL NOT weaken [20.12_ts_invariants.md](20.12_ts_invariants.md).

**Namespace:** SRP ≠ Relational Basin **RB** (Pipeline A).

## 1. Cold Path vs Hot Path

```text
COLD (off hot path):  policy + registries + compile inputs → routing table epoch → publish routing_epoch_id
HOT (per B pass):     srp_lookup(commit_id, semantic_snapshot_ref, routing_epoch_id) → table row refs only
```

1. **HLR-20.055-001:** SRP table compilation SHALL run only on the **cold path** — not during per-cycle Pipeline B hot-path realization (HLR-20.012-006).
2. **HLR-20.055-002:** Hot-path Pipeline B SHALL perform **lookup only** against an already-published `routing_epoch_id` table set.
3. **HLR-20.055-003:** Hot-path SRP SHALL NOT mutate routing table content, publish new epochs, or invoke compilation routines.

---

## 2. Epoch Publication

4. **HLR-20.055-004:** Each published routing epoch SHALL receive a unique `routing_epoch_id` immutable for the published artifact set.
5. **HLR-20.055-005:** Epoch publication SHALL be atomic: consumers SHALL NOT observe partially published tables for a given `routing_epoch_id`.
6. **HLR-20.055-006:** Epoch publication SHALL record `epoch_publish_record` with `routing_epoch_id`, `table_schema_version`, `policy_signature`, `compile_reason_codes[]`, and content hash.
7. **HLR-20.055-007:** Stale-epoch consumption on the hot path SHALL reject or apply deterministic fallback with audit evidence — never silent mixed-era routing (HLR-20.012-013).

---

## 3. Cold-Path Compile Inputs

8. **HLR-20.055-008:** Cold-path compilation MAY use representative `semantic_core` field **schemas** and policy registries — not live per-turn TP or `lane_id` inputs.
9. **HLR-20.055-009:** Cold-path compilation SHALL be deterministic for identical compile inputs, registry versions, and `policy_signature`.
10. **HLR-20.055-010:** SRP cold path SHALL NOT read `routing_metadata` from Relational Basin **RB** as a compile authority (A-layer routing ≠ B-layer tables).

---

## 4. Hot-Path Lookup

11. **HLR-20.055-011:** Hot-path `srp_lookup` SHALL take `(commit_id, semantic_snapshot_ref, routing_epoch_id, trig_rb_output_ref?)` and return deterministic table row candidate refs for exec planning.
12. **HLR-20.055-012:** Hot-path lookup SHALL read only approved fields from frozen `semantic_core` per 20.206 §3.1.
13. **HLR-20.055-013:** Hot-path lookup SHALL NOT use `seed` to select routing rows (HLR-20.012-010).
14. **HLR-20.055-014:** Lookup misses SHALL emit fixed reason code `SRP_LOOKUP_MISS` and SHALL block `exec_plan` commit unless deterministic fallback row is defined in table metadata.

---

## 5. GB and Audit

15. **HLR-20.055-015:** Epoch publication MAY require GB approval per policy table; denial SHALL leave prior epoch active with audit record.
16. **HLR-20.055-016:** All hot-path lookup decisions SHALL append `srp_lookup_record` to `exec_trace` with `routing_epoch_id`, matched row ref, and `rationale_codes[]`.

---

## 6. Verification Focus

- Hot-path trace contains no SRP compile stages (20.36 Class 1)
- Identical lookup inputs → identical row refs
- Stale `routing_epoch_id` → `REGEN_STALE_EPOCH` / `SRP_STALE_EPOCH`
- No `lane_id` / `tp_id` in SRP inputs or audit records
