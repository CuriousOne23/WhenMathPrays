# 20.40 OB Requirements

**Document ID:** 20.40  
**Version:** 0.3  
**Date:** 2026-06-06  
**Status:** CP-approved — dual-pipeline OB specification (v0.2 CP refinements applied)

## Purpose

Defines deterministic **Object Basin (OB)** behavior, interfaces, invariants, and observability within **Pipeline A (meaning construction)**.

OB is a **local evidence and TR-input extractor** — a deterministic language-pattern detector that emits structured pre-semantic cues for the Thought Router. OB SHALL NOT perform merge/split arbitration (RB), truth interpretation (TB), or semantic routing derivation (`TP.TR`).

This module SHALL NOT weaken invariants in [20.12_ts_invariants.md](20.12_ts_invariants.md).

**Integration contract:** OB → TR-input → `tr_needs_update` flow is normatively specified in [20.37](20.37_thought_router_tr_specification.md) Semantic Interpretation Flow Contract; this document defines OB-specific obligations.

## Parent Scope

- **Pipeline:** Pipeline A only — OB SHALL NOT read `exec_plan` or `exec_trace`
- **Semantic authority:** meaning field semantics defer to [20.31](20.31_semantic_specification.md) §4
- **Messy-input:** classification at OB safe boundaries per [20.17](20.17_messy_input_handling.md)
- **Numeric encoding:** ΔH% contributions use Q32.32 per [20.95](20.95_ts_numeric_policy.md)
- **Bounds:** global overflow and TCU envelopes per 20.30 §8 and [20.90](20.90_ts_parameter_table.md)
- **Does not modify:** 20.10, 20.12, 20.20, 20.30 bootstrap documents

## Non-Goals

- TR field derivation (`TP.TR`) — TR routine only (20.37)
- Routing arbitration, fan-out, lane selection — RB (20.50)
- Truth interpretation channels — TB (20.60)
- Pipeline B realization, OuB expression, IMR corrections
- Geometric trajectory interpretation — DCB (20.106) influences family selection only

## 1. Dual-Pipeline Boundary Discipline

| Concern | OB posture |
|---------|------------|
| `semantic_core` | Writes lane-local evidence and TR-input projections; commits via Merge/`mtp_update` — not direct envelope bypass |
| `TP.TR`, `thought_router_fields` | **No write**; may set `tr_needs_update = true` |
| `exec_plan`, `exec_trace`, `supervisory` | **No read/write** |
| `routing_epoch_id` | **No read/write** |
| `truth_hypotheses` | **No read, no write**; truth evaluation is downstream (TB / 20.140) |
| `messy_input_record` | MAY append/classify at safe boundaries; **no resolve/smooth/clear** of contradiction or underspec |
| Seed | **SHALL NOT influence** OB activation or evidence outputs (HLR-20.012-010) |

**Pipeline B forbidden:** OuB, OpBeh/OBG/XlateR, IMR, SRP SHALL NOT alter OB outputs retroactively or mutate OB-derived meaning in `semantic_core` (20.17).

## 2. OB Input and Output Contracts

### 2.1 Input (lane-local TP view)

OB SHALL accept a deterministic lane-local TP input containing (HLR-20.040-021):

- visible and suppressed semantic projection fields
- ΔH% potential (Q32.32)
- lane identifier and routing context from RB
- lineage/provenance fields
- read-only MTP / `semantic_core` snapshot fields required for local pattern extraction
- `policy_signature` (read-only bounds context)

OB SHALL NOT depend on TP creation order, allocation sequence, or address identity for output derivation (HLR-20.040-040).

**Approved MTP / `semantic_core` read set (HLR-20.040-043):** OB MAY read only lane-local projection fields, `propositions[]` refs required for pattern anchoring, `lineage[]` context, `semantic_tags[]` (meaning-layer only), `messy_input_record` (read-only classifier context), `overflow_metadata`, `stability_metadata`, `policy_signature`, and `mtp_snapshot_id`. OB SHALL NOT read `truth_hypotheses`, `thought_router_fields`, `done_state` commitment fields, or any execution/supervisory envelope fields.

### 2.2 Output (deterministic OB record)

OB SHALL emit (HLR-20.040-022):

```text
ob_output {
  evidence_fields[],        // canonical sort by evidence_id
  tr_input_fields{},        // pre-semantic TR-input per 20.37 §4.1
  delta_h_contribution,     // Q32.32
  delta_h_missing_mass,     // Q32.32
  lineage_additions[],      // canonical ordering per 20.95
  activation_metadata{},
  execution_diagnostics{},
  messy_input_delta?,       // when detector fires at OB boundary
  overflow_metadata?        // when bounds exceeded
}
```

**TR-input fields (minimum):** pattern IDs, clause boundaries, negation markers, modality markers, syntactic shape, raw deltaH (pre-TR), provenance, routing metadata, structural cues — per [20.37](20.37_thought_router_tr_specification.md) §4.1.

**Dirty flag:** when OB writes or updates TR-input or other semantic-relevant TP fields, OB SHALL set `TP.tr_needs_update = true` and SHALL NOT write `TP.TR` (20.37 §3.2–3.3).

**`activation_metadata{}` ordering (HLR-20.040-042):** Nested keys SHALL sort lexicographically; ID arrays (`pattern_family_ids[]`, `lane_refs[]`) SHALL sort by stable ID; numeric activation weights SHALL be canonical Q32.32 before export and replay diff.

## 3. OB Role — Pattern Detector, Not Interpreter

OB SHALL function as a deterministic **language-pattern detector** (HLR-20.040-023):

- identifies pattern-family signatures in lane-local TP views
- emits structured evidence and TR-input cues
- SHALL NOT perform semantic interpretation, stance assignment, inference, or correction
- SHALL NOT interpret `TP.TR` semantics (read for bookkeeping only per 20.37)

OB SHALL be a **semantic/stance basin for local evidence extraction**; OB SHALL NOT be classified as a geometric meta-basin (HLR-20.040-027).

**DCB:** geometric meta-basin; MAY influence OB family selection through TR routing hints only; SHALL NOT perform OB semantic extraction (HLR-20.040-028).

---

## 4. Messy-Input at OB Safe Boundaries

Per [20.17](20.17_messy_input_handling.md), OB participates in deterministic messy-input detection at safe boundaries:

| Class | OB obligation |
|-------|----------------|
| `MI_CONTRA` | Emit evidence supporting parallel traces; set `conflict_flag` pathway data; **no single-winner collapse** |
| `MI_VAGUE` | Surface underspec cues in evidence; **no slot fill** |
| `MI_AFFECT` | Tag affect-bearing pattern families; **no auto-resolve** of vagueness or contradiction |
| `MI_INCOMP` | Surface missing-slot cues; **no generative completion** |
| `MI_NOISE` | Spelling-independent concept-based activation (HLR-20.040-007, 20.17-018) |

**Detector order** when multiple classes apply at OB: **MI_CONTRA → MI_VAGUE → MI_AFFECT → MI_INCOMP → MI_NOISE**; exported `messy_input_class[]` uses canonical lexicographic sort (20.17-038).

Messy-input tag changes at OB SHALL set `tr_needs_update = true` (20.37-056).

---

## 5. ΔH%, Bounds, and Overflow

- OB SHALL emit bounded ΔH% contribution and missing-mass records compatible with Merge semantics (HLR-20.040-005, -006); stored values **Q32.32**, −0→+0 per 20.95.
- OB SHALL enforce 20.30 §8 bounds: activation bounds, evidence payload bounds, per-basin TCU envelopes (HLR-20.040-024).
- On exceedance, OB SHALL emit canonical overflow telemetry per 20.30 §8.3: `overflow_flag`, `overflow_type`, `overflow_source_basin`, `overflow_cycle`, `truncated_fields`, `ΔH%_normalization_applied`, `tcu_overrun_amount` (HLR-20.040-025).
- Degradation SHALL be deterministic; **no silent evidence drop** (HLR-20.040-026).
- Under overflow, messy-input primary flags (`conflict_flag`, `underspec_flag`) SHALL be preserved before optional field pruning (20.17-031).

---

## 6. Replay and Determinism

- OB outputs SHALL reproduce from `(lane-local TP view, read-only MTP context, policy_signature)` — **seed excluded** (HLR-20.040-009, HLR-20.012-010).
- Strip replay removing `exec_plan`/`exec_trace` SHALL leave OB-committed evidence in `semantic_core` stable for Pipeline A-only equivalence (20.36 Class 1).
- Evidence and TR-input serialization SHALL use canonical ordering before hash/replay diff (20.95).

## Worked Example — OB → TR-Input → TR

| Step | Actor | Outcome |
|------|-------|---------|
| 1 | RB | Routes TP to OB lane |
| 2 | OB | Detects pattern family; writes `tr_input_fields` into `TP.input_fields` |
| 3 | OB | Sets `tr_needs_update = true`; does **not** write `TP.TR` |
| 4 | OB | Emits `delta_h_contribution` (Q32.32) + evidence_fields |
| 5 | RB | Sees stale flag; routes to TR routine |
| 6 | TR | Derives `TP.TR` from TR-input + read-only MTP |
| 7 | Merge/`mtp_update` | Evidence projects into `semantic_core` |
| 8 | Strip replay | Pipeline B removed → OB evidence + TR-input history unchanged |

## Normative Requirements

1. HLR-20.040-001: OB SHALL process lane-local TP views only.
2. HLR-20.040-002: OB activation SHALL be determined by deterministic routing, lane projection, and firing-order rules for identical TS state and inputs.
3. HLR-20.040-003: OB SHALL NOT perform merge or split arbitration.
4. HLR-20.040-004: OB execution ordering SHALL be deterministic under identical scheduler inputs.
5. HLR-20.040-005: OB SHALL emit structured local evidence fields and bounded ΔH% contribution records.
6. HLR-20.040-006: OB SHALL preserve ΔH% contribution and missing-mass accounting compatibility with downstream merge semantics.
7. HLR-20.040-007: OB SHALL treat semantically equivalent noisy surface forms as concept-equivalent for activation and evidence extraction.
8. HLR-20.040-008: OB SHALL NOT perform probabilistic inference, stochastic correction, or hallucinated content insertion.
9. HLR-20.040-009: OB outputs SHALL be deterministic and reproducible for identical lane input, MTP context, and `policy_signature`; seed SHALL NOT influence OB outputs.
10. HLR-20.040-010: OB SHALL expose deterministic test interfaces with explicit inputs, expected outputs, invariants, and failure modes.
11. HLR-20.040-011: OB SHALL expose test hooks sufficient for unit, integration, system, and property-based verification.
12. HLR-20.040-012: OB lifecycle transitions (entry, running, completion/exit) SHALL be explicitly logged and observable.
13. HLR-20.040-013: OB SHALL expose observability data required by MB pathways, including activation context, lane identifiers, evidence payloads, and ΔH% attribution.
14. HLR-20.040-014: OB telemetry SHALL support deterministic diagnostic consumption by GB, OuB, and IB without mutating OB core semantics.
15. HLR-20.040-015: OB SHALL define measurable TCU budgets (min/typ/max) and per-tick TCU reporting fields.
16. HLR-20.040-016: OB overload/degradation behavior SHALL be deterministic, policy-bounded, and auditable.
17. HLR-20.040-017: OB behavior SHALL be platform-independent and SHALL NOT depend on hardware-, OS-, or runtime-specific nondeterministic effects.
18. HLR-20.040-018: OB contracts SHALL prioritize top-down thought-processing semantics over implementation-specific mechanics.
19. HLR-20.040-019: OB interfaces and internal state representation SHALL remain modifiable, debuggable, and architecturally transparent.
20. HLR-20.040-020: OB documentation artifacts (contracts, invariants, and diagnostics fields) SHALL remain complete and version-aligned with TS architecture updates.
21. HLR-20.040-021: OB SHALL accept a deterministic lane-local TP input containing visible semantic fields, suppressed semantic fields, ΔH% potential, lane identifier, routing context, lineage/provenance fields, and MTP snapshot fields required for local pattern extraction.
22. HLR-20.040-022: OB SHALL emit a deterministic output object containing structured evidence fields, TR-input structural cues, ΔH% contribution, ΔH% missing-mass record, updated lineage/provenance fields, OB activation metadata, OB execution diagnostics, and observability/telemetry fields required by MB, GB, OuB, and IB.
23. HLR-20.040-023: OB SHALL function as a deterministic language-pattern detector, identifying pattern-family signatures in lane-local TP views and emitting structured evidence without performing semantic interpretation, inference, or correction.
24. HLR-20.040-024: OB SHALL enforce applicable global boundedness constraints defined in 20.30 section 8, including OB activation bounds, evidence payload bounds, and per-basin TCU envelopes.
25. HLR-20.040-025: When a global bound condition affects OB execution, OB SHALL emit deterministic overflow/degradation tags and stability telemetry conforming to the canonical overflow field schema in 20.30 section 8.3.
26. HLR-20.040-026: OB degradation behavior under global-bound exceedance SHALL follow deterministic, policy-bounded actions and SHALL NOT silently drop evidence fields without explicit tagging and logging.
27. HLR-20.040-027: OB SHALL be a semantic/stance basin for local evidence extraction; OB SHALL NOT be classified as a geometric meta-basin.
28. HLR-20.040-028: DCB is a geometric meta-basin that MAY influence OB family selection through TR routing hints but is not an OB and SHALL NOT perform OB semantic extraction.
29. HLR-20.040-029: OB SHALL operate exclusively in Pipeline A; SHALL NOT read `exec_plan` or `exec_trace` (HLR-20.038-021).
30. HLR-20.040-030: OB SHALL write TR-input fields to `TP.input_fields` and SHALL set `tr_needs_update = true` when semantic-relevant outputs change; OB SHALL NOT write `TP.TR` (20.37).
31. HLR-20.040-031: OB SHALL NOT read `TP.TR` for semantic derivation; optional read for multi-TP slot bookkeeping only (20.37 §2.2).
32. HLR-20.040-032: OB SHALL NOT write, read for derivation, or encode `routing_epoch_id`; SHALL NOT read or write `truth_hypotheses` (HLR-20.040-041).
33. HLR-20.040-033: OB messy-input classifiers SHALL follow 20.17 detector order and canonical export sort; OB SHALL NOT smooth contradiction, fill underspec slots, or clear messy-input tags.
34. HLR-20.040-034: OB ΔH% contribution and missing-mass fields SHALL use canonical Q32.32 per 20.95; comparisons and replay export SHALL use canonical integer form.
35. HLR-20.040-035: OB evidence and TR-input arrays SHALL use deterministic canonical ordering before export, hash, and replay diff per 20.95/20.39.
36. HLR-20.040-036: Strip replay removing Pipeline B envelopes SHALL preserve OB-committed evidence in `semantic_core` for Pipeline A-only equivalence (20.36 Class 1).
37. HLR-20.040-037: GB and MB MAY consume OB telemetry read-only; GB SHALL NOT mutate OB outputs or write `TP.TR`/`tr_needs_update` on OB's behalf.
38. HLR-20.040-038: Under `overflow_flag`, OB SHALL preserve `conflict_flag` and `underspec_flag` primary markers before optional field pruning (20.17-031).
39. HLR-20.040-039: OB SHALL NOT perform merge/split, routing fan-out decisions, or inquiry instantiation — those remain RB/GB responsibilities.
40. HLR-20.040-040: OB output derivation SHALL NOT depend on TP creation order, allocation sequence, or container address identity; only explicit canonical lane inputs and stable IDs MAY influence outputs.
41. HLR-20.040-041: OB SHALL NOT read `truth_hypotheses` from MTP or `semantic_core` for pattern extraction or TR-input derivation; truth evaluation consumes OB evidence downstream via TB (20.140).
42. HLR-20.040-042: `activation_metadata{}` nested keys and ID arrays SHALL use deterministic canonical ordering before export, hash, and replay diff — lexicographic key sort; stable-ID array sort; numeric weights canonical Q32.32.
43. HLR-20.040-043: OB SHALL read only the approved MTP/`semantic_core` field set enumerated in §2.1; reads outside that set SHALL be treated as conformance failures.

## OB Invariants

- **Determinism:** identical effective input state yields identical OB activation and output semantics.
- **Isolation:** OB SHALL not assume RB routing authority, TB truth-interpretation authority, or TR semantic derivation authority.
- **Auditability:** each OB output SHALL be attributable to explicit lane input and deterministic processing steps.
- **TR boundary:** OB signals TR staleness; TR alone commits `TP.TR`.

## Conformance

Implementation conforms when:

- OB processes lane-local views only; no exec-envelope access
- TR-input written; `tr_needs_update` set on semantic-relevant changes; `TP.TR` never written by OB
- messy-input detection follows 20.17 order without resolution/smoothing
- ΔH% uses Q32.32; canonical array ordering in replay export
- overflow preserves primary messy-input flags
- seed change does not alter OB outputs for fixed inputs
- strip replay preserves OB evidence in `semantic_core`
- OB does not read `truth_hypotheses`
- `activation_metadata{}` uses canonical nested ordering in replay export
- OB reads limited to approved MTP/`semantic_core` field set (§2.1)

## Verification Focus

- 20.36 Class 1: strip B → OB evidence stable in `semantic_core`
- 20.36 Class 2: overflow preserves `conflict_flag`/`underspec_flag` through OB path
- 20.37 integration: OB sets dirty flag; TR clears only after recompute
- Golden fixture rejects non-canonical evidence array ordering
- Noisy-input spelling variants produce identical concept activation (HLR-007)
- TP creation-order permutation produces identical OB output bytes
- Fixture rejects non-canonical `activation_metadata` key ordering
- Harness rejects OB reads outside approved MTP field allowlist
