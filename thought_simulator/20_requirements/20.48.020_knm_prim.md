# **20.48.020_knm_prim.md — KnM Primitive Specification**

## **1. Introduction**

The **Knowledge Medium Primitive (KnM)** is the second grounding stage in the TS knowledge pipeline.  
It operates immediately after **KnC** has produced coarse grounding and before **KnF** performs fine grounding.

KnM performs **medium‑depth grounding**, attaching contextual, domain‑specific, and ambiguity‑resolving knowledge to the SSR datastream. This grounding tier is more precise than KnC but intentionally less granular than KnF, providing TS with a balanced abstraction tier for Path B expression and entropy‑conditioned routing.

KnM is the **moderate‑precision, moderate‑entropy** grounding stage, responsible for resolving ambiguity that coarse grounding cannot address.

---

## **2. Purpose**

The purpose of KnM is to:

- attach **medium identity**, **medium relations**, **medium domain anchors**, and **medium qualifiers** to SSR‑K,
- compute **medium grounding entropy** $H\_{Kn_{medium}}$,
- populate the **medium abstraction tier** for Path B,
- resolve lexical ambiguity using contextual cues,
- interface with the grammar‑atomic **KnDt** to retrieve medium‑depth entries,
- prepare SSR‑K for fine grounding by KnF.

KnM ensures TS has a **contextual, domain‑aware grounding tier** available for expression or surgical questioning.

---

## **3. Discussion of the KnM Block**

KnM is the **second grounding primitive** in the KnB pipeline:

```
Path A → KnC → KnM → KnF → Path B
```

KnM reads the SSR datastream produced by KnC and extracts:

- coarse identity anchors  
- coarse relational primitives  
- coarse domain anchors  
- coarse qualifiers  
- semantic tags  
- proposition fragments  
- contextual indicators  
- domain‑specific hints  

KnM then queries **KnDt** using these contextual and domain‑specific indicators.  
KnDt returns **medium‑depth grammar‑atomic entries**, which KnM attaches to SSR‑K in the **medium tier fields**.

KnM performs:

- contextual disambiguation,  
- domain‑specific refinement,  
- moderate truth validation,  
- ambiguity resolution.

KnM does **not** perform:

- fine identity resolution,  
- deep truth validation,  
- multi‑hop grounding,  
- semantic inference beyond medium depth.

KnM computes:

$$
H\_{Kn_{medium}} = 1 - \frac{precision_{medium}}{max_{precision}}
$$

This entropy value is used by Path B to determine whether medium expression is appropriate or whether surgical questioning is required.

---

## **4. Field Definitions**

### **4.1 Fields Read from SSR**

KnM reads the following SSR fields:

- `identity_coarse[]`  
- `relation_coarse[]`  
- `domain_anchor_coarse[]`  
- `qualifier_coarse[]`  
- `truth_validation_coarse[]`  
- `semantic_tags[]`  
- `proposition_set[]`  
- `lane_local_identity`  
- `KnDt_keywords[]`  
- `KnDt_addresses[]`  
- `delta_h_percent` ($H_{SSR}$)  
- `policy_markers[]`

These fields provide the lexical, semantic, and contextual cues required for medium grounding.

### **4.2 Fields Written to SSR‑K**

KnM writes the following fields:

- `identity_medium[]`  
- `relation_medium[]`  
- `domain_anchor_medium[]`  
- `qualifier_medium[]`  
- `truth_validation_medium[]`  
- `H_Kn_medium`  
- `Kn_level = "KnM"`  

These fields form the **medium abstraction tier** consumed by KnF and Path B.

---

## **5. Interface to KnDt**

KnM interfaces with **KnDt (Knowledge Database)** using:

- `KnM_REQUEST`  
- `KnM_RESULT`  
- `KnM_VALIDATE`

KnM performs the following steps:

1. Extract contextual indicators from SSR.  
2. Issue a `KnM_REQUEST` to KnDt.  
3. Retrieve medium‑depth grammar‑atomic entries via `KnM_RESULT`.  
4. Validate grounding using `KnM_VALIDATE`.  
5. Write medium grounding fields into SSR‑K.  
6. Compute $H\_{Kn_{medium}}$.

KnDt returns:

- medium identity anchors  
- medium relational primitives  
- medium domain anchors  
- medium qualifiers  
- medium truth‑validation primitives  

KnM does not modify KnDt and does not perform multi‑hop queries.

## **6. SHALL Requirements (HLRs)**

### **Identity Grounding**
- **HLR-20.48.020-001** — KnM **shall** attach `identity_medium[]` entries derived from contextual identity anchors returned by KnDt.  
- **HLR-20.48.020-002** — KnM **shall** refine identity beyond coarse grounding but shall not perform fine identity resolution.

### **Relation Grounding**
- **HLR-20.48.020-003** — KnM **shall** populate `relation_medium[]` using contextual relational primitives retrieved from KnDt.  
- **HLR-20.48.020-004** — KnM **shall** resolve relational ambiguity using contextual cues.

### **Domain Anchors**
- **HLR-20.48.020-005** — KnM **shall** populate `domain_anchor_medium[]` using domain‑specific anchors from KnDt.  
- **HLR-20.48.020-006** — KnM **shall** refine domain anchors beyond coarse grounding but shall not perform fine domain resolution.

### **Qualifiers**
- **HLR-20.48.020-007** — KnM **shall** attach `qualifier_medium[]` entries representing contextual descriptive features.  
- **HLR-20.48.020-008** — KnM **shall** not attach fine qualifiers.

### **Truth Validation**
- **HLR-20.48.020-009** — KnM **shall** populate `truth_validation_medium[]` using medium truth‑validation primitives.  
- **HLR-20.48.020-010** — KnM **shall** not perform deep truth validation.

### **Entropy**
- **HLR-20.48.020-011** — KnM **shall** compute $H\_{Kn_{medium}}$ using the formula:
  
$$
H\_{Kn_{medium}} = 1 - \frac{precision_{medium}}{max_{precision}}
$$  

- **HLR-20.48.020-012** — KnM **shall** write `H_Kn_medium` into SSR‑K.

### **SSR‑K Update**
- **HLR-20.48.020-013** — KnM **shall** set `Kn_level = "KnM"` in SSR‑K.  
- **HLR-20.48.020-014** — KnM **shall** not overwrite coarse or fine fields.

### **Pipeline Behavior**
- **HLR-20.48.020-015** — KnM **shall** operate deterministically and shall not perform inference beyond medium grounding depth.  
- **HLR-20.48.020-016** — KnM **shall** prepare SSR‑K for KnF without altering Path A fields.

## **7. Use by Future TS Blocks**

### **KnF**
KnF reads:

- `identity_medium[]`  
- `relation_medium[]`  
- `domain_anchor_medium[]`  
- `qualifier_medium[]`  

KnF uses these as **contextual anchors** for fine grounding.

### **Path B**
Path B uses:

- `identity_medium[]`  
- `relation_medium[]`  
- `domain_anchor_medium[]`  
- `qualifier_medium[]`  
- `truth_validation_medium[]`  
- `H_Kn_medium`

Path B selects medium expression when:
  
$$
H_{total} = H_{SSR} + H\_{Kn_{medium}}
$$  

falls within the medium‑entropy range.

### **Surgical Questioning**
If medium grounding is ambiguous, Path B uses medium fields to generate targeted clarification questions.

---

## **8. Conclusion**

KnM is the contextual grounding primitive in TS.  
It attaches medium‑depth, domain‑aware knowledge to SSR‑K, resolving ambiguity that coarse grounding cannot address. KnM interfaces with KnDt, computes medium grounding entropy, and prepares SSR‑K for fine grounding by KnF.

KnM is deterministic, contextual, and essential for TS’s entropy‑aware expression pipeline.
