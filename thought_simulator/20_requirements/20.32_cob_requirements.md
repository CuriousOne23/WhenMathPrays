## Purpose

COB is the Conversation Object Basin. It maintains identity-layers, referent maps, temporal anchors, discourse anchors, field-importance maps, and identity-layer lineage. COB applies CST correction signals and produces the stabilized identity-layer snapshot consumed by CIL.

COB is the long-horizon identity substrate of the Path-A context layer. It provides the stable, deterministic foundation that CST measures, CIL integrates with short-term cues, and CEx extracts from for TP metadata.

---

## Position in Architecture

COB sits between CST and CIL:

CST → COB → CIL → CEx → CE → TS → COB

COB receives structured meaning output from TS (via SSRGn) and correction signals from CST. It does not interact with OB, IB, RB, TB, InB, OuB, or USP rule content.

COB is the authoritative store of long-horizon conversational identity. Structural changes to identity layers occur only through deterministic lifecycle operations triggered by CST signals or internal capacity rules.

## Normative Requirements

**HLR-20.32-001:** COB maintains identity-layers, referent maps, temporal anchors, discourse anchors, field-importance maps, and identity-layer lineage.  

**HLR-20.32-002:** COB applies CST correction signals to identity-layer structures.  

**HLR-20.32-003:** COB produces the stabilized identity-layer snapshot consumed by CIL.  

**HLR-20.32-004:** COB does not interact with OB, IB, RB, TB, InB, OuB, or USP rule content.  

**HLR-20.32-005:** COB does not perform placeholder promotion, replay/export, compaction, or redaction.  

**HLR-20.32-006:** COB does not participate in Track H USP snapshot versioning.  

**HLR-20.32-007:** COB maintains determinism and replay equivalence for all identity-layer operations.  

**HLR-20.32-008:** COB does not perform semantic interpretation or canonical semantics derivation.  

**HLR-20.32-009:** COB outputs are consumed exclusively by CIL for intake packet formation.  

**HLR-20.32-010:** COB SHALL NOT read or mutate OB, RB, TB, IB, InB, OuB, or MTP internal state.  

**HLR-20.32-011:** COB lifecycle transitions SHALL occur only at deterministic safe boundaries.  

**HLR-20.32-012:** COB maintains versioning and schema stability for all identity-layer structures.  

**HLR-20.32-013:** COB SHALL maintain a maximum of 20 identity layers.  

**HLR-20.32-014:** Each identity layer SHALL conform to the following schema:

```json
IdentityLayer {
    layer_id: StableID,                    // deterministic across replay
    referent_map: ReferentMap,
    lineage: LineageStructure,
    strength: float,                       // centrality to user
    importance: float,                     // centrality to conversation
    ambiguity: float,                      // internal referent conflict
    decay_state: float,
    timestamps: {
        created: TurnID,
        updated: TurnID
    }
}
```

**HLR-20.32-015:** Each referent map entry SHALL conform to the following schema:

```json
ReferentEntry {
    referent_id: StableID,
    surface_forms: [string],               // supports multi-word
    attributes: { key: value },
    strength: float,
    confidence: float,
    ambiguity: float,
    lineage_pointer: StableID,
    timestamps: {
        created: TurnID,
        updated: TurnID
    }
}
```

**HLR-20.32-016:** COB SHALL ingest new meaning exclusively through SSRGn packets using deterministic merge logic.  

**HLR-20.32-017:** When merging new meaning, COB SHALL apply strength-weighted averaging of the form:

```math
new_strength = α * old_strength + (1 - α) * incoming_strength
```

**HLR-20.32-018:** COB SHALL resolve conflicts using confidence weighting, ambiguity penalties, lineage continuity, and CST override signals.  

**HLR-20.32-019:** COB SHALL create a new identity layer only when incoming referents do not match any existing layer above the creation threshold, lineage continuity cannot be established, ambiguity exceeds threshold, CST issues a new-identity signal, or referent cluster analysis indicates a distinct identity domain.  

**HLR-20.32-020:** COB SHALL split an identity layer when ambiguity exceeds threshold, referent clusters diverge, CST issues a split signal, or lineage continuity breaks.  

**HLR-20.32-021:** COB SHALL merge identity layers when referent clusters converge, ambiguity drops below threshold, CST issues a merge signal, or decay suggests consolidation.  

**HLR-20.32-022:** When capacity is exceeded (21st identity), COB SHALL compute an eviction score of the form:

```math
eviction_score = w1*(low strength) + w2*(low importance) + w3*(high decay_state) + w4*(low recency) + w5*(high ambiguity)
```

and SHALL evict the lowest-score layer (or merge first if ambiguity is high).  

**HLR-20.32-023:** COB SHALL apply decay each turn according to:

```math
decay_state = decay_state + β * time_since_update
strength = strength * (1 - γ * decay_state)
importance = importance * (1 - γ * decay_state)
```

**HLR-20.32-024:** COB SHALL prune referents, compress attributes, and summarize lineage when referent count, ambiguity, decay_state, or lineage depth exceed defined limits.  

**HLR-20.32-025:** COB SHALL retire a layer only when decay_state exceeds retirement threshold, both strength and importance fall below minimum, CST issues a retire signal, the referent map collapses, or lineage continuity breaks irrecoverably.  

**HLR-20.32-026:** COB SHALL respond to CST signals (split, merge, weaken, strengthen, freeze, thaw, retire, ambiguity, drift, collapse) using deterministic algorithms and SHALL log all signal applications for replay.  

**HLR-20.32-027:** While frozen, COB SHALL halt merges, splits, pruning, decay, and assignment, and SHALL queue incoming updates for deterministic replay upon thaw.  

**HLR-20.32-028:** COB SHALL detect identity collapse, referent collapse, lineage collapse, and continuity collapse, and SHALL enter recovery mode by freezing, applying deterministic recovery (split/merge/prune/retire/reassign), and thawing.  

**HLR-20.32-029:** COB SHALL guarantee that identical sequences of SSRGn packets and CST signals produce identical identity-layer state, including layer IDs, referent maps, lineage, strength, importance, ambiguity, and decay_state.  

**HLR-20.32-030:** COB SHALL never allow spontaneous creation, deletion, or mutation of identity layers outside of the defined lifecycle rules and CST signals.  

**HLR-20.32-031:** COB SHALL archive lineage upon eviction or retirement rather than delete it.  

**HLR-20.32-032:** COB SHALL enforce deterministic ordering of all identity layers and referent map entries.  

**HLR-20.32-033:** COB SHALL bound the number of referents per identity layer, lineage depth, and ambiguity entries to prevent unbounded growth.  

**HLR-20.32-034:** COB SHALL produce a stabilized identity-layer snapshot after each update cycle for exclusive consumption by CIL.

## Inputs and Outputs

**Inputs:**
- Structured meaning output from TS (via SSRGn packets)
- Correction signals from CST
- Short-term cues from CIL (for integration context only)

**Outputs:**
- Stabilized identity-layer snapshot for CIL
- Referent/temporal/discourse/field-importance structures
- Identity-layer lineage
- Stability metadata (strength, importance, ambiguity, decay_state)

---

## Functional Boundaries

COB is strictly non-semantic and focused on identity-layer maintenance. It does not perform semantic interpretation, placeholder promotion, replay/export, compaction, redaction, or USP snapshot versioning. It does not interact with OB, IB, RB, TB, InB, OuB, or USP rule content.

COB never modifies TP, semantic_core, or Path-B state. Structural changes occur only through the defined deterministic lifecycle operations and CST signals.
