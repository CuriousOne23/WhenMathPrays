## **2. Background**
Following the completion of **20.500 (Dual‑Pipeline Refactor)** and **20.510 (Track H Coordination)**, several A‑side and B‑side runtime modules required alignment:

- TPU (TP‑Update subsystem)  
- ISc (Inference Scorer)  
- Routing modules (SRP, routing tables, TrigRB)  
- XP lifecycle  
- OuB boundaries  
- TR/RB semantic alignment  
- Implementation guidance  
- Core data structures  

These modules were originally drafted in parallel but had never undergone a **full cross‑document consistency sweep**.

This refactor closes that gap.

---

## **3. Why This Refactor Was Needed**
This refactor was required to:

1. **Finalize TPU and ISc** as fully Stage‑4 modules  
2. **Align routing** (SRP, routing tables, TrigRB) with A/B pipeline boundaries  
3. **Ensure XP and OuB** follow correct read/write authority  
4. **Align TR and RB** with messy‑input, ΔH%, and routing semantics  
5. **Update implementation guidance** (20.38) to reflect the modern pipeline  
6. **Update core data structures** (20.39) to reflect envelope boundaries  
7. **Re‑validate all 20‑series documents** for invariant compliance  
8. **Ensure no meaning generation** in TPU, ISc, OuB, or routing  
9. **Ensure deterministic replay** across all updated modules  

This was a **short, surgical refactor**, not a new architecture.

## **5. Program Order**
This refactor followed the same staged structure as 20.510:

1. **Stage 0 — Preconditions**  
   - 20.500 and 20.510 must be complete  
   - All routing modules must be present  
   - TPU and ISc drafts must exist  

2. **Stage 1 — Naming & Wire Resolution**  
   - TPU/ISc naming finalized  
   - Routing table schema finalized  
   - Trigger schema finalized  

3. **Stage 2 — Normative Updates**  
   - TPU and ISc updated  
   - XP and OuB updated  
   - Routing modules updated  

4. **Stage 3 — Cross‑Ref Updates**  
   - 20.12, 20.30, 20.36, 20.90, 20.190, 20.200 updated  

5. **Stage 4 — Serial Review**  
   - Each updated document reviewed individually  
   - TR and RB validated for alignment  

6. **Stage 5 — Boundary Grep**  
   - A/B pipeline boundaries checked  
   - Writer authority checked  
   - Replay invariants checked  

7. **Stage 6 — Close‑Out**  
   - All modules marked Stage‑4 ready  
   - Program closed
