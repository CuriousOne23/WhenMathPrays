# 20.525 20-Series Directory Refactor Plan

## Purpose
This document defines the structured plan to refactor the `thought_simulator/20_requirements/` directory. The refactor will address ordering, self-containment, entanglement, numbering clarity, and separation of concerns while preserving all existing content, HLR numbers (via mapping), and the proven prefix schema.

**Status**: Draft v0.1  
**Date**: 2026-06-22  
**Owner**: Curious One / Grok Collaboration / Copilot

## 1. Numbering Schema (Approved)

**Format**: `20.xxx.yyy`

- **Design Documents (Core Requirements & Architecture)**: `xxx` = 010–499  
  - Increment `xxx` by **10** (start at 010)  
  - `yyy` = attached sub-documents (000–999)

- **Refactor Documents**: `xxx` = 500–599  
  - Increment `xxx` by **5** (start at 505)  
  - Used for mapping, plans, audits, transition docs

- **Reference Documents**: `xxx` = 700–999  
  - Increment `xxx` by **5** (start at 705)  
  - Glossary, white papers moved to reference, architecture notes, etc.

**Master Index**: `20.000_master_index.md` (or similar low number) will list all blocks with purpose and current documents.

## 2. HLR Numbering Handling
Current format: `HLR-20.xxx.yyy-nnn`

- HLR numbers will be updated to match new container numbering.
- A dedicated **Old-to-New HLR Mapping** document (`20.500_old_to_new_hlr_mapping.md`) will record every change.
- No HLR numbers will be deleted or reused — only remapped.
- All references to old HLRs will be updated systematically using the mapping.

## 3. Refactor Objectives (Aligned to User's 9 Points)
1. **Logical Ordering** — Arrange `xxx` blocks by functional/logical flow.
2. **Self-Containment** — Each primitive/process written from its own perspective (inputs, processing, outputs) with minimal cross-references except to approved signal flow docs.
3. **Signal Flow Integration** — Dedicated documents defining mode, execution order, and governing flows. Primitives point to these.
4. **HLR Numbering Cleanup** — Preserve all existing HLR content; only update prefixes via mapping.
5. **Prefix Numbering Sequence** — Consistent use of the new schema.
6. **Refactor Document Separation** — All transition artifacts in 500-series.
7. **Reference Document Separation** — Glossary, papers, etc. moved to 800-series.
8. **Preserve Helpful Prefix Schema** — Carry forward and improve.
9. **Primitive Scope** — Each primitive does one job (or explicitly justify multiples).
