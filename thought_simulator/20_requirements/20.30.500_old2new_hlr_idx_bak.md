## 0. Purpose

This document provides the traceability index between:

- the legacy monolithic 20.30 HLRs (`HLR‑20.030‑001` → `HLR‑20.030‑351`), and  
- the new modular HLRs defined in:

- 20.30.010_ts_ops.md  
- 20.30.020_cycle_alloc.md  
- 20.30.030_tcu_budgeting.md  
- 20.30.040_mcs_rules.md  
- 20.30.050_merge_formal.md  
- 20.30.060_truth_completion.md  
- 20.30.070_tpu_mtp_sem.md  
- 20.30.080_resp_gen_sem.md  

This file does not define new requirements; it records the mapping after all new subfiles exist.

---

## 1. Mapping philosophy

- **Architectural mapping:** each old HLR maps to the new module where its semantics now live.  
- **Splits allowed:** one old HLR may map to multiple new HLRs.  
- **Merges allowed:** multiple old HLRs may map to one new HLR.  
- **NA:** used when a legacy HLR is retired or no longer applicable.

Columns:

- **Old HLR:** legacy identifier (`HLR‑20.030‑xxx`).  
- **New HLR(s):** one or more new identifiers (`HLR‑20.30.xxx.yyy`) or `NA`.  
- **Notes:** split/merged/retired/moved/other clarifications.
