# **20.30.080 — Response Generation Semantics**  
**Status:** Normative (HLR‑20.30.080‑xxx only)  
**Scope:** Expression‑layer semantics, seed isolation, realization mapping  
**Excludes:** Meaning construction (Pipeline A), merge semantics, truth/completion, TPU commit

---

# **0. Purpose**

This document defines the semantics of the **Response Generator (RG)**, the final stage of Pipeline B.  
It describes:

- how the RG converts the frozen MTP into surface‑form output  
- how expressive variability is introduced  
- how the random seed is isolated  
- how deterministic replay is preserved  
- how the RG interacts with the A/B boundary  

The RG **does not construct meaning**.  
It expresses meaning that has already been finalized by Pipeline A.

---

# **1. Response Generator Overview**

The RG is responsible for:

- realization planning  
- expression mapping  
- surface‑form generation  

It consumes:

- the frozen MTP  
- the `commit_id`  
- the response‑generator seed  

The RG is **deterministic given (MTP, seed)**.

It does not:

- modify the MTP  
- alter meaning  
- reinterpret truth or completion  
- perform semantic inference  

It is an **expression‑only** subsystem.

---

# **2. Input to the Response Generator**

The RG receives:

- the frozen MTP snapshot  
- the `commit_id`  
- the response‑generator seed  
- realization metadata from Pipeline B  

The RG treats the MTP as **immutable**.

---

# **3. Realization Planning**

Realization planning determines:

- the structure of the output  
- the ordering of expressed elements  
- the mapping from semantic fields to linguistic constructs  
- the level of expressive detail  

Realization planning is deterministic for a fixed seed.

---

# **4. Expression Mapping**

Expression mapping converts:

- propositions → sentences  
- stance/affect → tone  
- intent → directive/expressive forms  
- semantic tags → structural cues  

Expression mapping is deterministic for a fixed seed and does not modify meaning.

---

# **5. Variability and Seed Isolation**

Expressive variability is introduced **only** through the response‑generator seed.

The seed influences:

- lexical choice  
- phrasing  
- stylistic variation  
- ordering of equivalent expressions  

The seed does **not** influence:

- OB/RB/TB semantics  
- ΔH%  
- truth evaluation  
- completion evaluation  
- merge behavior  
- TPU commit  
- MTP content  

Seed isolation ensures that meaning construction remains deterministic.

---

# **6. Replay Semantics**

Replay equivalence requires:

```
(MTP, seed) → identical output
```

If the seed is unchanged, the RG produces identical surface‑form output.  
If the seed changes, meaning remains identical but expression may vary.

Replay determinism applies only to the expression layer; meaning is fixed by Pipeline A.

---

# **7. Output Structure**

The RG produces:

- a surface‑form response  
- optional structured metadata (e.g., tone, style, realization trace)  
- a deterministic mapping from semantic fields to output segments  

The output is a **pure expression** of the MTP.

---

# **8. Normative Requirements (HLR‑20.30.080‑xxx)**

These are the **only** SHALL‑bearing requirements in this file.

### **HLR‑20.30.080‑001 — Immutable MTP**  
The RG SHALL treat the MTP as immutable and SHALL NOT modify meaning.

### **HLR‑20.30.080‑002 — Deterministic Realization**  
The RG SHALL produce deterministic realization behavior for a fixed (MTP, seed) tuple.

### **HLR‑20.30.080‑003 — Seed‑Isolated Variability**  
Expressive variability SHALL be controlled exclusively by the response‑generator seed.

### **HLR‑20.30.080‑004 — No Semantic Inference**  
The RG SHALL NOT perform semantic inference, reinterpret meaning, or alter truth/completion state.

### **HLR‑20.30.080‑005 — Replay‑Safe Output**  
For identical (MTP, seed) tuples, the RG SHALL produce identical surface‑form output.

### **HLR‑20.30.080‑006 — Deterministic Mapping**  
The RG SHALL map semantic fields to surface‑form constructs using deterministic rules.

### **HLR‑20.30.080‑007 — A/B Boundary Compliance**  
The RG SHALL operate strictly after `mtp_update` and SHALL NOT access pre‑commit semantic state.

### **HLR‑20.30.080‑008 — No Write‑Back**  
The RG SHALL NOT write to TP, MTP, or any Pipeline A structure.

---

# **9. Summary**

20.30.080 defines the TS’s expression layer:

- deterministic realization  
- deterministic expression mapping  
- seed‑isolated variability  
- immutable MTP  
- replay‑safe output  
- no semantic inference  
- strict A/B boundary compliance  

This file completes the definition of Pipeline B.
