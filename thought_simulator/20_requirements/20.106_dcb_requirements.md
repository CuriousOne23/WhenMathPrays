# 20.106 Directional Conversation Basin (DCB) Requirements

**Document ID:** 20.106  
**Version:** 0.3  
**Date:** 2026-06-06  
**Status:** Approved v0.3 — §8 second-pass GATE (2026-06-07; CuriousOne23, Copilot, Grok; boundary check only; no edits)

## Purpose

Defines the **Directional Conversation Basin (DCB)** as a **geometric meta-basin** and non-persistent geometric observer that observes TP trajectory geometry and emits **ephemeral directional-change events** for TR consumption only.

DCB provides geometric routing hints — not semantic meaning. It SHALL NOT perform OB-class extraction, TB interpretation, RB routing, or TR field derivation.

This module SHALL NOT weaken invariants in [20.12_ts_invariants.md](20.12_ts_invariants.md).

**Integration contract:** lifecycle, consumption, and ephemeral-event rules are normatively co-specified in [20.37](20.37_thought_router_tr_specification.md) §4.4 and [20.50](20.50_rb_requirements.md) HLR-20.050-033. Stability qualitative argument: [20.165](20.165_dcb_stability_requirements.md).

Trajectory geometry cross-reference: [20.105_tp_requirements.md](20.105_tp_requirements.md) (TP coordinate fields); numeric encoding of persisted geometry: [20.95](20.95_ts_numeric_policy.md).

## Parent Scope

- **Pipeline:** Pipeline A geometric overlay only — DCB SHALL NOT read `exec_plan` or `exec_trace`
- **Classification:** geometric meta-basin per [20.20](20.20_ts_primitives.md) HLR-20.020-019
- **Stability:** bounded non-expansive feedback per 20.30 HLR-20.030-321 and 20.165
- **Does not modify:** 20.10, 20.12, 20.20, 20.30 bootstrap documents

## Non-Goals

- Semantic interpretation (TB), evidence extraction (OB), routing arbitration (RB)
- `TP.TR` / `thought_router_fields` derivation or mutation
- Messy-input classification or resolution (20.17)
- Numeric invariant thresholds as normative policy (deferred to 20.95 / 50-series per 20.165)
- Persistence of DCB events on TP or in `semantic_core`

## 1. Dual-Pipeline Boundary Discipline

| Concern | DCB posture |
|---------|------------|
| `semantic_core` | **No write** |
| `TP` fields | **No write** (observe geometry from persisted TP state only) |
| `TP.TR`, `thought_router_fields`, `routing_metadata` | **No read for derivation, no write** |
| `messy_input_record` | **No read/write** — geometry only |
| `truth_hypotheses` | **No read/write** |
| `exec_plan`, `exec_trace`, `supervisory` | **No read/write** |
| `routing_epoch_id` | **No read/write** |
| `tr_needs_update` | **No write** (HLR-20.106-020) |
| Seed | **SHALL NOT influence** event emission (HLR-20.012-010) |

**Pipeline B forbidden:** OuB, IMR, SRP SHALL NOT inject, alter, or consume DCB directional-change events.

---

## 2. Definition and Classification

DCB SHALL be classified as a **geometric meta-basin** (HLR-20.106-001):

- SHALL NOT be a semantic or stance basin (OB, TB class)
- SHALL NOT perform meaning construction, semantic interpretation, or OB-class evidence extraction (HLR-20.106-002)
- SHALL NOT overlap OB authority per HLR-20.020-012 (HLR-20.106-003)

---

## 3. Trajectory Geometry (Normative)

DCB observation SHALL depend only on persisted geometric state (HLR-20.106-004–008):

| Quantity | Definition |
|----------|------------|
| **Position** | TP coordinate in trajectory space from persisted TP state |
| **Direction** | Geometric tangent of TP trajectory at observation step |
| **Curvature** | Rate of change of direction vector along trajectory |

Multi-step observation SHALL use consecutive persisted TP instances and MAY use MTP-held **trajectory projection fields** only (not authoritative meaning fields) to relate steps across the conversation horizon (HLR-20.106-007).

Geometry definitions SHALL remain implementation-agnostic in this module; when numeric values are persisted or logged, encoding SHALL follow [20.95](20.95_ts_numeric_policy.md) (HLR-20.106-008).

**Approved read set (HLR-20.106-025, HLR-20.106-035):** DCB MAY read persisted TP trajectory coordinates, direction vectors, step indices, `tp_id`, `lane_id`, and MTP trajectory-projection fields explicitly designated for geometric horizon stitching. DCB SHALL NOT read `propositions[]`, `messy_input_record`, `thought_router_fields`, `routing_metadata`, `truth_hypotheses`, or execution/supervisory envelopes. DCB observation and event emission SHALL depend only on fields in this approved set; any read or implicit dependency on MTP authoritative semantic fields or other TP/MTP fields outside the set SHALL be a conformance failure.

## 4. Directional-Change Events

### 4.1 Emission rules

- DCB SHALL observe TP trajectory within the deterministic TS cycle (HLR-20.106-009)
- DCB SHALL emit events when curvature or directional deviation exceeds a **bounded geometric invariant** (HLR-20.106-010); invariant labels are geometric — numeric thresholds are not normative in this module
- DCB SHALL NOT emit an unbounded number of directional-change events per TP per cycle; per-cycle emission SHALL remain finite and non-expansive (HLR-20.106-036, 20.165)
- Events SHALL be **geometric signals only** — no semantic labels, stance, or meaning categories (HLR-20.106-011)

### 4.2 Ephemeral event schema (minimum)

```text
directional_change_event {
  event_id,                 // deterministic id from (tp_id, cycle_id, step_index, invariant_id)
  tp_id,
  cycle_id,
  step_index,
  deviation_class,          // CURVATURE | DIRECTION (geometric enum)
  invariant_id,             // geometric invariant label
  tangent_ref{},            // read-only geometry snapshot ref
  curvature_ref{},          // read-only geometry snapshot ref
  ephemeral: true           // MUST NOT persist on TP
}
```

**Debug/replay log ordering (HLR-20.106-028):** When event batches are logged off-TP for diagnostics, events SHALL sort by `(cycle_id, step_index, event_id)` lexicographic before hash/export.

### 4.3 Consumption and lifecycle

| Rule | Source |
|------|--------|
| Execute **after OB**, **before TR** in same cycle | HLR-20.106-012, 20.37 §7 |
| Events are **ephemeral TR inputs** — not persisted on TP | HLR-20.106-014, 20.037-047 |
| **RB SHALL NOT** consume events directly | HLR-20.106-015, 20.050-033 |
| TR consumes **only when** `tr_needs_update = true` and RB routes to TR | HLR-20.106-016, 20.037-046 |
| When `tr_needs_update = false`, events are **discarded unused** | 20.37 §4.4 |
| DCB SHALL NOT set `tr_needs_update` | HLR-20.106-020 |

---

## 5. Determinism, and Replay

- DCB is a **bounded geometric observer** prior trajectory direction may influence present routing **only indirectly** through TR consumption. (HLR-20.106-017)
- Feedback SHALL be bounded, non-recursive, and non-expansive (HLR-20.106-018, 20.165)
- DCB SHALL NOT recursively modify its own geometric input state (HLR-20.106-019)
- Events SHALL be **recomputable** from persisted TP trajectory state (+ permitted MTP projection fields) for deterministic replay (HLR-20.106-021)
- Emission SHALL reproduce from `(persisted trajectory state, policy_signature)` — **seed excluded** (HLR-20.106-024)
- DCB SHALL NOT depend on TP creation order or allocation identity (HLR-20.106-029)
- Strip replay: `semantic_core` SHALL NOT require persisted DCB events; TR strip-test replays recompute events from trajectory (20.36 Class 1, HLR-20.106-027)

## Worked Example — Ephemeral Event + TR Gate

| Step | Actor | Outcome |
|------|-------|---------|
| 1 | RB | Routes TP to OB |
| 2 | OB | Writes TR-input; sets `tr_needs_update = true` |
| 3 | DCB | Observes trajectory; curvature invariant exceeded → emits ephemeral event |
| 4 | RB | Sees `tr_needs_update = true`; routes to TR (not downstream TB) |
| 5 | TR | Consumes OB TR-input + ephemeral DCB event; derives `TP.TR` |
| 6 | DCB event | **Not** written to TP or `semantic_core` |
| 7 | Alt path | If `tr_needs_update = false` → DCB event discarded; TR not run |
| 8 | Replay | Recompute identical events from persisted trajectory bytes |

## Normative Requirements

1. HLR-20.106-001: DCB SHALL be classified as a geometric meta-basin element and SHALL NOT be classified as a semantic or stance basin.
2. HLR-20.106-002: DCB SHALL NOT perform meaning construction, semantic interpretation, or OB-class evidence extraction.
3. HLR-20.106-003: DCB SHALL NOT overlap OB authority boundaries defined in HLR-20.020-012.
4. HLR-20.106-004: DCB SHALL depend on TP position as a geometric coordinate in trajectory space derived from persisted TP state.
5. HLR-20.106-005: DCB SHALL depend on TP direction vector as the geometric tangent of the TP trajectory at the observation step.
6. HLR-20.106-006: DCB SHALL depend on curvature as the rate of change of the TP direction vector along the trajectory.
7. HLR-20.106-007: Multi-step trajectory observation SHALL use consecutive persisted TP instances and MAY use MTP-held trajectory projection fields when required to relate steps across the conversation horizon.
8. HLR-20.106-008: Trajectory geometry definitions in this module SHALL remain implementation-agnostic and SHALL NOT prescribe numeric policy (see 20.95 for numeric bounds).
9. HLR-20.106-009: DCB SHALL observe the TP trajectory across steps within the deterministic TS cycle.
10. HLR-20.106-010: DCB SHALL emit directional-change events when curvature or directional deviation exceeds a bounded geometric invariant; the invariant bound SHALL be geometric and SHALL NOT be specified as numeric policy in this module.
11. HLR-20.106-011: Directional-change events SHALL be geometric signals only and SHALL NOT encode semantic labels, stance, or meaning categories.
12. HLR-20.106-012: DCB SHALL execute after TP update and after OB processing, and before the TR routine for the same cycle.
13. HLR-20.106-013: DCB SHALL NOT write to TP fields, MTP authoritative semantic fields, or TP audit records.
14. HLR-20.106-014: DCB directional-change events SHALL be ephemeral TR inputs and SHALL NOT be persisted as TP fields.
15. HLR-20.106-015: RB SHALL NOT consume DCB directional-change events directly.
16. HLR-20.106-016: DCB directional-change events SHALL be consumed by the TR routine only on cycles where `tr_needs_update = true` and RB routes the TP to the TR routine.
17. HLR-20.106-017: DCB SHALL be a bounded feedback element because it uses prior trajectory direction to influence present routing through TR consumption.
18. HLR-20.106-018: DCB feedback SHALL be bounded, non-recursive, and non-expansive.
19. HLR-20.106-019: DCB SHALL NOT recursively modify its own geometric input state.
20. HLR-20.106-020: DCB SHALL NOT set `tr_needs_update`; trajectory-only change SHALL NOT by itself force TR execution.
21. HLR-20.106-021: DCB directional-change events SHALL be recomputable from persisted TP trajectory state (and permitted MTP trajectory projection fields) for deterministic replay.
22. HLR-20.106-022: DCB SHALL operate in Pipeline A only; SHALL NOT read `exec_plan` or `exec_trace` (HLR-20.038-021).
23. HLR-20.106-023: DCB SHALL NOT write or mutate `semantic_core`, `messy_input_record`, `thought_router_fields`, `TP.TR`, or `truth_hypotheses`.
24. HLR-20.106-024: DCB event emission SHALL be reproducible from `(persisted trajectory state, policy_signature)`; seed SHALL NOT influence events (HLR-20.012-010).
25. HLR-20.106-025: DCB SHALL read only persisted TP trajectory geometry and permitted MTP trajectory-projection fields per §3; reads of meaning-layer or execution-layer fields SHALL be conformance failures.
26. HLR-20.106-026: DCB SHALL NOT read `thought_router_fields`, `TP.TR`, `routing_metadata`, `routing_semantics`, or `truth_hypotheses` for event derivation.
27. HLR-20.106-027: Strip replay removing Pipeline B envelopes SHALL NOT require persisted DCB events in `semantic_core`; events SHALL recompute identically from trajectory for TR equivalence (20.36 Class 1).
28. HLR-20.106-028: Off-TP diagnostic event batches SHALL use deterministic sort order `(cycle_id, step_index, event_id)` before export/hash.
29. HLR-20.106-029: DCB event emission SHALL NOT depend on TP creation order, allocation sequence, or container address identity.
30. HLR-20.106-030: Pipeline B modules SHALL NOT inject, modify, or persist DCB directional-change events.
31. HLR-20.106-031: DCB SHALL NOT create, modify, or clear messy-input tags; geometric observation SHALL NOT substitute for 20.17 classifiers.
32. HLR-20.106-032: When DCB is disabled by policy, TR derivation SHALL proceed without geometric hints; conformance harnesses SHALL verify identical semantics to no-event baseline for fixed inputs.
33. HLR-20.106-033: DCB influence on OB family selection SHALL occur only indirectly through TR `routing_semantics` per 20.37-044 — never by direct OB mutation.
34. HLR-20.106-034: DCB SHALL NOT read `routing_metadata` from TP or MTP for trajectory observation or event derivation.
35. HLR-20.106-035: DCB trajectory observation and event emission SHALL depend only on the approved TP/MTP field set in §3; any read or implicit dependency on MTP authoritative semantic fields or other fields outside that set SHALL be a conformance failure.
36. HLR-20.106-036: DCB SHALL NOT emit an unbounded number of directional-change events per TP per cycle; per-cycle emission SHALL remain finite and non-expansive per HLR-20.106-018 (numeric caps deferred to 20.90 / 20.165).

## Functional Boundaries

- **DCB:** geometric trajectory observation and ephemeral event emission only
- **TR:** sole consumer of ephemeral DCB events (when gated)
- **RB:** no direct DCB consumption; routing uses committed `TP.TR` only
- **OB:** semantic evidence extraction; DCB does not replace OB

## Conformance

Implementation conforms when:

- DCB classified as geometric meta-basin; no semantic outputs
- lifecycle ordering post-OB, pre-TR; no TP/`semantic_core` writes
- events ephemeral; recomputable from trajectory; not required in strip replay of `semantic_core`
- `tr_needs_update` gating honored; DCB never sets dirty flag
- RB does not consume events directly
- seed change does not alter events for fixed trajectory
- approved geometry-only read set enforced; no `routing_metadata` reads
- per-cycle event emission finite and non-expansive (HLR-20.106-036)

## Verification Focus

- Identical trajectory → identical event sequence (replay recompute)
- `tr_needs_update = false` → events discarded unused
- TR gate ordering matches 20.37 contract table
- RB routing unchanged by raw DCB events without TR refresh (20.50-033)
- Harness rejects DCB reads of `thought_router_fields`, `routing_metadata`, MTP fields outside approved trajectory-projection set, and messy-input fields
- Harness rejects unbounded per-cycle event emission for fixed trajectory inputs
- DCB-disabled policy path matches no-event baseline
- 20.165 stability prototypes: non-expansive event rate under repeated cycles
