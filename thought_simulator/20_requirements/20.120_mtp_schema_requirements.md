# 20.120 MTP Schema Requirements

**Document ID:** 20.120  
**Version:** 0.2  
**Date:** 2026-06-07  
**Status:** Approved v0.2 — Stage 4 GATE (2026-06-07; CuriousOne23, Copilot, Grok; no edits required)

## Purpose

Defines normative **MTP wire schema** fields required for deterministic replay, audit, CIL/COB/COP integration, and the Pipeline A → Pipeline B handoff. This module **materializes** commit-marker and snapshot-pin fields referenced by [20.115](20.115_mtp_requirements.md) (HLR-20.115-034–039) and [20.206](20.206_pipeline_a_b_synchronization_contract.md) (§2.1 `mtp_commit_record`).

**This module owns:** MTP field names, wire types, ordering tokens, integration pins, and `commit_id` encoding on MTP exports.  
**Sibling authority:** commit semantics and derivation preimage → 20.115; freeze contract → 20.206; `semantic_core` content → 20.31 / 20.39.

**Naming authority:** [20.500](20.500_refactoring_for_dual_TS_pipeline.md) §5 — **`commit_id`** canonical; **`mtp_snapshot_id`** deprecated alias in legacy exports only.

## Parent Scope

| Module | Role |
|--------|------|
| [20.115](20.115_mtp_requirements.md) | MTP lifecycle, `mtp_update`, `commit_id` derivation preimage |
| [20.206](20.206_pipeline_a_b_synchronization_contract.md) | `mtp_commit_record` minimum schema; B read set |

- MTP aggregation / merge algorithms — 20.115  
- `semantic_core` proposition semantics — 20.31  
- XP or `exec_*` envelope fields — 20.205 / 20.39  
- Mechanical rename of legacy `mtp_snapshot_id` in CP-approved basin modules — Stage 4 per-doc / §8 re-review only

## 1. Core Meaning Fields

MTP schema SHALL expose aggregated meaning fields consumed by Pipeline A basins and published (post-commit) to Pipeline B via frozen `semantic_core`.

1. **HLR-20.120-001:** MTP schema SHALL define explicit fields for stance, affect, intent, hypotheses (`truth_hypotheses` or equivalent), and lineage.
2. **HLR-20.120-003:** MTP field updates (pre-commit) SHALL be field-wise deterministic for identical TP inputs, profile state, and signature-bound policies.
3. **HLR-20.120-004:** MTP records SHALL include identifiers required for replay and audit: at minimum `mtp_id`, `cycle_id`, `policy_signature`, `execution_signature`, and append-only audit correlation tokens.

### 1.1 Minimum `semantic_core` export view (normative sketch)

```text
semantic_core_export {
  commit_id,                    // present after mtp_update; see §2
  mtp_id,
  cycle_id,
  semantic_snapshot_ref,          // frozen bytes ref or content hash — §2.2
  propositions[],                 // canonical sort by stable proposition_id
  stance{}, affect{}, intent{},
  truth_hypotheses[],
  lineage[],                      // canonical (module_id, tp_seq, lineage_seq)
  delta_h{},                      // Q32.32 per 20.95
  stability_metadata{},
  overflow_metadata{},
  thought_router_fields{},
  messy_input_record?,
  policy_signature,
  execution_signature
}
```

4. **HLR-20.120-015:** `semantic_core_export` arrays (`propositions[]`, `truth_hypotheses[]`, `lineage[]`) SHALL use deterministic canonical ordering before serialization per [20.95](20.95_ts_numeric_policy.md) and [20.39](20.39_ts_core_data_structures.md) HLR-20.039-019.

## 2. `commit_id` and Commit Record Wire

### 2.1 `commit_id` field

`commit_id` is the canonical MTP commit marker emitted at `mtp_update`. It binds XP, `exec_plan`, and `exec_trace` for one frozen meaning snapshot ([20.206](20.206_pipeline_a_b_synchronization_contract.md) HLR-20.206-004–006).

5. **HLR-20.120-009:** Every post-`mtp_update` MTP export, `mtp_commit_record`, and integration manifest that references a committed snapshot SHALL include **`commit_id`** as a required top-level field.
6. **HLR-20.120-010:** `commit_id` SHALL be immutable for the referenced snapshot; schema SHALL NOT permit in-place mutation of `commit_id` on a committed record.
7. **HLR-20.120-012:** Legacy wire fields named `mtp_snapshot_id` SHALL be treated as a **deprecated alias** for `commit_id` on read paths only; new normative fixtures and schema versions SHALL emit `commit_id` as primary and MAY emit `mtp_snapshot_id` as a mirrored alias until Stage 4 per-doc renames complete ([20.500](20.500_refactoring_for_dual_TS_pipeline.md) §5, [20.115](20.115_mtp_requirements.md) HLR-20.115-038).

### 2.2 `commit_id` derivation and wire encoding (D8 — draft resolution)

**Preimage (authoritative):** per [20.115](20.115_mtp_requirements.md) HLR-20.115-039:

```text
commit_preimage {
  mtp_id,
  cycle_id,
  semantic_core_content_hash,
  policy_signature,
  execution_signature
}
```

8. **HLR-20.120-011:** `commit_id` SHALL equal the lowercase hexadecimal SHA-256 digest (64 characters, no `0x` prefix) of the canonical serialized `commit_preimage` per [20.95](20.95_ts_numeric_policy.md) HLR-20.095-013/018.
9. **HLR-20.120-016:** `semantic_core_content_hash` SHALL be computed from canonical serialization of the committed `semantic_core` export view **excluding** `commit_id`, `mtp_snapshot_id`, and evidence-only timestamp fields.
10. **HLR-20.120-017:** `semantic_snapshot_ref` on `mtp_commit_record` SHALL equal `semantic_core_content_hash` when a content-hash ref is used (open item **D2** in 20.206/20.39 may allow embedded-bytes refs; hash form SHALL remain valid).

### 2.3 `mtp_commit_record` wire schema

Implements [20.206](20.206_pipeline_a_b_synchronization_contract.md) §2.1 and [20.115](20.115_mtp_requirements.md) HLR-20.115-036.

```text
mtp_commit_record {
  commit_id,                    // wire: §2.2
  cycle_id,
  mtp_id,
  policy_signature,
  execution_signature,
  semantic_snapshot_ref,
  commit_reason_codes[],        // canonical sort; e.g. TRUTH_DONE_COMPLETE
  mtp_schema_version,           // e.g. "mtp-1"
  lane_merge_summary_ref?,      // audit only; not a B input
  mtp_snapshot_id?              // deprecated alias; mirror commit_id if present
}
```

11. **HLR-20.120-018:** `mtp_commit_record` SHALL be append-only; implementations SHALL reject updates that alter any field of a persisted record for a given `commit_id`.

## 3. Ordering and Integration Pins (CIL / COB / COP)

### 3.1 Sequence tokens and FIFO integrity

12. **HLR-20.120-005:** MTP schema SHALL include deterministic sequence-token and FIFO index fields required for CIL and COB ordering integrity: at minimum `mtp_seq` (monotonic MTP lifecycle sequence), `integration_seq` (monotonic CIL integration sequence per conversation scope), and `fifo_index` (deterministic queue position evidence on CIL-integrated exports).

Authoritative ordering SHALL derive from these tokens — not wall-clock timestamps ([20.115](20.115_mtp_requirements.md) HLR-20.115-017, [20.33](20.33_cil_requirements.md) HLR-20.032-014).

### 3.2 Snapshot and replay identifiers (D11 — draft resolution)

Integration layers use snapshot pins that MUST align with MTP commit semantics without conflating pre-commit drafts with post-`mtp_update` commits.

| Field | Role | `commit_id` relationship |
|-------|------|--------------------------|
| **`commit_id`** | Canonical committed-snapshot marker | Authority for B binding and committed-state replay |
| **`cil_snapshot_pin`** | CIL coherent-snapshot pin on integration IO | SHALL equal `commit_id` when pinning post-`mtp_update` state; pre-commit intake MAY use `mtp_draft_snapshot_ref` (content hash of draft `semantic_core`) — distinct from `commit_id` |
| **`cob_replay_evidence_ref`** | COB manifest / replay-evidence linkage | SHALL include `commit_id` when referencing committed MTP state |
| **`cop_basis_commit_id`** | COP proposal basis pin | SHALL equal `commit_id` for proposals evaluated against committed meaning ([20.34](20.34_cop_requirements.md) `mtp_snapshot_id` basis field — deprecated alias name) |

13. **HLR-20.120-006:** MTP schema SHALL include `commit_id`, `semantic_snapshot_ref`, `cil_snapshot_pin`, and `cob_replay_evidence_ref` sufficient for CIL snapshot coherence and COB replay-evidence linkage.
14. **HLR-20.120-013:** For any CIL integration event occurring after `mtp_update`, `cil_snapshot_pin` SHALL equal the `commit_id` of the committed snapshot being integrated.
15. **HLR-20.120-014:** COB replay/export manifests that reference MTP meaning state SHALL carry `commit_id`; manifests SHALL NOT rely on `mtp_snapshot_id` alone in new schema versions.

### 3.3 Profile binding and audit correlation

16. **HLR-20.120-007:** MTP schema SHALL include `policy_signature`, `execution_signature`, and `mtp_schema_version` fields required for deterministic profile precedence across CIL, COB, and COP integrations ([20.33](20.33_cil_requirements.md) HLR-20.032-012, [20.32](20.32_cob_requirements.md) HLR-20.031-016).
17. **HLR-20.120-008:** MTP schema SHALL include lifecycle/audit correlation identifiers (`mtp_seq`, `audit_seq`, `integration_seq`) sufficient to trace CIL integration events, COB lifecycle transitions, and COP-visible proposal outcomes in append-only audit chains.

## 4. Schema Versioning

18. **HLR-20.120-002:** MTP schema changes SHALL be versioned via `mtp_schema_version`; incompatible versions SHALL be rejected with deterministic audit reason codes. Backward-compatibility SHALL be reviewed before bumping `mtp_schema_version`.

## 5. Functional Boundaries

| Field group | Pipeline | B-visible? |
|-------------|----------|------------|
| `commit_id`, `semantic_snapshot_ref`, `semantic_core_export` meaning fields | A (published at `mtp_update`) | Yes — read-only via commit index |
| `mtp_seq`, `integration_seq`, `fifo_index`, CIL/COB pins | A + integration layers | Audit / integration only — not B routing inputs |
| `exec_plan`, `exec_trace`, `xp_id` | B | **Forbidden** on MTP schema |

MTP SHALL NOT embed XP or execution-manifold fields ([20.115](20.115_mtp_requirements.md) §7, [20.205](20.205_execution_packet_xp_requirements.md)).

---

## 6. Verification Focus

- `mtp_commit_record` golden fixture with `commit_id` (not legacy alias only)
- Deterministic `commit_id` reproduction from fixed `commit_preimage` (D8)
- Post-`mtp_update` export: `cil_snapshot_pin == commit_id`
- COB replay manifest carries `commit_id` and stable `cob_replay_evidence_ref`
- Legacy read path: `mtp_snapshot_id` alias resolves to same value as `commit_id`
- Strip replay: committed `semantic_core` unchanged by B (cross-ref 20.36 Class 1)
- Schema version reject path for unknown `mtp_schema_version`
