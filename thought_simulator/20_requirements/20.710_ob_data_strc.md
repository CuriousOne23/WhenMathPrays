## **1. Scope**

This document defines the canonical, serialization‑ready data structures for all Object Basin (OB) layers:

- SOB — Structural Object Basin  
- SROB — Structural Refinement Object Basin  
- CnOB — Constraint Object Basin  
- SmOB — Semantic Mapping Object Basin  

These structures are normative and must be used by all TS components, including:

- Path A (normalization, correction, uncertainty reduction)  
- Path B (realization, planning, execution)  
- RB routing  
- Governance and determinism enforcement  
- Replay and provenance systems  

All fields, invariants, and evolution rules defined herein are binding.

---

## **2. Normative Principles**

All OB structures MUST satisfy the following principles:

1. **Determinism:** All outputs must be deterministic and replayable.  
2. **Provenance:** All structures must include complete, traceable provenance.  
3. **Layer Independence:** Each OB layer must depend only on its immediate predecessor.  
4. **Pre‑Semantic Boundaries:** No semantic interpretation is permitted before SmOB.  
5. **Monotonic Entropy Reduction:** Entropy estimates must not increase across layers.  
6. **Non‑Negative Curvature:** Structural transformations must preserve curvature constraints.  
7. **Explicit Uncertainty:** All uncertainty, gaps, and conflicts must be explicitly represented.  
8. **Serialization‑Ready:** All structures must be serializable without loss.  
9. **Monotonic Evolution:** Extensions are permitted; destructive changes require versioning.  
10. **Pluggability:** Rulesets and routing policies must be swappable without structural changes.

These principles are normative and apply to all structures defined in this document.

## **3. Layer Output Structures (Normative)**

### **3.1 SOB — Structural Object Basin**  
**Output Type:** `SOB_ATOM_SET`  
**Purpose:** Canonical structural extraction from raw input.

```
SOB_ATOM_SET {
  version: OBVersion
  atoms: Array<SOB_Atom>
  provenance: InputReference
  metadata: {
    timestamp,
    input_hash,
    entropy_estimate,
    ruleset_id: RulesetID?
  }
}
```

#### **SOB_Atom**
```
SOB_Atom {
  id: AtomID
  type: SOB_TAG
  payload: SOB_Payload
  tags: Array<SOB_TAG>
  position: SourceLocation
  rhythm: RhythmInfo?
  ext: ExtensibleMetadata?
}
```

#### **SOB_Payload (Closed Union)**
```
SOB_Payload =
    TOKEN_DATA
  | SPAN_DATA
  | REL_DATA
  | GROUP_DATA
  | ORDER_DATA
  | PUNCT_DATA
```

---

### **3.2 SROB — Structural Refinement Object Basin**  
**Output Type:** `SROB_GRAPH`  
**Purpose:** Canonical structural graph refinement.

```
SROB_GRAPH {
  version: OBVersion
  nodes: Array<SROB_Node>
  edges: Array<StructuralEdge>
  annotations: Array<Annotation>
  provenance: SOB_Reference
  metadata: {
    structural_signature,
    ruleset_id: RulesetID,
    applied_rules: Array<RuleID>,
    entropy_delta
  }
}
```

---

### **3.3 CnOB — Constraint Object Basin**  
**Output Type:** `CONSTRAINT_LATTICE`  
**Purpose:** Canonical constraint extraction and entailment structure.

```
CONSTRAINT_LATTICE {
  version: OBVersion
  base_graph: SROB_Reference
  constraints: Array<Constraint>
  entailment_edges: Array<EntailmentEdge>
  conflicts: Array<CONSTRAINT_CONFLICT>
  provenance: SROB_Reference
  metadata: {
    ruleset_id: RulesetID,
    lattice_depth,
    entailment_count
  }
}
```

---

### **3.4 SmOB — Semantic Mapping Object Basin**  
**Output Type:** `SEMANTIC_SKELETON`  
**Purpose:** Canonical pre‑semantic mapping and residue extraction.

```
SEMANTIC_SKELETON {
  version: OBVersion
  slots: Array<Slot>
  referents: Array<ReferentAnchor>
  hooks: Array<MappingHook>
  bindings: Array<BindingEdge>
  residue: Array<NodeID | ConstraintID>
  carry_forward: {
    constraints: CONSTRAINT_LATTICE,
    uncertainty: Array<UncertaintyMarker>
  }
  provenance: CnOB_Reference
  metadata: {
    ruleset_id: RulesetID,
    semantic_boundary_markers
  }
  ext: ExtensibleMetadata?
}
```

## **4. Pluggable Behavior (Normative)**

### **4.1 RulesetID**
A versioned identifier for pluggable rule families.  
Rulesets MUST be:

- deterministic  
- monotonic  
- forward‑compatible  
- non‑destructive  

Rulesets MAY be swapped without altering structure definitions.

---

### **4.2 RB_RoutingPolicy**
Canonical routing policy structure.

```
RB_RoutingPolicy {
  signature_strategy: SignatureStrategyID
  ruleset_id: RulesetID?
  residue_weight: float
  binding_weight: float
  threshold: float
  fallback_policy: FallbackStrategy
}
```

All routing decisions MUST be deterministic under a fixed policy.

---

## **5. OB Map & Evolution Rules (Normative)**

The OB Map defines:

- registered OB layers  
- versioned structure definitions  
- allowed extensions  
- deprecation rules  
- monotonic evolution constraints  

Evolution MUST follow:

1. Additive extensions permitted.  
2. Field removal prohibited without version increment.  
3. Semantic changes prohibited without major version increment.  
4. Provenance fields MUST remain stable.  
5. Ruleset behavior MUST NOT alter structural invariants.

---

## **6. Extensibility Rules for Future OB Layers**

Future OB layers MUST:

- register in the OB Map  
- define a canonical output structure  
- preserve all normative principles  
- maintain monotonic entropy behavior  
- maintain deterministic provenance  
- define ruleset hooks  
- define uncertainty propagation rules  

No future layer may violate pre‑semantic boundaries or determinism constraints.
