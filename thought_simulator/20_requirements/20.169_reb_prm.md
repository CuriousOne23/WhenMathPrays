# 20.169 OuBB — Output Builder and Basin Primitive

## Purpose

OuBB is the terminal primitive of Path B. It accepts the partial realization
`tp.rpu_partial` produced by RPU and the realization-layer update fields written
by RPU, applies the assembly function $\Psi$ to format and emit a single,
channel-appropriate, user-visible artifact, and commits the result to
`tp.oubb_out`. OuBB does not perform planning, meaning interpretation, or semantic
modification; it applies only structural assembly, channel formatting, and
audience adaptation to content that RPU has already fully realized.

**[HLR-20.169-001]** The OuBB primitive SHALL accept `tp.rpu_partial` and all
realization-layer update fields written by RPU as its activation inputs, and SHALL
commit all `tp.oubb_out` output fields before Path B execution is considered
complete for the current turn.

## Input Contract

The table below defines all inputs OuBB reads. No other TP field, external store,
or runtime service may be accessed during OuBB execution.

| Field | Source Primitive | Required | Type | Validity Constraint |
|---|---|---|---|---|
| `tp.rpu_partial` | RPU | Required | structured object | must be present; `rpu_status` ∈ {`COMPLETE`, `HALTED`, `ABORTED`} |
| `tp.rpu_partial.rpu_status` | RPU | Required | enum | `COMPLETE`, `HALTED`, or `ABORTED`; any other value is a pre-condition fault |
| `tp.rpu_partial.accumulated` | RPU | Required | structured object | present and non-null when `rpu_status = COMPLETE` or `HALTED`; may be absent when `ABORTED` |
| `tp.rpu_partial.step_records` | RPU | Required | array | non-null; each entry carries `step_id`, `step_status` ∈ {`DONE`, `HALTED`, `SKIPPED`}, and `exec_result` |
| `tp.rpu_partial.reason_code` | RPU | Required | string | non-empty when `rpu_status` ∈ {`HALTED`, `ABORTED`}; empty string when `COMPLETE` |
| Realization-layer update fields | RPU | Required | per RPU output contract | all fields listed in RPU output contract §Realization-layer update fields must be present |
| `tp.truth_tags` | A-side | Required | array | may be empty |
| `tp.safety_flags` | A-side | Required | array | may be empty |

**[HLR-20.169-002]** The OuBB primitive SHALL read only the fields enumerated in
the Input Contract table; it SHALL NOT read from COB, from any meaning-layer field
owned by LI, from any realization substrate field owned by REx, from any plan field
owned by RPlan, or from any representation-layer field owned by TPTB, TPSF, or CoHI.

**[HLR-20.169-003]** The OuBB primitive SHALL perform a pre-condition check before
assembly begins: if `tp.rpu_partial` is absent, if `tp.rpu_partial.rpu_status` is
not a recognised enum value, or if any required realization-layer update field is
absent, OuBB SHALL set `tp.oubb_out.oubb_status` to `SUPPRESSED`, SHALL write
`reason_code = PRE_CONDITION_FAULT`, and SHALL halt without assembling any content.

## Transfer Function

The output status $\sigma_{\text{out}}$ is determined by
`tp.rpu_partial.rpu_status`:

$$
\sigma_{\text{out}} = \begin{cases}
\texttt{SUPPRESSED} & \text{if } \text{rpu}_{status} = \texttt{ABORTED}
                      \text{ or pre-condition fault} \\
\texttt{PARTIAL}    & \text{if } \text{rpu}_{status} = \texttt{HALTED} \\
\texttt{EMITTED}    & \text{if } \text{rpu}_{status} = \texttt{COMPLETE}
\end{cases}
$$

### Suppression Path

When `tp.rpu_partial.rpu_status = ABORTED`, no realization content is available
and no user-visible artifact is emitted.

**[HLR-20.169-004]** When `tp.rpu_partial.rpu_status = ABORTED`, the OuBB
primitive SHALL set `tp.oubb_out.oubb_status` to `SUPPRESSED`, SHALL propagate
`tp.rpu_partial.reason_code` into `tp.oubb_out.reason_code`, SHALL set
`tp.oubb_out.content` to an empty string, and SHALL NOT invoke $\Psi$.

### Partial Assembly Path

When `tp.rpu_partial.rpu_status = HALTED`, the accumulated partial result
$P = \text{tp.rpu}_{partial}.\text{accumulated}$ contains the realization
up to step $s\_{j^{\ast}-1}$. OuBB assembles only the content available in $P$.

**[HLR-20.169-005]** When `tp.rpu_partial.rpu_status = HALTED`, the OuBB
primitive SHALL invoke $\Psi$ on `tp.rpu_partial.accumulated`, SHALL set
`tp.oubb_out.oubb_status` to `PARTIAL`, SHALL propagate
`tp.rpu_partial.reason_code` into `tp.oubb_out.reason_code`, and SHALL emit
only the content derivable from steps marked `DONE` in
`tp.rpu_partial.step_records`.

### Full Assembly Path

When `tp.rpu_partial.rpu_status = COMPLETE`, $P$ contains the full accumulated
realization across all $k$ steps.

**[HLR-20.169-006]** When `tp.rpu_partial.rpu_status = COMPLETE`, the OuBB
primitive SHALL invoke $\Psi$ on `tp.rpu_partial.accumulated` and all
realization-layer update fields, and SHALL set `tp.oubb_out.oubb_status` to
`EMITTED`.

### Assembly Function $\Psi$

Let $P$ denote `tp.rpu_partial.accumulated`, let $\delta$ denote the
realization-layer update fields, let $\chi$ denote the channel identifier, and
let $\alpha$ denote the audience descriptor, both drawn from $\delta$.
$\Psi$ maps these to the final content string $\mathcal{A}$:

$$
\mathcal{A} = \Psi(P,\ \delta,\ \chi,\ \alpha,\ \texttt{tp.safety}_{flags})
$$

$\Psi$ applies three operations in order:

1. **Structural assembly** — assembles $P$'s realized token payload into a
   coherent document structure consistent with $\delta$.
2. **Channel formatting** — formats the assembled structure for $\chi$
   (e.g., email greeting/body/close for `channel = EMAIL`; concise prose for
   `channel = CHAT`).
3. **Audience adaptation** — adapts tone, terminology, and level of detail
   for $\alpha$ without altering the semantic content committed by LI.

**[HLR-20.169-007]** The OuBB primitive SHALL apply $\Psi$ in the order:
structural assembly, then channel formatting, then audience adaptation; it
SHALL NOT reorder these stages or omit any stage on the full or partial
assembly path.

**[HLR-20.169-008]** The OuBB primitive SHALL NOT introduce new semantic
content, new claims, new entities, or new commitments not present in
`tp.rpu_partial.accumulated`; all additions by $\Psi$ SHALL be restricted to
formatting, structural markers, and audience-appropriate phrasing.

**[HLR-20.169-009]** The OuBB primitive SHALL evaluate `tp.safety_flags`
during $\Psi$ and SHALL suppress any content element whose emission would
violate an active safety flag; when suppression reduces
`tp.oubb_out.content` to an empty string it SHALL set
`tp.oubb_out.oubb_status` to `SUPPRESSED` and SHALL write
`reason_code = SAFETY_SUPPRESSED`.

## Output Contract

The table below defines all fields OuBB writes. OuBB is the terminal
primitive; no downstream primitive reads these fields within Path B.

| Field | Type | Legal Values | Semantics |
|---|---|---|---|
| `tp.oubb_out.oubb_status` | enum | `EMITTED`, `PARTIAL`, `SUPPRESSED` | Overall emission outcome for the turn |
| `tp.oubb_out.content` | string | non-empty on `EMITTED` or `PARTIAL`; empty string on `SUPPRESSED` | Final user-visible artifact ready for channel delivery |
| `tp.oubb_out.channel` | string | non-empty; mirrors channel from realization-layer update fields | Channel on which `content` is formatted for delivery |
| `tp.oubb_out.audience` | string | non-empty; mirrors audience from realization-layer update fields | Audience for which `content` has been adapted |
| `tp.oubb_out.reason_code` | string | non-empty on `PARTIAL` or `SUPPRESSED`; empty string on `EMITTED` | Machine-readable cause of non-full emission |
| `tp.oubb_out.step_summary` | array | one entry per `tp.rpu_partial.step_records` entry | Per-step assembly outcome; each entry mirrors `step_id` and `step_status` |

**[HLR-20.169-010]** The OuBB primitive SHALL populate all fields in the
Output Contract table for every execution path (`EMITTED`, `PARTIAL`, and
`SUPPRESSED`); no output field SHALL be left absent or null except where
the table explicitly permits an empty string.

**[HLR-20.169-011]** The OuBB primitive SHALL emit exactly one
`tp.oubb_out.content` value per invocation; it SHALL NOT produce multiple
competing content strings or leave `tp.oubb_out.content` absent on any path.

**[HLR-20.169-012]** The OuBB primitive SHALL NOT write to any meaning-layer
field owned by LI, any realization substrate field owned by REx, any plan
field owned by RPlan, any execution field owned by RPU, or any
representation-layer field owned by TPTB, TPSF, or CoHI.

## When

OuBB runs once per turn. Its position in the Path B execution order is
fixed: after RPU has committed `tp.rpu_partial` and all realization-layer
update fields. OuBB is the last primitive to execute in Path B.

**[HLR-20.169-013]** The OuBB primitive SHALL NOT begin execution until RPU
has written `tp.rpu_partial.rpu_status` to a recognised enum value and all
realization-layer update fields to a completed state for the current turn.

## Why

RPU produces a fully executed partial realization but does not format or
emit it. Separating execution (RPU) from assembly and emission (OuBB) means
formatting and channel logic is isolated in one auditable place. OuBB can
handle degraded inputs from HALTED or ABORTED RPU executions gracefully
without requiring RPU to know anything about channels or audiences. The
three-path design ensures the pipeline always produces a defined output
state — EMITTED, PARTIAL, or SUPPRESSED — rather than silently failing.

## Is Not

OuBB is not a meaning extractor.
OuBB is not a semantic interpreter; it does not alter the meaning committed by LI.
OuBB is not a planner.
OuBB is not a scorer.
OuBB is not a router.
OuBB is not a memory system.
OuBB does not re-enter RPU's execution loop.
OuBB does not perform global inference.
OuBB does not modify COB.

## Example

RPU has set `tp.rpu_partial.rpu_status = COMPLETE` and written
`tp.rpu_partial.accumulated` = $P$ containing a fully realized token payload
for a friendly team-meeting reminder. Realization-layer update fields carry
`channel = EMAIL` and `audience = INTERNAL_TEAM`. `tp.safety_flags` is empty.

Pre-condition check passes. `rpu_status = COMPLETE`. Full assembly path begins.

$\Psi$ stage 1 — structural assembly: $P$'s token payload is assembled into
a document with subject, greeting, body, and closing fields.

$\Psi$ stage 2 — channel formatting: the assembled document is formatted as
email with a greeting line, paragraph body, and sign-off.

$\Psi$ stage 3 — audience adaptation: terminology simplified for
`INTERNAL_TEAM`; tone set to friendly-professional.

No safety flags are active. `tp.oubb_out.content` is set to the formatted
email string. `tp.oubb_out.oubb_status = EMITTED`.
`tp.oubb_out.channel = EMAIL`. `tp.oubb_out.audience = INTERNAL_TEAM`.
`tp.oubb_out.reason_code = ""`. `tp.oubb_out.step_summary` mirrors the three
`DONE` step records from `tp.rpu_partial.step_records`. Path B execution is
complete for the turn.
