# Path A — Meaning Dictionary Index

## 1. Overview

This index describes the canonical Path A meaning dictionary artifacts for the TS system.  
All dev and runtime dictionaries for Path A must be derived from these files and conform to `meaning_schema.yaml`.

- **Domain:** path_a  
- **Dictionary name:** `ts_meaning_dictionary`  
- **Schema:** `meaning_schema.yaml`  
- **Chunk format:** `json.gz`  
- **Revision:** `dct_rev00`  
- **Source corpus:** WordNet raw + TS semantic extensions  

---

## 2. Chunk files (dct_rev00)

The meaning dictionary is stored as a fixed‑size chunked set of JSON/GZ files:

- **Chunk 01:** `meaning_dictionary_01.json.gz`  
- **Chunk 02:** `meaning_dictionary_02.json.gz`  
- **Chunk 03:** `meaning_dictionary_03.json.gz`  
- **Chunk 04:** `meaning_dictionary_04.json.gz`  
- **Chunk 05:** `meaning_dictionary_05.json.gz`  
- **Chunk 06:** `meaning_dictionary_06.json.gz`  

> Each chunk contains a contiguous range of entry IDs and is generated by the `conversion_pipeline` using `ts_entry_builder.py` and `json_gzip_writer.py`.

---

## 3. Indexed fields

The following fields are indexed for fast lookup and routing:

- **Lemma:** canonical lemma string  
- **POS:** part of speech (`noun`, `verb`, `adj`, `adv`)  
- **Primitive class:** TS primitive class associated with the entry  
- **Semantic class:** semantic category for routing and invariants  
- **Cue profile:** semantic cue profile used by Path A primitives  

Sort order for global indices:

1. **lemma**  
2. **pos**  
3. **id**

---

## 4. Entry structure (summary)

Each entry in the meaning dictionary conforms to `meaning_schema.yaml` and includes:

- **id:** unique numeric identifier  
- **lemma:** canonical lemma  
- **pos:** part of speech  
- **gloss:** human‑readable gloss  
- **examples:** example usages  
- **semantic_roles:** optional role annotations (agent, patient, etc.)  
- **meaning_signature:** primitive_class, semantic_class, cue_profile, invariants  
- **routing_signature:** admissible_transitions, envelope_behavior, anomaly_behavior  
- **geometry_signature:** envelope_type, segmentation, admissible_shapes  
- **scalar_fields:** named scalar fields with constraints  

---

## 5. Relationships to other dictionaries

- **Dev dictionary:**  
  - Derived from the meaning dictionary.  
  - Contains additional debugging metadata and inspection logs.  
  - Lives under: `dictionaries/path_a/dev_dictionary/dct_rev00/`.

- **Runtime dictionary:**  
  - Compressed, optimized representation of the meaning dictionary.  
  - Used by Python/C++ runtime and replay engine.  
  - Lives under: `dictionaries/path_a/runtime_dictionary/dct_rev00/`.  
  - PSC dependency example:  
    ```yaml
    dependencies:
      meaning_dictionary: ts_meaning_dictionary
    ```

## 6. Tooling and maintenance

Primary tools for working with the meaning dictionary:

- **Inspection:**  
  - `tools/inspect_chunk.py`  
  - `tools/inspect_chunk_setup.yaml`  
  - `tools/inspect_chunk_users_guide.md`

- **Generation (conversion_pipeline):**  
  - `wordnet_loader.py`  
  - `gloss_extractor.py`  
  - `lemma_normalizer.py`  
  - `primitive_classifier.py`  
  - `cue_envelope_generator.py`  
  - `identity_anchor_generator.py`  
  - `invariant_generator.py`  
  - `routing_signature_generator.py`  
  - `ts_entry_builder.py`  
  - `json_gzip_writer.py`

> Once released, the meaning dictionary is treated as immutable; modifications are performed on the dev dictionary and then re‑generated through the pipeline.
