## 50-Series Glossary

| Term                          | Definition |
|-------------------------------|----------|
| **Governing Basin (GB)**      | The dedicated supervisory subsystem responsible for monitoring stability, detecting issues, and applying safe supervisory actions **without** mutating semantic state. |
| **Signal Monitor**            | Stateless Tier 1 component in the Governing Basin. Detects a specific condition (drift, oscillation, contradiction, population, etc.) and emits a SignalPacket. |
| **Signal Packet**             | Standardized, immutable data structure used for communication from Tier 1 (Signal Monitors) to Tier 2 (Supervisory Integrator). Contains monitor_id, signal_type, value, severity, timestamp, and minimal metadata. |
| **Supervisory Integrator**    | Tier 2 core of the Governing Basin. Collects SignalPackets, resolves conflicts, applies rules, makes final supervisory decisions, and tracks intervention frequency. |
| **Boundary Enforcer**         | Ultra-thin Tier 3 adapter. Applies approved supervisory actions through safe-boundary APIs only. Contains zero semantic logic. |
| **Safe Boundary**             | Explicit, deterministic interface through which the Governing Basin may influence the core TS without violating architectural invariants (non-mutation of semantic state). |
| **Supervisory Action**        | High-level command issued by the Governing Basin (e.g., Continue, Dampen, Slow, Stop/Safe-Mode). |
| **Intervention Frequency**    | Rate at which the Governing Basin issues non-Continue actions. Must be tracked, bounded, and monitored to prevent overload. |
| **Supervisory Decision**      | The output of the Supervisory Integrator containing the chosen action, reason_code, confidence, affected components, and timestamp. |

## Maintenance

This glossary (and its companion `glossary_term_registry.json`) is kept under observation via:

- `../scripts/validate_50_glossary_alignment.py` — non-blocking CI check that warns on drift or new candidate terms when 50-series design `.md` files are added, modified, or deleted.
- `../scripts/update_50_glossary.py` — local helper script. Run it to get a report of what terms appear to be new or stale and to generate review-only proposal files (`--write-proposals`). The script does the scanning work to reduce token usage during development, but **never auto-applies changes**. All updates require human review and explicit decision.

See `50.05_software_spec_construction_guide.md` and `../CONTRIBUTING_CHANGE_WORKFLOW.md` for full process details.
