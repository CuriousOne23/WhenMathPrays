## 1. Purpose and Scope

The **User Shorthand Profile (USP)** stores explicit shorthand rules derived from approved clarification outcomes. Responsibilities:

- versioned rule lifecycle (`ACTIVE` / `SUPERSEDED` / `REVOKED`)
- monotonic `usp_version_id` and content-addressed `usp_version_ref`
- read-only snapshot export for IIInB (`export_snapshot` — ACTIVE rules only)
- deterministic reject on cap overflow and GB veto (no ACTIVE mutation on veto)
- replay-identical active rule sets under identical commit sequences

USP **does not**:

- write TP, MTP, `semantic_core`, `exec_plan`, or `exec_trace`
- accept commits except via UPI ([50.90](50.90_upi_design_spec.md))
- perform per-turn meaning construction

**Cross-layer band:** 40.250 / 30.250 / 10.50.250 / 50.250.

## 3. Contracts and Invariants

- **Read-only IIInB (HLR-006–008):** IIInB loads pinned `usp_version_ref`; snapshot immutable for repair pass; read failures follow deterministic reject policy.
- **Versioning (HLR-009–012):** Each commit advances `usp_version_id`; `usp_version_ref` from [50.42](50.140_core_data_structs_design_spec.md) digest helper; supersede precedence deterministic.
- **Lifecycle (HLR-013–015):** create / supersede / revoke via `apply_commit`; revoked rules excluded from ACTIVE export.
- **GB veto (HLR-014):** veto SHALL NOT create ACTIVE entry; audit-only on veto path.
- **Cap (HLR-016):** active rule cap (default 256) overflow rejects with fixed reason code.
- **Replay (HLR-018–019):** identical commit sequence → identical ACTIVE set and `usp_version_ref`.
- **Struct anchor (HLR-10.50.80-001):** no duplicate snapshot schema — import from 30.140.

## 4. Operation Flow and State Transitions

1. UPI receives `clarification_event` after GB evaluation
2. On approve: `USPStore.apply_commit(pattern, expansion, rule_id, op=create|supersede|revoke)`
3. Store appends `usp_version_record` to audit; bumps `usp_version_id`
4. IIInB calls `export_snapshot()` at repair-pass start (read-only)
5. COB may `pin_usp_snapshot(usp_version_id, usp_version_ref)` for conversation scope

**Reject paths:** cap overflow, GB veto, invalid commit op — fixed reason codes, no ACTIVE mutation on veto.

## 5. Data and IO Contract

**`apply_commit` inputs**

- `pattern`, `expansion`, `rule_id`
- `op`: `create` | `supersede` | `revoke`

**`CommitResult` outputs**

- `usp_version_id`, `usp_version_ref`, `commit_status`, `reason_codes[]`

**`export_snapshot` output**

- `rules[]` — ACTIVE only, canonical ordering per 20.102-019

## 6. Observability and Logging

Every version transition appends audit evidence. Negative paths emit fixed reason codes suitable for replay diff. `usp_version_ref` is the primary replay pin for IIInB and COB.
