# 20.56 Routing Table Schema

**Document ID:** 20.56  
**Version:** 0.1  
**Date:** 2026-06-06  
**Status:** Approved v0.1 — Stage 4 GATE (2026-06-07; CuriousOne23, Copilot, Grok)

## Purpose

Defines the normative **wire schema** for SRP-published routing tables: epoch packaging, lookup rows, registry bindings, and the **invalid-combination matrix** for `(opbeh_id, obg_id, xlater_id)` triples (HLR-20.012-008).

Under multi-core Path A execution (20.115), routing tables SHALL treat any `core_id` and orthogonality-related gating fields as read-only match inputs and SHALL NOT collapse meaning-layer distinctions established by orthogonal Path A instances.


Tables are keyed by `routing_epoch_id` and consumed on the Pipeline B hot path only.

## 1. Epoch Package

```text
routing_epoch_package {
  routing_epoch_id,
  table_schema_version,      // e.g. "rtab-1"
  policy_signature,
  published_at_seq,            // evidence only; not wall-clock authority
  content_hash,

  trigger_index[],             // TrigRB key → row_id lookup
  routing_rows[],
  invalid_triple_matrix[],
  fallback_row_id?,
  registry_bindings {
    opbeh_registry_ref,
    obg_registry_ref,
    xlater_registry_ref
  }
}
```

1. **HLR-20.056-001:** Every published epoch SHALL ship as a single `routing_epoch_package` per HLR-20.055-005.
2. **HLR-20.056-002:** `table_schema_version` SHALL be explicit; incompatible versions SHALL be rejected on load with `RTAB_SCHEMA_REJECT`.
3. **HLR-20.056-003:** `content_hash` SHALL cover canonical serialization of all tables in the package (20.95 ordering).

## 2. Routing Row

```text
routing_row {
  row_id,
  match_key {                  // deterministic match dimensions from semantic_core + TrigRB
    trigger_class?,
    discourse_act?,
    messy_input_class_tag?,     // read-only gating; not A routing_metadata
    done_state_gate?,
    core_id_gate?,             // optional: per-core gating under multi-core Path A
    orthogonality_gate?,       // optional: orthogonality-domain gating
    priority                    // tie-break: lower number wins
  },
  resolved_triple {
    opbeh_id,
    obg_id,
    xlater_id
  },
  rationale_codes[],
  row_valid_from_epoch?,        // optional intra-epoch versioning
  row_valid_to_epoch?
}
```

4. **HLR-20.056-004:** `routing_row` match evaluation SHALL be deterministic and SHALL NOT use latent embeddings or probabilistic scores.
5. **HLR-20.056-005:** When multiple rows match, selection SHALL use lowest `priority` then lexicographic `row_id` tie-break.
- Under multi-core Path A execution, row selection semantics SHALL remain identical per `core_id`; `core_id_gate` MAY restrict the candidate set but SHALL NOT introduce nondeterministic behavior across cores.
6. **HLR-20.056-006:** Rows SHALL reference registry IDs only — not embedded behavior bodies.
  - Routing rows SHALL NOT encode cross-core fusion, reconciliation, or smoothing semantics; any `core_id_gate` or `orthogonality_gate` usage SHALL be gating-only and SHALL preserve meaning-layer distinctions established in Path A.

## 3. Invalid-Combination Matrix

```text
invalid_triple_entry {
  opbeh_id,
  obg_id,
  xlater_id,
  reject_reason_code          // fixed enum
}
```

7. **HLR-20.056-007:** Every epoch package SHALL include `invalid_triple_matrix[]` consulted before `exec_plan` commit (HLR-20.012-008).
8. **HLR-20.056-008:** Invalid triple attempts SHALL reject commit with `EXEC_TRIPLE_INVALID` and SHALL append audit entry to `exec_trace`.
9. **HLR-20.056-009:** Valid triples not listed as invalid SHALL still require registry existence checks per 20.41–20.43.

---

## 4. Trigger Index

10. **HLR-20.056-010:** `trigger_index[]` SHALL map `exec_trigger_id` / trigger class codes from [20.57](20.57_trig_rb_semantic_trigger_requirements.md) to candidate `row_id` lists in canonical sort order.
11. **HLR-20.056-011:** Trigger index keys SHALL NOT alias Thought Router **TR** or Relational Basin **RB** identifiers.

---

## 5. Serialization and CI

12. **HLR-20.056-012:** Routing table fixtures in CI (20.500 §6) SHALL use `routing_epoch_id` + `content_hash` pins for regeneration tests (20.207).
13. **HLR-20.056-013:** Arrays (`routing_rows`, `invalid_triple_matrix`, `trigger_index`) SHALL use canonical stable sort before hash (HLR-20.039-019 pattern).
- When `core_id_gate` or `orthogonality_gate` are present in `match_key`, their serialized representation SHALL follow the same canonical ordering rules and SHALL NOT affect determinism beyond explicit match filtering.
14.  **HLR-20.056-014:** Routing tables SHALL NOT contain `lane_id`, `tp_id`, or TP field paths.

---

## 6. Fallback Row

15. **HLR-20.056-015:** If `fallback_row_id` is present, `SRP_LOOKUP_MISS` SHALL resolve to that row with `rationale_codes[]` containing `FALLBACK_ROW_USED`.
16. **HLR-20.056-016:** Fallback triple SHALL still pass invalid-matrix and registry validation.
