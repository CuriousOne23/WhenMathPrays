# **1. Purpose**

The **Inquiry Basin (IB)** is a **post‑TS, post‑Merge, post‑TPU** subsystem responsible for:

- detecting unresolved ambiguity  
- managing inquiry state  
- generating clarification proposals  
- tracking inquiry evolution  
- supporting GB‑supervised inquiry resolution  
- providing structured inquiry metadata for Truth/Done and GBIB  

IB is **not** part of Pipeline A.  
IB performs **no lane‑parallel computation**, **no TP writes**, and **no meaning construction**.

IB operates **only** on:

- frozen `semantic_core`  
- frozen TP(N+1)  
- truth_interpretation_input{} from TB  
- GB supervisory context  

IB is part of the **Truth/Inquiry subsystem**, not the meaning‑construction pipeline.

---

# **2. Architectural Positioning (Updated)**

IB sits **after** the entire inference path and after TB:

```
Pipeline A:
    InB → IIInB → CEx → CE → ISc → Merge → TPU → TP(N+1) → MTP semantic_core

Post‑TS (Path‑B):
    TB → IB → GBIB → GB → (optional) clarification → CIL → UPI
```

Key points:

- IB is **not** a Pipeline‑A basin.  
- IB is **not** lane‑parallel.  
- IB does **not** write to TP or MTP.  
- IB is **read‑only** with respect to all meaning‑bearing structures.  
- IB is **supervised entirely by GB**.  
- IB is **paired with TB** as part of the truth/inquiry system.

---

# **3. Scope**

IB:

- detects ambiguity, contradiction, and missing structure  
- manages inquiry state machines  
- generates clarification proposals  
- tracks inquiry evolution  
- logs inquiry metadata (in its own subsystem, not TP)  
- supports GB‑supervised inquiry resolution  
- produces inquiry outputs for GBIB and 20.140  

IB SHALL NOT:

- write TP  
- write MTP  
- write semantic_core  
- write ΔH%  
- write routing metadata  
- write TR fields  
- write messy_input_record  
- participate in Merge  
- participate in Pipeline A  
- generate meaning  
- perform semantic repair  
- perform truth/done evaluation  
- operate per lane  

---

# **4. Inputs**

IB receives a **frozen, immutable** post‑TS snapshot:

```
ib_input {
    semantic_core_snapshot,
    truth_interpretation_input{},   // from TB
    propositions[],
    evidence_graph{},
    contradiction_markers?,
    uncertainty_markers?,
    lineage_refs[],
    stability_metadata,
    policy_signature,
    gb_supervisory_context,
    mtp_snapshot_id
}
```

All fields are **read‑only**.

---

# **5. Outputs**

IB produces:

```
ib_output {
    inquiry_state{},
    clarification_proposals[],
    missing_structure_markers[],
    contradiction_markers?,
    uncertainty_markers?,
    gb_recommendations[],
    inquiry_metadata{},
    inquiry_health{}
}
```

IB outputs feed:

- **GBIB**  
- **GB**  
- **20.140 Truth/Done**  
- **CIL** (for clarification events)  

IB produces **no writes** to TP, MTP, or semantic_core.

IB SHALL NOT:

- write any TP field  
- write any MTP field  
- write any semantic_core field  
- write ΔH%  
- write routing metadata  
- write TR fields  
- write messy_input_record  
- set tr_needs_update  
- participate in Merge  
- participate in Pipeline A  
- generate meaning  
- perform semantic repair  
- perform truth/done evaluation  
- operate per lane  
- read or write Pipeline‑B envelopes  
- mutate TB outputs  
- mutate truth_interpretation_input  

IB is **purely post‑TS**, **read‑only**, and **supervised**.

# **7. High‑Level Requirements (HLRs)**

### **HLR‑20.090‑001 — Post‑TS Position**  
IB SHALL operate only after TP(N+1) and semantic_core are fully committed.

### **HLR‑20.090‑002 — Read‑Only Semantics**  
IB SHALL NOT mutate TP, MTP, semantic_core, or any Pipeline‑A structure.

### **HLR‑20.090‑003 — Inquiry Detection**  
IB SHALL detect unresolved ambiguity, contradiction, and missing structure.

### **HLR‑20.090‑004 — Clarification Proposals**  
IB SHALL generate deterministic clarification proposals for GB review.

### **HLR‑20.090‑005 — GB‑Supervised Lifecycle**  
IB SHALL be created, evolved, merged, split, and retired only under GB supervision.

### **HLR‑20.090‑006 — No Lane Parallelism**  
IB SHALL NOT operate per lane; it consumes the unified semantic snapshot.

### **HLR‑20.090‑007 — Deterministic Inquiry State**  
IB SHALL maintain deterministic inquiry_state{} across cycles.

### **HLR‑20.090‑008 — No ΔH% Participation**  
IB SHALL NOT read or write ΔH% fields.

### **HLR‑20.090‑009 — No TR Interaction**  
IB SHALL NOT read or write `TP.TR` or `thought_router_fields`.

### **HLR‑20.090‑010 — No Messy‑Input Classification**  
IB SHALL NOT classify or modify messy_input tags; this is Pipeline‑A only.

### **HLR‑20.090‑011 — No Merge Participation**  
IB SHALL NOT participate in Merge or lineage mutation.

### **HLR‑20.090‑012 — Replay Equivalence**  
IB outputs SHALL be deterministic for identical semantic snapshots.

### **HLR‑20.090‑013 — Inquiry Metadata**  
IB SHALL maintain inquiry metadata (internal only) for GB supervision.

### **HLR‑20.090‑014 — Clarification Routing**  
IB SHALL produce clarification proposals for CIL only through GB approval.

### **HLR‑20.090‑015 — No TP Tagging**  
IB SHALL NOT write inquiry logs into TP; all logging is internal to IB.

### **HLR‑20.090‑016 — GB‑Only Supervisory Actions**  
All IB lifecycle transitions SHALL require explicit GB approval.

### **HLR‑20.090‑017 — Inquiry Health Monitoring**  
IB SHALL track inquiry health, stagnation, and contradiction persistence.

### **HLR‑20.090‑018 — No Meaning Generation**  
IB SHALL NOT generate meaning or modify semantic content.

# **9. Inquiry Logic (Minimal)**

IB performs:

- ambiguity detection  
- contradiction persistence detection  
- missing‑structure detection  
- clarification proposal generation  
- inquiry state evolution  
- GB‑supervised merge/split/retire decisions  
- inquiry health monitoring  

IB performs **no inference**, **no repair**, **no generation**, and **no probabilistic reasoning**.

Implementation conforms when:

- IB reads only semantic_core + TB input  
- IB produces only inquiry_state{} and clarification proposals  
- IB performs no writes  
- IB does not interact with Pipeline A  
- IB does not interact with routing or ΔH%  
- IB does not generate meaning  
- IB does not classify messy input  
- IB does not write TP logs  
- IB is deterministic and replay‑equivalent
