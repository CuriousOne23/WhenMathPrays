# **20.48.030_knf_prim.md — KnF Primitive Specification**

## **1. Introduction**

The **Knowledge Fine Primitive (KnF)** is the third and final grounding stage in the TS knowledge pipeline.  
It operates after **KnC** has produced coarse grounding and **KnM** has produced medium grounding. KnF performs **fine‑grained grounding**, attaching precise, domain‑specific, context‑resolved knowledge to the SSR datastream.

KnF is the **highest‑precision, lowest‑entropy** grounding stage. It resolves ambiguity that KnC and KnM cannot address and provides TS with the most detailed abstraction tier available for Path B expression and entropy‑conditioned routing.

KnF is responsible for producing the **fine abstraction tier**, which is used when TS has sufficient certainty to express precise meaning without requiring surgical questioning.

---

## **2. Purpose**

The purpose of KnF is to:

- attach **fine identity**, **fine relations**, **fine domain anchors**, and **fine qualifiers** to SSR‑K,
- compute **fine grounding entropy** $H\_{Kn_{fine}}$,
- populate the **fine abstraction tier** for Path B,
- perform deep contextual disambiguation,
- interface with the grammar‑atomic **KnDt** to retrieve fine‑depth entries,
- finalize grounded knowledge for deterministic expression.

KnF ensures TS has a **fully resolved, precise grounding tier** available when entropy is low.

---

## **3. Discussion of the KnF Block**

KnF is the **final grounding primitive** in the KnB pipeline:

```
Path A → KnC → KnM → KnF → Path B
```

KnF reads the SSR datastream produced by KnM and extracts:

- medium identity anchors  
- medium relational primitives  
- medium domain anchors  
- medium qualifiers  
- semantic tags  
- proposition fragments  
- contextual indicators  
- domain‑specific signals  
- truth‑validation cues  

KnF then queries **KnDt** using these fine‑resolution indicators.  
KnDt returns **fine‑depth grammar‑atomic entries**, which KnF attaches to SSR‑K in the **fine tier fields**.

KnF performs:

- deep contextual disambiguation,  
- fine identity resolution,  
- fine relational resolution,  
- fine domain anchoring,  
- fine qualifier attachment,  
- fine truth validation.

KnF does **not** perform:

- multi‑hop inference,  
- semantic guessing,  
- probabilistic reasoning.

KnF computes:

$$
H\_{Kn_{fine}} = 1 - \frac{precision_{fine}}{max_{precision}}
$$

This entropy value is used by Path B to determine whether fine expression is appropriate.

---

## **4. Field Definitions**

### **4.1 Fields Read from SSR**

KnF reads the following SSR fields:

- `identity_medium[]`  
- `relation_medium[]`  
- `domain_anchor_medium[]`  
- `qualifier_medium[]`  
- `truth_validation_medium[]`  
- `semantic_tags[]`  
- `proposition_set[]`  
- `lane_local_identity`  
- `KnDt_keywords[]`  
- `KnDt_addresses[]`  
- `delta_h_percent` ($H_{SSR}$)  
- `policy_markers[]`

These fields provide the contextual and domain‑specific cues required for fine grounding.

### **4.2 Fields Written to SSR‑K**

KnF writes the following fields:

- `identity_fine[]`  
- `relation_fine[]`  
- `domain_anchor_fine[]`  
- `qualifier_fine[]`  
- `truth_validation_fine[]`  
- `H_Kn_fine`  
- `Kn_level = "KnF"`  

These fields form the **fine abstraction tier** consumed by Path B.

---

## **5. Interface to KnDt**

KnF interfaces with **KnDt (Knowledge Database)** using:

- `KnF_REQUEST`  
- `KnF_RESULT`  
- `KnF_VALIDATE`

KnF performs the following steps:

1. Extract fine‑resolution indicators from SSR.  
2. Issue a `KnF_REQUEST` to KnDt.  
3. Retrieve fine‑depth grammar‑atomic entries via `KnF_RESULT`.  
4. Validate grounding using `KnF_VALIDATE`.  
5. Write fine grounding fields into SSR‑K.  
6. Compute $H\_{Kn_{fine}}$.

KnDt returns:

- fine identity anchors  
- fine relational primitives  
- fine domain anchors  
- fine qualifiers  
- fine truth‑validation primitives  

KnF does not modify KnDt and does not perform multi‑hop queries.

## **6. SHALL Requirements (HLRs)**

### **Identity Grounding**
- **HLR-20.48.030-001** — KnF **shall** attach `identity_fine[]` entries derived from fine identity anchors returned by KnDt.  
- **HLR-20.48.030-002** — KnF **shall** perform fine identity resolution using contextual and domain‑specific cues.

### **Relation Grounding**
- **HLR-20.48.030-003** — KnF **shall** populate `relation_fine[]` using fine relational primitives retrieved from KnDt.  
- **HLR-20.48.030-004** — KnF **shall** resolve relational ambiguity beyond medium grounding depth.

### **Domain Anchors**
- **HLR-20.48.030-005** — KnF **shall** populate `domain_anchor_fine[]` using fine domain anchors from KnDt.  
- **HLR-20.48.030-006** — KnF **shall** refine domain anchors to their most specific form.

### **Qualifiers**
- **HLR-20.48.030-007** — KnF **shall** attach `qualifier_fine[]` entries representing precise descriptive features.  
- **HLR-20.48.030-008** — KnF **shall** ensure qualifiers reflect fine‑resolution grounding.

### **Truth Validation**
- **HLR-20.48.030-009** — KnF **shall** populate `truth_validation_fine[]` using fine truth‑validation primitives.  
- **HLR-20.48.030-010** — KnF **shall** perform fine truth validation using domain‑specific cues.

### **Entropy**
- **HLR-20.48.030-011** — KnF **shall** compute $H\_{Kn_{fine}}$ using the formula:
  
$$
H\_{Kn_{fine}} = 1 - \frac{precision_{fine}}{max_{precision}}
$$  

- **HLR-20.48.030-012** — KnF **shall** write `H_Kn_fine` into SSR‑K.

### **SSR‑K Update**
- **HLR-20.48.030-013** — KnF **shall** set `Kn_level = "KnF"` in SSR‑K.  
- **HLR-20.48.030-014** — KnF **shall** not overwrite coarse or medium fields.

### **Pipeline Behavior**
- **HLR-20.48.030-015** — KnF **shall** operate deterministically and shall not perform inference beyond fine grounding depth.  
- **HLR-20.48.030-016** — KnF **shall** finalize grounded knowledge for Path B without altering Path A fields.

## **7. Use by Future TS Blocks**

### **Path B**
Path B uses:

- `identity_fine[]`  
- `relation_fine[]`  
- `domain_anchor_fine[]`  
- `qualifier_fine[]`  
- `truth_validation_fine[]`  
- `H_Kn_fine`

Path B selects fine expression when:
  
$$
H_{total} = H_{SSR} + H\_{Kn_{fine}}
$$  

falls within the fine‑entropy range.

### **Surgical Questioning**
If fine grounding is still ambiguous, Path B uses fine fields to generate highly targeted clarification questions.

### **Downstream TS Blocks**
Fine grounding supports:

- deterministic expression,  
- precise routing,  
- high‑resolution traceability,  
- domain‑specific reasoning blocks,  
- future TS modules requiring exact identity and relation resolution.

---

## **8. Conclusion**

KnF is the precision grounding primitive in TS.  
It attaches fine‑depth, context‑resolved, domain‑specific knowledge to SSR‑K, resolving ambiguity that coarse and medium grounding cannot address. KnF interfaces with KnDt, computes fine grounding entropy, and finalizes grounded knowledge for Path B.

KnF is deterministic, precise, and essential for TS’s high‑resolution expression pipeline.
