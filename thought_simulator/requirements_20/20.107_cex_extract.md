# **20.107 — CEx Extract (Version 3.0 — Deterministic Context Extraction Specification)**  
**Document ID:** 20.107  
**Version:** 3.0  
**Date:** 2026‑07‑20  
**Upstream:** IE (20.109), CIL (20.33)  
**Downstream:** CE (20.108), ISc (20.44), TPU (20.15)

---

# **1. Purpose** *(Informative)*

The Context Extractor (CEx) is the deterministic, bounded‑semantic primitive that consumes **IE output**, **CIL intake packets**, and **TP metadata** to produce the **next‑turn context envelope (CE)**.

CEx does not infer meaning, does not perform semantic repair, does not modify identity layers, does not compute stability, and does not perform global semantic reasoning.  
Its role is strictly mechanical:

- select the correct identity‑layer context for the present turn  
- extract bounded semantic context fields  
- normalize them into CE  
- write CE into `TP.metadata.context_metadata`  
- preserve deterministic replay

CEx is the first primitive that transforms IE + CIL into structured context.

---

# **2. Position in Path‑A** *(Informative)*

```
InB → IIInB → IE → CEx → CE → ISc → TPU → TP(N+1)
```

CEx is the first consumer of CIL and the first producer of CE.

---

# **3. Scope** *(Informative)*

CEx:

- reads IE.intake, IE.structure, IE.metadata  
- reads CIL.identity_selection_block, CIL.clarifying_fields, CIL.stability, CIL.next_context  
- reads TP.metadata.context_metadata, TP.metadata.msl_metadata, TP.metadata.clarifying_metadata  
- extracts bounded semantic context  
- writes CE into TP.metadata.context_metadata  
- records provenance  
- records extraction audit entries  
- guarantees deterministic replay

CEx does **not**:

- modify IE, CIL, COB, CST, TP.semantic, TP.process, TP.routing, TP.identity, TP.structural  
- perform semantic inference  
- perform repair  
- compute stability  
- create identity layers  
- modify clarifying metadata  
- modify routing metadata  
- use embeddings or probabilistic reasoning

---

# **4. Inputs** *(Informative)*

```
cex_input {
    ie_intake,            # IE.intake tokens, flags, structure, metadata
    cil_intake_packet,    # CIL identity, stability, clarifying, next_context
    tp_snapshot_id,       # turn identifier only
    policy_signature
}
```

---

# **5. Outputs** *(Informative)*

```
ce_output {
    CE,                           # context envelope
    extraction_audit[],           # deterministic audit entries
    context_provenance,           # origin + last_update
    version_tag
}
```

---

# **6. Extraction Behavior** *(Informative)*

CEx extracts explicit fields from IE + CIL + TP metadata, applies deterministic normalization, enforces bounded limits, and records drops/truncations.  
Malformed IE or CIL still produce a valid CE containing only valid extracted fields.

---

# **7. Determinism and Replay** *(Informative)*

CEx produces identical CE for identical IE, CIL, TP metadata, and policy_signature.  
Replay determinism is mandatory.

---

# **8. Error Handling** *(Informative)*

CEx never halts the pipeline.  
Malformed IE or CIL results in:

- extraction of valid fields  
- dropping invalid fields  
- audit entries  
- CE emission regardless of input quality

# **10. Normative Requirements (HLRs)**  
*(All SHALL statements have HLR numbers)*

---

## **10.1 Core Architectural Requirements**

### **HLR‑20.107‑001**  
CEx SHALL be the only module permitted to read CIL.

### **HLR‑20.107‑002**  
CEx SHALL consume IE.intake.ie_tokens and IE.intake.token_flags as its primary machine substrate.

### **HLR‑20.107‑003**  
CEx SHALL consume CIL.identity_selection_block, CIL.clarifying_fields, CIL.stability, and CIL.next_context exclusively through CIL.

### **HLR‑20.107‑004**  
CEx SHALL NOT perform semantic repair, inference, or meaning generation.

### **HLR‑20.107‑005**  
CEx SHALL write CE only into `TP.metadata.context_metadata`.

### **HLR‑20.107‑006**  
CEx SHALL NOT modify TP.semantic, TP.process, TP.routing_metadata, TP.identity_metadata, TP.structural_metadata, TP.continuity_metadata, or TP.freeze_metadata.

### **HLR‑20.107‑007**  
CEx SHALL treat all TP.metadata fields as read‑only except for context fields.

### **HLR‑20.107‑008**  
CEx SHALL record provenance for all context fields it writes.

### **HLR‑20.107‑009**  
CEx SHALL record extraction_audit entries for all drops, truncations, and normalizations.

### **HLR‑20.107‑010**  
CEx SHALL produce identical CE for identical IE, identical CIL, identical TP metadata, and identical policy_signature.

### **HLR‑20.107‑011**  
CEx SHALL NOT use embeddings, probabilistic reasoning, or latent inference.

### **HLR‑20.107‑012**  
CEx SHALL NOT modify IE, CIL, COB, CST‑Core, CST‑MS, CST‑Mux, or any upstream structure.

### **HLR‑20.107‑013**  
CEx SHALL enforce bounded limits on extracted fields.

### **HLR‑20.107‑014**  
CEx SHALL emit CE even when IE or CIL is malformed, extracting only valid fields.

### **HLR‑20.107‑015**  
CEx SHALL treat malformed IE or CIL as deterministic skip‑condition cases.

---

## **10.2 Identity‑Layer Selection Requirements**

### **HLR‑20.107‑016**  
CEx SHALL select the identity layer using CIL.identity_selection_block.

### **HLR‑20.107‑017**  
CEx SHALL apply continuity rules using TP.process.identity_layer_prev.

### **HLR‑20.107‑018**  
CEx SHALL use recency, frequency, and density metrics only as exposed in CIL.identity_selection_block.

### **HLR‑20.107‑019 (PLACEHOLDER)**  
CEx SHALL override continuity only when primary_certainty exceeds a deterministic threshold and ambiguity_score falls below a deterministic threshold.

### **HLR‑20.107‑020 (PLACEHOLDER)**  
CEx SHALL apply fallback selection when identity selection is indeterminate.

### **HLR‑20.107‑021**  
CEx SHALL mark fallback selections with CE.metadata.continuity_status = `"undetermined"`.

### **HLR‑20.107‑022 (PLACEHOLDER)**  
CEx SHALL apply collapse fallback when collapse_risk exceeds a deterministic threshold.

### **HLR‑20.107‑023**  
CEx SHALL include CE.metadata.continuity_status in CE.

### **HLR‑20.107‑024**  
CEx SHALL NOT modify ordering metrics.

### **HLR‑20.107‑025**  
CEx SHALL guarantee deterministic identity‑layer selection for identical inputs.

### **HLR‑20.107‑026 (New)**  
CEx SHALL default to the most recent identity layer (`last_referred`) when lineage cannot be determined.

### **HLR‑20.107‑027 (New)**  
CEx SHALL classify a turn as `new_conversation` when no existing identity layer matches IE tokens, MSL tokens, clarifying metadata, or CIL continuity/stability signals.

### **HLR‑20.107‑028 (PLACEHOLDER)**  
CEx SHALL record provenance for `new_conversation` classification in CE.metadata.context_provenance.

---

## **10.3 Clarifying‑Field Requirements**

### **HLR‑20.107‑029**  
CEx SHALL extract clarifying fields and hierarchical subfields from CIL.

### **HLR‑20.107‑030**  
CEx SHALL normalize clarifying‑field topology deterministically.

### **HLR‑20.107‑031**  
CEx SHALL enforce bounded limits on clarifying fields (10), subfields (100), and depth (4).

### **HLR‑20.107‑032**  
CEx SHALL record clarifying‑field drops and truncations in extraction_audit.

### **HLR‑20.107‑033**  
CEx SHALL treat clarifying metadata as read‑only.

### **HLR‑20.107‑034 (PLACEHOLDER)**  
CEx SHALL preserve clarifying‑field continuity across turns using identity‑layer selection rules.

---

## **10.4 Next‑Turn Context Requirements**

### **HLR‑20.107‑035**  
CEx SHALL read next‑turn context exclusively from CIL.next_context.

### **HLR‑20.107‑036**  
CEx SHALL treat all next‑turn context fields as read‑only.

### **HLR‑20.107‑037**  
CEx SHALL include next‑turn context fields in CE.

### **HLR‑20.107‑038**  
CEx SHALL NOT derive next‑turn context fields from clarifying metadata or structural cues.

### **HLR‑20.107‑039**  
CEx SHALL guarantee deterministic replay of next‑turn context extraction.

### **HLR‑20.107‑040**  
CEx SHALL NOT perform semantic interpretation when handling next‑turn context.

### **HLR‑20.107‑041**  
CEx SHALL include next‑turn context fields even when identity selection is ambiguous.

### **HLR‑20.107‑042**  
CEx SHALL preserve next‑turn context continuity across turns.

### **HLR‑20.107‑043**  
CEx SHALL NOT compute context coherence or context shift.

### **HLR‑20.107‑044**  
CEx SHALL record next‑turn context drops or truncations in extraction_audit.

### **HLR‑20.107‑045**  
CEx SHALL NOT write next‑turn context fields into clarifying fields.

### **HLR‑20.107‑046**  
CEx SHALL NOT interact with truth/done fields, routing fields, structural geometry, ΔH%, lineage, or Path‑B semantics.

### **HLR‑20.107‑047**  
CEx SHALL treat missing next‑turn context fields as deterministic empty‑context cases.

---

## **10.5 TP Integration Requirements**

### **HLR‑20.107‑048**  
CEx SHALL write CE into `TP.metadata.context_metadata` exactly as defined in 20.105 and 20.105.010.

### **HLR‑20.107‑049**  
CEx SHALL populate context_provenance according to 20.105.020.

### **HLR‑20.107‑050**  
CEx SHALL emit CE in a form consumable by RB, IdOB, ISc, MCB, OuBA, and SSRGn.

### **HLR‑20.107‑051**  
CEx SHALL write CE prior to TPU commit.

### **HLR‑20.107‑052**  
CEx SHALL NOT modify any TP fields outside `TP.metadata.context_metadata`.

### **HLR‑20.107‑053 (New)**  
CEx SHALL treat all TP.metadata.msl_metadata fields as read‑only.

### **HLR‑20.107‑054 (New)**  
CEx SHALL treat all TP.metadata.repair_metadata fields as read‑only.

### **HLR‑20.107‑055 (New)**  
CEx SHALL treat all TP.metadata.continuity_metadata fields as read‑only.

### **HLR‑20.107‑056 (New)**  
CEx SHALL NOT consume TP.metadata.routing_metadata directly and SHALL rely exclusively on CIL for routing‑adjacent context cues.

### **HLR‑20.107‑057 (New)**  
CEx SHALL NOT consume TP.metadata.freeze_metadata.

### **HLR‑20.107‑058 (New)**  
CEx SHALL NOT consume TP.metadata.identity_metadata directly.

### **HLR‑20.107‑059 (New)**  
CEx SHALL guarantee deterministic replay across all metadata usage.

---

# **11. Conformance** *(Informative)*

CEx conforms when:

- CE is deterministic  
- only allowlisted fields appear in CE  
- no semantic inference occurs  
- no unauthorized TP fields are accessed  
- extraction_audit is complete  
- malformed IE or CIL still yields valid CE  
- replay produces identical CE
