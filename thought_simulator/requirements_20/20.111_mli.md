# **20.111 MLI Requirements (v0.1 — Architecture‑Aligned)**  
**Document ID:** 20.111  
**Version:** 0.1  
**Date:** 2026‑06‑15  
**Status:** Draft v0.1 — Architecture‑Aligned (CuriousOne23, Copilot)

---

# **Purpose**

Defines deterministic **Meaning‑Layer Inference (MLI)** behavior as the mandatory first semantic stage of **Path B**, responsible for **bounded meaning selection**, **primitive validation**, and **confidence‑based resolution** of candidate interpretations produced by upstream components.

MLI performs **selection and validation only**.  
MLI SHALL NOT generate new semantic content, hallucinate, or silently guess.  
When meaning cannot be resolved with sufficient confidence, MLI SHALL mark the TP as **UNRESOLVED**, and Path B SHALL engage the user with clarifying questions.

MLI is **intentionally limited in scope**.  
It performs only local, per‑utterance meaning resolution using bounded, deterministic inference.  
MLI does not perform global conversation inference, does not consult CIL or CE, and does not use long‑range context.  
This limitation is by design: a local, non‑iterative MLI prevents semantic drift, avoids hallucination, and ensures that downstream components (Path B and CIL) receive stable, non‑speculative meaning.  
If MLI cannot resolve meaning with sufficient confidence, it emits UNRESOLVED rather than guessing.

MLI is the **exclusive upstream producer** of the TP‑level meaning assertion consumed by downstream Path B reasoning.

### **Updated Path B Ordering (HQ‑111‑001):**

```
Path A → MLI → Path B Reasoning → Downstream Planning
```

MLI is not a generative model, not a semantic constructor, and not a context extractor.  
MLI is a **bounded inference gate** that stabilizes meaning before Path B reasoning begins.

---

# **Non‑Goals**

MLI SHALL NOT:

- generate semantic content  
- perform gap‑fill or hallucination  
- resolve meaning through generative inference  
- perform context extraction (CE owns this)  
- construct CE or modify CE fields  
- perform long‑range inference  
- read or consult CIL  
- perform candidate generation (CEx owns this)  
- perform scoring beyond primitive salience and basin modifiers  
- write to semantic_core, MTP, TR, TB, GBIB, or GB  
- bypass user clarification when meaning is unresolved  

---

# **Parent Scope**

- **Program:** Track H (20.510)  
- **Reads:** Path A envelope, primitive candidates, basin profile  
- **Writes:** TP meaning assertion, TP unresolved‑meaning metadata  
- **Downstream Consumer:** Path B Reasoning  
- **Escalates:** Unresolved meaning → Path B user clarification  
- **Does not modify:** 20.10, 20.12, 20.20, 20.30

# **Functional Boundaries**

| Component | Relationship to MLI |
|----------|----------------------|
| **Path A** | Upstream producer of candidate representations |
| **CEx** | Upstream producer of primitive candidates |
| **CE** | Not produced or modified by MLI |
| **Path B** | **Immediate downstream consumer** of MLI output |
| **USP** | Read‑only for basin modifiers; no mutation |
| **CIL** | MLI SHALL NOT read CIL |
| **RB / OB / TR / TB** | MLI SHALL NOT appear in these pipelines |
| **semantic_core** | MLI SHALL NOT write or modify |

# **Normative Requirements (HLR‑20.111‑xxx)**

## **Activation and Placement**

1. **HLR‑20.111‑001:** MLI SHALL execute as the first semantic stage of Path B.  
2. **HLR‑20.111‑002:** MLI SHALL run immediately after Path A and before any Path B reasoning:  
   ```
   Path A → MLI → Path B
   ```
3. **HLR‑20.111‑003:** MLI SHALL NOT appear in RB→OB→TR→TB chains.  
4. **HLR‑20.111‑004:** MLI output SHALL be shaped for deterministic consumption by Path B.

---

## **Bounded Inference and Meaning Resolution**

5. **HLR‑20.111‑005:** MLI SHALL perform **selection and validation only**, not generation.  
6. **HLR‑20.111‑006:** MLI SHALL NOT hallucinate, fabricate, or guess semantic content.  
7. **HLR‑20.111‑007:** MLI SHALL emit exactly one meaning assertion OR an unresolved‑meaning marker.  
8. **HLR‑20.111‑008:** When meaning cannot be resolved with sufficient confidence, MLI SHALL mark the TP as `UNRESOLVED`.  
9. **HLR‑20.111‑009:** MLI SHALL record the cause of unresolved meaning in TP metadata.  
10. **HLR‑20.111‑010:** MLI SHALL NOT proceed to downstream reasoning when unresolved meaning is present.

---

## **User‑Clarification Loop**

11. **HLR‑20.111‑011:** Path B SHALL detect `UNRESOLVED` meaning and SHALL engage the user with clarifying questions.  
12. **HLR‑20.111‑012:** Path B SHALL offer candidate interpretations when available.  
13. **HLR‑20.111‑013:** Path B SHALL update the TP upon receiving user clarification.  
14. **HLR‑20.111‑014:** Path B SHALL update the USP when clarification reveals new user‑specific meaning.  
15. **HLR‑20.111‑015:** Path B SHALL NOT perform higher‑order reasoning until meaning stabilizes.

---

## **Primitive and Basin Logic**

16. **HLR‑20.111‑016:** MLI SHALL apply primitive salience scoring and basin modifiers deterministically.  
17. **HLR‑20.111‑017:** MLI SHALL apply primitive‑type precedence rules before salience‑only resolution.  
18. **HLR‑20.111‑018:** Basin‑dependent REVISION_THRESHOLD modifiers SHALL remain within bounded limits.  
19. **HLR‑20.111‑019:** MLI SHALL NOT emit contradictory assertions within a frame.  
20. **HLR‑20.111‑020:** MLI SHALL expose PRIMITIVE_CONFLICT and BASIN_PRIMITIVE_CONFLICT via TP metadata.

---

## **Revision Cycles and Confidence**

21. **HLR‑20.111‑021:** MLI SHALL perform bounded revision cycles to attempt meaning stabilization.  
22. **HLR‑20.111‑022:** If revision cycles fail, MLI SHALL emit `LOW_CONFIDENCE_FALLBACK` with provisional marking.  
23. **HLR‑20.111‑023:** Path B SHALL treat `LOW_CONFIDENCE_FALLBACK` as requiring user clarification.  
24. **HLR‑20.111‑024:** MLI SHALL NOT suppress safety flags under any circumstances.  
25. **HLR‑20.111‑025:** MLI SHALL escalate to fallback if the frame time budget is exceeded.

---

## **Write Authority (TP Only)**

26. **HLR‑20.111‑026:** MLI writes SHALL be confined to TP meaning fields and unresolved‑meaning metadata.  
27. **HLR‑20.111‑027:** MLI SHALL NOT write to CE, semantic_core, MTP, TR, TB, GBIB, or GB.  
28. **HLR‑20.111‑028:** MLI SHALL NOT read or modify TP.TR or any downstream semantic field.

---

## **Cross‑Program Separation**

29. **HLR‑20.111‑029:** MLI SHALL NOT interact with IB, TB, GBIB, or GB.  
30. **HLR‑20.111‑030:** MLI SHALL NOT read or write Pipeline B envelopes beyond TP meaning fields.  
31. **HLR‑20.111‑031:** MLI SHALL NOT read CIL for any purpose.

---

## **Bounds, Determinism, and Replay**

32. **HLR‑20.111‑032:** MLI SHALL enforce deterministic scoring and selection.  
33. **HLR‑20.111‑033:** MLI SHALL be fully replayable under fixed inputs.  
34. **HLR‑20.111‑034:** MLI SHALL use fixed reason codes for all unresolved‑meaning events.  
35. **HLR‑20.111‑035:** MLI SHALL report TCU usage for auditability.

# **Resolved Ambiguity Handling (New Section)**

MLI employs **bounded inference**.  
When meaning cannot be resolved with sufficient confidence, MLI SHALL:

1. Emit a TP with `mli_status = UNRESOLVED`.  
2. Record the cause of unresolved meaning.  
3. Emit no further semantic commitments for that representation.

Path B SHALL:

1. Detect unresolved meaning.  
2. Ask the user clarifying questions.  
3. Offer candidate interpretations when available.  
4. Update the TP and USP upon receiving clarification.  
5. Resume reasoning only after meaning stabilizes.
