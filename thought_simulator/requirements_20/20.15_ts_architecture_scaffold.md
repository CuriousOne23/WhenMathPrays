# **1. Purpose**

This document defines the complete, self‑contained architectural scaffold required to run a deterministic Path A logic simulation using only:

1. This document, and  
2. `path_a_full_context_test_run_cp.md`

This version incorporates **CEx‑CCR**, **semantic‑importance residues**, **CCR output envelopes**, and **COB projection rules**, ensuring full alignment with the updated CEx‑CCR specification.

The scaffold includes:

- unified TP datapacket  
- explicit primitive read/write tables  
- envelope‑grouped field lists  
- deterministic entropy model  
- deterministic routing model  
- deterministic identity/provenance model  
- unified refinement loop  
- deterministic termination rules  
- deterministic early‑exit rules  
- TPU commit semantics  
- OuBA freeze rules  
- step‑by‑step simulation procedure  
- **CCR‑aligned semantic‑importance envelope**  
- **CCR output envelope (`TP.cex.ccr`)**  
- **static CIL substrate integration**  
- **COB projection of importance residues**

IMR is removed.  
All metadata formerly carried by IMR is now stored directly in TP.

## ⭐ **2.3 Semantic‑Importance Envelope (NEW, CCR‑Aligned)**

This envelope carries **bounded semantic residues** emitted deterministically by Path‑A primitives (IdOB, SOB, SmOB, OuBA, SSRGn).

### **Fields**
```
TP.semantic.importance {
    entities[]: [
        { value: string, role: string, score: number }
    ],
    facts[]: [
        { value: string, role: string, score: number }
    ]
}
```

### **Purpose**
- Provides deterministic importance signals for **semantic‑residue alignment** in CEx‑CCR.  
- Supplies COB with the items to project into the selected CIL conversation.

Importance signals are **not free‑text summaries**; they are structured residues (names, objects, issues).

## ⭐ **2.9 CEx‑CCR Output Envelope (NEW)**

CEx‑CCR produces a deterministic envelope consumed by CEx‑Pck and COB.

### **Fields**
```
TP.cex.ccr {
    alignment: {
        identity: string,
        clarifying: string,
        context: string,
        continuity: string,
        reference: string,
        semantic_residue: string
    },
    scores: {
        ambiguity: number,
        collapse: number,
        drift: number,
        stability: number
    },
    decision: string,
    selected_conversation: number | null
}
```

### **Purpose**
- Provides deterministic alignment scores across six dimensions.  
- Provides deterministic decision outcome (`new`, `specific`, `fallback`).  
- Identifies the selected CIL conversation for COB projection.

# **11. Deterministic Termination Criteria (Corrected)**

### ⭐ **Fix #2 — precise definition of “unchanged across last two cycles”**

Termination requires:

1. `delta_h_percent ≤ 0.25`  
2. `smob_semantic_geometry` unchanged across last two cycles  
3. `context envelope` unchanged across last two cycles  
4. `cob_state_snapshot` unchanged across last two cycles  
5. `routing_path` ends in `stable`  

### **Definition of “unchanged across last two cycles”**

A “cycle” is defined as one full execution of:

```
RBU → TR → CTP → ISc → RTU → RB
```

- If only **one cycle** has occurred, “unchanged across last two cycles” means unchanged relative to the initial post‑SmOB state.  
- If **zero cycles** have occurred (early exit path), termination uses only the numeric threshold and routing stability.

This makes termination deterministic for all cases.

# **13. Simulation Procedure (Aligned + Deterministic)**

### **Step 1 — Intake**
InB → IIInB → IE

### **Step 2 — Context Extraction**
CEx → CE

### **Step 3 — Structural Pass**
SOB → SROB → CnOB → SmOB

### **Step 4 — Entropy Check**
ISc  
If stable → OuBA  
Else → continue

### **Step 5 — Meaning Construction**
SSG → STPX → RBU → TR → CTP → ISc → RTU → RB

### **Step 6 — Refinement Loop**
If RB says refine → run canonical loop:  
`IdOB → RBU → TR → CTP → ISc → RTU → RB`  
Repeat until stable.

### **Step 7 — OuBA Freeze**
Produce TPSnS.  
Simulation ends.

### **CCR Clarification**
During simulation, CEx‑CCR runs inside CEx and produces:

- deterministic alignment  
- deterministic scores  
- deterministic decision  
- deterministic selected conversation  

These values do not affect entropy, routing, or termination directly, but they determine:

- which CIL conversation COB updates  
- which semantic residues propagate forward

### **CIL Substrate Clarification**
The simulation uses a **static 10‑conversation CIL substrate**:

- stored in `cil_input.yaml`  
- identical across all runs  
- not modified except by COB projection  
- not replaced by dynamic CIL envelopes

This ensures deterministic replay.
