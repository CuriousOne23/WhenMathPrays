# ⭐ **3. Path‑A Pipeline — official primitive flow (v4.1; still official in 4.2)**

This is the **official Path A lineup**. Every lineup diagram in this scaffold SHALL be read as this flow. Earlier compact walks in this file remain as historical CEx-era sketches; they do not override this section.

```
Path A Flow:
InB (Beginning of Path A) → IIInB → IE → CEx → CE → TPU
  → SOB → SROB → CnOB → SmOB
  → WrdNm → ISc → SSG → STPX → RBU → DCB
  → TR → CTP → RB
  → WrdNm → ISc → RTU → TR → CTP → RB
  → IdOB → MCB → RBU → DCB
  → TR → CTP → RB
  → WrdNm → ISc → RTU → TR → CTP → RB
  → IdOB → MCB → RBU → . . .
OR
DCB → TR → CTP → RB → WrdNm → ISc → RTU → TR → CTP → RB → OuBA (End of Path A)
```

Read of the official flow:

- IdOB runs **after a committed RB** (second RB on the first cycle, then again after later RB passes). That matches `20.40.050` scheduling law, including HLR-062.  
- Live neighborhood immediately before IdOB is `RTU → TR → CTP → RB`, not `RB → RTU`. Older HLR text that says `RB → RTU` names the same routing-cycle *condition*; official order is RTU first, RB last.  
- The loop `IdOB → MCB → RBU → … → IdOB` is serial meaning refinement (`20.40.050-004`).  
- OuBA is the **exit**, not a peer of IdOB on the same tick.  
- Isolation tests may feed IdOB an utterance/card fixture without executing the live RB to the left of it (`20.40.050-053`). That does not rewrite this flow.

### **CEx‑Pck Integration**
CEx‑Pck is the packaging step inside **CEx** (CEx‑IE → CEx‑CCR → CEx‑Pck) before CE.

### **CE Integration**
CE is the canonical context envelope consumed downstream (ISc and later readers).

### Historical compact walk (v4.0, kept)

```
InB → IIInB → IE → CEx‑IE → CEx‑CCR → CEx‑Pck → CE
→ TPU → SOB → SROB → CnOB → SmOB
→ ISc → SSG → STPX → RBU → TR → CTP → ISc → RTU → RB
→ (refinement loop if needed) → OuBA → TPSnS
```

Missing from that sketch: WrdNm placements, DCB, IdOB, MCB, the double RB before first IdOB, and the OuBA-only exit. Use the official flow above.

# ⭐ **12. Path A continuation guide (v4.2)**

This section is the coordinated feel for building the **next** testbench and for reading the **previous** ones against the primitives. It does not replace §3 or the primitive law files.

## **12.1 Two geometries**

| Geometry | Feel | Machine form | Owner |
|----------|------|--------------|-------|
| Structure | Landscape / roads an utterance is typed onto | Six IDs + `structural_key` (+ optional residue / feature tags) | Structural OBs / SSG / isolation assignment tables |
| Meaning | Speaker’s intended projection stand-in | Six axes in $[0,1]$: physicality, sociality, temporality, intentionality, materiality, spatiality | IdOB after a legal map member is selected |

The **map** is a membership door (key → legal `group_id` set). **Rank** orders only those legal ids. CIE moves $M$ after birth and must not move the key. `residue_code` is leftover tension, not an automatic next six-tuple (RB owns next-OB search).

Do not let the names trade places: structure is not a six-axis score, and meaning is not a hash of the six IDs.

## **12.2 Write walls**

| Object | Writer | Everyone else |
|--------|--------|----------------|
| `TP.idob`, crossing `meaning_delta_h` | IdOB | read-only |
| `mcb_delta_h`, `mcb_semantics[]`, `TP.next_context{}` | MCB | IdOB does not need MCB to write the packet |
| CIE / $\alpha I$ | IdOB this hop | ≠ `TP.next_context.stance`, ≠ MSL stance |
| `pack_ids[]` | COB / CEx-Pck / CIL | RTU, IdOB, MCB, RBU do not invent |
| COB long-term ingest | OuBA freeze | no mid-lineup COB write |
| `process.routing_filter` | RB | IdOB restores if touched |
| next six-tuple | RB | `residue_code` / `expand_target` are hints |
| structural maps / six IDs | structural OBs or assignment tables | IdOB reads only |

If a new testbench writes across a wall, the measurement is no longer about cognition space — it is about the machine leaking into itself.

## **12.5 How to expand without hiding the door**

- Cover more English by growing **declared YAML** (assignment, map, groups, CIE, packs), loadable from disk, not “all English in RAM.”  
- Specialized packs (East LA, scientific, formal) are planned at CEx-Pck / COB / CIL. Triggers may later auto-load; today they may be manual. Architecture must allow the pack, not require every pack present.  
- Changing epsilon, axis count, or CIE formula is a **requirement revision + code revision**, not a silent runtime toggle. That force of clarity is intentional.  
- If traces show a missing dimension, IdOB should make the hole visible. Adding an axis requires: orthogonal, minimal, cognitively consequential, not derivable from the current six — then a new machine revision.  
- Leftover `residue_code` plus TP history is enough to expand dictionaries **manually**. Automatic residue → next six-tuple is RB work, not a hidden IdOB function.

## **12.6 How to convict the stake**

Useful questions (answerable):

- Two speaker-objects judged distinct land on the same $M$ → layout too coarse.  
- An axis never moves across intended contrasts → axis idle.  
- Two axes always move together → suspected non-orthogonality.  
- Δh spikes only from CIE / budget leak → instrument error.  
- Most ordinary utterances get no key or all collapse to one key → the six IDs are an empty frame; revise the instrument now.  
- CIE swap moves `structural_key` → wall broken.

Not useful as a stopping rule: “critics will not agree this is cognition.” That debate does not close. Visibility does.
