# **20.206 — Pipeline A/B Synchronization Contract (v0.4, Fully Rewritten)**  
**Status:** Normative — A/B Operational Boundary  
**Scope:** Defines the operational synchronization between Pipeline A and Pipeline B  
**Excludes:** Meaning construction, semantic_core, MTP semantics, merge/truth/done, identity metadata

---

# **0. Purpose**

20.206 defines the **operational synchronization contract** between:

- **Pipeline A** (local meaning construction)  
- **Pipeline B** (realization and expression)  

The A→B boundary is **not a meaning freeze** and does **not** involve MTP.  
It is a **purely operational handoff** of the finalized **OuBA** artifact into Pipeline B.

Pipeline B consumes **OuBA**, produces **OuBB**, and does not modify meaning.  
Pipeline B remains live. This contract does not retire Path B.

OuBA freeze is the sole COB meaning-ingest door (20.15 §2.14). That ingest rule is distinct from this A→B operational handoff.

---

# **1. Cycle Topology**

A TS cycle proceeds through:

1. **Pipeline A**  
   - local meaning construction  
   - OB/RB/TB/ΔH%/truth/completion  
   - ends at **OuBA**  

2. **Pipeline B**  
   - realization planning  
   - expression mapping  
   - surface‑form generation  
   - ends at **OuBB**  

3. **TS‑side commit**  
   - **MTPU‑prm** consumes OuBB  
   - produces new MTP snapshot  
   - emits `commit_id`  

The A→B boundary is **OuBA → B‑start**.

---

# **2. A→B Synchronization Requirements**

### **HLR‑20.206‑001 — Deterministic Handoff**  
Pipeline A SHALL produce exactly one **OuBA** artifact per cycle.  
Pipeline B SHALL begin only after OuBA is available.

### **HLR‑20.206‑002 — No Meaning Freeze**  
The A→B boundary SHALL NOT freeze meaning or semantic structures.  
Meaning remains internal to Path A and is not exposed to B.

### **HLR‑20.206‑003 — B Input Contract**  
Pipeline B SHALL consume only:

- OuBA  
- `routing_epoch_id`  
- `schema_version`  
- `synthesis_mode`  
- `seed`  

No meaning‑side fields SHALL be provided to B.

### **HLR‑20.206‑004 — Deterministic Start Conditions**  
Pipeline B SHALL start deterministically when:

- OuBA is finalized  
- required metadata is present  
- structural validation passes  

### **HLR‑20.206‑005 — No Back‑Propagation**  
Pipeline B SHALL NOT modify:

- TP  
- OuBA  
- meaning‑side fields  
- Path A state  

Corrections (IMR‑B) SHALL be routed through a **subsequent** Pipeline A cycle.

---

# **3. Allowed Inputs to Pipeline B**

Pipeline B MAY read:

- **OuBA**  
- `routing_epoch_id`  
- `schema_version`  
- `synthesis_mode`  
- `seed`  
- deterministic metadata required for realization  

Pipeline B SHALL NOT read:

- semantic_core  
- stance, affect, tone, register  
- TPTB, TPSF  
- ΔH%  
- truth hypotheses  
- completion state  
- TP contents  
- MTP contents  
- any meaning‑side fields  

---

# **4. Structural Validation Rules (VR)**

### **VR‑1 — Schema Version**  
B SHALL validate that `schema_version` matches supported realization schemas.

### **VR‑2 — Routing Epoch**  
B SHALL validate that `routing_epoch_id` is well‑formed and monotonic.

### **VR‑3 — Synthesis Mode**  
B SHALL validate that `synthesis_mode` is permitted for the current profile.

### **VR‑4 — OuBA Integrity**  
B SHALL validate that OuBA is structurally complete and deterministic.

### **VR‑5 — Seed Isolation**  
B SHALL validate that the realization seed is present and well‑formed.

### **VR‑6 — Forbidden Fields**  
B SHALL reject any input containing meaning‑side fields.

### **VR‑7 — Deterministic Replay**  
Given identical (OuBA, metadata, seed), B SHALL produce identical output.

---

# **5. IMR (Inter‑Module Retry) Semantics**

### **IMR‑A — A‑Side Retry**  
If OuBA is invalid, TS SHALL re‑run Pipeline A deterministically.

### **IMR‑B — B‑Side Retry**  
If B fails realization, TS SHALL re‑run Pipeline B with the same:

- OuBA  
- metadata  
- seed  

### **IMR‑C — Correction Path**  
If a correction requires meaning changes, TS SHALL route through a **new** Pipeline A cycle.

---

# **6. Ordering and Concurrency**

### **HLR‑20.206‑006 — Strict Ordering**  
Ordering SHALL be:

1. Path A → OuBA  
2. Path B → OuBB  
3. TS → MTPU‑prm → MTP  

### **HLR‑20.206‑007 — No Cross‑Pipeline Mutation**  
A and B SHALL NOT mutate each other’s artifacts.

### **HLR‑20.206‑008 — Deterministic Concurrency**  
If multi‑core execution is active, each pipeline SHALL maintain deterministic ordering guarantees.

---

# **7. Forbidden Behaviors**

Pipeline B SHALL NOT:

- read meaning‑side fields  
- modify meaning  
- modify TP  
- modify OuBA  
- write MTP  
- access semantic_core  
- access TPTB/TPSF  
- access truth hypotheses  
- perform inference beyond realization  

Pipeline A SHALL NOT:

- read MTP  
- depend on commit_id  
- depend on B output  

---

# **8. Summary**

20.206 defines the **operational** A/B boundary:

- A produces OuBA  
- B consumes OuBA  
- B produces OuBB  
- TS commits OuBB into MTP  
- commit_id is TS‑side only  
- no meaning is transferred across the boundary  

This removes all legacy meaning‑freeze semantics and aligns the A/B contract with the corrected TS architecture.

### **HLR‑20.206‑009 — Ingest door is not the A→B handoff**
OuBA freeze SHALL remain the sole COB meaning-ingest door. The A→B handoff specified in this document SHALL remain the operational consumption of OuBA by Pipeline B and SHALL NOT be read as a second COB ingest door or as a declaration that Pipeline B is inactive.
