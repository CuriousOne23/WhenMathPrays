# ⭐ **20.105.010 TP Metadata Fields — CCR‑Aligned, Deterministic, Replay‑Safe**  
**Document ID:** 20.105.010  
**Version:** 1.0  
**Date:** 2026‑08‑06  
**Status:** Active — CCR, Semantic‑Importance, and CIL‑Aligned  

---

# **1. Purpose**

This document defines the **metadata fields** carried by the Thought Packet (TP) within Path A.  
Metadata fields provide upstream‑observed information used by downstream primitives for:

- deterministic meaning refinement  
- routing  
- structural interpretation  
- identity continuity  
- semantic‑residue alignment  
- truth‑relation mapping  
- CCR decision support  
- COB projection  
- CIL substrate continuity  

This document is a normative extension of **20.105_tp_requirements.md**.

---

# **2. Scope**

This specification covers:

- metadata field definitions  
- envelope structure  
- provenance requirements  
- commit boundaries  
- immutability constraints  
- upstream annotation responsibilities  
- downstream consumption expectations  

It does **not** define primitive behavior or meaning‑refinement logic.

---

# **3. TP Metadata Field Categories**

TP metadata fields are grouped into the following categories:

- **TP.metadata.intake_metadata** — InB, IIInB  
- **TP.metadata.normalization_metadata** — IE  
- **TP.metadata.structural_metadata** — SOB, SROB, CnOB, SmOB  
- **TP.metadata.routing_metadata** — RBU, RB, RTU, CTP  
- **TP.metadata.expressive_metadata** — IIInB, IE  
- **TP.metadata.repair_metadata** — IE, TPU  
- **TP.metadata.provenance_metadata** — TPU  
- **TP.metadata.entropy_metadata** — TR, OuBA  
- **TP.metadata.continuity_metadata** — COB, CIL, CST  
- **TP.metadata.msl_metadata** — Meaning Signal Layer  
- **TP.metadata.context_metadata** — CEx, CE  
- **TP.metadata.residue_metadata** — OB‑Set  
- **TP.metadata.semantic_layer_metadata** — SSG, STPX  
- **TP.metadata.scoring_metadata** — ISc  
- **TP.metadata.identity_metadata** — IdOB  
- **TP.metadata.next_context_metadata** — MCB  
- **TP.metadata.freeze_metadata** — SSRGn  
- **TP.semantic.importance (NEW)** — Path‑A importance residues  
- **TP.cex.ccr (NEW)** — CEx‑CCR output envelope  
- **TP.metadata.semantic_residue_metadata (NEW)** — CCR semantic‑residue alignment  
- **TP.metadata.cil_metadata (NEW)** — CIL substrate selection metadata  

All TP fields MUST be emitted and consumed using canonical nested paths.
Flattening is a primitive-local operation and MUST NOT modify the TP envelope.

---

# **4. Normative Requirements**

The TP SHALL contain a metadata section composed of zero or more metadata fields defined in this document.  
**HLR‑20.105.010‑001**

Metadata fields SHALL be immutable once committed by TPU, except where a primitive is explicitly authorized to update a specific field.  
**HLR‑20.105.010‑002**

Each metadata field SHALL record its provenance.  
**HLR‑20.105.010‑003**

All metadata fields SHALL be accessible to downstream primitives without re‑inspection of upstream observations.  
**HLR‑20.105.010‑004**

Metadata fields SHALL preserve their values across TPU commits unless explicitly replaced.  
**HLR‑20.105.010‑005**

Metadata fields SHALL support deterministic replay.  
**HLR‑20.105.010‑006**

# ⭐ **5.18 TP.semantic.importance (NEW — CCR‑Aligned)**

Fields produced by SOB, SROB, CnOB, SmOB, IdOB, SSRGn:

```
TP.semantic.importance.entities[]: {
    value: string,
    role: string,
    score: number,
    provenance
}

TP.semantic.importance.facts[]: {
    value: string,
    role: string,
    score: number,
    provenance
}
```

Semantic‑importance SHALL contain bounded semantic residues used by CEx‑CCR.  
**HLR‑20.105.010‑018**

Semantic‑importance SHALL NOT contain free‑text summaries.  
**HLR‑20.105.010‑019**

Semantic‑importance SHALL support deterministic replay.  
**HLR‑20.105.010‑020**

## ⭐ **5.22 TP.ce.candidate_set (NEW — CE Candidate‑Set Envelope)**

Fields produced by CE:

```
TP.ce.candidate_set[]: {
    candidate_id: number,
    fftm_fields: {...},
    structural_features: {...},
    semantic_adjacent_features: {...},
    next_context_features: {...},
    provenance: {...}
}
```

Requirements:

- CE SHALL emit a finite candidate_set array.
- Each candidate SHALL contain deterministic FFTM and structural features.
- CE SHALL assign candidate_id deterministically.
- CE SHALL record provenance for each candidate.
- candidate_set SHALL support deterministic replay.
- candidate_set SHALL be immutable after TPU commit.
