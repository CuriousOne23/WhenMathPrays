# **1. Purpose** *(Informative)*

The Intake Envelope (IE) is the **final pre‑semantic representation** of the user’s input in Path‑A.

IE is the primitive that **first constructs the TP envelope** for Path‑A:

- IE consumes IIInB output  
- IE produces a **TP instance** containing:
  - `TP.intake`
  - `TP.structure`
  - `TP.metadata`
  - `TP.error`

IE ensures:

### 1. Deterministic repair integration  
IIInB proposes repairs; IE applies them to produce **TP.intake.normalized_text** and **TP.intake.tokens**.

### 2. Structural stability  
IE enforces the canonical TP structural schema:

- `TP.structure.tags`  
- `TP.structure.spans`  
- `TP.structure.markup`

### 3. Replay determinism  
IE constructs:

- `TP.metadata.repair_annotations`  
- `TP.metadata.replay`  
- `TP.metadata.ruleset_id`

### 4. Pre‑semantic safety  
IE guarantees that CEx receives:

- no semantic content  
- no inferred meaning  
- no ambiguity resolution  
- no nondeterministic fields  

### 5. Clean foundation for semantic processing  
IE bridges:

- **InB → IIInB** (canonicalization + repair proposals)  
- **CEx → CE → ISc → TPU → TP.semantic** (semantic processing)

IE is a **data‑integrity primitive**, not a semantic module.

---

# **2. Position in Pipeline** *(Informative)*

IE is produced:

- after InB → IIInB  
- before CEx  
- before any semantic interpretation  
- before `TP.semantic`, `TP.process`, or higher‑level metadata are constructed

IE is the **first primitive that emits a TP envelope** for Path‑A.

---

# **3. IE Output Schema (Canonical TP Mapping)** *(Informative)*

IE SHALL emit a TP instance with the following minimum fields:

```json
{
  "intake": {
    "tokens": ["string"],
    "normalized_text": "string"
  },
  "structure": {
    "tags": ["StructuralTag"],
    "spans": ["Span"],
    "markup": ["MarkupIndicator"]
  },
  "metadata": {
    "repair_annotations": ["RepairAnnotation"],
    "replay": "ReplayMetadata",
    "ruleset_id": "string"
  },
  "error": "TPError | null"
}
```

All field names SHALL conform to:

- **20.105_tp_requirements.md**  
- **20.105.010_tp_meta_fields.md**  
- **20.105.020_tp_meta_provenance.md**  
- **20.105.030_tp_meta_usage.md**

# **4. Normative Requirements (HLRs)**

## **4.1 Determinism Requirements**

**HLR‑20.109‑001**  
IE SHALL be deterministically reproducible from the same IIInB output.

**HLR‑20.109‑002**  
IE SHALL NOT include nondeterministic fields (timestamps, random IDs, environment‑dependent values) in `TP.metadata`.

---

## **4.2 Boundedness Requirements**

**HLR‑20.109‑003**  
IE SHALL enforce bounded size limits on `TP.intake` as defined by system intake constraints.

**HLR‑20.109‑004**  
IE SHALL truncate or summarize oversized `TP.intake` fields using a deterministic, documented procedure, and SHALL record such truncation in `TP.metadata.replay`.

---

## **4.3 Replayability Requirements**

**HLR‑20.109‑005**  
IE SHALL encode all information required for downstream components to replay the user’s input without accessing external state, stored in `TP.metadata.replay`.

**HLR‑20.109‑006**  
IE SHALL preserve ordering of user‑provided tokens, structures, and metadata in `TP.intake.tokens` and `TP.structure.tags`.

---

## **4.4 Structural Normalization Requirements**

**HLR‑20.109‑007**  
IE SHALL represent the user’s input using the normalized structural schema defined by the TP specification.

**HLR‑20.109‑008**  
IE SHALL include structural tags (token spans, block boundaries, markup indicators) in `TP.structure.tags` when present in IIInB output.

---

## **4.5 Repair Integration Requirements**

**HLR‑20.109‑009**  
IE SHALL incorporate all repair proposals from IIInB into `TP.intake.normalized_text` without semantic modification.

**HLR‑20.109‑010**  
IE SHALL mark repaired regions using `TP.metadata.repair_annotations`.

**HLR‑20.109‑016**  
IE SHALL read `IIInB_Output.anomaly_flags` and SHALL surface each unresolved anomaly as an anomaly‑provenance entry in `TP.metadata.repair_annotations`, enabling deterministic propagation downstream.

---

## **4.6 Token Normalization Requirements**

**HLR‑20.109‑011**  
IE SHALL contain a normalized token sequence in `TP.intake.tokens`, including whitespace normalization, canonicalization, and repair integration.

**HLR‑20.109‑012**  
IE SHALL preserve token boundaries exactly as defined by the IIInB tokenizer.

---

## **4.7 Structural Integrity Requirements**

**HLR‑20.109‑013**  
IE SHALL validate its emitted TP instance against the TP schema before being passed to CEx.

**HLR‑20.109‑014**  
IE SHALL reject malformed or incomplete structures and return a deterministic error envelope in `TP.error`, without emitting a partially valid TP instance.

---

## **4.8 Prohibited Content Requirements**

**HLR‑20.109‑015**  
IE SHALL NOT contain semantic interpretations, inferred meanings, candidate expansions, or truth‑evaluation artifacts.  
`TP.semantic` SHALL remain empty until CE → ISc → TPU.

---

# **5. Mathematical Form** *(Informative)*

$$
TP = \\{ TP.intake,\ TP.structure,\ TP.metadata,\ TP.error \\}
$$

Where:

- **TP.intake** = normalized token sequence + applied repairs  
- **TP.structure** = structural tags and spans  
- **TP.metadata** = replay metadata, ruleset identifiers, repair annotations  
- **TP.error** = deterministic error envelope (or null)

---

# **6. Example** *(Informative)*

An example TP emitted by IE may include:

- normalized tokens in `TP.intake.tokens`  
- repair annotations in `TP.metadata.repair_annotations`  
- structural tags in `TP.structure.tags`  
- deterministic replay metadata in `TP.metadata.replay`  

No semantic interpretation is included; `TP.semantic` remains empty.
