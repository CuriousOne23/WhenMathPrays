# ⭐ **20.109 — IE Primitive (TP‑Aligned, Version 3.3)**  
### *Updated to include bounded semantic operations for all primitives*

---

# **1. Purpose** *(Informative)*

The Intake Envelope (IE) is the **first committed intake constructor** in Path‑A.  
IE transforms IIInB’s output into a **machine‑efficient, deterministic TP envelope** consumed by all downstream primitives.

IE performs:

- deterministic repair integration  
- bounded semantic normalization  
- bounded semantic classification  
- structural construction  
- replay metadata encoding  

IE does **not** perform global semantic inference, intent inference, or context‑dependent rewriting.

IE is the **semantic compressor** of Path‑A: it applies **bounded, rule‑driven semantic operations** to produce a stable, normalized intake substrate.

---

# **2. Bounded Semantic Domain (New for v3.3)**

All primitives in Path‑A, including IE, operate within a **bounded semantic domain**:

### **Definition — Bounded Semantic Operation**  
A bounded semantic operation is a **local, rule‑driven transformation** that:

1. operates only on the current token or a small fixed window of adjacent tokens (≤5),  
2. uses only information explicitly provided by upstream primitives (IIInB),  
3. does not infer user intent, global meaning, or cross‑sentence semantics,  
4. is deterministic and replay‑stable,  
5. is explicitly authorized by a rule family in the primitive’s ruleset.

### **IE’s Allowed Bounded Semantic Operations**

IE MAY perform:

- **semantic classification** (normative / repaired / anomalous / unrecognized / null)  
- **semantic consolidation** when IIInB proposes a composite merge  
- **semantic normalization** only when IIInB proposes the repair  
- **semantic dictionary validation**  
- **semantic anomaly propagation**  

IE MAY NOT perform:

- semantic inference  
- semantic rewriting  
- semantic expansion not proposed by IIInB  
- semantic correction not proposed by IIInB  

This model applies identically to all primitives in Path‑A.

---

# **3. IE Role in Path‑A** *(Informative)*

IE is the **machine‑efficiency boundary** between IIInB and downstream primitives.

IE:

- applies IIInB repairs deterministically  
- performs bounded semantic operations  
- constructs committed tokens and normalized surface  
- classifies tokens semantically (bounded)  
- builds structural tags and spans  
- records provenance for deterministic replay  

IE does not modify upstream fields and does not perform global semantic interpretation.

---

```json
{
  "intake": {
    "tokens": ["string"],
    "ie_tokens": ["string"],
    "token_flags": ["TokenFlag"],
    "normalized_text": "string"
  },
  "structure": {
    "tags": ["StructuralTag"],
    "spans": ["Span"],

  },
  "metadata": {
    "repair_annotations": ["RepairAnnotation"],
    "replay": "ReplayMetadata",
    "ruleset_id": "string"
  },

```

Downstream primitives treat `ie_tokens` and `token_flags` as the **primary machine substrate**.

# **5. TP Fields Used and Produced by IE (Normative)**

### **HLR‑20.109‑017 — Fields Read by IE**  
IE SHALL read only:

- TP.intake.surface  
- TP.intake.tokens  
- TP.repair_proposals  
- TP.anomaly_flags  
- TP.intake.metadata.iiinb  

### **HLR‑20.109‑018 — Fields Written by IE**  
IE SHALL write only:

- TP.intake.normalized_text  
- TP.intake.ie_tokens  
- TP.intake.token_flags  
- TP.structure  
- TP.metadata.repair_annotations  
- TP.metadata.replay  
- TP.metadata.ruleset_id  
- TP.error  

### **HLR‑20.109‑019 — Prohibition on Upstream Mutation**  
IE SHALL NOT modify any upstream fields.

---

# **6. Determinism Requirements**

**HLR‑20.109‑001**  
IE SHALL be deterministically reproducible from identical IIInB output.

**HLR‑20.109‑002**  
IE SHALL NOT include nondeterministic fields.

---

# **7. Boundedness Requirements**

**HLR‑20.109‑003**  
IE SHALL enforce bounded size limits on TP.intake.

**HLR‑20.109‑004**  
IE SHALL record deterministic truncation in TP.metadata.replay.

---

# **8. Replayability Requirements**

**HLR‑20.109‑005**  
IE SHALL encode all provenance required for deterministic replay.

**HLR‑20.109‑006**  
IE SHALL preserve ordering of tokens, structures, and metadata.

---

# **9. Structural Normalization Requirements**

**HLR‑20.109‑007**  
IE SHALL represent input using the normalized structural schema.

**HLR‑20.109‑008**  
IE SHALL include structural tags when present or derivable.

---

# **10. Repair Integration Requirements**

**HLR‑20.109‑009**  
IE SHALL incorporate all IIInB repair proposals without semantic modification.

**HLR‑20.109‑010**  
IE SHALL mark repaired regions in TP.metadata.repair_annotations.

**HLR‑20.109‑016**  
IE SHALL surface all anomaly_flags as anomaly‑provenance entries.

**HLR‑20.109‑027**  
IE SHALL apply repair proposals deterministically and without reordering.

**HLR‑20.109‑028**  
IE SHALL apply each repair proposal exactly to its specified span.

**HLR‑20.109‑029**  
IE SHALL preserve rule identifiers and spans for all applied repairs.

---

# **11. Token Normalization Requirements**

**HLR‑20.109‑011**  
IE SHALL produce a normalized token sequence including repair integration.

**HLR‑20.109‑012**  
IE SHALL preserve token boundaries except where repairs modify them.

**HLR‑20.109‑030**  
IE SHALL preserve token boundaries unless explicitly modified by repair.

**HLR‑20.109‑031**  
IE SHALL emit tokens suitable for deterministic replay.

---

# **12. Structural Integrity Requirements**

**HLR‑20.109‑013**  
IE SHALL validate TP against the TP schema.

**HLR‑20.109‑014**  
IE SHALL reject malformed structures and emit TP.error.

**HLR‑20.109‑032**  
IE SHALL construct TP.structure deterministically.

**HLR‑20.109‑033**  
IE SHALL record structural provenance in TP.metadata.replay.

---

# **13. Prohibited Content Requirements (Updated for Bounded Semantics)**

**HLR‑20.109‑015**  
IE SHALL NOT perform global semantic interpretation or intent inference.

**HLR‑20.109‑034**  
IE SHALL NOT modify upstream fields.

**HLR‑20.109‑035**  
IE SHALL NOT introduce semantic content not authorized by bounded semantic rules.

**HLR‑20.109‑036**  
IE SHALL emit TP.error when deterministic construction fails.

---

# **14. Token‑Level Normative Classification**

**HLR‑20.109‑037**  
IE SHALL emit TP.intake.token_flags with one entry per token.

**HLR‑20.109‑038**  
IE SHALL classify each token using bounded semantic rules defined in ie_rules.yaml.

**HLR‑20.109‑039**  
IE SHALL NOT drop or replace tokens unless explicitly directed by rule.

---

# **15. Rule‑Driven Anomaly Handling**

**HLR‑20.109‑040**  
IE SHALL resolve anomaly_flags using bounded semantic rules.

**HLR‑20.109‑041**  
IE SHALL NOT perform normalization operations unless IIInB proposes them.

**HLR‑20.109‑042**  
IE SHALL record all anomaly resolutions in TP.metadata.repair_annotations.

---

# **16. Rule‑Driven Normalization and Spacing**

**HLR‑20.109‑043**  
IE SHALL construct normalized_text using rule‑driven whitespace behavior.

**HLR‑20.109‑044**  
IE SHALL insert or omit spaces according to rule‑driven behavior.

---

# **17. Downstream Consumption Model**

**HLR‑20.109‑045**  
IE SHALL produce TP.intake.ie_tokens and TP.intake.token_flags as the primary machine‑efficient substrate.

**HLR‑20.109‑046**  
IE SHALL ensure normalized_text is suitable for structural primitives, replay, provenance, and debugging.

**HLR‑20.109‑047**  
IE SHALL encode normative classification so downstream primitives can ignore or down‑weight unrecognizable tokens.

---

# **18. IIInB‑Driven Intake Construction**

**HLR‑20.109‑048**  
IE SHALL perform composite merges when IIInB repair proposals require merging multiple tokens.

**HLR‑20.109‑049**  
IE SHALL validate dictionary entries for merged tokens.

**HLR‑20.109‑050**  
IE SHALL mark tokens flagged as `no_entry` as anomalous.

**HLR‑20.109‑051**  
IE SHALL apply repetition‑collapse repairs only when IIInB proposes them.

**HLR‑20.109‑052**  
IE SHALL remove illegal characters only when IIInB proposes it.

**HLR‑20.109‑053**  
IE SHALL mark malformed tokens as anomalous.

**HLR‑20.109‑054**  
IE SHALL apply Unicode normalization only when IIInB proposes it.

**HLR‑20.109‑055**  
IE SHALL preserve IIInB token order except where repair spans modify it.

**HLR‑20.109‑056**  
IE SHALL construct normalized_text from committed IE tokens.

**HLR‑20.109‑057**  
IE SHALL construct TP.structure exclusively from IIInB structural tags and deterministic IE rules.

---

# **19. Mathematical Form**

IE produces the committed TP envelope:

$$
TP = \\{ TP.intake,\ TP.structure,\ TP.metadata,\ TP.error \\}
$$

---

# **20. Example**

An IE‑emitted TP instance includes:

- committed token sequence  
- bounded semantic classification  
- committed normalized surface  
- repair‑provenance annotations  
- anomaly‑provenance entries  
- structural tags  
- deterministic replay metadata  

TP.semantic remains empty.
