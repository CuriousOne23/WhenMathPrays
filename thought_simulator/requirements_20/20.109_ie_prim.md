# **1. Purpose** *(Informative — Cleaned)*

The Intake Envelope (IE) is the **first committed intake constructor** in Path‑A.  
IIInB performs tokenization, anomaly detection, and repair proposal generation.  
IE transforms IIInB’s output into a **machine‑efficient, committed TP envelope** used by all downstream primitives.

IE’s role is to:

- apply IIInB’s deterministic repair proposals  
- construct the committed token sequence  
- classify each token as normative, repaired, or anomalous  
- build structural tags and spans  
- generate normalized_text for debugging and structural primitives  
- encode deterministic replay metadata  

IE does **not** infer meaning, re‑tokenize, reinterpret anomalies, or invent repairs.  
IE is the **semantic compressor** of Path‑A: it packs IIInB’s raw semantic material into a deterministic, efficient TP envelope.

---

# **2. IE Role in Path‑A** *(Informative — Cleaned)*

IE is the **machine‑efficiency boundary** between IIInB and all downstream primitives.  
Downstream primitives consume IE’s committed tokens, token_flags, structure, and metadata without re‑deriving IIInB’s anomaly information.

IE:

- applies IIInB repairs deterministically  
- merges tokens when IIInB’s repairs require it  
- validates dictionary entries for merged tokens  
- constructs committed normalized surface  
- builds structural interpretation  
- records provenance for deterministic replay  

IE does not modify upstream fields and does not perform semantic interpretation.

---

# **3. IE Output Schema (Canonical TP Mapping)** *(Informative — Cleaned)*

IE emits a committed TP instance optimized for downstream consumption:

```json
{
  "intake": {
    "tokens": ["string"],          // raw IIInB tokens (read‑only)
    "ie_tokens": ["string"],       // committed tokens (post‑repair)
    "token_flags": ["TokenFlag"],  // normative/repaired/anomalous
    "normalized_text": "string"
  },
  "structure": {
    "tags": ["StructuralTag"],
    "spans": ["Span"],
    "markup": ["MarkupIndicator"]
  },
  "metadata": {
    "repair_annotations": ["RepairAnnotation"],
    "replay": "ReplayMetadata",
    "ruleset_id": "string"
  },
  "error": "TPError | null"
}
```

Downstream primitives treat `ie_tokens` and `token_flags` as the **primary machine substrate**.

# **3.1 TP Fields Used and Produced by IE (Normative)**

### **HLR‑20.109‑017 — TP Fields Read by IE**  
IE SHALL read only the following IIInB‑produced fields:
- TP.intake.surface  
- TP.intake.tokens  
- TP.repair_proposals  
- TP.anomaly_flags  
- TP.intake.metadata.iiinb  

### **HLR‑20.109‑018 — TP Fields Written by IE**  
IE SHALL write only:
- TP.intake.normalized_text  
- TP.intake.ie_tokens  
- TP.intake.token_flags  
- TP.structure  
- TP.metadata.repair_annotations  
- TP.metadata.replay  
- TP.metadata.ruleset_id  
- TP.error  

### **HLR‑20.109‑019 — Prohibition on Upstream Mutation**  
IE SHALL NOT modify:
- TP.intake.surface  
- TP.intake.tokens  
- TP.repair_proposals  
- TP.anomaly_flags  
- TP.intake.metadata.iiinb

# **4. Normative Requirements (HLRs)**

## **4.1 Determinism Requirements**

**HLR‑20.109‑001**  
IE SHALL be deterministically reproducible from the same IIInB output.

**HLR‑20.109‑002**  
IE SHALL NOT include nondeterministic fields.

---

## **4.2 Boundedness Requirements**

**HLR‑20.109‑003**  
IE SHALL enforce bounded size limits on TP.intake.

**HLR‑20.109‑004**  
IE SHALL record deterministic truncation in TP.metadata.replay.

---

## **4.3 Replayability Requirements**

**HLR‑20.109‑005**  
IE SHALL encode all provenance required for deterministic replay.

**HLR‑20.109‑006**  
IE SHALL preserve ordering of tokens, structures, and metadata.

---

## **4.4 Structural Normalization Requirements**

**HLR‑20.109‑007**  
IE SHALL represent input using the normalized structural schema.

**HLR‑20.109‑008**  
IE SHALL include structural tags when present or derivable.

---

## **4.5 Repair Integration Requirements**

**HLR‑20.109‑009**  
IE SHALL incorporate all IIInB repair proposals without semantic modification.

**HLR‑20.109‑010**  
IE SHALL mark repaired regions in TP.metadata.repair_annotations.

**HLR‑20.109‑016**  
IE SHALL surface all anomaly_flags as anomaly‑provenance entries.

**HLR‑20.109‑027**  
IE SHALL apply repair proposals deterministically and without reordering.

**HLR‑20.109‑028**  
IE SHALL apply each repair proposal exactly to its specified span.

**HLR‑20.109‑029**  
IE SHALL preserve rule identifiers and spans for all applied repairs.

---

## **4.6 Token Normalization Requirements**

**HLR‑20.109‑011**  
IE SHALL produce a normalized token sequence including repair integration.

**HLR‑20.109‑012**  
IE SHALL preserve token boundaries except where repairs modify them.

**HLR‑20.109‑030**  
IE SHALL preserve token boundaries unless explicitly modified by repair.

**HLR‑20.109‑031**  
IE SHALL emit tokens suitable for deterministic replay.

---

## **4.7 Structural Integrity Requirements**

**HLR‑20.109‑013**  
IE SHALL validate TP against the TP schema.

**HLR‑20.109‑014**  
IE SHALL reject malformed structures and emit TP.error.

**HLR‑20.109‑032**  
IE SHALL construct TP.structure deterministically.

**HLR‑20.109‑033**  
IE SHALL record structural provenance in TP.metadata.replay.

---

## **4.8 Prohibited Content Requirements**

**HLR‑20.109‑015**  
IE SHALL NOT include semantic interpretations or inferred meanings.

**HLR‑20.109‑034**  
IE SHALL NOT modify upstream fields.

**HLR‑20.109‑035**  
IE SHALL NOT introduce semantic content.

**HLR‑20.109‑036**  
IE SHALL emit TP.error when deterministic construction fails.

---

## **4.9 Token‑Level Normative Classification**

**HLR‑20.109‑037**  
IE SHALL emit TP.intake.token_flags with one entry per token.

**HLR‑20.109‑038**  
IE SHALL classify each token as normative, repaired, anomalous, unrecognized, or null according to rule‑driven behavior defined in ie_rules.yaml.

**HLR‑20.109‑039**  
IE SHALL NOT drop or replace tokens unless explicitly directed by rule.

---

## **4.10 Rule‑Driven Anomaly Handling**

**HLR‑20.109‑040**  
IE SHALL resolve anomaly_flags using rule‑driven behavior defined in ie_rules.yaml.

**HLR‑20.109‑041**  
IE SHALL NOT perform spelling correction, shorthand expansion, repetition collapse, punctuation normalization, or Unicode normalization unless IIInB proposes the correction.

**HLR‑20.109‑042**  
IE SHALL record all anomaly resolutions in TP.metadata.repair_annotations.

---

## **4.11 Rule‑Driven Normalization and Spacing**

**HLR‑20.109‑043**  
IE SHALL construct TP.intake.normalized_text using rule‑driven whitespace behavior defined in ie_rules.yaml.

**HLR‑20.109‑044**  
IE SHALL insert or omit spaces between tokens according to rule‑driven behavior.

---

## **4.12 Downstream Consumption Model**

**HLR‑20.109‑045**  
IE SHALL produce TP.intake.ie_tokens and TP.intake.token_flags as the primary machine‑efficient substrate for downstream primitives.

**HLR‑20.109‑046**  
IE SHALL ensure normalized_text is suitable for structural primitives, replay, provenance, and debugging.

---

## **4.13 Machine‑Efficiency Enforcement**

**HLR‑20.109‑047**  
IE SHALL encode normative classification so downstream primitives can ignore or down‑weight unrecognizable tokens without re‑deriving anomaly information.

---

## 4.14 IE Responsibilities for IIInB‑Driven Intake Construction

### **HLR‑20.109‑048 — Composite Merge Responsibility**  
IE SHALL perform composite merges when IIInB repair proposals require merging multiple tokens into a single committed token.

### **HLR‑20.109‑049 — Dictionary Validation of Merged Tokens**  
IE SHALL validate dictionary entries for merged tokens produced by composite merges.

### **HLR‑20.109‑050 — Handling of `no_entry` Anomalies**  
IE SHALL mark tokens flagged as `no_entry` by IIInB as anomalous in TP.intake.token_flags.

### **HLR‑20.109‑051 — Handling of Repetition Anomalies**  
IE SHALL apply repetition‑collapse repairs only when IIInB proposes them.

### **HLR‑20.109‑052 — Handling of Illegal Characters**  
IE SHALL remove illegal characters only when IIInB proposes an `illegal_character.removed` repair.

### **HLR‑20.109‑053 — Handling of Malformed Tokens**  
IE SHALL mark malformed tokens flagged by IIInB as anomalous.

### **HLR‑20.109‑054 — Handling of Unicode Normalization Repairs**  
IE SHALL apply Unicode normalization only when IIInB proposes it.

### **HLR‑20.109‑055 — Preservation of IIInB Token Order**  
IE SHALL preserve IIInB token order except where repair proposals explicitly modify spans.

### **HLR‑20.109‑056 — Committed Normalized Surface Construction**  
IE SHALL construct normalized_text from committed IE tokens using rule‑driven normalization.

### **HLR‑20.109‑057 — Committed Structural Construction**  
IE SHALL construct TP.structure exclusively from IIInB structural tags and deterministic IE rules.
