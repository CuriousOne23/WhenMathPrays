# **1. Purpose** *(Informative)*

The TS Inference Scorer (ISc) is a **deterministic scoring primitive** in Path‑A.  
Its role is to evaluate a **finite candidate set** of interpretations or state transitions derived from:

- **ContextEnvelope (CE)**  
- **IntakeEnvelope (IE)**  
- **Upstream inference wiring (CEx)**  

ISc:

- does **not** generate meaning  
- does **not** expand candidates  
- produces a **normalized distribution**  
- computes **entropy, ΔH%, confidence, and rationale codes**  
- may trigger **COP escalation** when policy thresholds are met  

ISc strengthens ambiguity detection, uncertainty propagation, and meaning stability while preserving TS invariants and safe‑boundary rules.

---

# **2. Scope** *(Informative)*

ISc operates **only** in the inference path:

```
InB → IIInB → IE → CEx → CE → ISc → TPU → OB → RB
```

ISc is **not**:

- a basin  
- a coprocessor  
- a realization component  
- a TP subsystem  

ISc does **not**:

- read CIL directly  
- invoke IIInB  
- interact with IB, TB, GBIB, or GB  
- write directly to TP  

---

# **3. Architectural Position** *(Informative)*

ISc appears only in the **Inference Path**, not in:

- Normal Path  
- Clarification Path  
- Post‑TS Path  

Merge is internal to TPU.

---

# **4. Definitions** *(Informative)*

- **Candidate Set** — finite interpretations or transitions derived from CE + IE.  
- **ISc Distribution** — normalized probability distribution over candidates.  
- **Entropy / ΔH%** — structural‑uncertainty metrics.  
- **Rationale Codes** — interpretable feature‑level explanations.

# **5. Core Scoring Requirements (Normative)**

### **HLR‑200.45‑002 — CE‑Derived Candidate Set**  
ISc SHALL operate exclusively on a finite candidate set derived from CE and IE.

### **HLR‑200.45‑003 — No Meaning Generation**  
ISc SHALL NOT generate new meanings or expand the candidate set.

### **HLR‑200.45‑004 — Deterministic Scoring**  
ISc SHALL produce identical outputs for identical inputs, state, and seed.

### **HLR‑200.45‑005 — Transparent Features**  
ISc SHALL use interpretable scoring features and SHALL log all features in rationale metadata.

### **HLR‑200.45‑006 — Normalized Distribution**  
ISc SHALL output a normalized probability distribution over the candidate set.

### **HLR‑200.45‑007 — Uncertainty Metrics**  
ISc SHALL compute entropy, ΔH%, confidence, and rationale codes using the unified ΔH% definition.

### **HLR‑200.45‑008 — COP Escalation**  
ISc SHALL trigger COP escalation when policy thresholds are met.

### **HLR‑200.45‑009 — No TP Mutation**  
ISc SHALL NOT write directly to TP; outputs SHALL reach TP only via Merge → TPU.

### **HLR‑200.45‑010 — Replay Safety**  
ISc SHALL satisfy replay invariants.

### **HLR‑200.45‑011 — TCU Bound**  
ISc SHALL operate within the TCU budget defined in 20.90.

### **HLR‑200.45‑012 — Inference Path Only**  
ISc SHALL operate only in the inference path and SHALL NOT interact with Pipeline B.

# **6. FFTM‑Based Semantic Scoring (Four Field Token Model) (Normative)**

### **HLR‑200.45‑058 — FFTM Feature Consumption**  
ISc SHALL score candidates using the four FFTM meaning fields:

- token_surface  
- token_base  
- token_expression  
- token_intent  

### **HLR‑200.45‑061 — Meaning‑Layer Weighting**  
ISc SHALL weight meaning‑layer cues (token_expression, token_intent) more heavily than surface‑form cues unless architecture‑level evidence dictates otherwise.

### **HLR‑200.45‑062 — Architecture‑Aligned Weight Tuning**  
ISc MAY adjust FFTM weights only when justified by architecture‑level evaluation.

### **HLR‑200.45‑063 — Replay‑Safe Weight Application**  
ISc SHALL apply FFTM weights using the canonical scoring equation:

$$
\text{score}(c) = w_s \cdot f_s(c) + w_b \cdot f_b(c) + w_e \cdot f_e(c) + w_i \cdot f_i(c)
$$

### **HLR‑200.45‑064 — No Overfitting to Path‑A Tests**  
ISc SHALL NOT tune weights to pass specific Path‑A test items.

### **HLR‑200.45‑065 — Semantic‑Core Integrity**  
ISc SHALL NOT modify semantic_core or FFTM fields.

### **HLR‑200.45‑069 — Rationale Metadata Integration**

### **HLR‑200.45‑083 — TP‑Stream Metadata Consumption**
ISc SHALL consume applicable deterministic TP‑stream metadata when such metadata improves scoring accuracy or stability.

### **HLR‑200.45‑084 — Read‑Only Discipline**
ISc SHALL treat all TP‑stream metadata as read‑only and SHALL NOT modify any TP fields.

### **HLR‑200.45‑085 — Metadata Applicability Rule**
ISc SHALL consume TP‑stream metadata only when such metadata is relevant to scoring and SHALL ignore metadata that is not applicable.

### **HLR‑200.45‑086 — Forbidden Metadata Consumption**
ISc SHALL NOT consume routing_metadata, ΔH%, truth/done fields, lineage fields, or any Pipeline‑B envelopes.

### **HLR‑200.45‑087 — Structural‑Only Interpretation**
ISc SHALL treat all consumed TP‑stream metadata as structural or semantic‑adjacent features and SHALL NOT perform semantic inference.

### **HLR‑200.45‑088 — Rationale Integration**
ISc SHALL include consumed TP‑stream metadata in rationale metadata when such metadata affects scoring or ranking.

# **8.1 TP‑Stream Metadata Consumption (Informative)**

ISc may consume deterministic, bounded, pre‑semantic or semantic‑adjacent metadata present in the TP‑stream when such metadata is applicable to scoring. Applicable metadata includes:

- context_metadata (CE)
- residue_metadata (OB‑Set)
- semantic_layer_metadata (SSG, STPX)
- scoring_metadata (ISc)
- identity_metadata (IdOB)
- continuity_metadata (COB, CIL, CST)
- expressive_metadata (IIInB, IE)
- normalization_metadata (IE)
- next_context_metadata (MCB)

ISc treats all TP‑stream metadata as read‑only.  
ISc ignores metadata that is not applicable to scoring.  
ISc does not consume routing_metadata, ΔH%, truth/done fields, lineage fields, or any Pipeline‑B envelopes.  
ISc interprets TP‑stream metadata only as structural or semantic‑adjacent features.  
ISc may include consumed metadata in rationale metadata when it affects scoring.

# **9. Next‑Turn Context Handling (Normative)**

### **HLR‑200.45‑070**  
ISc SHALL read next‑turn context fields exclusively from CE.context_fields{}.

### **HLR‑200.45‑071**  
ISc SHALL treat next‑turn context fields as pre‑semantic structural metadata.

### **HLR‑200.45‑072**  
ISc SHALL include next‑turn context fields exactly as provided.

### **HLR‑200.45‑073**  
ISc SHALL treat next‑turn context fields as structural scoring features.

### **HLR‑200.45‑074**  
ISc SHALL NOT derive next‑turn context fields from clarifying fields or identity‑layer metadata.

### **HLR‑200.45‑075**  
ISc SHALL guarantee deterministic replay of next‑turn context handling.

### **HLR‑200.45‑076**  
ISc SHALL NOT perform semantic inference on next‑turn context fields.

### **HLR‑200.45‑077**  
ISc SHALL preserve next‑turn context continuity across turns.

### **HLR‑200.45‑078**  
ISc SHALL NOT compute coherence or shift; it SHALL only reflect CE values.

### **HLR‑200.45‑079**  
ISc SHALL include next‑turn context fields in TPU update requests exactly as defined.

### **HLR‑200.45‑080**  
ISc SHALL treat missing next‑turn context fields as deterministic empty‑context cases.

### **HLR‑200.45‑081**  
ISc SHALL NOT interact with truth/done fields, routing fields, ΔH%, lineage, or Path‑B semantics when processing next‑turn context.

### **HLR‑200.45‑082**  
ISc SHALL record next‑turn context drops or truncations in rationale metadata.
