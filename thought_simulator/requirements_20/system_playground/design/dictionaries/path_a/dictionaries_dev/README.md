# **dictionaries_dev — Developer Dictionary Workspace (TS Path A)**

This directory contains the **developer‑layer dictionary** for TS Path A.  
It is the working area where dictionary revisions are inspected, modified, and prepared before being promoted into runtime form.

Developer dictionaries contain **full semantic entries**, including:

- lemma  
- gloss  
- primitive  
- invariant  
- cue envelope  
- identity anchor  
- routing signature  

These entries are stored in **chunked JSON‑GZIP files** and organized into **versioned release directories**.

---

```
dictionaries_dev/

└── tools/                  # Developer dictionary tools (tracked)

    ├── modify_dev_dct_setup.yaml
    ├── modify_development_dct_userguide.md
    ├── output/             # New chunks + manifest_revNN.json written here (local)
    └── insp_chnk_log/      # Logs for inspect_chunk.py (local)
```

**Status (paths only):** On GitHub this folder tracks `README.md`, `modify_entries.json`, and `tools/` only. There is **no** committed `dct_rev00/*.json.gz` tree here. Full developer `*.json.gz` chunks (and any local release folders that hold them) stay on the developer machine and are not GitHub-visible. Meaning-dictionary releases that *are* tracked live under `../meaning_dictionary/dct_rev00/` (README / manifest / examples / tools; gzips still local-only).

# 🔹 **Release Directories (`dct_revNN/`)**

When present **locally**, a release directory may contain:

- a complete set of developer dictionary chunks (`*.json.gz` — local-only, not on GitHub)  
- a manifest (`manifest.json` or `manifest_revNN.json`)  
- optional user‑provided files (e.g., `modify_entries.json`)  

Tracked Path A meaning releases (README / manifest / examples / tools; gzips still local-only) live under `../meaning_dictionary/dct_revNN/`. This `dictionaries_dev/` workspace itself does not publish a GitHub-visible gzip tree.

Release directories are **immutable**: tools never write into them.  
New revisions are written into `tools/output/`, and users manually move them into the appropriate release directory.

This prevents accidental overwrites and preserves revision history.

---

# 🔹 **Tools Directory (`tools/`)**

The `tools/` directory contains all developer‑side utilities:

### ✔ `inspect_chunk.py`  
Read‑only inspection tool for developer dictionary chunks.  
Uses `inspect_chunk_setup.yaml` to locate the active release directory.

### ✔ `modify_dev_dct.py`  
Developer dictionary editor for adding, modifying, and deleting entries.  
Uses `modify_dev_dct_setup.yaml` to locate:

- the active release directory  
- the input file  
- chunk filename prefix  

### ✔ `output/`  
All new chunk files and new manifest revisions are written here.  
Users manually move them into the correct release directory.

### ✔ `insp_chnk_log/`  
Log files generated by `inspect_chunk.py`.

---

# 🔹 **Setup Files**

Each tool has its own setup file:

### `inspect_chunk_setup.yaml`
Specifies:

- active release directory  
- chunk prefix  
- log directory  

### `modify_dev_dct_setup.yaml`
Specifies:

- active release directory  
- chunk prefix  
- input file location  

This design keeps tools **immutable** and configuration **explicit**.

# 🔹 **Developer Dictionary Workflow**

### **1. Inspect a release**
Use:

```
python inspect_chunk.py meaning_dictionary_dev_03.json.gz
```

Configuration is read from `inspect_chunk_setup.yaml`.

### **2. Modify a release**
Edit `modify_entries.json` inside the release directory, then run:

```
python modify_dev_dct.py
```

The tool:

- loads the highest manifest revision  
- applies add/modify/delete operations  
- writes new chunk files into `tools/output/`  
- writes a new `manifest_revNN.json` into `tools/output/`  

### **3. Promote a revision**
Manually move files from:

```
tools/output/
```

into the appropriate release directory:

```
dct_revNN/
```

This preserves revision history and prevents accidental overwrites.

---

# 🔹 **Manifest Revisioning**

Every run of `modify_dev_dct.py` produces:

```
manifest_revNN.json
```

Where `NN` = highest existing revision + 1.

Example:

- If `manifest.json` exists → next = `manifest_rev01.json`  
- If `manifest_rev01.json` exists → next = `manifest_rev02.json`  

Manifests are **never overwritten**.

---

# 🔹 **Chunk Size Enforcement**

Normal mode enforces:

- **2.5–3.0 MB uncompressed** per chunk

If any chunk exceeds the limit:

- normal mode stops  
- user must increase `CHUNK_COUNT` in `config.py.json`  
- user must run batch mode:

```
python modify_dev_dct.py --batch
```

Batch mode re‑chunks the entire dictionary using WDP.
