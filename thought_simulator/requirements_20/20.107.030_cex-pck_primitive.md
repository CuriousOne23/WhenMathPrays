# ⭐ **20.107.030 — CEx‑Pck Primitive (TP‑Aligned, Version 2.0)**  
### *Deterministic Packaging Layer for CEx Context, Continuity, and CCR‑Aligned Metadata*  
### *Aligned with 20.105, 20.105.010, 20.105.020, 20.105.030, 20.15, and CEx‑CCR*

---

# **1. Purpose (Informative)**

CEx‑Pck is the **third and final internal module** of the CEx primitive:

1. **CEx‑IE** — extracts bounded structural hints  
2. **CEx‑CCR** — computes alignment, scores, decision, selected conversation  
3. **CEx‑Pck** — packages context, MSL tokens, continuity metadata, semantic‑residue metadata, and CIL substrate metadata into TP

CEx‑Pck is the **turn‑local context architect** for Path‑A.  
It produces all TP metadata required by:

- **CE** (context envelope)  
- **OB‑Set** (SOB, SROB, CnOB, SmOB)  
- **IdOB** (identity‑conditioned meaning)  
- **TR/RB** (routing)  
- **COB/CIL/CST** (continuity, lineage, stability)  
- **TPU, CTP, RTU, OuBA, SSRGn** (commit, freeze, replay)

CEx‑Pck performs **no semantic interpretation**, **no lineage updates**, **no meaning construction**, and **no modification of CCR output or semantic‑importance residues**.

CEx‑Pck is:

- deterministic  
- bounded‑semantic  
- replay‑safe  
- TP‑aligned  
- CCR‑aware  
- downstream‑aware  

---

# **2. Inputs (Normative)**

CEx‑Pck SHALL read **only** the following TP envelopes and metadata:

---

## **2.1 CEx‑IE envelope (`TP.cex.ie`)**

Bounded structural hints:

```
topic_hint
intent_hint
continuity_hint
reference_hint
register_hint
politeness_hint
direction_hint
coherence_hint
importance_hint
structural_phrases[]
```

CEx‑Pck SHALL NOT modify these fields.

---

## **2.2 CEx‑CCR envelope (`TP.cex.ccr`)**

Deterministic CCR output:

```
alignment.identity
alignment.clarifying
alignment.context
alignment.continuity
alignment.reference
alignment.semantic_residue

scores.ambiguity
scores.collapse
scores.drift
scores.stability

decision
selected_conversation
provenance
```

CEx‑Pck SHALL NOT modify any CCR fields.

---

## **2.3 Semantic‑Importance envelope (`TP.semantic.importance`)**

Bounded semantic residues:

```
entities[]: { value, role, score, provenance }
facts[]:    { value, role, score, provenance }
```

CEx‑Pck SHALL NOT modify semantic‑importance values, roles, or scores.

---

## **2.4 Next‑Context metadata (`TP.metadata.next_context`)**

If present:

```
next_context
direction
coherence
stance
subculture
next_context_provenance
```

CEx‑Pck SHALL use next_context only for **context construction**, never for direct modification.

---

## **2.5 CIL substrate reference**

From CCR:

```
selected_conversation
cil_reference
```

CEx‑Pck SHALL NOT modify CIL substrate content.

---

## **3.2 TP.metadata.msl_metadata (Meaning Signal Layer)**

```
TP.metadata.msl.intent
```


Entities/facts SHALL be referenced from `TP.semantic.importance`, not transformed.

# **4. Deterministic Rule Ordering (Normative)**

CEx‑Pck SHALL execute steps in the following exact order:

1. Read IE structural hints  
2. Read CCR output  
3. Read semantic‑importance residues  
4. Read next_context metadata  
5. Derive context envelope fields  
6. Construct MSL tokens  
7. Construct continuity + relevance flags  
8. Construct CIL metadata  
9. Construct semantic‑residue alignment metadata  
10. Validate envelope boundaries and provenance  
11. Emit deterministic TP output  

This ordering SHALL be identical in Python and C++.

---

# **5. Normative Requirements — Context Construction**

**HLR‑20.107.030‑001**  
CEx‑Pck SHALL derive context fields using IE hints, CCR alignment, and next_context.

**HLR‑20.107.030‑002**  
When `CCR.decision = new`, CEx‑Pck SHALL set reset flags and SHALL NOT copy forward next_context.

**HLR‑20.107.030‑003**  
When `CCR.decision = specific`, CEx‑Pck SHALL copy forward next_context when CCR continuity alignment is `moderate` or `strong`.

**HLR‑20.107.030‑004**  
When `CCR.decision = fallback`, CEx‑Pck SHALL set fallback continuity flags.

**HLR‑20.107.030‑005**  
CEx‑Pck SHALL NOT infer meaning or semantic roles when constructing context.

---

# **6. Normative Requirements — MSL Construction**

**HLR‑20.107.030‑006**  
CEx‑Pck SHALL construct MSL tokens using IE hints and next_context.

**HLR‑20.107.030‑007**  
MSL tokens SHALL be bounded, structured, and replay‑safe.

**HLR‑20.107.030‑008**  
CEx‑Pck SHALL NOT generate free‑text semantic interpretations.

---

# **7. Normative Requirements — CIL Metadata**

**HLR‑20.107.030‑009**  
CEx‑Pck SHALL copy `selected_conversation` verbatim from CCR.

**HLR‑20.107.030‑010**  
CEx‑Pck SHALL set `cil_reference` deterministically to the static CIL substrate.

**HLR‑20.107.030‑011**  
CEx‑Pck SHALL record provenance for CIL metadata.

---

# **8. Normative Requirements — Semantic‑Residue Metadata**

**HLR‑20.107.030‑012**  
CEx‑Pck SHALL populate semantic‑residue metadata using CCR semantic_residue alignment and semantic‑importance residues.

**HLR‑20.107.030‑013**  
CEx‑Pck SHALL NOT modify semantic‑importance values, roles, or scores.

**HLR‑20.107.030‑014**  
CEx‑Pck SHALL record provenance for semantic‑residue metadata.

---

# **9. Normative Requirements — Provenance**

**HLR‑20.107.030‑015**  
CEx‑Pck SHALL record provenance for every metadata field it writes.

**HLR‑20.107.030‑016**  
CEx‑Pck SHALL preserve CCR provenance, semantic‑importance provenance, and CIL provenance.

**HLR‑20.107.030‑017**  
CEx‑Pck SHALL NOT introduce nondeterministic provenance values.

---

# **10. Normative Requirements — Determinism**

**HLR‑20.107.030‑018**  
Given identical IE, CCR, semantic‑importance, and next_context inputs, CEx‑Pck SHALL produce identical output.

**HLR‑20.107.030‑019**  
CEx‑Pck SHALL use deterministic ordering and stable data structures.

**HLR‑20.107.030‑020**  
Python and C++ implementations SHALL produce identical TP output.

---

# **11. Forbidden Behavior**

CEx‑Pck SHALL NOT:

- modify IE fields  
- modify CCR fields  
- modify semantic‑importance fields  
- modify CIL substrate content  
- infer meaning  
- use embeddings  
- use global semantics  
- write outside its allowed metadata categories  
- perform lineage updates (COB/CIL/CST responsibility)  

---

# **12. Processing Summary (Informative)**

CEx‑Pck:

1. Reads IE hints, CCR output, semantic‑importance, next_context  
2. Constructs context envelope  
3. Constructs MSL tokens  
4. Projects CCR decision + selected_conversation into CIL metadata  
5. Projects semantic‑residue alignment into TP metadata  
6. Emits deterministic TP metadata for CE, OB‑Set, IdOB, TR, RB, COB, CIL, CST, and OuBA  

This completes the definition of **20.107.030 — CEx‑Pck Primitive (Version 2.0)**.
