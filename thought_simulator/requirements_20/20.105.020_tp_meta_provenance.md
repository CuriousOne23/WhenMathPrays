# **1. Purpose**

This document defines the **provenance rules** governing metadata fields within the Thought Packet (TP).  
Provenance ensures:

- deterministic replay  
- stable routing  
- consistent meaning refinement  
- traceable identity continuity  
- correct CCR decision lineage  
- correct COB projection lineage  
- correct CIL substrate lineage  
- correct IdOB crossing-packet lineage  

This document normatively extends **20.105_tp_requirements.md** and **20.105.010_tp_meta_fields.md**.

---

# **2. Scope**

This specification covers:

- provenance structure  
- origin rules

- commit lineage rules  
- update authorization rules  
- replay‑safety constraints  
- CCR‑aligned provenance  
- semantic‑importance provenance  
- CIL substrate provenance  
- COB projection provenance

It does **not** redefine metadata fields or primitive behavior.

# **3. TP Layers Relevant to Provenance**

The TP organizes information into layers that support clear provenance tracking:

- **Intake Layer** — InB, IIInB, IE  
- **Structural Layer** — SOB, SROB, CnOB, SmOB  
- **Routing Layer** — RBU, RB, RTU, CTP  
- **Meaning Signal Layer (MSL)** — qualifiers, clarifications, stance, shading, intent, direction, coherence, subculture  
- **Continuity Layer** — identity anchors, referent lineage, clarifying metadata  
- **Semantic‑Importance Layer (NEW)** — bounded semantic residues  
- **CCR Output Layer (NEW)** — alignment, scores, decision, selected conversation  
- **Semantic‑Residue Alignment Layer (NEW)** — CCR residue alignment  
- **CIL Substrate Layer (NEW)** — selected conversation, CIL reference  
- **IdOB Crossing Layer (v1.1)** — `TP.idob`, meaning_delta_h  
- **Provenance & Audit Layer** — TPU commit lineage  
- **Entropy & Trajectory Layer** — TR, OuBA  

These layers ensure full traceability and deterministic replay.

---

# **4. Provenance Structure**

Each metadata field carries provenance describing:

- the primitive that produced the field  
- the primitive that last updated the field  
- the TPU commit in which the field was written  
- the lineage of commits affecting the field  

Provenance is stored under:

```
TP.metadata.provenance
```

All TP fields MUST be emitted and consumed using canonical nested paths.
Flattening is a primitive-local operation and MUST NOT modify the TP envelope.

---

# **5. Normative Requirements**

Each metadata field SHALL record the identity of the primitive that produced it.  
**HLR‑20.105.020‑001**

Each metadata field SHALL record the identity of the primitive that last updated it.  
**HLR‑20.105.020‑002**

Each metadata field SHALL record the TPU commit identifier associated with its most recent update.  
**HLR‑20.105.020‑003**

Metadata fields SHALL preserve a lineage of commit identifiers representing all commits that modified the field.  
**HLR‑20.105.020‑004**

Metadata fields SHALL only be updated by primitives explicitly authorized to modify those fields.  
**HLR‑20.105.020‑005**

Provenance history SHALL be immutable once recorded, except when extended by authorized updates.  
**HLR‑20.105.020‑006**

Provenance information SHALL support deterministic replay.  
**HLR‑20.105.020‑007**

All provenance information SHALL be visible to downstream primitives.  
**HLR‑20.105.020‑008**

# ⭐ **11A. IdOB crossing-packet provenance (v1.1)**

### **HLR-20.105.020-032**
When TPU commits `TPU.idob_update` / `TP.idob`, provenance SHALL record origin = IdOB, last update = IdOB, the TPU commit id, and (when replay care is required) the YAML-revision / pack identifiers used for that hop.

### **HLR-20.105.020-033**
IdOB-prm SHALL NOT write `TP.metadata.provenance` itself. TPU remains the authoritative provenance writer.

### **HLR-20.105.020-034**
Crossing-packet provenance SHALL support deterministic replay: identical hop inputs + identical committed YAML revision → identical packet and identical provenance extension.

# **12. Primitive Responsibilities (Updated for CCR)**

### **CEx / CE**
Record provenance for all context_metadata fields.

### **OB‑Set (SOB, SROB, CnOB, SmOB)**
Record provenance for residue_metadata and semantic‑importance fields.

### **SSG / STPX**
Record provenance for semantic_layer_metadata.

### **ISc**
Record provenance for scoring_metadata.

### **IdOB**
Record (via TPU commit) provenance for `TP.idob`, meaning_delta_h, optional identity_metadata, and semantic‑importance updates.

### **MCB**
Record provenance for next_context_metadata.

### **OuBA / SSRGn**
Record provenance for freeze_metadata and semantic‑importance updates.

### **CEx‑CCR (NEW)**
Record provenance for:

- CCR alignment  
- CCR scores  
- CCR decision  
- selected_conversation  
- semantic‑residue alignment  

### **COB (NEW)**
Record provenance for:

- semantic_residue.important_entities  
- semantic_residue.important_facts  
- CIL projection lineage  

### **TPU**
Authoritative writer for commit provenance.

# **13. Provenance Equations**

### Commit Lineage Representation

$$
\text{lineage} = \\{ c_1, c_2, \ldots, c_n \\}
$$

### Provenance Update Rule

When a primitive \(P\) updates a metadata field:

$$
\text{provenance.last}_{update} = P
$$

and the commit lineage is extended accordingly.
