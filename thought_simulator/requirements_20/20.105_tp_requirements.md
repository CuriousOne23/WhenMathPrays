# **1. Purpose**

This document defines the **deterministic Thought Packet (TP)** used throughout Path A.  
TP is the canonical, lane‑local, per‑turn working unit consumed and produced by Pipeline‑A primitives.  
It carries:

- semantic envelopes  
- context envelopes  
- structural geometry  
- routing metadata  
- identity metadata  
- clarifying metadata  
- Meaning Signal Layer (MSL) tokens  
- entropy trajectory  
- provenance  
- freeze metadata  
- **semantic‑importance residues (NEW)**  
- **CEx‑CCR output envelope (NEW)**  
- **CIL substrate selection metadata (NEW)**

TP is the **only** operand exchanged across deterministic Path‑A boundaries.  
Authoritative meaning commits only at:

**TPU → OuBA → semantic_core**.

TB, IB, Truth/Done, and all Path‑B semantics are out of scope and SHALL NOT appear on TP.  
**HLR‑20.105‑001**

---

# **2. TP Role in Pipeline A**

TP serves as:

- the deterministic carrier of meaning‑construction signals,  
- the structured projection of upstream observations,  
- the routing operand for arbitration and pathway selection,  
- the continuity anchor for identity and referent lineage,  
- the provenance‑tracked record of all updates,  
- the deterministic substrate for replay‑safe simulation,  
- the envelope carrier for **semantic‑importance** and **CCR output**.

All TP fields MUST be emitted and consumed using canonical nested paths.
Flattening is a primitive-local operation and MUST NOT modify the TP envelope.

All primitives except TPU and OuBA are TP‑stream read‑only and SHALL NOT modify committed meaning‑layer fields.  
**HLR‑20.105‑094**

TP SHALL NOT duplicate authoritative semantic_core fields.  
**HLR‑20.105‑006**

---

# **3. Evaluation‑Derived Metadata Fields**

TP may contain two evaluation‑derived metadata fields:

- **TPTB** — Truth Metadata  
- **TPSF** — Safety Metadata  

These fields are produced exclusively by their evaluation stages and SHALL be read‑only for all downstream components.  
**HLR‑20.105‑002**

Lane‑local TPs SHALL NOT contain TPTB, TPSF, or any evaluation‑derived metadata prior to evaluation.  
**HLR‑20.105‑003**

# **6. Dual‑Pipeline Boundary Discipline**

Pipeline A maintains strict separation from Path B.  
Pipeline B SHALL be TP‑stream read‑only and SHALL NOT invoke TPU or modify semantic_core.  
**HLR‑20.105‑004**

---

# **7. TP as Lane‑Local Projection**

TP SHALL represent the canonical per‑step meaning‑construction unit exchanged across deterministic Pipeline‑A boundaries.  
**HLR‑20.105‑005**

TP carries lane‑specific views of propositions, refs, ΔH%, suppression markers, routing context, and basin outputs.  
TP SHALL NOT duplicate authoritative semantic_core fields.  
**HLR‑20.105‑006**

# **9. Identity Block (immutable after creation)**

```json
tp_identity {
  tp_id,
  tp_seq,
  cycle_id,
  lane_id,
  parent_tp_id?,
  schema_version,
  profile_signature,
  wire_map_version,
  policy_signature,
  timestamp_evidence?
}
```

Identity block fields SHALL be immutable after TP creation.  
**HLR‑20.105‑007**

---

# **10. Lineage Log (append‑only)**

```json
lineage_log[] {
  lineage_seq,
  module_id,
  event_type,  // CREATE | SPLIT | MERGE | UPDATE | RETIRE
  parent_ref?,
  child_refs[],
  partition_rationale_ref?,
  merge_contribution_ref?
}
```

Lineage extensions SHALL append only.  
**HLR‑20.105‑008**

---

# **11. Intake‑Bound Repair Fields**

IIInB produces repair proposals only.  
IE SHALL apply all proposed repairs deterministically when producing the final intake object.  
**HLR‑20.105‑009**

---

# **12. Meaning Signal Layer (MSL) and Clarifying Metadata**

TP SHALL carry a Meaning Signal Layer (MSL) containing short structured tokens for:

- qualifiers  
- clarifications  
- stance  
- shading  
- intent  
- direction  
- coherence  
- subculture  

**HLR‑20.105‑090**

Clarifying metadata SHALL be bounded:

- max 10 fields  
- max 100 subfields  
- max 4 hierarchical levels  
**HLR‑20.105‑091**

Clarifying metadata SHALL record provenance and importance scores.  
**HLR‑20.105‑092**

MSL tokens and clarifying metadata SHALL be propagated deterministically through Path A.  
**HLR‑20.105‑093**

---

# **13. Metadata Immutability and Provenance**

All metadata fields SHALL be immutable once committed by TPU, except where a primitive is explicitly authorized to update a specific field.  
**HLR‑20.105‑010**

Each metadata field SHALL record its provenance.  
**HLR‑20.105‑011**

TP safe_boundary_marker and blocked_relation_log entries SHALL be written only at safe boundaries.  
**HLR‑20.105‑012**

---

# **14. Semantic‑Importance Envelope (NEW)**

Path‑A primitives (SOB, SROB, CnOB, SmOB, IdOB, SSRGn) emit deterministic importance signals:

```
TP.semantic.importance {
    entities[]: { value: string, role: string, score: number },
    facts[]:    { value: string, role: string, score: number },
    provenance
}
```

TP SHALL carry a semantic‑importance envelope containing bounded semantic residues used by CEx‑CCR for semantic‑residue alignment.  
**HLR‑20.105‑096**

Semantic‑importance entries SHALL be structured residues, not free‑text summaries.  
**HLR‑20.105‑097**

Only authorized primitives SHALL update semantic‑importance fields.  
**HLR‑20.105‑098**

Semantic‑importance SHALL support deterministic replay.  
**HLR‑20.105‑099**

---

# **15. CEx‑CCR Output Envelope (NEW)**

CEx‑CCR SHALL produce a deterministic envelope:

```
TP.cex.ccr {
    alignment: {
        identity,
        clarifying,
        context,
        continuity,
        reference,
        semantic_residue
    },
    scores: {
        ambiguity,
        collapse,
        drift,
        stability
    },
    decision,
    selected_conversation,
    provenance
}
```

TP SHALL carry the CCR output envelope for downstream consumption by CEx‑Pck, COB, CIL, and CST.  
**HLR‑20.105‑100**

CCR output SHALL be immutable after TPU commit.  
**HLR‑20.105‑101**

CCR output SHALL support deterministic replay.  
**HLR‑20.105‑102**

---

# **16. CIL Substrate Selection Metadata (NEW)**

TP SHALL carry:

- `selected_conversation`  
- `cil_reference`  

representing the deterministic selection made by CEx‑CCR.  
**HLR‑20.105‑103**

COB SHALL use this metadata to project semantic‑importance residues into the selected CIL conversation.  
**HLR‑20.105‑104**

CIL substrate references SHALL be immutable after commit.  
**HLR‑20.105‑105**

---

# **17. COB Projection Rules (NEW)**

COB SHALL:

- read `TP.semantic.importance`  
- read `TP.cex.ccr.selected_conversation`  
- project importance residues into the selected CIL conversation  
- perform linear copy‑forward without inference or transformation  
**HLR‑20.105‑106**

COB SHALL NOT modify semantic‑importance scores or roles.  
**HLR‑20.105‑107**

COB projection SHALL support deterministic replay.  
**HLR‑20.105‑108**

---

# **18. Deterministic Replay Requirements (NEW)**

Given identical IE hints, CIL substrate, and semantic‑importance signals, CEx‑CCR SHALL produce identical CCR output.  
**HLR‑20.105‑109**

Given identical CCR output and semantic‑importance signals, COB SHALL produce identical CIL projections.  
**HLR‑20.105‑110**

TP SHALL support deterministic replay across all primitives.  
**HLR‑20.105‑111**
