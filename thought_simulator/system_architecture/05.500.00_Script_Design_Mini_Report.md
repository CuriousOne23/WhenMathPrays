## 2. Proposed Script Architecture

**Language & Location (recommended):** Python 3, placed in `thought_simulator/scripts/rename_10_architecture.py` (or `00_program_governance/scripts/` for governance alignment). Modeled on existing rename_identity.py and 30/40-series migration tooling.

**Core Flow (high-level):**

1. Load approved 05.500 document and verify status/signatures.
2. Build comprehensive manifest by scanning all required file types across all tiers.
3. Generate human-readable mini-report + JSON manifest.
4. Dry-run mode: show every planned change.
5. Interactive confirmation gate (or explicit `--yes` flag for CI).
6. Apply non-structural reference updates.
7. Perform directory + file renames (with backup/rollback support).
8. Update indexes and governance docs.
9. Re-scan + verification.
10. Write final report and update 05.500 Close-out section.

**Safety Features (required):**
- Full manifest as single source of truth for the run.
- Atomic rename where filesystem supports it (or best-effort with clear rollback instructions).
- Detailed before/after logging per file.
- `--dry-run` that produces the exact same manifest and preview report without touching the tree.
- Explicit checkpoint after mini-report review (the script can read a "review_approved" marker or simply rely on updated 05.500 status).

## 4. Key Design Decisions & Rationale

- **Manifest-driven**: Every change is derived from the audit manifest. This makes the run reproducible and auditable.
- **Two-pass reference handling**: First update references while the old directory still exists (safer for relative links), then perform the rename.
- **Internal file renames**: Any remaining legacy "system_architecture" filenames inside the tree will be renamed as part of Phase 5 so the final structure matches the 10.00–10.30 plan exactly.
- **Governance updates as first-class citizens**: The script will treat updates to 05.500, 50.00, wave notes, etc. as mandatory steps, not afterthoughts.
- **Review gate**: The script will refuse to enter Phase 4 (actual reference updates) or Phase 5 (renames) unless the 05.500 document shows recent review notes from CuriousOne23 and CP (or an explicit `--force-after-review` flag with logging).

## 5. Risks & Mitigations

- Risk: Accidental breakage of many cross-layer links.  
  Mitigation: Manifest + full dry-run + re-scan verification + explicit human gate after mini-report.

- Risk: The script itself (or other .py files) contains references that need updating.  
  Mitigation: The script will be written to be self-updating or will operate on a pre-generated manifest that includes its own source.

- Risk: Partial failure during rename.  
  Mitigation: Best-effort backup of changed files/directories before structural changes; clear rollback instructions in the final report.

- Risk: 05.20 and 40.07 (the two new governance documents) are still being finalized.  
  Mitigation: The mini-report will flag these explicitly; the script will be designed to run cleanly even if those files are added later.
