# 00.00.40 Normative, Evidence, and Conformance Rules

## Purpose
Defines canonical cross-document rules for normative content, evidence content, conformance precedence, and IB lifecycle authority.

## Rule 1: Normative vs Evidence Boundary
Normative fixtures, templates, and required-shape definitions SHALL be authored in 20-series requirement documents.

Run-derived traces, logs, measurements, and implementation-observed outputs SHALL be authored in 30-series verification documents.

A document SHALL NOT mix normative requirements and run-derived evidence without explicit section-level boundary labeling.

## Rule 2: Conformance Chain
The canonical conformance chain is:

1. 20.31 semantics define meaning.
2. 20.35 reference algorithms implement semantics.
3. 30-series verification checks algorithm conformance.

If algorithm behavior conflicts with semantics, semantics win and algorithm documentation SHALL be corrected.

## Rule 3: IB Lifecycle Single-Source Precedence
IB authority is partitioned as follows:

1. 20.31 defines the meaning of IB fields and states.
2. 20.34 defines governance, control boundaries, and lifecycle transition authority.
3. 20.35 defines operational realization of those transitions.

Precedence rule:

- 20.31 semantics override 20.34 and 20.35.
- 20.34 control/lifecycle rules override 20.35.
- 20.35 SHALL NOT override either 20.31 or 20.34.

## Rule 4: GB Evaluation Scope in COP/IB Requirements
20.34 SHALL define GB evaluation boundaries only:

- required inputs
- required outputs
- required boundary conditions
- allowed supervisory transitions

20.34 SHALL NOT define detailed evaluation procedures, scoring logic, heuristics, or algorithmic decision flow.

Detailed procedure belongs in 20.35 and verification checks belong in 30-series documents.
