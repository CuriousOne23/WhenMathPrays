# 50.33_CIL Design Support

## 1. Purpose and Scope

This design support specification defines deterministic Conversation Integration Layer (CIL) behavior, invariants, and IO contracts promoted from canonical CIL requirements and 30-layer verification evidence.

## 3. Contracts and Invariants

- CIL intake preserves deterministic FIFO ordering across equivalent sequence-controlled inputs.
- Snapshot coherence remains pinned to explicit deterministic snapshot identifiers.
- Classification, tie-break, and ambiguity escalation behavior is deterministic under active profile policy.
- CIL does not instantiate inquiry channels directly; GB mediation is required.
- Unsupported profiles and invalid control states are rejected with fixed deterministic reason codes.
- Routing and supervisory-state transitions occur only at deterministic safe boundaries.

## 4. Operation Flow and State Transitions

- Accept deterministic intake packets into a FIFO queue.
- Process next packet under active profile threshold policy.
- Integrate directly when confidence is sufficient, or escalate ambiguity to GB through deterministic request channels.
- Apply timeout/default or late-approval re-entry outcomes through deterministic supervisory response handling.
- Persist append-only audit records for intake, escalation, reject, and re-entry outcomes.

## 5. Data and IO Contract

Input fields:
- `event_type` (`ingest|process_next|gb_response|profile_change`)
- `sequence` (int, monotonic)
- `safe_boundary` (bool)
- `payload` (JSON object)
- `snapshot_id` (string)
- `packet_id` (string)
- `confidence` (float in [0,1])
- `decision` (`approve|deny|timeout|late_approve`)

Output fields:
- `sequence`
- `pending_queue`
- `integrated_packets`
- `escalation_requests`
- `audit_log`
- `active_profile`
- `verification_digest`

## 6. Observability and Logging

- Intake, classification, escalation requests, supervisory responses, and reject paths must emit append-only audit records.
- Audit records must carry fixed deterministic reason codes for accept/reject/re-entry outcomes.
- Determinism evidence must remain replay-visible through canonical artifact outputs.

## 7. Verification Obligations

- Deterministic FIFO intake and snapshot coherence scenarios are mandatory.
- Deterministic classification/escalation and late-approval re-entry scenarios are mandatory.
- Negative-path scenarios must cover sequence violations, safe-boundary violations, direct inquiry bypass attempts, and unsupported profile states.

## 9. Change Control

- Any new CIL event type, supervisory response enum, or profile mode requires synchronized updates to 10.50.33, 30.33 verification ledgers, and this design support specification.
- TCU measurement fields are not mandatory at this design stage; they become required only when CIL enters the TCU budgeting promotion path.

## CPU Execution Cycle Design Obligations (per 10.50.33.TCU and 20.150)

### 50.34.TCU.10 Design for bounded per-tick cost
- Obligation ID: 50.34.TCU.10
- Satisfies: 10.50.33.TCU.10
- Design notes:
  - Identify cycle-consuming per-tick operations in the CIL subsystem.
  - Define expected O() behavior for each operation.
  - Ensure no unbounded loops or data-dependent worst-case growth.
  - Document dependence on input cardinality N and explicit bounds.

### 50.34.TCU.20 Design for deterministic behavior
- Obligation ID: 50.34.TCU.20
- Satisfies: 10.50.33.TCU.20
- Design notes:
  - Define which code paths are active for a given scenario ID.
  - Ensure fixed seed + fixed N + fixed configuration + fixed hardware/runtime profile
    produces the same execution path and cycle band.

### 50.34.TCU.30 Provisional-budget vs measured-budget
- Obligation ID: 50.34.TCU.30
- Satisfies: 10.50.33.TCU.30
- Design notes:
  - Document provisional-budget assumptions (min/typ/max and percent tick budget).
  - Specify where measured-budget will be recorded (30 capsules and 40 harness artifacts).
  - Specify harness evidence fields for future TCU promotion: scenario_id, seed, N, config_hash, cycles_measured.

### 50.34.TCU.40 Integration with scheduler and global tick budget
- Obligation ID: 50.34.TCU.40
- Satisfies: 10.50.33.TCU.40
- Design notes:
  - Show how provisional-budget fits into the global tick budget.
  - Define backpressure, shedding, or deferral behavior when measured-budget exceeds target.
