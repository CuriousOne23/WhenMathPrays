## 1. Purpose and Scope

The **User Preference Integrator (UPI)** orchestrates clarification outcomes into authorized USP commits. Responsibilities:

- FIFO processing of `clarification_event_v1` records
- GB governance gate before every commit attempt
- `UpiCommitRecord` production with `gb_reason_code` and audit append
- monotonic `integration_seq` ordering
- bounded pending-commit and USP-cap enforcement
- replay-identical commit records under identical event sequences

UPI **does not**:

- mutate `semantic_core`, `exec_plan`, `exec_trace`, or TP/MTP directly
- bypass GB evaluation on commit paths
- write USP except via `USPStore.apply_commit`

**Cross-layer band:** 40.103 / 30.103 / 10.50.103 / 50.103.

## 3. Contracts and Invariants

- **FIFO orchestration (HLR-005–008):** Events processed in `integration_seq` order; incomplete events reject deterministically.
- **GB gate (HLR-009–011):** Approve → `COMMITTED` + `GB_APPROVED`; veto → `GB_VETOED`, USP unchanged, audit append only.
- **Determinism (HLR-012–014):** Replay-identical records; monotonic integration sequence.
- **Bounds (HLR-015–016):** USP cap overflow and pending-commit cap enforced before commit.
- **Audit (HLR-022):** Append-only `audit_log` on all paths.
- **Delegation (HLR-10.50.103-001):** USP mutation only through `USPStore.apply_commit`.
- **Live GB (HLR-10.50.103-002):** `gb_evaluator=evaluate_upi_commit` from 40.36/30.36 W2 harness.

## 4. Operation Flow and State Transitions

1. CIL emits `clarification_event_v1` with monotonic `integration_seq`
2. UPI `process_event` or `process_fifo` receives ordered events
3. GB evaluator returns approve/veto + `gb_reason_code`
4. On approve: `USPStore.apply_commit` → `UpiCommitRecord` with `COMMITTED`
5. On veto: record `GB_VETOED`; USP version unchanged

**FIFO restore:** out-of-order input lists re-sorted by `integration_seq` before processing (`positive_fifo_two_events`).

## 5. Data and IO Contract

**`clarification_event_v1` (input)**

- `event_id`, `integration_seq`, `pattern`, `expansion`, `scope` (conversation)

**`UpiCommitRecord` (output)**

- `commit_status`: `COMMITTED` | `GB_VETOED` | `REJECTED`
- `gb_reason_code`: e.g. `GB_APPROVED`, `GB_VETOED`, harness stub codes
- `usp_version_id`, `usp_version_ref` (on successful commit)
- `reason_codes[]` on reject paths

## 6. Observability and Logging

Append-only audit on every path. `gb_reason_code` propagated for downstream replay and COB-visible audit. Veto paths must leave USP snapshot unchanged (evidenced jointly with 30.36).
