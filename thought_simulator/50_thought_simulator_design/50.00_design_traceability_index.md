## Index maintenance

Update this index in the **same change set** when:

- A level-1 `50.*.md` design file is **added, renamed, or removed** (excluding `50.00` and level-2 `50.xx.yy_*`)
- Cross-layer **paths** or anchors in the table change
- A **placeholder** row becomes a real design file

Do **not** update this index for **content-only** edits inside an existing design spec.

Process guide: [50.05_software_spec_construction_guide.md](50.05_software_spec_construction_guide.md). 30-tier module list: [30.01_verification_inventory_index.md](../30_verification/30.01_verification_inventory_index.md).

## Change Control

This index is a release-coupled governance artifact for **structural and mapping** changes. Path corrections, row additions/removals, and anchor updates must stay auditable.

## Deterministic Update Rules

Rows in the mapping table must remain alphabetically sorted by Macro / Domain (case-insensitive lexical order). Sorting and comparisons must use deterministic ordering only; no timestamp, filesystem order, or locale-dependent ordering is allowed.

## CI enforcement

| Check | Mode | What it compares |
|-------|------|------------------|
| GitHub Actions `validate_design_traceability.yml` | **Blocking** on PR/push | Level-1 `50.*.md` files ↔ table design-doc column |
| `scripts/validate_50_traceability_index.py` | **Warning** (local pre-PR) | Same structural rules; level-2 `50.xx.yy_*` excluded |

Failure / warning conditions:

- Any level-1 design file on disk is missing from the table.
- Any table row references a non-existent design file.
- Table rows are not alphabetically sorted by Macro / Domain.

## Backward-Flow Forward-Equivalence Checkpoint

When a backward-flow transaction is initiated from a 20 -> 10 canonical update, this index participates in the completion gate for design synchronization.

Required checkpoint outcomes:

- all 50-series design files remain represented correctly in this table after synchronization
- 10-series anchor and 30-series verification paths remain valid for updated rows
- any changed mapping is updated in the same transaction as corresponding design-file changes
- backward-flow execution log records final assertion: `Forward-Equivalence State: YES`
