# 50.36 — Global Basin (GB) Design Specification

## 1. Purpose

Translate the canonical requirements of 10.50.36 into a concrete, implementable design for the Global Basin (GB), incorporating verified behavior from 40.36 prototypes and deterministic evidence from harness execution.

---

## 2. Design Overview

GB is a **non‑mutating**, **asynchronous**, **deterministic** supervisory subsystem that evaluates global semantic stability and issues bounded supervisory actions at safe boundaries.

GB operates as:

- a pure supervisory evaluator  
- a deterministic classifier  
- a bounded TCU consumer  
- a safe‑boundary action selector  
- a global governance authority for IB/OB/COP lifecycle events  

---

## 3. Design Principles

- **Non‑mutation** — GB SHALL NOT modify TP/MTP state.  
- **Safe‑boundary gating** — All actions apply only at safe boundaries.  
- **Determinism** — Identical inputs produce identical outputs.  
- **Fallback precedence** — TCU fallback overrides event‑type actions.  
- **Asynchronous operation** — GB never blocks TS.  
- **Replayability** — All decisions are reconstructible from logs.  

---

## 4. Subsystem Architecture

### 4.1 Components

- **Classifier** — maps event_type + metadata → request_class  
- **TCU Manager** — enforces bounded TCU envelope  
- **Action Selector** — deterministic supervisory action engine  
- **Log Engine** — append‑only supervisory log generator  
- **Reference Generator** — deterministic GB reference IDs  

### 4.2 Data Flow

TS → GB: event
GB → Classifier → TCU Manager → Action Selector → Log Engine
GB → TS: supervisory_action + diagnostics + log_entry


---

## 5. Supervisory Action Model

### 5.1 Action Taxonomy

GB supports:

`Stop, Slow, Dampen, Escalate, SafeMode, ReduceDepth, SuspendInquiry, Crop, Prune, Reshape, Kill, Approve, Deny, None`

### 5.2 Fallback Precedence

If `tcu_fallback = True`, GB SHALL return:

supervisory_action = SafeMode


regardless of event_type.

This is confirmed by 40.36 harness evidence.

---

## 6. TCU Envelope Design

- **min** = 1  
- **typ** = 3  
- **max** = 5  

TCU usage is deterministic and SHALL degrade to SafeMode when exceeding typ.

---

## 7. Logging Design

Each supervisory decision SHALL produce:

- gb_reference  
- event_type  
- sequence  
- request_class  
- supervisory_action  
- rationale  
- safe_boundary flag  
- tcu_usage  
- tcu_fallback  
- overflow diagnostics  

Logs are append‑only and deterministic.
