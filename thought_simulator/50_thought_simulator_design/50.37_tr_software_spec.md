## 1. Overview

This document provides the software specification for the Thought Router (TR) module, promoted from the successful 40.37 exploratory prototype.

## 2. Purpose

The Thought Router is responsible for the initial deterministic routing of input thoughts/messages to the appropriate processing basin.

## 3. Requirements Traceability

- **10.50.37.TR.10** Deterministic Routing
- **10.50.37.TR.20** Basin Selection Rules
- **10.50.37.TR.30** ΔH% Assignment
- **10.50.37.TR.40** Input Validation

## 4. Functional Specification

### 4.1 Core Interface
```python
class ThoughtRouter:
    def route(self, input_message: dict) -> dict
```

### 4.2 Routing Logic

- If input contains mathematical keywords → `math_basin` (ΔH% = 0.15)
- If input contains reflective/thought keywords → `thought_basin` (ΔH% = 0.08)
- Otherwise → `general_basin` (ΔH% = 0.05)
- Invalid input → `{"route": "error", "reason": "invalid_input"}`

### 4.3 Non-Functional Requirements

- **Determinism**: Same input must always produce identical output
- **Performance**: O(1) routing decision (simple keyword check)
- **Separation of Concerns**: Routing only — no meaning construction
- **Observability**: All decisions include route + delta_h

## 5. Design Decisions

- Rule-based implementation (no ML / embeddings in this layer)
- Fully deterministic (no randomness)
- Minimal state (stateless router)
