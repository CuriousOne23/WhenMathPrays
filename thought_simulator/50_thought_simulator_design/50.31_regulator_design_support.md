# 50.31_Regulator Design Support

## 1. Purpose and Scope

This design support specification defines regulator decision behavior, invariants, and IO contracts promoted from canonical regulator requirements and verification evidence.

## 2. Source Index

- `10_thought_simulator_req/10.50_regulator_requirements.md`
- `30_verification/30.50_regulator_prototypes/30.50_regulator_prototypes_verification_capsule.md`
- `30_verification/30.50_regulator_prototypes/30.50_regulator_prototypes_requirements_delta.md`
- `30_verification/30.30_verification_glossary.md`

## 3. Contracts and Invariants

- Regulator behavior is deterministic for equivalent inputs in deterministic mode.
- Policy mode semantics are explicit and auditable.
- Validation rejects unsupported policy identifiers and invalid pressure values.

## 4. Operation Flow and State Transitions

- Accept `regulator_input` payload.
- Validate contract fields.
- Apply selected policy (`clamp` or `attenuate`) to produce action payload.
- Emit replay-safe digest and decision metadata.

## 5. Data and IO Contract

Input fields:
- `policy` (string)
- `pressure` (float, >= 0)
- `max_delta` (float, > 0)

Output fields:
- `action`
- `applied_delta`
- `rationale`
- `verification_digest`

## 6. Observability and Logging

- Every regulator decision must include digest-bearing output for replay comparability.
- Validation errors must return deterministic message classes.

## 7. Verification Obligations

- Deterministic replay scenario coverage is required for release coupling.
- Policy comparison scenario coverage is required when adding new policies.
- Negative-path coverage for invalid policy and invalid numeric input is mandatory.

## 8. Traceability

- HLR anchor: `HLR-20.450-001`, `HLR-20.450-002`, `HLR-20.450-003`
- Verification evidence: `regulator_verification_run_2026-05-28.json`
- Canonical requirement anchor: `10.50_regulator_requirements.md`

## 9. Change Control

- Any new policy mode requires update to canonical requirements and verification scenario ledger in `30_verification` before release coupling.
