## 1. Purpose and Scope

The **Core Data Structs (Track H conversation layer)** band defines versioned, data-only struct shapes and helpers for:

- `UspSnapshot` — immutable shorthand rule snapshot for IIInB read-only load
- `InputRepairTag` — intake-bound repair audit tags with canonical ordering
- `ConversationLayerState` — conversation-scoped partition separate from four runtime envelopes
- audit exports: `ClarificationEvent`, `UpiCommitRecord`, `UspVersionRecord`, `CobUspSnapshotPin`
- canonical JSON serialization and content-addressed digests (`compute_usp_version_ref`)

This band **does not**:

- implement USP commit logic ([50.102](50.102_usp_design_spec.md))
- orchestrate UPI FIFO ([50.103](50.103_upi_design_spec.md))
- model full MTP / four-envelope internals (W3+)

**Cross-layer band:** 40.50 / 30.220 / 10.50.220 / 50.100.

## 3. Contracts and Invariants

- **Envelope separation (HLR-021, 025):** USP rules, clarification payloads, and repair tags SHALL NOT reside in `semantic_core`, `exec_plan`, or `exec_trace`. `ConversationLayerState` rejects forbidden keys (e.g. `semantic_core`).
- **Snapshot immutability (HLR-022):** `UspSnapshot` round-trips canonically; `usp_version_ref` is content-addressed digest over canonical JSON; IIInB digest compatibility evidenced (`positive_iiinb_digest_compat`).
- **Audit ordering (HLR-024):** `InputRepairTag` export sorts by `(segment_ref, iiinb_event_id)`; audit struct exports are data-only and versioned.
- **Schema gate (HLR-019):** Unknown `schema_version` rejects with fixed reason `STRUCT_RSN_001_UNKNOWN_SCHEMA`.
- **Golden fixture (HLR-10.50.140-002):** `golden_usp_snapshot_v1.json` is the regression anchor for round-trip and digest.

## 4. Operation Flow and State Transitions

Structs are **passive data contracts** — no autonomous lifecycle. Typical compose flow:

1. USP builds `UspSnapshot` → `compute_usp_version_ref`
2. IIInB pins `usp_version_ref` for repair pass (read-only)
3. CIL emits `ClarificationEvent` → UPI → GB → USP commit
4. COB pins `CobUspSnapshotPin` on conversation scope
5. Export/hash uses `canonical_json` + `canonical_digest` before audit append

## 5. Data and IO Contract

**Schema identifiers (normative)**

| Struct | `schema_version` |
|--------|------------------|
| `UspSnapshot` | `usp_snapshot_v1` |
| `ConversationLayerState` | `conversation_layer_v1` |
| `ClarificationEvent` | `clarification_event_v1` |

**Serialization**

- `canonical_json(payload)` — sorted keys, `separators=(",", ":")`, `ensure_ascii=True`
- `compute_usp_version_ref(snapshot)` — SHA-256 over canonical snapshot export

**Key struct fields (reference)**

- `UspSnapshot`: `rules[]` with `rule_id`, `pattern`, `expansion`, `state` (`ACTIVE`/`SUPERSEDED`/`REVOKED`)
- `InputRepairTag`: `segment_ref`, `iiinb_event_id`, repair outcome fields
- `UpiCommitRecord`: `commit_status`, `gb_reason_code`, `usp_version_id`, `usp_version_ref`

## 6. Observability and Logging

Struct module emits deterministic reject reason codes on schema violations. Digest exports support replay comparability across USP, IIInB, and COB pin paths.
